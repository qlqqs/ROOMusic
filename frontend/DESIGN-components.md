# ROOMusic Classical 落地设计指南：组件、播放与页面能力

> 本文是 [Classical 落地设计指南](DESIGN.md)的第 5–7 节；阅读规则、来源与“原型事实 / 落地规范 / 待确认调整”三种状态的含义见那份文件的第 1 节，文中“M1a 实现”“M4 实现”等标注的含义同样以它的开头说明为准。

## 5. 组件合同与完整状态

| 组件 | 保留的 Classical 语言 | 落地合同 |
| --- | --- | --- |
| 主导航/搜索入口 | 细图标、分组小标题、整行金色轻底 | 链接负责导航，按钮负责命令；当前页有可访问语义；未知总数不显示原型数字；命令面板快捷键不是 M1 必做能力 |
| Release 列表/封面 | 带裱边的正方形封面、标题与元信息分级 | 有界分页，保持实体 ID；缺封面、加载和图片失败分别处理，不自动拉外部封面；卡片主链接与操作按钮不嵌套 |
| 版本/介质选择 | 下边线标签、紧凑分段选择 | 版本选择不等于播放；多 Medium 按真实层级和顺序；只有批准后的真实聚合数据才展示跨 Release 标签和对比（M4 起：管理员指定的默认版本标签与版本对比） |
| 曲目行/队列项 | 序号、名称/署名、右对齐时长，细线分隔 | 播放与菜单用明确控件，不能仅靠可点击 `div`；当前项有文字/图标语义；未知时长不伪造；支持长标题 |
| 证据/差异 | 字段、原值、新值、来源分栏，差异下划线 | 删除线不能是唯一差异提示，增加“原值/建议值”；未知、冲突、截断分别显示；扫描观察不冒充人工修正 |
| 按钮/输入 | 透明底、`4px` 圆角、`1px` 描边 | 默认、悬停、按下、焦点、禁用、提交中完整；输入有 label 与关联错误；禁用原因可被键盘/读屏获取 |
| 标签/状态 | 小矩形或功能性标记 | 状态文字不可只剩颜色或圆点；“需要关注”不是“已经确认错误”，缺失值不是确定的异常 |
| 目录/扫描 | 紧凑表格、状态与诊断分区 | M1 展示真实状态/诊断计数；M5 ⑥ 建立了服务端持久化的进度合同（先数文件、再逐个目录读取标签→整理专辑→保存，整体按各目录文件数加权、不倒退），据此显示真实的工作进度百分比、当前阶段与“第 i / 共 R 个目录”；仍不显示预计剩余时间或入库漏斗，不用动画、计时或诊断数代替进度；取消请求不等于已取消 |
| 成员/目录操作 | 朴素表单、操作范围与记录 | 只暴露现有允许动作；后端确认后再显示成功；恢复目录不是回滚全部资料库 |
| 对话框/面板 | 浅表面、细边框、最高层级轻阴影 | 标题、焦点约束、取消/关闭与焦点恢复明确；不能只靠点遮罩关闭；阻塞性错误留在操作区，不仅短 toast |
| 短反馈 | 小面积描边、轻阴影 | 只确认用户刚触发且已被服务端确认的结果；失败有下一步；不常驻“已载入”占据内容区 |
| 播放器/歌词/Steward | 延续同一字色与边线体系 | 分阶段启用；播放器必须由媒体真实事件驱动；歌词需要真实来源；Steward 文字不是执行或审批凭据 |

**M1b 实现**（专辑列表与详情的组件形态，细节见[前端组件规范](../.trellis/spec/frontend/component-guidelines.md)）：

- 专辑卡片：整张卡片是一个链接（里面没有按钮），显示封面、标题、专辑艺人（没有则用艺人）与“年份 · 介质数（多于一张才写）· 曲目数”，多版本时有“N 个版本”标签，需要关注时有“需要关注”标签；每页 48 张，顺序就是接口的顺序，没有排序控件。
- 封面四态：加载中（同尺寸静态底色）、已加载、没有封面（深色底上排标题的确定性文字版面）、加载失败（同样的版面加“封面无法加载”，详情页可重新加载）；卡片里的封面是装饰，详情页的封面有替代文字。
- 版本导航：多于一个版本时才出现，用链接加 `aria-current`（不是 ARIA 标签页）：选择写进地址，前进、后退与分享都成立；链接说明取成员摘要里有的字段（年份、介质类型、介质与曲目数）。
- 介质逐段列出：每张介质一个带标题的分段，多于一张时顶部有“跳到第 N 张”的页内链接（把焦点放到分段标题上，不改地址）；曲目行是序号、标题、与专辑艺人不同的曲目艺人、署名（“角色：姓名”）、时长（未知写“—”）与 CUE 标记，不显示来源文件名。
- 证据：详情底部折叠的“来源与证据”，摘要（字段、来源、可信度、处理方式）所有登录用户可读；管理员展开后才能点“查看完整证据”（字段值、候选、原因码与归组依据）。不在折叠面板里另加“需要关注”的解释段落；人工修正的字段只用一句话说明页面上显示的是改过的值。

**M3 实现**（管理员的受治理操作，组件约定见[前端组件规范](../.trellis/spec/frontend/component-guidelines.md)；普通成员没有任何编辑入口）：

- 专辑详情头部的操作区：“编辑发行信息”“归入其他专辑…”，组内多于一个版本时还有“移出为独立专辑”；操作结果就近显示在操作区的行内提示里（成功提示带“撤销”，不用 toast，不用成功动画）。
- 编辑发行信息：模态对话框，八个字段各一个分组，三选一（使用扫描值 / 自定义 / 留空，标题与专辑艺人没有“留空”），写明扫描值；扫描结果不确定的字段多一个“确认扫描值”；
  只提交动过的字段，底部的操作条固定，窄屏上保存按钮始终在视野里；409 时保留草稿并显示最新状态。
- 归入其他专辑：模态对话框，按标题搜索，结果是带封面的单选列表（不含当前专辑），选中后用状态行预览“归入后会和《…》的 N 个版本放在一起”，确认才提交；移出为独立专辑是带影响说明的确认对话框。
- “人工修正”标记：字段显示的是管理员改过的值时，在头部的年份与流派旁、证据表的字段名旁与编辑对话框的字段标题里出现，文字加笔图标；证据里的扫描结论照旧，不把人工选择写成高置信标签。
- “修改记录”：专辑详情底部、“来源与证据”之后的折叠区块（与证据同一种折叠面板），展开后列这个版本最近 5 条记录并链接到“全部记录”；撤销的结果提示放在折叠区块外。
- “操作记录”页（导航“资料库”下，管理员）：一张表——时间、操作者、专辑（链接）、改动（类型名加逐行的“字段：前 → 后”）、操作；可撤销的行有“撤销”，其余在同一位置写出原因（已撤销、之后又有修改……）；
  最新的在前，每页 20 条，可按版本筛选并写明在看哪张专辑的记录；窄屏上每行堆叠成“标签：值”。撤销前的确认对话框写明会改回什么。
  这是账簿式的记录，不是审批队列，也不是“回滚到某一点”：只有最近一次修改可以撤销，撤销本身也留一条记录且不能再撤销。

**M4 实现**（默认版本与版本对比，组件约定见[前端组件规范](../.trellis/spec/frontend/component-guidelines.md)）：

- 默认版本：全库一个、由管理员逐张指定；没有指定的专辑仍按“年份最早”自动选择。它成为专辑的代表版本：专辑卡片的封面与标题、列表排序、打开专辑时先显示的版本、
  版本导航的顺序都跟着变。版本导航里生效中的默认版本带“默认版本”标签（文字加书签图标，所有成员可见），自动选择时没有任何标签。
- 设定入口在专辑详情头部（管理员，多于一个版本时）：不是默认版本的版本有“设为默认版本”，包括自动选出的那个（钉住之后，以后归入更早的版本也不会把它挤下去）；
  默认版本上是“改回自动选择”。不弹确认对话框，结果就近提示并带“撤销”，页面停在刚才那个版本。移出默认版本时，确认对话框说明专辑改按自动规则、它回来时会重新成为默认版本。
- 版本对比：版本导航标题旁的“对比版本”，所有登录成员可用。对话框宽 `min(980px, 视口宽度减两侧边距)`、最高 `90vh`，标题行与“关闭”固定、内容在对话框内部滚动；
  “字段 × 版本”的表格以版本 1（默认版本或自动选出的代表版本）为基准，与它不同的格加金色下划线并带读屏文字；没有值写“—”；人工修正带标记；
  全部为空的行不出现，标题与专辑艺人只在不同时出现；音频格式写具体参数（如“FLAC · 24 bit / 96 kHz”），多种格式逐项注明曲目数，不写“最高音质”之类的结论；
  列头的“查看这个版本”关闭对话框并切换到该版本。容器窄于 640px 时每个字段堆叠成“版本 N：值”。
- 操作记录：类型名“设定默认版本”，改动写成“默认版本：自动选择 → 《标题》（2015 · Remaster）”；“专辑”列对这类记录链接到专辑本身；
  专辑详情的“修改记录”同时列出这个版本的记录和这张专辑的默认版本记录。

### 数据与操作状态

以下是界面必须表达的含义，不是要求后端新增同名枚举或端点：

| 状态 | 用户应看到什么 / 下一步 |
| --- | --- |
| 首次加载 | 同区域轻量占位并保留结构；不出现示例音乐、不把等待画成空库 |
| 就绪 / 空结果 | 展示真实内容；区分尚无资料、筛选无结果、权限不可见。可清空筛选；普通用户不出现管理员添加入口 |
| 刷新中 / 旧数据 | 可辨认旧结果与刷新状态；失败仍可局部重试，不把过期结果当作管理写入的最新依据 |
| 网络或服务异常 | 保留可安全展示的上下文，说明可重试动作；不泄露堆栈或主机路径，不自动切到演示模式 |
| 会话失效 `401` | 进入会话恢复；清除当前身份缓存与私人状态，M2 停止播放，避免下一账号看到前一账号内容 |
| 无权限 `403` | 当前动作被拒绝；不等同于注销，不以重试按钮制造可越权的假象 |
| 冲突 `409` | 保留非敏感草稿，解释资源已变化，提供刷新/比对/重新提交；不自动盖掉别人的修改 |
| 写入中 / 成功 / 失败 | 防重复提交；按资源/操作的真实结果结束等待，接受请求不等于执行完成；失败不显示成功勾号 |
| 扫描运行 / 取消请求中 | 以服务端状态与 `cancel_requested_at` 为依据；启动、取消操作与进度轮询区分；取消请求中仍显示进度，不立即变成“已取消” |
| 扫描完成 / 失败 / 已取消 / 不完整 | 不能全部归为“完成”；失败、取消、不完整或离线均不能暗示已执行全部目录的缺失对账（停下前确认被新文件替换的旧曲目仍会标为缺失，这与对账不同）；进度停在停下的位置、不补满，只有成功是 100%；报告分别为完整（成功）、只含已保存变化（非成功）或“没能生成” |
| 恢复可用 / 不可用 | 只有后端支持的逆操作才提供入口；扫描记录、自然语言说明或前端点击历史不能生成恢复点 |

组件只接收解码后的类型与显示模型并发出用户意图。会话、角色、根目录、revision、幂等和恢复的最终决定都在后端，
隐藏控件或前端校验不构成授权。普通浏览界面只用安全资源标识；管理视图也仅展示服务端按权限明确返回的信息。

## 6. 播放与队列：M2a 真实媒体事件驱动

[既有队列交互合同](../.trellis/spec/frontend/player-design-guidelines.md)是可迁移的用户意图；旧模拟时钟、
本地个人库、演示入口与存储格式不是恢复目标。综合原型的定时自增进度、固定曲序、生成歌词和硬编码信号路径均不得成为播放器实现。

| 用户动作 | 必须保留的语义 |
| --- | --- |
| 立即播放歌曲或列表 | 替换当前播放上下文，并从明确选中的项目开始；不是偷偷追加 |
| 下一首播放 | 插入当前项之后；不切走当前播放 |
| 加入队列 | 追加到队尾，不中断当前播放，不重置进度 |
| 排序/移除条目 | 按队列条目身份操作；同一 Track 可有多个队列条目，不能用 Track ID 删除所有重复项 |
| 收藏去重 | 以曲目身份而非队列条目身份去重；收藏与歌单由服务端按用户保存（M5 ② ③，已实现），同一首在一个歌单里只出现一次；“存为歌单”按队列顺序只留第一次出现的；不恢复旧本地库作为权威 |
| 自然结束与循环 | 顺序模式末曲暂停；列表循环回到首曲；单曲循环仅作用于自然结束，手动切歌仍切换 |
| 随机与上一首 | 可选曲目多于一首时避免连续重复，上一首可回到实际播放的上一项，而不是再随机一次 |
| 未知时长/不可定位 | 显示未知值，禁用无依据的拖动，不靠模拟时钟推断结束；真实结束仍由媒体事件报告 |
| 刷新恢复 | M2a 使用按账号命名的 sessionStorage，仅存标识/模式/位置，恢复后保持暂停；不沿用旧个人库格式 |
| 退出、失效、切换身份 | 停止当前音频并清理身份相关的队列/缓存；不跨用户继承历史或收藏 |

M2 需补齐无曲目、等待媒体、缓冲、播放、暂停、结束、格式不支持、来源缺失、鉴权失败、网络中断、
重试和拖动失败等状态；真实播放事件与明确错误决定状态，不因按下按钮就显示“正在播放”。

信号路径区分“源文件参数”“服务端传输/派生处理”（直出为“原文件直出”，ALAC 为“无损转换”并写明 PCM 核对）“浏览器已知状态”“未知系统输出”，不声称 Bit-perfect、
硬件 DAC 格式或硬件音量。歌词没有授权来源、内容或时间戳时显示缺失/纯文本状态，不能生成占位歌词冒充真实内容。
跨版本切换与曲目对应关系须待 M4 数据合同；不能按相同数组下标认定为同一首录音，也不把高采样率直接命名为“最高音质”。

### M2a 的落地合同

队列为空不显示底栏；桌面底栏 68px 横跨工作区，窄屏固定底部，ResizeObserver 根据实际高度预留主内容留白并计入安全区。
正在播放页提供完整控制、信号路径与按条目 ID 操作的队列；专辑卡片仍不加播放按钮，播放入口只在详情。
导航分为聆听/资料库，只有已交付页面出现（配置类管理页在设置里，见 DESIGN.md 第 4 节）；设置分栏宽度 `--layout-settings-nav-width`（176px）。菜单按钮采用键盘模式，不依赖最低浏览器版本未覆盖的 Popover API。
播放进度有“播放进度”名称与时间 aria-valuetext；仅曲目变化与错误公告，不能逐秒打扰读屏。

入口与同步会话结束清理见[播放与个人状态规范](../.trellis/spec/frontend/playback-and-personal-state.md)，API/源文件版本与10秒复核见
[播放合同](../.trellis/spec/backend/playback-contracts.md)。格式仍以真实自动化与[三组手工实播记录](../.trellis/tasks/10-06-m2a-acceptance-followup/research/manual-acceptance.md)收口；
ALAC 不直出（只有 Safari 能解码）：M2b 起服务端用 ffmpeg 无损转换成 FLAC 后交付，等待转换时显示“正在准备”，信号路径写明无损转换；
ffmpeg 不可用时 ALAC 仍标注“这种格式目前不能直接播放”。精确 CUE 分轨与服务端历史不在 M2b 范围。

### M2b 歌词的落地合同

歌词只来自音频文件内嵌的标签（扫描时提取，接口解析，规则见[歌词合同](../.trellis/spec/backend/lyrics-contracts.md)），没有就写“这首曲目没有内嵌歌词”，
不生成占位歌词。正在播放页首屏是“封面 | 歌词”两栏，标题、艺人、专辑、状态与控制在两栏下方（容器宽度小于 760px 时单栏：封面、标题与控制、歌词）；
歌词区域与封面同高，内部滚动，上下渐隐，来源说明在底部（“内嵌歌词 · 逐行同步 · 点任一行跳到该处”）。
与原型的差异：当前行只改颜色并加左侧标记，不放大字号（原型放大当前行并带 `.3s` 字号过渡，每次换行都会让整份歌词的行高跳动）；
已唱过的行用次要文字色，三种颜色对背景的对比度都不低于 4.5:1。跟随滚动把当前行放在中部，用户一旦自己滚动就暂停并出现“回到当前行”；
媒体可拖动时每行是按钮（点击或 Enter 跳转，Tab 只停在当前行，方向键移动），不可拖动时是普通文本；不设 `aria-live`，当前行变化不播报。
页面布局与交互细则见[播放器规范](../.trellis/spec/frontend/player-design-guidelines.md)的“M2b 歌词面板”。

## 7. 页面能力与阶段边界

下表的阶段归属按 2026-09-28 批准的 Core 1 路线（D1、D4），不是交付现状或自动排期。现有路由已对照
[app.go](../backend/internal/app/app.go)（路由表由各 `httpapi` 包注册），字段依据
[projection.go](../backend/internal/catalog/projection.go)、[scans.go](../backend/internal/library/scans.go)
和 [root_operations.go](../backend/internal/library/httpapi/root_operations.go)。具体 DTO 与错误合同仍由相应规范/子任务维护。

| 页面/场景 | 已有 API 依据 | 缺口与 M1 的诚实呈现 | 建议阶段 |
| --- | --- | --- | --- |
| 初始化/登录/会话 | `setup/status`、`setup/admin`、`auth/login/logout/me` | 原型未提供完整认证流程，必须补齐；不能因已有后端就声称已有可用前端 | M1a |
| 概览 | 已公开 Release 列表、登录用户可见扫描状态与进度、管理员目录资源；M5 ⑥ 的 `release-groups/recently-added` | 只组合可获得的数据，不推算全库容量、全部曲目数或“本周新增”之类的统计；“最近新增”只显示接口给的最多 8 张专辑（按当前可见版本里最早的加入时间），且只显示能排满的行（宽屏一行，窄屏最多两行），没有时整块隐藏；“最近播放”只显示服务端保存的本人记录（最多 8 张专辑与上次播放时间，不画进度、剩余时间；M5 ①起有“全部历史”链接到历史页）；缺的区块隐藏 | M1a 简版；P：概览“最近播放”（已实现，可清除自己的历史）；个人库随 M5 |

| 艺人 | M5 ⑤ 的 `artists`、`artist-candidates` 与各摘要上的 `artist_refs` | M5 ⑤：导航“聆听”下的“艺人”列表（查找、首字母分组：A–Z、假名、#；按名字或专辑数排序，按专辑数时不分组；只看某个角色），艺人页（名字、作为专辑艺人的专辑、按角色分栏的参与曲目，播放全部、随机播放与心形）；收藏页“艺人”一栏；专辑页、曲目署名、播放器、正在播放、历史、收藏、歌单与搜索结果里的艺人名是链接（专辑卡片上仍是文字），艺人数据还在整理时都是纯文字、不加说明。前端**不自行按字符串拆名或认人**，只消费后端给出的 `artist_refs`；后端按版本化的规范化键自动归一，管理员可以合并、拆开（别名或按专辑）、改名，资料库下的“可能是同一位”只是提示。传记、照片与合作网络不做 | M5 ⑤（已实现） |

| 收藏/历史/播放列表 | P 的播放历史；M5 ② ③ 的收藏与歌单接口（`/me/favorites…`、`/me/playlists…`） | 不沿用旧本地个人库或演示身份，只有本人可读可改。M5 ①“我的音乐”的历史页签（`/me/history`）按曲目汇总、最近播放倒序，可播放、入队、逐首移除与清除全部。**M5 ② ③**：“我的音乐”的页签顺序改为收藏、歌单、历史，`/me` 默认打开收藏；专辑详情头部与每一行曲目、历史与收藏与歌单的每一行、播放器栏与正在播放页都有心形（已收藏为实心，点一下切换，各处同步）；“收藏”页签分“专辑 / 曲目”，按收藏时间倒序，页里取消收藏的行留到离开为止，缺失曲目与暂时不可用的专辑灰色显示仍可取消；“歌单”页签列出歌单（封面拼图、曲目数、总时长；有时长未知的曲目时写“1 小时 20 分以上”），详情可拖动或用菜单（上移、下移、移到最前、移到最后）排序，移除后可撤销，改名与删除（确认）；曲目“更多”里的“添加到歌单…”、专辑头部“添加到歌单…”（当前版本整张）与队列“存为歌单”都能加入；“播放全部”先去掉缺失的再取前 10,000 首替换队列 | P 播放历史（已实现）；M5 ① 历史页面；M5 ② ③ 收藏与歌单（已实现） |
| 元数据问题 | Release 候选字段、关注计数与证据；M4 的问题列表、版本的问题与核对接口 | M1 可查看现有证据；M3 起管理员可在专辑详情修正字段、调整归组并撤销；**M4 第二项**：管理员的“元数据问题”页（导航“资料库”，不显示数量）按版本列出三类问题，来源与介质类型、归组冲突、缺失曲目可以标记为已核对（不弹确认，可撤销，情况变了重新提醒），专辑详情有“查看问题”；普通成员只看到“需要关注”的数字变化。**M4 第三项**：管理员的“待认领”页（导航“资料库”，不显示数量）列出已不可见、留有人工修改的旧版本，推荐文件或目录相同的新版本、也能搜索别的版本，预览逐项说明（迁移、因为新版本已有而保留、默认版本改回自动选择、缺失曲目的核对不迁移）后一次认领，不弹确认、可撤销；专辑详情的“可能接替了已不可见的《…》”点进去就是认领 | M3 基础、M4 第二项与第三项（2026-10-17 已实现） |
| 扫描目录/过程 | `library-roots`、`scans`（含管理员的扫描记录列表）、`scans/active`、取消、状态和诊断；M5 ⑥ 的扫描进度字段与 `scans/{id}/report` | 管理员可使用已有添加/禁用/恢复、启动/取消；“扫描记录”按开始时间倒序分页，每行进入扫描详情，诊断数是问题数而不是进度；M5 ⑥ 起概览与扫描详情显示进度条与阶段，管理员的扫描详情有报告（专辑与曲目的新增/更新/消失、新增专辑与“可能接替了《…》”）；旧扫描没有进度与报告，不补算；暂停、定时/监听、剩余时间与报告导出仍不支持 | M1a 现状，扫描记录随 F3；进度与报告随 M5 ⑥ |
| 审批与日志/成员 | `library-root-operations`、目录恢复、`users` 与会话撤销；M3 的 `operations` 与撤销 | M1 命名为目录操作记录/成员管理，不冒充通用审批；M3 的“操作记录”页只记管理员对专辑的修正、归组与撤销（目录与成员的操作不并入）；角色按现有 `admin/user`，不复制编辑者/听众三角色表，没有审批队列 | M1a 现状；M3 操作记录与撤销（已实现）；审批随 M6 |
| Music Steward | 仅有模式与权限规范，无对应运行时 API | 不显示能对话或批准的空外壳，不把示例回答当数据 | M6，Core 1 之后 |

M1 不是“只读界面”：它包含已存在且按后端授权执行的管理写操作；只读约束针对音乐源文件。
B0 是独立的行为保持拆包，不顺带增加 UI 所需的新接口。M4 必须依赖 M3 的修正/操作写路径，
不能先做一个只在浏览器里合并、拆分和撤销的可点击外壳。顺序与范围以 Core 1 路线为准，各阶段细节在对应子任务中评审。
