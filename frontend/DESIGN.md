# ROOMusic Classical 落地设计指南

> 核对日期：2026-09-27（阶段与批准状态于 2026-09-28 同步）。本文是 Classical 前端的设计锚点，不是功能交付证明。
> 2026-09-28 已批准 Core 1 截止范围与部分 ADR 项（见 [Core 1 路线](../docs/architecture/core-1-roadmap.md)）；各阶段业务实现仍在各自子任务中批准。
> 文中 M1 泛指 M1a（外壳与管理）与 M1b（专辑浏览），M2 泛指 M2a（直出播放）与 M2b（派生与歌词）。
> 核对时 `frontend/src/` 与旧 `frontend/DESIGN.md` 均不存在；现有 package/config 文件不代表界面已恢复。

## 1. 阅读规则与来源

本文用三种状态区分依据，避免把样机、规范和决策混为一谈：

- **原型事实**：从仓库设计源文件读取的颜色、尺寸、画面或模拟行为，不代表生产能力。
- **落地规范**：以后实现 Classical 时必须保留的视觉原则、交互语义和安全边界；不授权提前实现功能。
- **待确认调整**：原型未覆盖或与真实能力冲突的方案，必须在对应子任务或 ADR 中确认，不能默认为已采纳。

### 方向选择依据

**原型事实**：探索稿将产品描述为“一间有目录、有校对、有档案的唱片室”，以衬线字、细线和描边组织信息。
综合原型可观察到以下组合：概览接近 `1a`；专辑详情结合 `1c` 标签页、`1d` 对比和 `1e` 结构树；
正在播放结合书页式封面、歌词、信号路径与队列；问题页结合 `1n` 收件箱与 `1o` 校对稿；
扫描结合 `1p` 目录表和 `1q` 报告；审批结合 `1r` 待办与 `1s` 账簿；Steward 使用右侧停靠面板。
这是源码对照，不是补写一份不存在的逐方向历史批准记录。

**落地规范**：继续这一套浅色 Classical，而不是恢复旧月刊、朱红强调色、hash 三页导航或早期深色青绿方案。
书卷气来自字形、分栏、细线和留白，不来自营销 Hero、装饰性大卡片、全局玻璃效果或给唱片封面统一染色。

## 2. 短设计 brief

| 项目 | 落地意图 |
| --- | --- |
| 产品与受众 | 面向个人、家庭和小型私有群体的自托管音乐资料库；支持大量发行版本的浏览、核对和后续聆听 |
| 功能契约 | 用户在首屏辨认所在页面、当前 Release/扫描/操作对象、可执行动作及真实状态；版本与证据比宣传文案优先 |
| 气质 | 安静、严谨、可阅读的唱片目录与校对账簿；不把管理页做成营销页 |
| 三个表现拨盘 | 视觉变化约 3/10：稳定可预测；动效约 2/10：只解释状态；信息密度约 6/10：紧凑但不牺牲字号。数值是本次提炼的沟通参考，不是用户已确认的新配置 |
| 五个核心决定 | 纸面与墨色为主体；金色主要作描边与小面积强调；衬线标题与正文角色分开；版本、介质、曲目层级显式；证据、改动前后和执行状态分区 |
| 识别性动作 | 以版本标签和差异下划线表达“为什么不同”；以朴素的账簿表达“谁做了什么”，不靠成功动画暗示已执行 |
| 反目标 | 不伪造播放、统计、推荐、恢复点或权限；不把普通管理入口隐藏在 Steward 对话里；不复制整套设计工具运行时 |
| 资产策略 | 正式封面仅来自获授权的资源接口，缺失时使用确定性占位；探索稿色块、示例人物、唱片数据和编号不作为产品默认内容 |
| 可观察结果 | 首屏能区分浏览对象与播放对象；长标题与多碟结构可读；管理失败可恢复；窄屏可完成核心动作；未实现能力不冒充成功 |

M1 的核心动作是登录、浏览/搜索、查看 Release 与证据，以及具备权限时进行现有成员、目录和扫描管理。
真实播放属于 M2，修正、通用审批、跨版本组织、艺人、个人数据与 Steward 按后续阶段解锁。

## 3. 设计变量：来源值与落地映射

以下数值均为 CSS 像素或源 CSS 表达式。`--color-*` 等是设计资产已有变量；新增的语义名称是
**拟提取映射**，不是当前 `frontend/src/` 中已存在的 token。实现时集中定义，组件不能各自复制一套近似值。

### 3.1 色彩与语义

| 源变量 | 原始值 | 落地用途 |
| --- | --- | --- |
| `--color-bg` | `#f3f2f2` | 页面、侧栏、播放栏共享的浅灰纸面 |
| `--color-surface` | `#eae9e9` | 裱边、对话框等次级表面；不叠成多层无语义灰卡片 |
| `--color-text` | `#201f1d` | 标题、正文、主要数据 |
| `--color-accent` | `#b68235` | 细线、轮廓、进度和小面积强调；不作为普通小字的默认颜色 |
| `--color-accent-2` | `#ac803e` | 原始兼容色；不是获选的第二品牌色，也不借此添加第二套状态色 |
| `--color-divider` | `color-mix(in srgb, #201f1d 16%, transparent)` | 结构分隔线，常见宽度 `1px`；不能单独承担错误或选中语义 |
| `--color-neutral-700` | `#605d5d` | 原型常用次要文字，可映射 `--text-secondary` |
| `--color-neutral-800` | `#444141` | 说明、证据等仍需清晰阅读的正文 |
| `--color-accent-700` | `#7d5411` | 原型链接、选中标签、强调文字，可映射 `--text-accent` |
| `--color-accent-100` / `--color-accent-800` | `#fff3e4` / `#5a3b0a` | 强调标签的浅底/深字组合 |
| 导航选中底 | `color-mix(in srgb, var(--color-accent) 11%, transparent)` | 综合原型与 Sidebar 的整行轻底；配合文字和当前页语义 |
| 曲目/列表轻底 | 金色 `8%` 混合；悬停常用墨色 `4%`–`6%` 混合 | 表达当前项或指向状态；不能用作播放、权限或操作成功的唯一证据 |

色阶完整保留，按 `100 → 900` 排列：

| 色阶 | 100 | 200 | 300 | 400 | 500 | 600 | 700 | 800 | 900 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `neutral` | `#f8f4f4` | `#eae7e7` | `#d7d3d3` | `#bab6b6` | `#9b9797` | `#7d7979` | `#605d5d` | `#444141` | `#2d2b2b` |
| `accent` | `#fff3e4` | `#ffe3bf` | `#facb8d` | `#e1ad66` | `#c28d41` | `#a06f24` | `#7d5411` | `#5a3b0a` | `#3a270d` |
| `accent-2` | `#fff3e4` | `#ffe3be` | `#f5cd96` | `#dbaf70` | `#bc8f4e` | `#9b7232` | `#79561f` | `#573d14` | `#382810` |

**落地规范**：保持单一金色强调角色，主按钮默认透明底描边，不变成整块金色填充。
缺失、冲突、失败、取消、无权限必须有文字及必要图标；金色不自动等于成功或风险等级。
源稿未定义完整成功/警告/危险语义色，不能未经审阅扩成红绿状态调色板。

**可读性风险**：按源纯色计算，`accent` 对 `bg` 约为 `3.02:1`，对 `surface` 约为 `2.78:1`；
`accent-700` 对二者约为 `5.97:1` / `5.50:1`，`neutral-700` 约为 `5.83:1` / `5.38:1`。
因此不能照搬设计系统说明中“强调色至少 3:1”到所有背景；普通小字、焦点和关键边界须逐个核对。
这些是静态纯色计算，不是叠层、透明度或浏览器渲染的验收结果。

### 3.2 字体与字号

| 角色 | 源稿事实 | 提炼规则 |
| --- | --- | --- |
| 标题 | `_ds` 为 `"Cormorant Garamond", system-ui, sans-serif`；四份 HTML 覆盖为 `"Cormorant Garamond", "Noto Serif SC", serif` | 保留中西文衬线配对的来源，不把 CSS 基础回退误写成页面实际字体选择 |
| 正文 | `_ds` 为 `"Lora", system-ui, sans-serif`；页面覆盖为 `"Lora", "Noto Serif SC", serif` | 当前视觉基线仍是这一配对；不是已决定替换为无衬线 |
| 字重 | `--font-heading-weight: 600`；正文 `400`；大展示标题多为 `400` | 层级优先通过字号、位置和间距建立，不全局加粗 |
| 基础字号 | body `15px / 1.55`；h1–h6 为 `42/32/25/20/16/13px`，标题行高 `1.12` | 可映射基础字体刻度；不把基础 h1 `42px` 当作所有原型页面标题的真实尺寸 |
| 页面覆盖 | 概览标题 `56px`、专辑 `60px`、扫描/审批 `48px`、问题面板 `34px`；区块标题常见 `17/20px` | 拟提取展示/页面/面板/区块角色；大字仅用于对象或页面标题，不侵占操作区 |
| 数据与辅助文字 | 曲目标题 `14px`，常规表格 `13–14px`，说明 `12–13px`，眉批与时间常见 `10–11.5px` | 这是原型事实而非最低可读字号的认可；小字号调整见下文 |
| 按钮 | `_ds .btn` 使用标题字体 `14px`；综合原型另有 `button{font-family:inherit}`，但类选择器优先级更高，不能据此认定 `.btn` 已改用正文栈 | 区分 `.btn`、普通按钮与内联字体覆盖；移植时核对实际级联结果，避免同类动作偶然换字形 |
| 数字 | 表格、时长、计数使用 `font-feature-settings:'tnum'` | 数字列使用等宽数字特性；正文不整段套用，单位与数字保持清晰 |

**字体分发（2026-09-28 已批准，见 ADR 0001 决策记录）**：生产不依赖公网字体。用 Fontsource
自托管 Cormorant Garamond、Lora、Noto Serif SC 的 400 与 600 字重，保留 `unicode-range` 分片与系统
字体回退；字体许可、包体积与布局位移阈值在 M1a 复核。“中文标题保留衬线、密集 UI 改系统栈”
仍只是待比较候选，不能在本指南中写成已采纳。M1a 评审须覆盖中日英混排、长人名、目录编号、
不同系统回退和字体未加载场景，不凭字体名保证观感一致。

**落地规范与排版修正提案**：

- 不靠斜体表达 UI 强调，使用正体字重、颜色、位置；原型品牌字、编辑笔记及生成封面文字中的斜体不作为控件规范。真实封面图像内的字形不被改写。
- 源 CSS 标题为负字距，原型也有 `-.02em`；不将其全局施加于中文。中文标题与正文单独核对，不为了模仿西文紧排压缩中文笔画。
- 原型的两端对齐、紧行高和 `10–12px` 辅助字需要可读性复核。候选基线为正文/操作文案 `14–15px`、辅助信息不小于 `12px`、中文段落行高 `1.6–1.75`；具体替换刻度与字体选型一起确认，不在 M0 改源资产。
- 关键错误、确认、权限和不可逆说明不使用“辅助小字”降级。标题可换行，完整名称通过详情或可聚焦披露获得，不只依赖 `title` 或鼠标悬停。
- 日期、数量和时长来自实际数据；未知值显示“未知”或 `—`，不写成 `0`、`00:00`、已完成或虚构精度。

### 3.3 间距、边缘与深度

| 源 token / 样式 | 值 | 落地映射 |
| --- | --- | --- |
| `--space-1/2/3/4/6/8` | `4.6 / 9.2 / 13.8 / 18.4 / 27.6 / 36.8px` | 保留原始 `1.15×` 间距刻度；基础组件用该组 token，不擅自四舍五入成另一套 `4/8px` 系统 |
| `--radius-sm/md/lg` | `2 / 4 / 7px` | 小标签、输入/按钮/卡片、对话框；不沿用旧设计的 `22px` 卡片圆角 |
| `.tag` | `3px` 圆角，即 `radius-md × .75` | 可提取标签派生值，不再单建大胶囊系统 |
| 圆形例外 | 播放按钮、头像用 `50%`；恢复点标记有 `999px` | 圆形控制与紧凑标记是功能例外，不推广到普通容器 |
| `--shadow-sm` | `0 1px 2px`，`#2d2b2b` 混合 `14%` 透明底 | 轻微抬升，默认内容不必加阴影 |
| `--shadow-md` | `0 3px 10px`，同色 `16%` | 原型大封面、短反馈等局部层级 |
| `--shadow-lg` | `0 12px 32px`，同色 `22%` | 模态/抽屉层，不给所有卡片使用 |
| 边框与焦点 | 常规 `1px`；原型 `focus-visible` 为 `2px` 金色 outline、外偏移 `2px` | 焦点几何可复用，颜色须按实际表面对比核对；不可复制 `outline:none` 而漏掉替代焦点 |
| `.plate` | `6px` surface 裱边、`1px` divider 外线；原滤镜为 `sepia(.22) saturate(.82) contrast(1.05)` | 保留裱边语言；真实唱片封面是否保留滤镜待确认，默认不能把色偏处理当作忠实封面展示 |

原型中还有 `24/28/40/44/48px` 的布局数值，它们并不都来自 `--space-*`。
实现应把这些固定用途提取成布局 token，而不是为“统一刻度”偷偷改变布局；探索页卡片外壳的 `6px` 圆角也不自动成为产品第四档圆角。

### 3.4 布局 token 对照

| 拟提取角色 | 已核对的原型值 | 落地边界 |
| --- | --- | --- |
| `--layout-sidebar-width` | `216px` | 桌面主导航列；不是窄屏必须保留的固定占位 |
| `--layout-player-height` | `68px` | 桌面播放栏；仅 M2 有真实播放器时占位，窄屏重排后的实际高度另算 |

| 页面纵向留白 | 概览顶部 `34px`、扫描 `32px`、专辑 `30px`；页面底部常见 `40/44px` | 按页面角色提取；不得以固定高度裁掉内容 |
| `--layout-content-max` | 概览/扫描 `1240px`，播放 `1280px` | 指主内容内部上限，不含 `216px` 主导航；不把探索画框 `1280 × 800` 当固定设备尺寸 |

| 封面 | 专辑 `216 × 216px`；播放栏 `44 × 44px`；正在播放封面列 `minmax(200px,min(400px,42%))` | 预留正方形区域，缺失/加载/失败不改变布局；窄屏不能仍强制最小 `200px` 双列 |
| 播放栏三列 | 独立 PlayerBar 为 `300px minmax(0,1fr) 300px`；综合原型为 `minmax(0,300px) minmax(0,1fr) minmax(0,260px)` | 以综合原型的可收缩结构为参考，记录差异而不是谎称两者一致 |
| 播放栏内部 | 水平内边距 `22px`、列间距 `24px`；中区最大 `540px`；主圆按钮 `32px`，全页播放按钮 `56px` | 视觉大小与命中区分开，补齐键盘/触屏控制 |
| 对话框 | 基础 `min(440px,100%)`；版本对比 `min(980px,100%)`、最大 `90vh` | 窄屏支持内部滚动、可见关闭与焦点恢复，不能照搬固定表宽 |

## 4. 应用布局与导航

### 桌面落地规范

- 原型外壳是左侧导航与右侧主内容，M2 播放栏横跨底部；不是旧月刊的刊头加 hash 页签。
- M1 不为无媒体能力的播放器预留永久空行，更不显示演示曲目和暂停按钮。M2 才接入真实播放生命周期。
- 左侧按“聆听 / 资料库”组织入口，底部为当前身份；只有真实可用的页面进入主导航。管理员管理功能与普通浏览分层，不复制示例用户或角色。
- 桌面导航与主内容各自占满可用高度、独立滚动；可收缩容器显式允许收缩，隔离滚动链。播放栏、主区和抽屉不能相互盖住最后一行。
- 专辑信息顺序为对象标题与来源 → 当前发行版本属性 → Medium → Track → 署名/证据；M1b 以阶段 I 的 ReleaseGroup 为对象，在 M3 人工归组之前一组只有一个版本，不能暗示多个版本已被聚合。
- 当前浏览的 Release、当前播放曲目和队列上下文是不同状态。打开另一张专辑不能隐式打断播放；点击明确的播放动作才改变播放上下文。
- 搜索、筛选、分页与可分享的详情选择应可刷新、前进后退；瞬时抽屉、焦点、未提交表单保持局部状态。路由与服务器状态已批准采用 TanStack Router 与 TanStack Query（ADR 0001），实际 URL 形状由 M1a 决定，不复制原型 `setState({view})` 充当路由。

### 响应式：事实、目标与候选

**原型事实**：探索稿以 `1280 × 800` 为画框；综合原型虽有 `flex-wrap`、`auto-fill` 与 `clamp()`，
仍保留固定 `216px` 导航和桌面多列，未提供完整移动布局或已验证的断点。不能宣称其已经支持手机。

**落地目标**：桌面采用独立滚动工作区；手机只保留一个主滚动区，抽屉为临时任务面板，不制造多重嵌套滚动。
不缩小整张桌面画布适配手机，不靠横向滚动完成主要导航、播放或确认动作。

| 待确认的初始断点提案 | 布局行为 |
| --- | --- |
| `≥1200px` | 保留 `216px` 侧栏和桌面留白；次级结构树/说明栏仍须按实际内容宽度折叠，不能仅凭视口宽就全开 |
| `768–1199px` | 缩减页面留白；结构树、问题详情或说明区按需展开；大表格保留关键列，必要时局部滚动 |
| `<768px` | 主导航由具名按钮打开；主区单列，封面/标题/动作重新排列；M2 播放栏精简为曲目信息、播放/暂停、切歌和队列入口，次要控制进入可访问面板 |

这些断点是实现起点，不是从原型读取的 token，也不是 M0 已验证结论。后续至少覆盖 `375px`、`768px`、
`1024px`、`1280px` 和宽屏；短视口、文字放大、横向布局及长标题须单独验收。
移动播放栏若固定定位，底部留白与安全区域必须由实际高度计算；无播放栏时不遗留空白。

## 5. 组件合同与完整状态

| 组件 | 保留的 Classical 语言 | 落地合同 |
| --- | --- | --- |
| 主导航/搜索入口 | 细图标、分组小标题、整行金色轻底 | 链接负责导航，按钮负责命令；当前页有可访问语义；未知总数不显示原型数字；命令面板快捷键不是 M1 必做能力 |
| Release 列表/封面 | 带裱边的正方形封面、标题与元信息分级 | 有界分页，保持实体 ID；缺封面、加载和图片失败分别处理，不自动拉外部封面；卡片主链接与操作按钮不嵌套 |
| 版本/介质选择 | 下边线标签、紧凑分段选择 | 版本选择不等于播放；多 Medium 按真实层级和顺序；只有批准后的真实聚合数据才展示跨 Release 标签和对比 |
| 曲目行/队列项 | 序号、名称/署名、右对齐时长，细线分隔 | 播放与菜单用明确控件，不能仅靠可点击 `div`；当前项有文字/图标语义；未知时长不伪造；支持长标题 |
| 证据/差异 | 字段、原值、新值、来源分栏，差异下划线 | 删除线不能是唯一差异提示，增加“原值/建议值”；未知、冲突、截断分别显示；扫描观察不冒充人工修正 |
| 按钮/输入 | 透明底、`4px` 圆角、`1px` 描边 | 默认、悬停、按下、焦点、禁用、提交中完整；输入有 label 与关联错误；禁用原因可被键盘/读屏获取 |
| 标签/状态 | 小矩形或功能性标记 | 状态文字不可只剩颜色或圆点；“需要关注”不是“已经确认错误”，缺失值不是确定的异常 |
| 目录/扫描 | 紧凑表格、状态与诊断分区 | M1 展示真实状态/诊断计数；没有总量与进度合同就不用百分比、预计剩余时间或入库漏斗；取消请求不等于已取消 |
| 成员/目录操作 | 朴素表单、操作范围与记录 | 只暴露现有允许动作；后端确认后再显示成功；恢复目录不是回滚全部资料库 |
| 对话框/面板 | 浅表面、细边框、最高层级轻阴影 | 标题、焦点约束、取消/关闭与焦点恢复明确；不能只靠点遮罩关闭；阻塞性错误留在操作区，不仅短 toast |
| 短反馈 | 小面积描边、轻阴影 | 只确认用户刚触发且已被服务端确认的结果；失败有下一步；不常驻“已载入”占据内容区 |
| 播放器/歌词/Steward | 延续同一字色与边线体系 | 分阶段启用；播放器必须由媒体真实事件驱动；歌词需要真实来源；Steward 文字不是执行或审批凭据 |

### 数据与操作状态

以下是界面必须表达的含义，不是要求后端新增同名枚举或端点：

| 状态 | 用户应看到什么 / 下一步 |
| --- | --- |
| 首次加载 | 同区域轻量占位并保留结构；不出现示例音乐、不把等待画成空库 |
| 就绪 / 空结果 | 展示真实内容；区分尚无资料、筛选无结果、权限不可见。可清空筛选；普通用户不出现管理员添加入口 |
| 刷新中 / 旧数据 | 可辨认旧结果与刷新状态；失败仍可局部重试，不把过期结果当作管理写入的最新依据 |
| 网络或服务异常 | 保留可安全展示的上下文，说明可重试动作；不泄露堆栈或主机路径，不自动切到演示模式 |
| 会话失效 `401` | 进入会话恢复；清除当前身份缓存与私人状态，M2 停止播放，避免下一账号看到前一账号内容 |
| 无权限 `403` | 当前动作被拒绝；不等同于注销，不以重试按钮制造可越权的假象 |
| 冲突 `409` | 保留非敏感草稿，解释资源已变化，提供刷新/比对/重新提交；不自动盖掉别人的修改 |
| 写入中 / 成功 / 失败 | 防重复提交；按资源/操作的真实结果结束等待，接受请求不等于执行完成；失败不显示成功勾号 |
| 扫描运行 / 取消请求中 | 以服务端状态与 `cancel_requested_at` 为依据；启动、取消操作与进度轮询区分 |
| 扫描完成 / 失败 / 已取消 / 不完整 | 不能全部归为“完成”；失败、取消、不完整或离线均不能暗示已执行缺失对账 |
| 恢复可用 / 不可用 | 只有后端支持的逆操作才提供入口；扫描记录、自然语言说明或前端点击历史不能生成恢复点 |

组件只接收解码后的类型与显示模型并发出用户意图。会话、角色、根目录、revision、幂等和恢复的最终决定都在后端，
隐藏控件或前端校验不构成授权。普通浏览界面只用安全资源标识；管理视图也仅展示服务端按权限明确返回的信息。

## 6. 播放与队列：保留语义，不保留模拟实现

[既有队列交互合同](../.trellis/spec/frontend/player-design-guidelines.md)是可迁移的用户意图；旧模拟时钟、
本地个人库、演示入口与存储格式不是恢复目标。综合原型的定时自增进度、固定曲序、生成歌词和硬编码信号路径均不得成为播放器实现。

| 用户动作 | 必须保留的语义 |
| --- | --- |
| 立即播放歌曲或列表 | 替换当前播放上下文，并从明确选中的项目开始；不是偷偷追加 |
| 下一首播放 | 插入当前项之后；不切走当前播放 |
| 加入队列 | 追加到队尾，不中断当前播放，不重置进度 |
| 排序/移除条目 | 按队列条目身份操作；同一 Track 可有多个队列条目，不能用 Track ID 删除所有重复项 |
| 收藏去重 | 以曲目身份而非队列条目身份去重；收藏/歌单的服务端用户隔离属于 M5，不恢复旧本地库作为权威 |
| 自然结束与循环 | 顺序模式末曲暂停；列表循环回到首曲；单曲循环仅作用于自然结束，手动切歌仍切换 |
| 随机与上一首 | 可选曲目多于一首时避免连续重复，上一首可回到实际播放的上一项，而不是再随机一次 |
| 未知时长/不可定位 | 显示未知值，禁用无依据的拖动，不靠模拟时钟推断结束；真实结束仍由媒体事件报告 |
| 刷新恢复 | 若 M2 选择恢复队列，恢复后保持暂停；持久化方案另定，不能因此沿用旧个人库格式 |
| 退出、失效、切换身份 | 停止当前音频并清理身份相关的队列/缓存；不跨用户继承历史或收藏 |

M2 需补齐无曲目、等待媒体、缓冲、播放、暂停、结束、格式不支持、来源缺失、鉴权失败、网络中断、
重试和拖动失败等状态；真实播放事件与明确错误决定状态，不因按下按钮就显示“正在播放”。

信号路径区分“源文件参数”“服务端传输/派生处理”“浏览器已知状态”“未知系统输出”，不声称 Bit-perfect、
硬件 DAC 格式或硬件音量。歌词没有授权来源、内容或时间戳时显示缺失/纯文本状态，不能生成占位歌词冒充真实内容。
跨版本切换与曲目对应关系须待 M4 数据合同；不能按相同数组下标认定为同一首录音，也不把高采样率直接命名为“最高音质”。

## 7. 页面能力与阶段边界

下表是**阶段提案**，不是交付现状或自动排期。现有路由已对照
[application.go](../backend/cmd/roomusic/application.go)，字段依据
[catalog_api.go](../backend/cmd/roomusic/catalog_api.go)、[scans.go](../backend/cmd/roomusic/scans.go)
和 [root_operations.go](../backend/cmd/roomusic/root_operations.go)。具体 DTO 与错误合同仍由相应规范/子任务维护。

| 页面/场景 | 已有 API 依据 | 缺口与 M1 的诚实呈现 | 建议阶段 |
| --- | --- | --- | --- |
| 初始化/登录/会话 | `setup/status`、`setup/admin`、`auth/login/logout/me` | 原型未提供完整认证流程，必须补齐；不能因已有后端就声称已有可用前端 | M1a |
| 概览 | 已公开 Release 列表、登录用户可见扫描状态、管理员目录资源 | 只组合可获得的数据，不推算全库容量、全部曲目数、本周新增或播放历史；缺的区块隐藏 | M1a 简版；聆听历史随 P（阶段 I 之后），个人库随 M5 |
| 专辑库/基础搜索 | `GET /api/v1/releases` 的分页、搜索与关注筛选 | M1b 以阶段 I 的 ReleaseGroup 只读接口为列表单位，一组一个版本时自然退化；“需要关注”与全库问题收件箱不是同一能力；排序/筛选不超出 API | M1b |
| 专辑详情/证据 | Release 详情安全摘要、管理员 `/{id}/evidence`、`artworks/{id}` | 真实 Release/Medium/Track、已有署名与来源；无数据不补编曲/作词等角色；按组只读接口由阶段 I 提供，版本对比/默认版本尚无合同 | M1b 基础；M4 版本组织 |
| 正在播放/底栏/歌词 | 尚无注册的曲目串流/歌词接口 | 隐藏播放入口及演示曲目；格式参数只作为源信息，不等同可播放证明 | M2a 直出；M2b 派生与歌词；跨版本关联随 M4 |
| 艺人 | 当前 Release/Track 中有署名文字 | 不存在完整艺人/别名、传记、合作网络页；不把同名字符串合并成人物实体 | M5 |
| 全局搜索/命令面板 | 基础 Release 检索可复用 | 原型跨艺人/专辑/曲目、编号分面与自然语言查询未完整提供；M1 不因搜索框而隐含新增接口 | M1b 基础；M5 增强 |
| 收藏/历史/播放列表 | 尚无完整服务端个人库 API | 不沿用旧本地个人库或演示身份；播放历史在阶段 I 之后由服务端按用户隔离保存（P），跨用户隔离必须成立 | P 播放历史；M5 收藏与歌单 |
| 元数据问题 | Release 候选字段、关注计数与证据 | M1 可查看现有证据，不伪造待办状态、忽略、应用或撤销；持久修正与结构操作需写路径 | M3 基础；M4 整理 |
| 扫描目录/过程 | `library-roots`、`scans`、`scans/active`、取消、状态和诊断 | 管理员可使用已有添加/禁用/恢复、启动/取消；无进度百分比、暂停、定时/监听或漏斗报告合同 | M1a 现状；增强另立子任务 |
| 审批与日志/成员 | `library-root-operations`、目录恢复、`users` 与会话撤销 | M1 命名为目录操作记录/成员管理，不冒充通用审批；角色按现有 `admin/user`，不复制编辑者/听众三角色表 | M1 现状；M3 通用治理 |
| Music Steward | 仅有模式与权限规范，无对应运行时 API | 不显示能对话或批准的空外壳，不把示例回答当数据 | M6 候选，未自动纳入 Core 1 |

M1 不是“只读界面”：它包含已存在且按后端授权执行的管理写操作；只读约束针对音乐源文件。
B0 是独立的行为保持拆包，不顺带增加 UI 所需的新接口。M4 必须依赖 M3 的修正/操作写路径，
不能先做一个只在浏览器里合并、拆分和撤销的可点击外壳。最终顺序和范围以阶段评审为准。

## 8. 原型不实承诺与落地调整表

下表记录需要修正的产品表达，不修改原始设计资产，也不把替代功能自动批准为需求。

| 原型表达/行为 | 事实或约束 | 落地处置与待确认项 |
| --- | --- | --- |
| 固定专辑总数、容量、近期统计与首页便笺 | 均含硬编码示例；现有接口不保证全部统计 | 不展示虚构数值；先用可核对数据组成简版，新增统计另提案 |
| 专辑按 ReleaseGroup 只出现一次，默认版/四版对比 | M1b 使用阶段 I 的按组只读接口，初期一组一个版本；Core 1 只允许人工确认归组（M3 起），不能由标题相似性自动分组 | 保留版本区分；默认版与差异对比在 M4 |
| 高采样率版本称为“最高音质” | 文件参数不是听感与制作质量结论 | 展示具体格式参数；版本偏好规则需独立确认 |
| Bit-perfect、未重采样、USB DAC、硬件音量 | 当前没有可验证的端到端输出链路 | M2 只标注已知环节与未知状态，媒体 ADR 不通过则不作保证 |
| 本地 LRC、逐行歌词点击定位、1 秒推进播放 | 原型为生成文本与定时状态，非读取真实歌词/音频 | M2 基于真实来源、时间戳和媒体事件；未知时间禁用定位 |
| 扫描进度 `64%`、完成自增、文件总量/剩余时间 | 当前扫描 DTO 无相应进度合同 | 用真实扫描状态/诊断；不以动画、计时或诊断数代替总进度 |
| 暂停/继续、每天增量、监听后 30 秒入库 | 当前只有启动/取消等接口，无暂停与监听调度合同 | M1 不呈现为可用；定时/增量/暂停需独立需求与后端支持 |
| 置信度小于 `0.85` 才等待确认、自动跨目录归并 | 原型阈值和数字不是后端分组/授权规则 | 显示已有证据语义；保守分组，不根据 UI 数值新增权威合并策略 |
| 扫描完成就有恢复点、回滚此点及之后所有记录 | 扫描观察、目录管理记录和通用操作日志是不同对象 | 扫描不提供虚构撤销；M1 仅支持现有目录恢复；M3 另评审通用恢复合同 |
| 删除重复文件、回收站保存 30 天 | 音乐源只读；没有文件删除/回收站能力 | 删除入口不落地；若需“从资料库排除”，作为尚待实现的数据库操作另提案 |
| 缺失视频介质自动补建、外部参照/封面/编辑笔记 | 无已批准的来源及相应完整写路径 | 隐藏或只呈现已有证据；不编造来源、候选图像和完整元数据 |
| 原型元数据问题可应用、忽略、撤销 | 本地状态变化不代表持久化、revision 或可逆性 | M3/M4 才接真实操作；不能复用前端按钮历史作为恢复依据 |
| 管理员/编辑者/听众、所有写入一律确认 | 当前角色为 `admin/user`；未来执行模式的审批路径不同 | 不改称现有权限；M3 评审角色/风险；Steward 模式不得自审，Operator 跳过审批不跳过校验 |
| Steward 已读资料、生成列表、批准后即成功 | 示例回复和本地状态没有执行凭据 | M6 前隐藏；未来分离提案、审批、执行和恢复状态，依据后端结果 |
| 小字号、斜体、问题行左侧 `2px` 选中条 | 原型含可读性与偏好冲突 | 小字号/字体方案待确认；UI 强调改用正体；选中态用整块轻底和全边界/字重。结构树/栏目分隔线仍可表达真实结构 |
| `.plate` 给图片统一复古滤镜 | 可能改变真实封面颜色 | 裱边保留，滤镜保留与否另确认；不得改写或生成替代源封面 |
| 移动端直接沿用桌面宽度、仅鼠标可点击的 `div` | 样稿不是完整可访问实现 | 使用语义控件、明确命中区、响应式重排；本轮没有截图或浏览器验收证据 |

## 9. 可访问性、文案与动效门槛

以下为后续实现的项目验收目标，不是本轮已经完成的无障碍认证。

- 主要页面有 `nav/main` 等地标和有序标题；导航用链接、动作用按钮、结构数据用列表/表格。不能直接移植设计工具自定义标签或可点击 `div`。
- 核心流程仅用键盘可完成，焦点始终可见；所有图标命令都有完整名称。选中、展开、按下与禁用具有相应可访问状态，不仅换颜色。
- 输入具有可编程 label，错误紧邻并关联对应字段；对话框有名称、焦点管理、安全时支持 Esc/取消/关闭与焦点恢复；抽屉明确是模态还是非模态，不能一边挡住内容一边让焦点穿透。
- 普通正文/操作小字以对比度不低于 `4.5:1`、关键控件与焦点以不低于 `3:1` 为验收目标。实际背景、浅色表面、悬停、透明度和禁用说明均分别检查，不凭 token 名称判断。
- 桌面小图标与手机触摸均有足够命中区；触屏核心操作以至少 `44 × 44px` 的命中区作为项目目标。可保持原型细小图形，但不能把 `12px` 进度线或 `16px` 图标直接当作唯一操作范围。
- 队列如支持拖拽排序，必须提供等价的键盘或按钮操作，不让拖拽成为唯一方式。
- 进度/音量使用有名称、范围、当前值与键盘操作的控件；无能力或未知时长时明确不可用。非确定进度不暴露伪造的百分比。
- 扫描与操作状态只在有意义变化时公告，不逐文件播报；歌词逐行与播放时间不持续占用读屏公告，提供不自动滚动或静态阅读方式。
- 长标题、长艺人名和证据文本可收缩、换行或按需展开；保留完整内容的获取路径。包含超过 `1000` 字的合法标题验收，不用绝对定位状态标签覆盖操作区。
- 文案使用简体中文，曲名/艺人保留原文；未知来源明确未知。敏感主机路径、凭据、真实音乐清单与私人媒体不进入公共截图、日志或演示数据。
- 页面不做装饰性自动运动。悬停、展开等只过渡必要属性，不用 `transition:all`；源稿歌词的 `.3s` 字号/颜色过渡仅是样机事实，M2 需评估布局跳动。支持减少动态效果偏好，不能让动效成为操作完成的必要条件。
