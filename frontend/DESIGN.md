### 方向选择依据

**原型事实**：探索稿将产品描述为“一间有目录、有校对、有档案的唱片室”，以衬线字、细线和描边组织信息。
综合原型可观察到以下组合：概览接近 `1a`；专辑详情结合 `1c` 标签页、`1d` 对比和 `1e` 结构树；
正在播放结合书页式封面、歌词、信号路径与队列；问题页结合 `1n` 收件箱与 `1o` 校对稿；
扫描结合 `1p` 目录表和 `1q` 报告；审批结合 `1r` 待办与 `1s` 账簿；Steward 使用右侧停靠面板。
这是源码对照，不是补写一份不存在的逐方向历史批准记录。

**落地规范**：继续这一套浅色 Classical，而不是恢复旧月刊、朱红强调色、hash 三页导航或早期深色青绿方案。
安静的气质来自分栏、细线和留白，不来自营销 Hero、装饰性大卡片、全局玻璃效果或给唱片封面统一染色。

## 2. 短设计 brief

| 项目 | 落地意图 |
| --- | --- |
| 产品与受众 | 面向个人、家庭和小型私有群体的自托管音乐资料库；支持大量发行版本的浏览、核对和后续聆听 |
| 功能契约 | 用户在首屏辨认所在页面、当前 Release/扫描/操作对象、可执行动作及真实状态；版本与证据比宣传文案优先 |
| 气质 | 安静、严谨、可阅读的唱片目录与校对账簿；不把管理页做成营销页 |
| 三个表现拨盘 | 视觉变化约 3/10：稳定可预测；动效约 2/10：只解释状态；信息密度约 6/10：紧凑但不牺牲字号。数值是本次提炼的沟通参考，不是用户已确认的新配置 |
| 五个核心决定 | 纸面与墨色为主体；金色主要作描边与小面积强调；系统无衬线字体，标题与正文靠字号和字重区分；版本、介质、曲目层级显式；证据、改动前后和执行状态分区 |
| 识别性动作 | 以版本标签和差异下划线表达“为什么不同”；以朴素的账簿表达“谁做了什么”，不靠成功动画暗示已执行 |
| 反目标 | 不伪造播放、统计、推荐、恢复点或权限；不把普通管理入口隐藏在 Steward 对话里；不复制整套设计工具运行时 |
| 资产策略 | 正式封面仅来自获授权的资源接口，缺失时使用确定性占位；探索稿色块、示例人物、唱片数据和编号不作为产品默认内容 |
| 可观察结果 | 首屏能区分浏览对象与播放对象；长标题与多碟结构可读；管理失败可恢复；窄屏可完成核心动作；未实现能力不冒充成功 |

M1 的核心动作是登录、浏览/搜索、查看 Release 与证据，以及具备权限时进行现有成员、目录和扫描管理。
真实播放属于 M2，修正、通用审批、跨版本组织、艺人、个人数据与 Steward 按后续阶段解锁。

## 3. 设计变量：来源值与落地映射

以下数值均为 CSS 像素或源 CSS 表达式。`--color-*` 等是设计资产已有变量；新增的语义名称是
**拟提取映射**，不是当前 `frontend/src/` 中已存在的 token。实现时集中定义，组件不能各自复制一套近似值。

### 3.1 色彩与语义

| 源变量 | 原始值 | 落地用途 |
| --- | --- | --- |
| `--color-bg` | `#f3f2f2` | 页面、侧栏、播放栏共享的浅灰纸面 |
| `--color-surface` | `#eae9e9` | 裱边、对话框等次级表面；不叠成多层无语义灰卡片 |
| `--color-text` | `#201f1d` | 标题、正文、主要数据 |
| `--color-accent` | `#b68235` | 细线、轮廓、进度和小面积强调；不作为普通小字的默认颜色 |
| `--color-accent-2` | `#ac803e` | 原始兼容色；不是获选的第二品牌色，也不借此添加第二套状态色 |
| `--color-divider` | `color-mix(in srgb, #201f1d 16%, transparent)` | 结构分隔线，常见宽度 `1px`；不能单独承担错误或选中语义 |
| `--color-neutral-700` | `#605d5d` | 原型常用次要文字，可映射 `--text-secondary` |
| `--color-neutral-800` | `#444141` | 说明、证据等仍需清晰阅读的正文 |
| `--color-accent-700` | `#7d5411` | 原型链接、选中标签、强调文字，可映射 `--text-accent` |
| `--color-accent-100` / `--color-accent-800` | `#fff3e4` / `#5a3b0a` | 强调标签的浅底/深字组合 |
| 导航选中底 | `color-mix(in srgb, var(--color-accent) 11%, transparent)` | 综合原型与 Sidebar 的整行轻底；配合文字和当前页语义 |
| 曲目/列表轻底 | 金色 `8%` 混合；悬停常用墨色 `4%`–`6%` 混合 | 表达当前项或指向状态；不能用作播放、权限或操作成功的唯一证据 |

色阶完整保留，按 `100 → 900` 排列：

| 色阶 | 100 | 200 | 300 | 400 | 500 | 600 | 700 | 800 | 900 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `neutral` | `#f8f4f4` | `#eae7e7` | `#d7d3d3` | `#bab6b6` | `#9b9797` | `#7d7979` | `#605d5d` | `#444141` | `#2d2b2b` |
| `accent` | `#fff3e4` | `#ffe3bf` | `#facb8d` | `#e1ad66` | `#c28d41` | `#a06f24` | `#7d5411` | `#5a3b0a` | `#3a270d` |
| `accent-2` | `#fff3e4` | `#ffe3be` | `#f5cd96` | `#dbaf70` | `#bc8f4e` | `#9b7232` | `#79561f` | `#573d14` | `#382810` |

**落地规范**：保持单一金色强调角色，主按钮默认透明底描边，不变成整块金色填充。
缺失、冲突、失败、取消、无权限必须有文字及必要图标；金色不自动等于成功或风险等级。
源稿未定义完整成功/警告/危险语义色，不能未经审阅扩成红绿状态调色板。

**可读性风险**：按源纯色计算，`accent` 对 `bg` 约为 `3.02:1`，对 `surface` 约为 `2.78:1`；
`accent-700` 对二者约为 `5.97:1` / `5.50:1`，`neutral-700` 约为 `5.83:1` / `5.38:1`。
因此不能照搬设计系统说明中“强调色至少 3:1”到所有背景；普通小字、焦点和关键边界须逐个核对。
这些是静态纯色计算，不是叠层、透明度或浏览器渲染的验收结果。

**M1a 实现**：语义文字色为主文字 `--color-text`、次要 `neutral-700`、强调 `accent-700`；小字与链接用 `accent-700`，`accent` 只用于描边与细线；
主按钮沿用透明底与 `accent` 描边，文字改用 `accent-700`；控件边界取 `neutral-600`（对纸面约 3.8:1），`--color-divider` 只做结构分隔；
焦点环为 2px `accent-700`、外偏移 2px。axe 的 `color-contrast` 在所有已实现页面状态下没有 serious 或 critical 问题。

### 3.2 字体与字号

2026-11-07 起（任务“界面极简”，用户反馈原来的衬线字体太尖锐、太大、不好一眼看清）：全站改用系统无衬线字体，字号整体缩小。
原型的 Cormorant Garamond / Lora / Noto Serif SC 衬线配对不再使用，三个 `@fontsource-variable/*` 依赖和随页面分发的字体文件已删除，页面不加载任何网络字体。

| 角色 | 落地值（`frontend/src/styles/tokens.css`） |
| --- | --- |
| 字体栈 | `--font-body`：`system-ui, -apple-system, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", "Source Han Sans SC", "Noto Sans SC", sans-serif`；`--font-heading` 与它相同，标题靠字号与字重区分 |
| 字重 | 正文 400；标题与页面标题 600；按钮 500。不全局加粗，不用斜体表达强调 |
| 字阶 | `--fs-12/13/14/15/16/18/20/24`，最小 12px |
| 正文 | 14px，行高 1.6 |
| 控件、表格与次要文字 | 13px；标签、时间与辅助说明 12px |
| 标题 | 页面标题宽屏 24px、窄屏 20px（很长的标题降为 20px / 18px）；区块标题 16px；小标题 15px；标题行高 1.3 |
| 数字 | 时长、计数、进度、表格数值用 `font-variant-numeric: tabular-nums`，正文不整段套用；无衬线字体本来就是等高数字，不再需要 `lining-nums` |

**落地规范**：

- 中文标题与正文不加负字距；标题可换行，完整名称通过详情或可聚焦披露获得，不只依赖 `title` 或鼠标悬停。
- 关键错误、确认和不可逆说明不用辅助小字降级。
- 日期、数量和时长来自实际数据；未知值显示“未知”或 `—`，不写成 `0`、`00:00`、已完成或虚构精度。
- 没有装中文无衬线字体的系统（例如精简的 Linux 服务器）会回退到系统默认字体；常见桌面和手机系统都自带栈里的某一款。

### 3.3 间距、边缘与深度

| token / 样式 | 值 | 落地映射 |
| --- | --- | --- |
| `--space-1/2/3/4/6/8` | `4 / 8 / 12 / 16 / 24 / 32px` | 2026-11-07 从原型的 `1.15×` 刻度（`4.6 / 9.2 / 13.8 / 18.4 / 27.6 / 36.8px`）收紧为 4 的倍数；组件只用这组 token |
| `--control-height` | 桌面 `32px`；触屏（`pointer: coarse`）与 `<768px` 窄屏 `44px` | 按钮、输入与菜单项的最小高度；触控尺寸不随收紧而缩小 |
| 页面内边距 | 横向 `32px`、纵向 `24px`；`768–1199px` 为 `24 / 20px`；`<768px` 为 `16 / 16px` | 页面区块间距 `24px`，区块内 `12px` |
| `--color-divider` | `color-mix(in srgb, #201f1d 10%, transparent)` | 2026-11-07 从 16% 调淡；区块与列表的分隔线，不承担控件识别 |
| `--radius-sm/md/lg` | `2 / 4 / 7px` | 小标签、输入/按钮、对话框与菜单浮层；不沿用旧设计的 `22px` 卡片圆角 |
| 标签 | `3px` 圆角，无边框，淡底色 | 见 [DESIGN-components.md](DESIGN-components.md) 第 5 节 |
| 圆形例外 | 播放按钮、头像用 `50%`；恢复点标记有 `999px` | 圆形控制与紧凑标记是功能例外，不推广到普通容器 |
| `--shadow-sm` | `0 1px 2px`，`#2d2b2b` 混合 `14%` 透明底 | 轻微抬升，默认内容不加阴影 |
| `--shadow-md` | `0 3px 10px`，同色 `16%` | 大封面、菜单浮层、短反馈等局部层级 |
| `--shadow-lg` | `0 12px 32px`，同色 `22%` | 模态/抽屉层，不给所有卡片使用 |
| 边框与焦点 | 输入与主要按钮 `1px`；`focus-visible` 为 `2px` `accent-700` outline、外偏移 `2px` | 次要文字按钮、只有图标的按钮和标签没有边框；不可去掉焦点环 |
| `.plate` | `6px` surface 裱边、`1px` divider 外线 | 保留裱边；正方形、`object-fit: contain` 不裁切，不加滤镜（M1b 实现并经用户确认，2026-10-03） |

原型中还有 `24/28/40/44/48px` 的布局数值，它们并不都来自 `--space-*`；固定用途提取成布局 token（见 3.4），不为“统一刻度”改变布局。

### 3.4 布局 token 对照

| 拟提取角色 | 已核对的原型值 | 落地边界 |
| --- | --- | --- |

| `--layout-content-max` | 概览/扫描 `1240px`，播放 `1280px` | 指主内容内部上限，不含 `216px` 主导航；不把探索画框 `1280 × 800` 当固定设备尺寸 |
| `--layout-structure-width` | `260px` | 专辑详情可折叠结构树；M1 只呈现已有 Release/Medium/Track |
| `--layout-issue-list-width` | `380px` | 元数据问题页与待认领页的列表栏（M4 已用）；详情有 `860px` 上限，容器窄于约 `900px` 时改顺序导航（带侧栏时 1024px 视口也是顺序导航） |
| `--layout-steward-width` | `390px`、`max-width:100%` | 后续侧面板；没有 Steward 运行能力时不呈现聊天外壳 |
| 说明侧列 | 版本说明 `250px`；概览/账簿侧列上限 `320px` | 不能挤压曲目/表格主要信息，空间不足时移到下方 |
| 封面 | 专辑 `216 × 216px`；播放栏 `44 × 44px`；正在播放封面列 `minmax(200px,min(400px,42%))` | 预留正方形区域，缺失/加载/失败不改变布局；窄屏不能仍强制最小 `200px` 双列 |
| 播放栏三列 | 独立 PlayerBar 为 `300px minmax(0,1fr) 300px`；综合原型为 `minmax(0,300px) minmax(0,1fr) minmax(0,260px)` | 以综合原型的可收缩结构为参考，记录差异而不是谎称两者一致 |
| 播放栏内部 | 水平内边距 `22px`、列间距 `24px`；中区最大 `540px`；主圆按钮 `32px`，全页播放按钮 `56px` | 视觉大小与命中区分开，补齐键盘/触屏控制 |
| 对话框 | 基础 `min(440px,100%)`；版本对比 `min(980px,100%)`、最大 `90vh` | 窄屏支持内部滚动、可见关闭与焦点恢复，不能照搬固定表宽 |

## 4. 应用布局与导航

### 桌面落地规范

- 原型外壳是左侧导航与右侧主内容，M2 播放栏横跨底部；不是旧月刊的刊头加 hash 页签。
- M1 不为无媒体能力的播放器预留永久空行。M2a 在队列非空时接入真实底栏与 `/now-playing`，清空后不留占位；不显示演示曲目。
- 左侧按“聆听 / 资料库”组织入口，底部为用户菜单（设置 / 退出登录）；扫描目录、成员、操作记录、备份在“设置”里（`/settings/*`），侧栏资料库分组只留待办类页面；只有真实可用的页面进入主导航。管理员管理功能与普通浏览分层，不复制示例用户或角色。
- 桌面导航与主内容各自占满可用高度、独立滚动；可收缩容器显式允许收缩，隔离滚动链。播放栏、主区和抽屉不能相互盖住最后一行。
- 专辑信息顺序为对象标题与来源 → 当前发行版本属性 → Medium → Track → 署名/证据；M1b 以阶段 I 的 ReleaseGroup 为对象，没有人工归组时一组只有一个版本（M3 起管理员可以把版本归到一起），不能暗示多个版本已被自动聚合。
- 当前浏览的 Release、当前播放曲目和队列上下文是不同状态。打开另一张专辑不能隐式打断播放；点击明确的播放动作才改变播放上下文。
- 搜索、筛选、分页与可分享的详情选择应可刷新、前进后退；瞬时抽屉、焦点、未提交表单保持局部状态。路由与服务器状态采用 TanStack Router 与 TanStack Query（ADR 0001）；M1a 的 URL 形状是 `/`、`/setup`、`/login?redirect=`、`/library`、`/library/scans/$scanId`、`/members`（2026-11 起迁到 `/settings/library`、`/settings/library/scans/$scanId`、`/settings/members`，旧地址重定向；另有 `/settings/account`、`/settings/operations`、`/settings/backups`），不复制原型 `setState({view})` 充当路由。**M1b 实现**：专辑列表 `/albums?q=&attention=required&page=`（第 1 页不写页码），
专辑详情 `/albums/$groupId?release=`（`release` 只在选中非代表版本时出现）；从列表进入详情时把列表参数放进路由的 history state，详情页的“返回专辑列表”据此恢复筛选与页码，
直接打开详情时回到 `/albums`（见[前端状态规范](../.trellis/spec/frontend/state-management.md)）。

### 响应式：事实、目标与候选

**原型事实**：探索稿以 `1280 × 800` 为画框；综合原型虽有 `flex-wrap`、`auto-fill` 与 `clamp()`，
仍保留固定 `216px` 导航和桌面多列，未提供完整移动布局或已验证的断点。不能宣称其已经支持手机。

**落地目标**：桌面采用独立滚动工作区；手机只保留一个主滚动区，抽屉为临时任务面板，不制造多重嵌套滚动。
不缩小整张桌面画布适配手机，不靠横向滚动完成主要导航、播放或确认动作。

| 断点（M1a 采用） | 布局行为 |
| --- | --- |
| `≥1200px` | 保留 `216px` 侧栏和桌面留白（页面内边距 32px，内容上限 `1240px`）；导航与主内容各自滚动；次级结构树/说明栏仍须按实际内容宽度折叠，不能仅凭视口宽就全开 |
| `768–1199px` | 缩减页面留白（24px），侧栏保留；结构树、问题详情或说明区按需展开 |
| `<768px` | 顶部栏加具名的“菜单”按钮，打开原生 `<dialog>` 模态导航；页面只有一个滚动区，页面内边距 16px，控件最小高度 44px；M2 播放栏精简为曲目信息、播放/暂停、切歌和队列入口，次要控制进入可访问面板 |

表格不按视口宽度而按**容器宽度**堆叠：容器小于 640px 时每行改为“标签：值”（CSS 容器查询），因为带侧栏时 768px 视口里内容区只有约 500px；
任何宽度下都不产生横向滚动。M1a 用 Playwright 在 `375px`、`768px`、`1024px`、`1280px`、`1440px` 下断言页面与主内容区都没有横向溢出；
长标题已在 M1b 验收（见 3.2 与 [DESIGN-acceptance.md](DESIGN-acceptance.md) 第 10 节）；短视口、文字放大与横向布局仍未单独验收。
移动播放栏若固定定位，底部留白与安全区域必须由实际高度计算；无播放栏时不遗留空白。
