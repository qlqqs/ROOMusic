## 8. 原型不实承诺与落地调整表

下表记录需要修正的产品表达，不修改原始设计资产，也不把替代功能自动批准为需求。

| 原型表达/行为 | 事实或约束 | 落地处置与待确认项 |
| --- | --- | --- |
| 固定专辑总数、容量、近期统计与首页便笺 | 均含硬编码示例；现有接口不保证全部统计 | 不展示虚构数值；先用可核对数据组成简版，新增统计另提案 |
| 专辑按 ReleaseGroup 只出现一次，默认版/四版对比 | M1b 使用阶段 I 的按组只读接口，初期一组一个版本；Core 1 只允许人工确认归组（M3 已提供“归入其他专辑”与“移出为独立专辑”），不能由标题相似性自动分组 | 保留版本区分；**M4 实现**：管理员逐张指定的默认版本与所有成员可用的版本对比（见 [DESIGN-components.md](DESIGN-components.md) 第 5 节的“M4 实现”） |
| 版本对比底部的“为什么没有合并”说明、点列头切换版本、以“台湾首版”为基准 | 没有“为什么没有合并”的数据来源；版本没有“首版”之类的可靠名称 | **M4 实现**：不显示这段说明，不编造理由；基准是版本 1（默认版本或自动选出的代表版本），列头写“版本 N”；切换用列头里明确的“查看这个版本”链接，不是可点击的整列表头 |
| 操作记录“为《范特西》设置默认版本”，范围“1 ReleaseGroup” | 记录写的是真实的前后状态 | **M4 实现**：类型名“设定默认版本”，改动行写出前后的默认版本（“自动选择 → 《…》（年份 · 版本说明）”），专辑列链接到专辑 |
| 高采样率版本称为“最高音质” | 文件参数不是听感与制作质量结论 | 展示具体格式参数；版本偏好规则需独立确认 |
| Bit-perfect、未重采样、USB DAC、硬件音量 | 当前没有可验证的端到端输出链路 | M2 只标注已知环节与未知状态，媒体 ADR 不通过则不作保证 |
| 本地 LRC、逐行歌词点击定位、1 秒推进播放 | 原型为生成文本与定时状态，非读取真实歌词/音频 | M2b 已落地：基于内嵌标签、接口解析的时间戳与媒体事件；媒体不可定位时各行不可点 |
| 扫描进度 `64%`、完成自增、文件总量/剩余时间 | 原型的数字是动画与计时；M5 ⑥ 建立了服务端持久化的进度合同（计数后固定总数、按目录文件数加权的工作进度），但没有剩余时间 | **M5 ⑥ 实现**：百分比与“已处理 A / T 个文件”来自服务端，整体不倒退，只有成功到 100%，失败/取消/不完整停在停下的位置；验收看真实计数、单调与各终态；不以动画、计时或诊断数代替总进度，不显示剩余时间 |
| 暂停/继续、每天增量、监听后 30 秒入库 | 当前只有启动/取消等接口，无暂停与监听调度合同 | M1 不呈现为可用；定时/增量/暂停需独立需求与后端支持 |
| 置信度小于 `0.85` 才等待确认、自动跨目录归并 | 原型阈值和数字不是后端分组/授权规则 | 显示已有证据语义；保守分组，不根据 UI 数值新增权威合并策略 |
| 扫描完成就有恢复点、回滚此点及之后所有记录 | 扫描观察、目录管理记录和通用操作日志是不同对象 | 扫描不提供虚构撤销；M1 仅支持现有目录恢复；M3 建立了操作记录与单条撤销（只撤销发行最近一次修改，撤销本身也留记录），没有“回滚到某点” |
| 删除重复文件、回收站保存 30 天 | 音乐源只读；没有文件删除/回收站能力 | 删除入口不落地；若需“从资料库排除”，作为尚待实现的数据库操作另提案 |
| 缺失视频介质自动补建、外部参照/封面/编辑笔记 | 无已批准的来源及相应完整写路径 | 隐藏或只呈现已有证据；不编造来源、候选图像和完整元数据 |
| 原型元数据问题可应用、忽略、撤销 | 本地状态变化不代表持久化、revision 或可逆性 | M3 已接真实的修正、归组与撤销（后端确认并写记录）；**M4 第二项实现**：“忽略”落地为可撤销的“标记为已核对”（后端记住依据，扫描之后情况变了重新提醒），“应用修正”是“编辑发行信息”；不能复用前端按钮历史作为恢复依据 |
| 问题收件箱一行一个问题，严重程度、置信度、“当前/建议”对照，“交给 Steward” | 严重程度、置信度与建议值没有后端来源，样例问题多依赖外部参照或结构操作 | **M4 第二项实现**：**按版本列出**（一行一个有问题的版本与各类数目，用户 2026-10-16 选择），详情逐节写原因与依据；只有扫描结论里已有的三类问题（拿不准的字段、同一目录的归组冲突、缺失曲目）；没有严重程度、置信度、建议值、批量操作与“交给 Steward” |
| 管理员/编辑者/听众、所有写入一律确认 | 当前角色为 `admin/user`；未来执行模式的审批路径不同 | 不改称现有权限；M3 沿用 `admin/user`（只有管理员能改，提交即生效并记录），没有 editor 与审批；Steward 模式不得自审，Operator 跳过审批不跳过校验 |
| Steward 已读资料、生成列表、批准后即成功 | 示例回复和本地状态没有执行凭据 | M6 前隐藏；未来分离提案、审批、执行和恢复状态，依据后端结果 |
| 小字号、斜体、问题行左侧 `2px` 选中条 | 原型含可读性与偏好冲突 | 小字号/字体方案待确认；UI 强调改用正体；选中态用整块轻底和全边界/字重。结构树/栏目分隔线仍可表达真实结构 |
| `.plate` 给图片统一复古滤镜 | 可能改变真实封面颜色 | 裱边保留，滤镜保留与否另确认；不得改写或生成替代源封面 |
| 移动端直接沿用桌面宽度、仅鼠标可点击的 `div` | 样稿不是完整可访问实现 | 使用语义控件、明确命中区、响应式重排；M1a、M1b 用 Playwright 五种宽度与真实页面截图验证 |
| 专辑详情按介质分段切换（Medium 标签）、右侧“结构树”栏 | 分段切换只适合两三张介质，结构树没有数据来源 | **M1b 实现**：介质逐段列出，任意张数都能完整呈现，多于一张时顶部有页内跳转链接；不做结构树侧栏 |
| 版本选择用下边线标签并自带对比 | 版本选择会写进地址，对比与默认版本没有合同 | **M1b 实现**：版本导航是带 `aria-current` 的链接，只在组里有多个版本时出现；**M4 实现**：导航标题旁的“对比版本”与默认版本标签 |
| 卡片上的播放、收藏、“交给 Steward”按钮，艺人名链接 | 播放、个人库、Steward 与艺人页都未实现 | **M1b 实现**：都不出现（不做禁用占位），艺人名是纯文字；卡片整张是一个链接。**M5 ⑤**：卡片仍整张是一个链接、艺人名仍是文字（不嵌套链接）；艺人名链接出现在专辑页、曲目行、播放器与各列表的曲目行里 |

## 9. 可访问性、文案与动效门槛

以下为后续实现的项目验收目标，不是本轮已经完成的无障碍认证。

- 主要页面有 `nav/main` 等地标和有序标题；导航用链接、动作用按钮、结构数据用列表/表格。不能直接移植设计工具自定义标签或可点击 `div`。
- 核心流程仅用键盘可完成，焦点始终可见；所有图标命令都有完整名称。选中、展开、按下与禁用具有相应可访问状态，不仅换颜色。
- 输入具有可编程 label，错误紧邻并关联对应字段；对话框有名称、焦点管理、安全时支持 Esc/取消/关闭与焦点恢复；抽屉明确是模态还是非模态，不能一边挡住内容一边让焦点穿透。
- 普通正文/操作小字以对比度不低于 `4.5:1`、关键控件与焦点以不低于 `3:1` 为验收目标。实际背景、浅色表面、悬停、透明度和禁用说明均分别检查，不凭 token 名称判断。
- 桌面小图标与手机触摸均有足够命中区；触屏核心操作以至少 `44 × 44px` 的命中区作为项目目标。可保持原型细小图形，但不能把 `12px` 进度线或 `16px` 图标直接当作唯一操作范围。
- 队列如支持拖拽排序，必须提供等价的键盘或按钮操作，不让拖拽成为唯一方式。
- 进度/音量使用有名称、范围、当前值与键盘操作的控件；无能力或未知时长时明确不可用。非确定进度不暴露伪造的百分比。
  只读的扫描进度条（`role="progressbar"`）不是播放进度那样可调节的控件，不需要键盘调节，也不进入 Tab 顺序。
- 扫描与操作状态只在有意义变化时公告，不逐文件播报；歌词逐行与播放时间不持续占用读屏公告，提供不自动滚动或静态阅读方式。
- 长标题、长艺人名和证据文本可收缩、换行或按需展开；保留完整内容的获取路径。包含超过 `1000` 字的合法标题验收，不用绝对定位状态标签覆盖操作区。
- 文案使用简体中文，曲名/艺人保留原文；未知来源明确未知。敏感主机路径、凭据、真实音乐清单与私人媒体不进入公共截图、日志或演示数据。
- 页面不做装饰性自动运动。悬停、展开等只过渡必要属性，不用 `transition:all`；源稿歌词的 `.3s` 字号/颜色过渡仅是样机事实；M2b 评估后只改颜色与左侧标记，不放大当前行，避免布局跳动。支持减少动态效果偏好，不能让动效成为操作完成的必要条件。
