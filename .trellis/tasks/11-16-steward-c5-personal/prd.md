# 管家 C5：播放与个人库工具、页面上下文

## 目标

管家能替当前用户控制播放与队列、管理收藏和歌单、查看播放历史，并且知道用户正在看哪个页面、正在播放什么
（父任务 R2、R9）。

## 背景与约束

- 播放状态在服务端：队列、模式、播放进度都在分区（zone）里，浏览器只是输出端和遥控器；`zones.Service.Command`
  执行后经 SSE 推给浏览器（`backend/internal/zones/commands.go:25,61-64`）。后端工具可以直接控制播放。
- “当前控制哪个分区”只存在浏览器的 `localStorage`，后端不知道；工具必须带 `zone_id`。
- 个人库的服务层入口：`listening.Service`（历史）、`personal.Service`（收藏、歌单，写入统一走 `Execute`，
  `backend/internal/personal/playlist_retry.go:28`）、`zones.Service`（播放、队列、设备音量）。三者都已在
  `backend/internal/app/app.go:107-113` 构造，尚未传给 `registerSteward`。
- 这些写入都不经过 `operations.Run`，是按用户的普通写入；按父任务设计属于 `personal` 范围：三种模式下直接执行，
  MCP 只读令牌拒绝、读写令牌允许，`Revertible` 为否。
- 非 `read` 工具目前在三处被挡住：`steward/tool/registry.go:89-92`（调用入口拒绝）、`steward/runtime/run.go:141`
  （只把 `read` 工具发给模型）、MCP 列表里读写令牌能看到但调用失败。
- 发消息的请求体只有 `{text}`，用 `DisallowUnknownFields` 解码（`steward/httpapi/events.go:26-29`）。
- 前端：当前路径在 `app/shell/app-shell.tsx:99`；正在播放在 `PlayerSnapshot.current`
  （`features/player/zones/controller.ts:23-47`）；发消息在模块级的 `run/run-store.ts:80,96`。
- ADR 0005 第 3 节：用户本人的歌单、收藏、播放历史、播放状态可以发给本人配置的模型端点；其他成员的不发。
  标题来自文件标签，属于不可信文本（第 4 节）。
- 原型：输入框上方一行标签“正在看：…”“正在播放：…”（`temp/steward-design/index.html:122-125,397`）。

## 决定

| 编号 | 日期 | 选择者 | 决定 |
| --- | --- | --- | --- |
| D1 | 2026-11-16 | 主代理 | 清空全部播放历史不做成工具；删除某首曲目的播放记录、删除歌单可以做（删除歌单不能恢复，仍按 personal 直接执行） |
| D2 | 2026-11-16 | 主代理 | 上下文由前端随消息发送，用户可以在输入框上方点掉某一项，当条消息就不带它；上下文存在用户消息上，不显示在消息正文里 |
| D3 | 2026-11-16 | 主代理 | 上下文带上当前控制的分区 ID 与名称，模型调用播放工具时默认用它；没有上下文时模型先调用读取播放状态的工具 |

## 需求

- R1 调用入口放开 `personal` 范围：鉴权后直接执行；运行时把 `read` 与 `personal` 工具都发给模型；
  MCP 读写令牌可以调用，只读令牌看不到也调不了。`shared` 仍然拒绝（留给 C6）。
- R2 只读工具：播放状态（分区、设备、当前曲目、模式）、分区队列、播放历史、最近播放的专辑、收藏列表
  （曲目、专辑、艺人）、歌单列表、歌单内容。
- R3 `personal` 工具：播放控制（播放、暂停、停止、上一首、下一首、跳转位置）、播放指定曲目或专辑
  （替换队列、下一首播放、加到队尾）、队列编辑（移除、移动、清空）、播放模式、转移分区、设备音量与静音；
  收藏与取消收藏；歌单的新建、改名、删除、加曲目、移除曲目、移动曲目；删除一条播放历史。
- R4 工具结果里的失败原因要让模型能转述：分区离线、没有可用的输出、歌单版本冲突、目标不存在。
- R5 发消息与继续接口接受可选的 `context`：页面（路径、类型、对象 ID、标题）与播放（分区 ID 与名称、曲目 ID、
  标题、艺人、状态）。后端校验长度后存在用户消息上，发给模型时作为带来源标记的附加内容放在该条用户消息里。
- R6 输入框上方显示“正在看”“正在播放”两个标签，可以分别点掉；没有内容时不显示这一行。
- R7 对话里的工具条目给新工具配中文名称、主要参数和结果说明。

## 验收

- A1 说“暂停”“下一首”“把这张专辑加到队列后面”，当前分区的播放随之变化，浏览器不刷新即可看到。
- A2 在专辑页问“这张专辑是谁录的”，管家不追问是哪张专辑。
- A3 “把正在放的这首加到歌单 X”“收藏这张专辑”生效，个人库页面能看到。
- A4 普通成员能用以上全部工具，且只影响自己的数据；用户甲的会话拿不到用户乙的歌单、收藏、历史和分区。
- A5 分区离线时管家说明原因，没有副作用。
- A6 MCP 只读令牌列不出也调不了 `personal` 工具；读写令牌可以。
- A7 点掉“正在播放”后发送，请求体与落库的上下文里没有播放信息。
- A8 上下文里的标题含指令文本时，按带来源标记的不可信文本进入模型请求（用假模型端点核对请求体）。

## 不做

- 清空全部播放历史（D1）；设备改名与删除；PEQ 预设与分区音效设置（随 C9）。
- 改动曲库的工具与确认流程（C6）。
