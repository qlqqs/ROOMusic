# 完善前端音乐库展示

## 规划状态

- 任务状态：`planning`
- 规划决策路线：人工选择（Human selection）。本文件记录的是待审核的推荐方案；用户明确批准最新规划后，才允许执行 `task.py start`。
- 推荐方案：以 **Release/专辑优先** 完善浏览工作台，不在本任务新增独立艺术家页、全局曲目页或真实播放服务。

## 当前执行边界与任务拆分

- 用户已明确要求：若规划包含后端配套，先完成后端；前端实现暂缓并保留在本父任务中。
- 已建立可独立验收的后端子任务：`.trellis/tasks/09-04-release-list-artwork-backend`，负责发行列表摘要的 nullable artwork REST 投影、测试和运行合同同步。
- 本父任务继续保持 `planning`，不因子任务存在而启动；后端子任务完成并归档后，再为前端展示创建/启动后续子任务。
- 子任务依赖关系：前端子任务可消费后端 additive 字段，但不反向要求本后端子任务实现任何 `frontend/src/**` 或生成资产。

## 目标与用户价值

扫描完成后，用户应能在首屏快速认出自己的音乐：通过真实封面、标题、艺术家、年份、介质和曲目数量浏览发行版本，使用搜索/筛选缩小范围，再在清晰的 `Release -> Medium -> Track` 详情中检查元数据。当前页面虽然已经能请求这些数据，但列表只显示标题首字占位图，详情位于列表下方且操作层级不够清楚；本任务要把“已经扫描”转化为“可以高效浏览”。

## 背景与已确认事实

- 产品权威模型是 `ReleaseGroup -> Release -> Medium -> Track`，不是文件夹浏览器；普通浏览应围绕发行版本组织。
- 当前列表查询已经支持分页、标题/艺术家/曲目搜索和 `attention=required` 筛选，详情查询已经返回发行元数据、Medium/Track、封面、署名和安全 evidence 摘要。
- 当前发行卡片在 `frontend/src/main.tsx:477-487` 只显示标题首字占位图；真实封面在 `frontend/src/main.tsx:499-503` 进入详情后才展示。
- 当前列表 DTO 在 `frontend/src/api.ts:35-47` 没有 artwork；详情 DTO 在 `frontend/src/api.ts:67-80` 已有 nullable artwork 资源信息。
- 后端列表投影和扫描查询位于 `backend/cmd/roomusic/catalog_api.go:54-70`、`174-245`、`296-320`；受鉴权封面资源已注册为 `GET /api/v1/artworks/{id}`（`backend/cmd/roomusic/application.go:75-78`）。
- 当前前端状态和渲染集中在 `frontend/src/main.tsx`，样式集中在 `frontend/src/styles.css`；没有 router、query/cache、组件库或独立 DOM 测试工具。
- 播放器目前只是本地演示状态（`frontend/src/main.tsx:97-98`、`383-386`、`610`），Core 0 没有音频流 endpoint；本任务不能把演示控件描述成真实播放。
- 前端设计规范要求深色工作台、发行信息高密度、桌面三栏/移动堆叠、固定播放器不遮挡内容、语义 HTML 和可见焦点；后端仍是权限、路径和只读边界的唯一权威。

## 范围内需求

### R1. 工作台导航与浏览入口

保留现有同源登录和侧栏结构，并把入口语义明确化：

- “媒体库”导航回到发行版本列表并显示结果总数。
- “播放队列”导航滚动/聚焦到队列区域；没有曲目时显示可恢复的空状态。
- 管理员可见“管理中心”入口；普通用户不渲染管理入口，但仍必须安全处理后端 401/403。
- “退出登录”继续调用现有登出 API，清理当前选中发行版本和浏览状态。

### R2. 列表工具栏与 URL 状态

媒体库工具栏必须提供以下按钮/控件：

| 控件 | 可见文字/名称 | 行为与状态 |
| --- | --- | --- |
| 搜索提交 | “搜索”或带 `aria-label="搜索音乐库"` 的按钮 | 提交当前输入，按现有后端语义搜索 Release 标题、艺术家、Album Artist 和 Track 标题；回车等价于点击。 |
| 清除搜索 | “清除” | 仅在有已提交查询时显示；清空输入、删除 URL 的 `q` 并回到第一页。 |
| 需要检查筛选 | “只看需要检查”/“显示全部” | 切换 `attention=required`，重置到第一页，使用 `aria-pressed`，不依赖颜色表达状态。 |
| 视图切换 | “网格”“列表” | 在封面网格和密集列表之间切换；属于本地 UI 状态，不写入服务端，不改变查询结果。 |
| 刷新 | “刷新媒体库” | 重新请求当前查询/筛选/页码；保留 URL 状态，显示刷新中状态，避免旧请求覆盖新结果。扫描终态变化时自动触发同等刷新。 |
| 分页 | “上一页”“下一页” | 继续使用服务端分页和安全页界限；加载期间禁用，页码超界时按现有 `replaceState` 规则规范化。 |
| 管理员扫描 | “扫描音乐库”/“停止扫描” | 沿用既有扫描 API、取消语义和权限；扫描完成后刷新列表，未完成/失败/取消时展示明确提示。 |

查询参数继续由 `release_filters.ts` 统一读写：`q`、`attention`、`page`，并新增可选的 `release` 作为当前详情的可分享标识；视图模式不进入 URL，避免把纯展示偏好变成服务端查询条件。

### R3. 发行版本卡片与封面

- 网格卡片显示：封面、发行标题、Album Artist（无则回退 Artist）、年份、`碟数 / 曲目数`、介质/来源标签以及 attention 数量。
- 列表行显示同一组核心字段，并增加更紧凑的可扫描布局；两种视图共用同一 typed view model，不能各自重新解释 DTO。
- 列表 API 增加 nullable `artwork` 摘要（`resource_id`、MIME、宽高），浏览器只用 `/api/v1/artworks/{resource_id}` 读取受鉴权资源，不接触原始文件路径。
- 封面组件必须区分：加载中、无封面、图片损坏/加载失败和成功；失败回退到稳定的标题首字/音乐符号占位，不让单张图片阻塞整页。
- 卡片是可聚焦的语义按钮，名称包含发行标题和艺术家；使用稳定 Release ID 作为 key，不用标题、数组位置或文件名作为身份。
- 卡片本身只负责“查看详情”，不在卡片内部嵌套第二个按钮；播放动作放到详情和队列区域，避免无效/非法嵌套交互。

### R4. 发行详情面板

点击卡片后打开可关闭的详情面板：桌面端从右侧进入并保留列表上下文，移动端变为全宽上下堆叠面板。面板需要有明确标题、关闭按钮、焦点回收和 Escape 关闭行为；当前详情 ID 写入 URL，浏览器前进/后退可恢复或关闭它。

详情面板按钮与功能：

| 控件 | 可见文字/名称 | 行为 |
| --- | --- | --- |
| 关闭详情 | “关闭详情” | 清除 `release` 参数，返回列表并把焦点还给打开该详情的卡片。 |
| 播放首曲 | “播放首曲” | 将第一条可见 Track 放入本地演示队列并设为当前项；无曲目时禁用并说明原因。 |
| 播放全部 | “播放全部” | 按后端返回的 Medium/Track 顺序建立有界本地演示队列；不请求音频、不写服务端。 |
| 展开/收起全部 | “全部展开”“全部收起” | 控制 Medium disclosure；单个 Medium 也可独立展开/收起，默认展开第一碟。 |
| 单碟展开 | “展开碟片 N”/“收起碟片 N” | 显示该 Medium 的标题和曲目，使用 `aria-expanded` 与稳定 Medium ID。 |
| 曲目播放 | “播放《曲目名》” | 将该 Track 设为当前演示项；当前项有可见 active 状态和辅助文本。 |
| 查看完整证据（管理员） | 现有按钮 | 继续请求管理员 evidence endpoint；普通浏览只显示安全摘要，403/失败可重试。 |

面板内容顺序固定为：封面与发行标题 → 艺术家/年份/介质/碟数/曲目数 → 可用发行字段（流派、版本、唱片公司、目录号、条码）→ 署名 → Medium/Track → 可折叠的整理证据。空字段显示“未记录”，不显示原始绝对路径。

### R5. Track 与元数据可读性

- Track 行按服务端 Medium/Track 顺序显示位置、标题、Track Artist、时长和可用音频事实（codec、bit depth、采样率、声道、bitrate、CUE 起点）。
- 纯展示格式化集中在 catalog view-model/formatter 中：时长统一为 `mm:ss`，采样率/codec/来源使用用户可读标签，未知值使用“未记录”而非 `undefined`。
- 现有 provenance/evidence 仍可查看，但技术字段不得覆盖标题和播放意图；长文本截断并通过 `title`/辅助文本保留完整名称。
- 不新增艺术家详情页、独立曲目全库页或按文件夹浏览；搜索命中曲目仍定位到所属 Release。

### R6. 本地演示队列与底部播放器

在不改变“无音频服务”边界的前提下完善可见状态：

- 队列面板显示当前曲目、所属艺术家、队列长度和空队列提示。
- 队列按钮：播放/暂停、上一首、下一首、移除当前项、清空队列；上一首/下一首只在本地有界队列中工作。
- 固定底栏显示封面缩略图、曲目、艺术家、上一首/播放/下一首、当前序号和“演示模式”标识；队列入口可聚焦。
- 移除无实际行为的伪进度拖动、音量和下载控件；若保留进度文案，必须明确“演示”且不让用户误以为音频已连接。
- 切换 Release 或刷新列表不丢失当前本地队列，登出时清空；队列不写入 localStorage、URL 或服务端。

### R7. 加载、空、错误与扫描联动

每个数据区域都要有可见且可恢复的状态：

- 初始加载：骨架/占位布局，不让页面突然跳动。
- 刷新中：保留上一组结果并标记“正在刷新”，而不是瞬间显示空列表。
- 无扫描数据：提示管理员启动扫描；普通用户显示安全说明。
- 搜索无结果：显示查询词和“清除搜索”按钮。
- attention 无结果：显示“没有需要检查的发行版本”和“显示全部”按钮。
- 列表/详情网络错误：按区域显示错误、重试按钮和安全消息；401 返回登录恢复，403 显示无权访问，404 清除失效详情，503 保留上下文后可重试。
- 封面错误：局部回退，不把整页标为失败。
- 扫描 `running`、`succeeded`、`failed`、`canceled`、`incomplete` 必须使用不同文案；只有 `succeeded` 自动刷新并可提示“结果已更新”，不得由前端猜测扫描完成。

### R8. 响应式、可访问性与安全

- 桌面端保持导航/内容/队列工作区；详情抽屉打开时不得遮蔽关键列表操作，必要时提供遮罩和关闭动作。
- `375px` 与 `768px` 断点下改为上下堆叠；无横向滚动依赖，封面、按钮和长标题不溢出。
- 搜索、视图切换、筛选、分页、详情面板和队列按钮全部有语义名称、可见焦点、键盘路径和适当 live region；不以颜色单独表达 attention/错误/播放状态。
- 浏览器继续使用 HttpOnly cookie 和 `requestApi`，不读取 token，不将绝对路径、SQL/堆栈、管理员证据或凭据写入 URL/存储/普通用户界面。
- 音乐目录继续只读；本任务不改标签、不移动文件、不下载外部封面。

## 配套 REST 合同

这是一个向后兼容的 additive 投影变更，不新增迁移：

- `GET /api/v1/releases` 每项新增 `artwork: ReleaseArtworkDTO | null`；后端从现有 `release_artworks` 关系读取，缺失时返回 `null`。
- `ReleaseArtworkDTO` 只包含受控 `resource_id`、白名单 MIME、正宽高；列表和详情共用同一 decoder/type owner。
- artwork 资源仍通过现有鉴权 endpoint 返回，缓存和路径安全语义不变。
- 后端列表仍只返回含 `present` Track 的 Release，分页上限、搜索、attention 过滤和排序不变；不做 N+1 的逐 Release 详情请求。
- 后端子任务先更新 API 投影、后端测试与 Core 0 运行合同；前端 decoder 与展示测试在后续子任务更新。旧字段消费者不会因为新增字段而改变权限行为。

## 验收标准

1. 登录后首屏显示清晰的发行版本工作台：搜索、清除、刷新、attention 筛选、网格/列表切换、结果计数和分页均可操作。
2. 至少包含封面的 Release 在网格和列表中显示真实受鉴权封面；无封面、加载失败或损坏图片稳定回退，不影响其它卡片。
3. 点击卡片打开详情面板，标题、艺术家、发行事实、署名、所有 Medium 和 Track 层级可读；关闭、Escape、浏览器前进/后退均不会留下过期详情。
4. “播放首曲”“播放全部”、单曲播放、上一首/下一首、暂停、移除和清空队列在本地演示状态中产生正确可见变化，并明确标注未连接音频服务。
5. 搜索、attention、分页、刷新和扫描终态联动保持现有 REST 语义；旧查询结果不会覆盖新查询，详情/封面请求失败有局部重试路径。
6. `running/succeeded/failed/canceled/incomplete` 扫描状态文案和可用动作互不混淆；失败、取消或未完成不会被 UI 表示为“库已完整更新”。
7. 普通用户看不到管理员完整 evidence 和管理按钮；任意 401/403/404/503 均不会泄露绝对路径、token 或内部错误。
8. 桌面宽度和 `375px` 窄屏没有核心内容遮挡、横向溢出、焦点丢失或固定播放器遮挡末尾内容；键盘可完成搜索、筛选、打开/关闭详情和队列控制。
9. API decoder、纯展示格式化、URL 状态和组件/交互测试覆盖有效、空值、malformed、未知/越界和失败恢复路径。
10. 受影响的 `npm run lint`、`npm run typecheck`、`npm run test`、`npm run build`、后端 catalog 定向测试、`gofmt`/`go vet`/构建和生成资产一致性检查通过。

## 明确范围外

- 真实音频流、`<audio>` 播放、音频 Range endpoint、播放历史、跨会话队列和音量控制。
- 独立艺术家浏览、独立曲目全库浏览、歌词、收藏、评分和推荐。
- metadata 编辑、标签回写、改名/移动/删除、Release 合并/拆分。
- 外部封面或 MusicBrainz/AI provider、Meilisearch、GraphQL、Redis、PWA、插件和 Agent runtime。
- 新增数据库表/迁移或改变扫描、权限、Operation Journal 业务规则。

## 关键决策、风险与延期

- 发行版本优先是推荐的信息架构：它直接复用现有权威 API，避免为了“艺术家页”制造第二套聚合/权限/分页模型。
- 详情采用可关闭的右侧面板/移动堆叠，而非全新路由库；这样保留列表上下文并控制依赖，代价是需要实现焦点管理和 URL 选中状态。
- 封面列表摘要会增加一次轻量后端投影变更；若实际查询计划显示代价过高，可回退为列表占位图并把真实封面列表化延期，但不得改成前端逐项请求详情的 N+1 方案。
- 当前前端是过渡单体；只抽取 catalog 真实组件和纯 formatter，不在本任务进行全量 feature 目录迁移或引入状态库。
- 测试优先使用现有 Vitest/TypeScript 门禁；若组件交互需要 DOM 环境，实施阶段只增加最小测试依赖并记录锁文件变化，不引入 UI 组件库。
