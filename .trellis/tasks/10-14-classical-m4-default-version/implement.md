# M4 默认版本与版本对比：执行计划

需求见 [prd.md](prd.md)，设计见 [design.md](design.md)。

**通用约定**

- 提交：每一步单独提交到本地 `main`，提交信息用中文，不推送，不用 `--amend`。
  改动前端源码的提交要同时重新构建并提交 `backend/cmd/roomusic/web`。
- 提交前检查：用 `git checkout-index -a --prefix=<临时目录>/` 导出暂存区，在完整文件树上跑这一步的验证；`git diff --cached --check` 必须干净。
- 数据库测试：只用 `roomusic-test` Compose 项目（`--env-file /dev/null`、绝对路径的 compose 文件、空闲端口、随机库名，结束时 `down -v`），
  不碰用户自己的 `roomusic` 项目。
- 素材：自动化只用合成素材，不读真实 `music/`。
- 停进程：只按 PID 停自己启动的进程。

## 步骤

- [ ] **1. 迁移 0018 与操作记录的组目标（无行为变化）**
  - 迁移 0018（design §2）。
  - operations：新增 `TargetReleaseGroup`、`TypeReleaseGroupDefault`，`Description.Album`，`RevertResult` 改为目标类型加目标 ID，
    `List` 支持 `group_id` 以及与 `release_id` 的并集（design §5）。
  - operations/httpapi：增加 `group_id` 筛选和列表项的 `album`。
  - 前端：同步改解码器（撤销响应、列表项的 `album`）。
  - 门禁：
    - 现有 operations、catalog 和 app 的测试改动只限于撤销响应的新形状；
    - 新增并集筛选的测试，覆盖分页和总数；
    - 迁移后的约束能拒绝未知的类型和目标类型。
- [ ] **2. 默认版本的读写接口**
  - catalog：代表版本规则的默认项（design §3）；组详情增加 `revision` 与 `default_release_id`；执行器与 `GroupDefaultOperations`（撤销与展示）；
    `POST /api/v1/release-groups/{id}/default`；app 注册新的 Kind；接口样本。
  - 测试：
    - 读取与生效：设定后代表版本、列表排序、组详情的成员顺序与标题快照都跟着变；没有设定时与现在逐项一致；默认版本不可见或被移出时回到自动规则，回来后重新生效。
    - 写入状态：改回自动；`no_changes`（包括清除失效中的默认版本算作变化）；`not_in_group`；过期版本 409；组不存在或没有可见成员 404。
    - 撤销：恢复前态，包括失效中的前态；之后又有调整时 `revert_conflict`；撤销的幂等。
    - 记录：`Describe` 给出专辑、改动和能否撤销；列表的并集筛选。
    - 并发：设定默认版本与归组同时进行时不死锁。
    - HTTP 层：401、403（跨源、非管理员）、400 都没有副作用；同键重放、同键异义。
    - 真实重扫：**合成素材真实重扫后默认版本保持**。
- [ ] **3. 版本对比接口**
  - catalog：对比读取（固定数量的查询）；`GET /api/v1/release-groups/{id}/comparison`；接口样本。
  - 测试：
    - 内容：有效值与 `corrected_fields`；只计 present 曲目；时长求和以及全部未知时为 null；格式分组与排序。
    - 顺序与上限：成员顺序与组详情一致（默认版本在前）；最多 100 个，`release_count` 是完整数量。
    - 错误与权限：组不存在或没有可见成员 404；普通成员可读；未登录 401。
- [ ] **4. 前端：专辑页的默认版本标记与版本对比**
  - catalog：解码器；版本导航的“默认版本”标签与“对比版本”按钮；对比对话框（design §7）；对比的查询与钩子；
    `AlbumDetailView` 增加地址规范化暂缓开关。
  - 测试（Vitest）：
    - 标签只在生效中的默认版本上出现；
    - 对比表的行、差异标记与读屏文字、空行隐藏、人工修正标记、格式文字（不出现“最高音质”）；
    - 列头切换版本后对话框关闭、焦点恢复；
    - 规范化暂缓：命令进行中不改地址，刷新完成后按新数据规范化。先写一个测试确认 M3 归组跳到已缓存专辑时的现状，再决定是否在这一步一起修。
- [ ] **5. 前端：设为默认版本、改回自动选择、记录与撤销**
  - governance：
    - 命令种类 `default`：结果提示、撤销、`onMoved` 让页面停在当前版本；
    - 头部按钮；移出默认版本时的说明；
    - 操作记录的类型名、改动行、专辑列、撤销确认；
    - “修改记录”与操作记录页的组筛选（地址参数 `group`）。
  - app：页面把 `revision` 与 `default_release_id` 交给操作区，并传入规范化暂缓开关。
  - 测试（Vitest）：
    - 请求：请求体与幂等键；
    - 页面行为：设定或清除后页面仍显示同一个版本，提示带“撤销”，撤销后恢复；409 与结果不确定时的处理；
    - 权限：普通成员没有任何入口；
    - 记录：“修改记录”列出专辑级记录，并能从那里撤销；操作记录页的专辑列与组筛选。
- [ ] **6. Playwright（路由模拟）**
  - 先在 `src/test/governance-data.ts` 补上默认版本与对比的共享行为，Vitest 的假接口与 Playwright 的模拟共用。
  - 用例：设定、改回、撤销、对比；五种宽度、axe（WCAG 2.1 A/AA）、纯键盘；对话框内部不溢出（滚动宽度检查）。
- [ ] **7. 真实服务用例**
  - `frontend/e2e/real/` 新增用例。素材是两张合成 WAV 专辑；`syntheticWav` 增加可选的采样率与位深，让其中一张是 24 bit / 96 kHz。WAV 的 INFO 不带年份，年份用 M3 的修正接口设定。
  - 流程：
    1. 把两张专辑归到一起；
    2. 页面上设为默认版本：专辑列表显示它，打开专辑先显示它；
    3. 重扫：默认版本保持；
    4. 打开对比对话框：两种格式的差异被标出；
    5. 在“修改记录”里撤销：回到自动规则；
    6. 收尾：清理素材并重扫。
  - 权限：普通成员能打开对比，没有设定入口，写接口返回 403。
  - 反向验证：临时让扫描清空默认版本，确认用例会失败，随即还原。
- [ ] **8. 文档同步**

## 风险与回滚点

- **代表版本规则（第 2 步）牵动全部按组读取**：门禁是“没有设定时输出不变”，失败就回退这一步。
  如果 PostgreSQL 的窗口排序不接受子查询，就改为连接 `release_groups`，语义不变。
- **扫描写入路径不改**：实现中如果发现必须改 `persist.go`，先停下说明原因，不扩大范围。
- **锁顺序**：先发行、后组，与归组一致。死锁测试失败时，不能靠重试掩盖。
- **撤销响应与列表项形状改变（第 1 步）**：前端解码器与样本在同一个提交里更新，契约测试守住。
- **前端规范接近上限**：状态规范 23.6 KB，组件规范 21.1 KB；细节放进有余量的钩子规范。
- 每一步独立提交，可以单独 revert；迁移 0018 一旦提交，就只向前修复。
