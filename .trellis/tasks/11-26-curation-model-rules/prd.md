# 模型调用的通用规则

父任务：`.trellis/tasks/11-26-curation-chain-review`。每条决定的现状、依据和代码位置见父任务 `prd.md` 的对应段落（下表“出处”一栏）；规则汇总见 `docs/architecture/adr/0009-curation-chain-review.md`。

本任务只实现下面列出的决定，不改其他段的行为。实施中发现某条决定做不到或需要改，先停下报告，由主代理回父任务问用户。

## 目标

按父任务 B4.1、B4.2 的决定，改整理链调用模型的通用规则：报错分类、空返回、额度、单次发送大小、分批和先后。

## 范围

| 事项 | 出处 | 要做的 |
| --- | --- | --- |
| 报错五类 | B4.1 表 | ① 请求本身的问题（400 等）；② 配置问题（401、403、模型不存在、不支持工具调用）；③ 额度用完（402，或 429、400 里写明额度、余额不足）；④ 临时问题（429 限流，500、502、503、504、529，超时，连不上，回复中途断了）；⑤ 回复格式不对、空返回。各自怎么处理见 B4.1 表。现有分类在 `backend/internal/steward/provider/errors.go:70-115`，快速重试在 `backend/internal/steward/provider/client.go:117-157`，调度在 `backend/internal/curation/model/scheduler.go:573-579,620-639` |
| 出错不计次 | B4.1 表 | 只有模型真正给了回复才算这一项的次数；“定不了”算一个答案，记下理由，不重试 |
| 空返回 | B4.1 表 | 这一项重来，间隔最长 3 分钟，连续 3 次记“模型没给出结果”并停下；连续 10 项空返回，暂停模型任务，提示换模型 |
| 来源暂停不开会话 | B4.1 表 | 需要的来源在暂停时，这一项不开模型会话 |
| 合并额度 | B4.2 表 | 所有模型用量（含子任务 10 的艺人联网）合成一份，默认每天 1000 万 token；去掉单独的联网额度（迁移 `0091` 加的设置）；用完停下模型任务，排着的不丢，第二天或调高后接着做 |
| 去掉“用满后 7 天” | B4.2 表 | `backend/internal/curation/model/item.go:185-197` |
| 单次最多发送 | B4.2 表 | 新设置，默认 12.8 万 token，可改；凑批不超过它，并给回答留余量；单张就超长的，先只留最接近的几个候选，还超就记“内容太长”、不交模型；取代 1 MB 的限制（`item.go:57`） |
| 分批 | B4.2 表 | 同类项按内容长短凑批；本地辅助一次一个目录；整批被拒（400）就拆开一张一张重试 |
| 任务先后 | B4.2 表 | 本地辅助 → 识别判断 → 名字与艺人核对。本任务做排队先后的框架；三类各自的做法在子任务 8、9 |
| 未配置模型 | B4.2 表 | 三类都不做，设置页显示“未配置模型” |
| 设置页 | 文档决定 | 配置问题的原因与“测试/重试”、额度、单次最多发送（提示本机模型的上下文长度）。本任务提供接口，界面由主代理做 |
| 规范 | 文档 | 整理合同、`.trellis/spec/backend/steward-runtime-contracts.md` 里改到的段落 |

- 审查不可用的退避（`scheduler.go:642-706`）随子任务 9 去掉整理链审查一起删，本任务不单独改。
- “升级时清掉巡检项、联网项和未采用的建议”挪到子任务 9，和去掉这些功能一起做。

## 不做

- 三类模型任务各自的提示词和回答（子任务 8、9）；艺人联网（子任务 10）。

## 验收

- [ ] 用模拟上游（`script.go`、`scenario.go`）的报错样本：400 只影响这一项且不重试；401、403 停下全部模型任务并给出原因；402 停下并每小时探测一次；429、5xx 先快速重试、再暂停，最长 3 分钟；空返回连续 3 次停这一项，连续 10 项暂停全部。
- [ ] 来源暂停时不建模型会话（计数为 0）。
- [ ] 额度用完就停下，调高后接着做，排着的项不丢。
- [ ] 超过单次最多发送的批被拆开；单张超长的记“内容太长”。
- [ ] 新规则各有对照样本，用合成数据；只跑改动涉及的包和用例。
- [ ] 改到的规范同步改（见各行）。
- [ ] 合入前跑依赖门禁 `TestPackageDependencyDirections`。
