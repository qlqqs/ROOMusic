# 目录监听与定时扫描

父任务：`.trellis/tasks/11-26-curation-chain-review`。每条决定的现状、依据和代码位置见父任务 `prd.md` 的对应段落（下表“出处”一栏）；规则汇总见 `docs/architecture/adr/0009-curation-chain-review.md`。

本任务只实现下面列出的决定，不改其他段的行为。实施中发现某条决定做不到或需要改，先停下报告，由主代理回父任务问用户。

## 目标

按父任务 A1.1“目录监听”和 A3 最后一行的决定：文件变了几秒内只重扫那个目录；监听不到的曲库目录改为定时增量扫描；确认扫描不再扫全库。

## 范围

| 事项 | 出处 | 要做的 |
| --- | --- | --- |
| 只扫一个目录 | A1.1、A3 | 增量扫描能只扫一个目录（碟片子目录连同上一级），作为监听和确认扫描共用的入口 |
| 目录监听 | A1.1“目录监听” | 首次全量扫描完成后才开始监听各曲库目录；新建、删除、改动、改名记到所在目录，同目录合并，最后一次事件后安静 2 秒再处理，一直在写就往后推；到期只重扫这个目录 |
| 监听不到的目录 | A1.1“Linux 上的限制” | 自动识别：挂载类型是网络共享（NFS、SMB/CIFS 等），或监听挂不上（数量到上限等）；这类曲库目录按间隔定时增量扫描，可选 15 分钟、1 小时、4 小时、12 小时、每天，默认 1 小时；程序不改系统设置 |
| 设置页 | 同上 | 每个曲库目录标出“实时监听”还是“定时扫描”，定时扫描的可以选间隔。本任务提供接口，界面由主代理做 |
| 确认扫描 | A3 表最后一行 | 专辑成员 60 秒没变后，只重扫这张专辑所在的目录确认，不再做全库增量扫描（`backend/internal/library/curation_observations.go:194-207`） |
| 手动扫描、每天定时扫描 | A1.1 | 保留，作为监听漏掉时的兜底 |

- 用现有依赖 `golang.org/x/sys/unix` 的 inotify，不新增依赖。确有必要加依赖时先报告。

## 不做

- 读文件前后比修改时间（子任务 2）。
- 改系统的监听上限。

## 验收

- [ ] 往监听中的目录拷入一张专辑（合成文件、独立临时目录，不碰现有实例），拷完几秒内出现在曲库，期间不出现半张专辑。
- [ ] 删除、改名、移动目录后几秒内反映。
- [ ] 首次全量扫描期间不触发监听重扫。
- [ ] 模拟网络共享或监听挂不上时，该目录改为定时扫描，接口报告“定时扫描”和间隔。
- [ ] 确认扫描只读这张专辑的目录（按读取计数验证）。
- [ ] 新规则各有对照样本，用合成数据；只跑改动涉及的包和用例。
- [ ] 改到的规范同步改（见各行）。
- [ ] 合入前跑依赖门禁 `TestPackageDependencyDirections`。
