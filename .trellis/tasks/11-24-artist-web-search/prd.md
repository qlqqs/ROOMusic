# 艺人资料补全：手动资料与网络搜索

现状调研：`research/repo.md`。界面设计稿：`../11-24-artist-media-ui/research/mockup.html`（可交互，浏览器直接打开）。

## 目标

没对上 MusicBrainz 的艺人（多见于华语流行歌手、网络歌手）也能有图片和简介：

- 管理员能手动补，也能指定这个艺人对应的 MusicBrainz 或 Wikidata 条目，让现有的有许可来源接着补；
- 打开“网络搜索”后，自动整理的模型层联网认人：认出身份就写对应、走有许可来源；认不出但搜到资料就直接写入“模型整理”的图片与简介；
- 插件也能按名字给没有 MBID 的艺人补资料；
- 艺人页用图标表示来源与操作，优雅、注重交互细节。

## 现状

- 资料只从艺人的 MusicBrainz 对应出发（上一轮 M8 的决定 K1）；对应只在发行对上 MusicBrainz 后按署名对位写入。
- 没有管理员手动给艺人加图片、简介或外部对应的入口。
- 插件的 `artist_image`、`artist_bio` 已收到艺人名，但调度要求先有 MBID。
- 自动整理已有模型层（待定项、独立审查、例外、按日额度、模型批次、撤销）；管家已有联网搜索（SearXNG、Tavily、模型自带）。

## 子任务

| 子任务 | 交付 | 顺序 |
| --- | --- | --- |
| `11-24-artist-manual-media` | 管理员上传图片、编辑简介、指定对应（含预览）；人工层优先；艺人范围的“不对”（撤销并抑制） | 先做 |
| `11-24-artist-web-search-model` | 网络搜索：模型层艺人身份待定项、两个后台工具、候选例外；插件按名字查；来源设置的“网络搜索”开关 | 在手动资料合入后（共用资料表与来源枚举） |
| `11-24-artist-media-ui` | 艺人页来源印章与弹层、拖放与粘贴识别、撤回、候选确认、简介编辑、去掉“专辑艺人”“曲目艺人”标签；设置页“网络搜索”行；例外列表认得艺人候选 | 跟随两个后端子任务的接口分两段做 |

## 需求

- R1 权限：所有写入、标记、开关、例外处理只有管理员能做；普通账号只读，能看到图片、简介和来源。
- R2 来源分四类并在界面上区分：有许可的外部来源、模型整理（附引用网页）、插件、管理员提供。
- R3 优先级：管理员提供 > 有许可来源 > 插件 > 模型整理。
  - 管理员提供的资料单独存放、遮住自动层（不删除）；管理员移除后自动层重新显示。
  - 自动层只补空缺，但等级高的来源可以替换等级低的（有许可来源替换插件与模型整理，插件替换模型整理）；同级不互相覆盖。
- R4 身份对应（写入 MBID 或 Wikidata 条目）保持严格：手动指定要先预览确认；模型提交要经程序复查与独立审查，拿不准的转人工例外。对应写入后走现有的有许可来源补全。
- R5 展示用资料放宽：模型整理与插件的图片、简介不经审查直接写入自动层，带来源与引用，可撤销；“不对”撤销并写抑制标记，同一来源条目以后不再写入。
- R6 “网络搜索”是一个开关（默认开），依赖开启者的管家对话模型与搜索来源；任一缺失时不可开并说明缺什么。插件按名字查不受这个开关控制，跟插件自己的开关走。
- R7 只处理主署名艺人（有专辑艺人或曲目艺人署名、不只是合作者角色），用量由模型层现有的每日 token 额度控制。
- R8 外发数据：艺人名与少量曲目名、专辑名（用于区分同名的人），与现有发行匹配相同，在 ADR 0005 范围内；不外发音频、路径或账号信息。
- R9 艺人页页头去掉“专辑艺人”“曲目艺人”两个标签；作词、作曲等其他角色可点，跳到下方对应角色的曲目区。艺人列表的角色筛选不变。

## 跨子任务验收

- X1 一位没有 MBID 的合成艺人：打开网络搜索后，mock 的模型与搜索让它走通三条路——认出身份（写对应 → 有许可来源补全）、认不出但有资料（模型整理写入）、拿不准（例外 → 管理员采纳）。
- X2 管理员在艺人页手动上传、编辑、指定对应、标记不对与撤回，结果与整理记录一致；普通账号看不到这些入口，接口返回 403。
- X3 撤销与抑制：任一来源的资料被标记不对后不会再被自动写回；管理员提供的资料不被自动流程覆盖。
- X4 界面与设计稿一致：390 与 1440 两种宽度截图无溢出，图标按钮都有读屏名与提示，键盘可达，`prefers-reduced-motion` 下没有转动。
- X5 全程只用合成数据与 mock，不访问真实外部主机。

## 不做

- 在多张图片之间挑选、裁剪工具（上传时按圆形预览居中裁切显示，不改原图）。
- 定期刷新已补上的资料。
- 网易云、QQ 音乐等商业平台的内置适配（可由第三方插件提供）。
- 普通账号的纠错建议入口。

## 规划决定

路线：人工选择。选定者 qlqq，2026-11-24 在对话中逐项确认方案（权限、来源分级、内置功能、图标化设计稿）并回复“做”；按记忆“规划完直接实现”，子任务不再等规划批准。
另由一个规划子代理评审两份后端设计，提出 A 7 条、B 8 条修改，全部采纳，记在各子任务 `design.md` 末尾的“评审修订”。

| 编号 | 决定 | 理由 |
| --- | --- | --- |
| D1 | 推翻 M8 的 K1“只从 MBID 出发、不按名字搜” | qlqq 认为原方案过严；改为身份严格、展示资料放宽（R4、R5） |
| D2 | 网络搜索做成内置的模型层功能，不做成插件或 skill | 模型、搜索、审查、额度、撤销都在模型层；插件沙箱不应拿到模型与搜索密钥（ADR 0007） |
| D3 | 插件只作为按名字查的数据来源接入 | 插件能补网络歌手资料，又不改变沙箱边界 |
| D4 | “模型联网认艺人”与“模型整理图片与简介”合为一个“网络搜索”开关 | qlqq 指定 |
| D5 | 界面以图标表达，文字进提示与读屏名；错误信息仍用文字 | qlqq 指定；`frontend/DESIGN.md` 对失败状态要求文字 |
| D6 | 模型整理的图片不要求许可 | 只有管理员能写入和撤销，部署不对外公开；记录来源页面 |
