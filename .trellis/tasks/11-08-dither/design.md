# 技术设计：位深转换与 TPDF 抖动

需求以 [prd.md](./prd.md) 为准。本子项是纯包 `backend/internal/dsp/dither` 加它在渲染会话里的接法（处理链 ⑧，父任务 [design.md](../11-08-audio-dsp-reference-port/design.md) §5.2，下称“父设计”）。
渲染会话见 [dsp-pipeline design.md](../11-08-dsp-pipeline/design.md)（下称“管线设计”）与 [design-delivery.md](../11-08-dsp-pipeline/design-delivery.md)。参考稿只引章节号，写作“参考稿 §N”。

## 0. 结论

- 量化器是链的出口：把 float64 planar 变成 16/24 位小端交错字节，交给 FLAC 编码器或 WAV 写出器。只在无损档使用；有损档把浮点直接交给编码器（design-delivery.md §1.2）。
- **直通**：块的 `Exact` 为真且源位深不超过目标位深时，逐位还原源的整数，不加抖动、不推进 LFSR。其余情况一律加 TPDF 抖动后取整。
- **TPDF**：31 位最大长度 LFSR（多项式 x³¹ + x²⁸ + 1，周期 2³¹ − 1），每次取值是 (−0.5, +0.5) LSB 的均匀值，两次取值相减得到 (−1, +1) LSB 的三角分布；不做噪声整形。
- 钳位到目标位深的范围，钳位的样本数就是削波数（供削波指示）。

## 1. 位深转换（T1，参考稿 §5.4、§6.6）

- 解码输出 MSB 对齐的 32 位整数，换成 float64 时除以 2³¹（管线设计 §4.3）。目标 `b` 位时，样本的定点值是 `x · 2^(b−1)`。
- **取高位**：源是整数、且位深 ≤ `b` 时，`x · 2^(b−1)` 正好是整数，等于“32 位 MSB 对齐的值右移 `32 − b` 位”，也就是参考稿的“32→24 取高 24 位、32→16 取高 16 位”。这一步在 float64 里做，结果与整型移位完全相同。
- **显式重打包**（参考稿 §5.4“取低位必须显式调用重打包”）：输出只有两个打包函数，`pack16`（2 字节小端）与 `pack24`（3 字节小端），按目标位深选一个，不存在“把 24 位放在 32 位容器里交出去”的路径。
- 目标是 DSD 时不经过量化器（第三批 PCM→DSD 在 ⑦，之后直接打包 1 bit 流）。
- 目标位深由 design-delivery.md §2.2 决定：链透明时等于源位深（16 或 24），开了处理时 24。

## 2. TPDF 抖动（T2，参考稿 §6.6）

### 2.1 LFSR

- 31 位 Fibonacci LFSR，反馈多项式 **x³¹ + x²⁸ + 1**（公开的本原三项式，最大长度，周期 2³¹ − 1）。状态非零；种子是固定的非零常数，所以同样的输入总得到同样的输出（便于测试与复现）。
- **一次取值**：寄存器推进 31 步，把 31 位状态整体作为整数 `r ∈ [1, 2³¹ − 1]`，换成 `u = r / 2³¹ − 0.5`，即 (−0.5, +0.5) 内的均匀值。每次推进 31 步使相邻两次取值不共享位（只推进 1 步时相邻状态只是移位，强相关）。2³¹ − 1 是素数，所以按 31 步取样的序列周期仍是 2³¹ − 1。
- 实现可以逐位推进（每次 31 次移位与异或），也可以用字并行一次产生多位；字并行实现必须与逐位实现产生同一序列（测试比对前 10⁴ 个取值）。
- 所有声道共用一个 LFSR，按“帧内声道 0、1、…”的顺序取值。

### 2.2 三角分布与“±0.5 LSB”

- 抖动值 `d = u₁ − u₂`，两次独立取值相减：分布是 (−1, +1) LSB 上的三角形，均值 0，方差 1/6 LSB²。
- **“±0.5 LSB”的含义**（prd 验收要求写明）：指**每次取值**的范围是 ±0.5 LSB，相减后的幅度是 ±1 LSB。理由：这是教科书的 TPDF（峰峰值 2 LSB），只有这个幅度才能让量化误差的一、二阶矩与信号无关（消除噪声调制）；若把相减后的结果缩到 ±0.5 LSB，抖动不足以去相关。
- 没有噪声整形（参考稿明确只有 TPDF）。

### 2.3 量化

```text
v = x · 2^(b−1) + d
q = floor(v + 0.5)                                  # 四舍五入；加了零均值的 d，平均误差为 0
q 超出 [−2^(b−1), 2^(b−1) − 1] 时钳到边界，削波数 +1
```

## 3. 何时抖动（T3）

量化器每块只做一次判断，判断依据由调用方（链的出口）从缓冲取来：

| 条件 | 处理 |
| --- | --- |
| `Exact` 为真，且 `0 < SourceBits ≤ b` | **直通**：`q = x · 2^(b−1)`（必为整数），不取抖动值、不推进 LFSR |
| 其余（样本被改过：电平化、Headroom、交叉淡化窗口、兼容性转换；或要降位深；或浮点源） | 加 TPDF 后取整 |

- 典型情形：电平化关、Headroom 关的 16/24 bit 源 → 直通，渲染流与源逐位相同（§1.1 的目标）；电平化开 → 24 位输出，每块都加抖动；24 bit 源遇到只能 16 位的输出 → 降位深，加抖动（信号路径标兼容转换）；MP3 等浮点源 → 加抖动。
- 只开交叉淡化时，只有窗口内的块被改过，只有这些块加抖动，其余块仍直通；块与块之间在直通与抖动之间切换时差异不超过 1 LSB，听不出来。
- 参考稿 §6.6 列了四个注入点（最终截断、16/24 位数字增益、24 位混音）。ROOMusic 的增益与混音都在 float64 里做，不存在中间的定点截断，所以只有“最终截断”这一处。

## 4. 削波统计（T4，参考稿 §6.10）

- `Quantize` 返回本次钳位的样本数。统计总是做（每样本一次比较），是否上报由 Headroom 的“削波指示”开关决定（管线设计 §8.2）。
- 直通路径不会削波（源整数一定在范围内），不比较。

## 5. 接口（`dsp/dither`，纯包，不导入任何包）

```go
// LFSR 是 31 位 Fibonacci LFSR（x^31 + x^28 + 1）。
type LFSR struct{ state uint32 }
func NewLFSR(seed uint32) *LFSR            // seed 取低 31 位，为 0 时改用固定的非零常数
func (l *LFSR) Next() uint32               // 推进 31 步，返回新的 31 位状态
func (l *LFSR) Uniform() float64           // (−0.5, +0.5)
func (l *LFSR) Triangular() float64        // Uniform() − Uniform()

// Quantizer 把 planar float64 量化成交错的小端定点字节。
type Quantizer struct{ /* bits、lfsr、scale */ }
func NewQuantizer(bits int, seed uint32) *Quantizer   // bits 只能是 16 或 24
// Quantize 把 src 的前 frames 帧追加到 dst 并返回；passthrough 为真时逐位直通。第二个返回值是削波数。
func (q *Quantizer) Quantize(dst []byte, src [][]float64, frames int, passthrough bool) ([]byte, int)
func (q *Quantizer) Reset()                           // LFSR 回到种子
```

- “是否直通”由调用方算好传入（`b.Exact && b.SourceBits > 0 && b.SourceBits <= bits`），量化器不认识 `chain.Buffer`，保持纯包。
- 稳态不分配：调用方传入复用的 `dst[:0]`。

## 6. 与编码器的衔接

- 链出口（`dsp/chain` 的量化阶段）每个量子调用一次 `Quantize`，把字节写给编码器：FLAC 时写 ffmpeg 的 stdin（`-f s16le|s24le`），WAV 时写在 44 字节头之后（design-delivery.md §1.1）。
- 流尾冲刷链之后最后一次 `Quantize`，然后关闭编码器输入。
- 信号路径：这一首在开流时就确定会被抖动（电平化开、Headroom 开、要降位深、浮点源）时，加一步 `dither{bits, kind: "tpdf"}`；只有交叉淡化窗口里抖动时不显示（瞬时，同交叉淡化本身不进信号路径）。

## 7. 测试范围（只测改动直接影响的行为）

`dsp/dither` 单元测试：

- **周期**：从种子出发，逐位推进恰好 2³¹ − 1 步回到种子，途中不回到种子（一次循环，约数秒；这是 prd 验收项，保留）。字并行实现（若有）与逐位实现的前 10⁴ 个取值相同。
- **分布**：10⁶ 个 `Triangular()`：全部落在 (−1, 1)；均值绝对值 < 0.005；方差在 1/6 的 ±2% 内；20 格直方图与三角形密度的偏差在 ±5% 内。`Uniform()` 全部落在 (−0.5, 0.5)。
- **直通**：随机 16 bit 与 24 bit 整数换成 float64 后 `Quantize(…, passthrough=true)`，输出字节与原整数的小端打包完全相同。
- **抖动线性化**：常数输入 0.3 LSB、`passthrough=false`，10⁵ 个输出的平均值与 0.3 LSB 相差 < 0.01 LSB，取值都在 {−1, 0, 1} LSB 内且不全相同（证明加了抖动而不是简单取整）。
- **钳位与削波**：输入 ±1.5 时输出为目标位深的最大/最小码，削波数等于样本数；输入 0 时削波数为 0。

渲染会话里的一条（随 dsp-pipeline 的会话测试一起写）：电平化开（未知增益 −5 dB）渲染 16 bit 源，解码后的 24 bit 样本与“源 × 增益直接四舍五入”的结果不全相同、且逐样本相差不超过 1 LSB。电平化关时的逐位一致由 dsp-pipeline 的 MD5 用例覆盖，这里不重复。
