# 整理艺人

父任务：`.trellis/tasks/11-26-curation-chain-review`。每条决定的现状、依据和代码位置见父任务 `prd.md` 的对应段落（下表“出处”一栏）；规则汇总见 `docs/architecture/adr/0009-curation-chain-review.md`。

## 目标

按父任务 G3 的决定：艺人联网查身份从整理链拆出来，改为手动触发的独立功能。

## 范围

| 事项 | 出处 | 要做的 |
| --- | --- | --- |
| 不再自动跑 | G3 表 | 去掉艺人资料队列里为没对上的艺人自动建联网项（`backend/internal/curation/program/artist_media_pass.go:361-400`） |
| 手动入口 | G3 表 | 艺人页“联网查找”查这一位；“整理艺人”按钮把所有没对上 MusicBrainz 的艺人排进去：专辑艺人在前，合辑里各首的艺人在后；查过且本地没变的跳过；随时可以停；额度用完就停，之后接着查。本任务提供接口，界面由主代理做（图标按钮，文字在提示和读屏名里） |
| 每位的上限 | G3 表 | 最多 10 次工具调用、5 万 token |
| 程序核对 | G3 表 | 用候选的 MusicBrainz 艺人编号去搜本地这位艺人的专辑，有一张结构对得上，就直接建对应，那张专辑也一起认出；对不上就把候选列在艺人页，用户点一下确认或否掉；不审查 |
| 额度 | G3、B4.2 | 和整理共用（子任务 7） |
| 显示条件 | G3 表 | 管家设置里配了网页搜索，才显示按钮 |
| 之后 | G3 表 | 确认对应以后，图片、简介由整理链照常补 |
| 规范 | 文档 | 整理合同、`.trellis/spec/backend/steward-web-contracts.md` 里改到的段落 |
