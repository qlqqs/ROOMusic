# 管家 C4：对话页

## 目标

登录用户在 ROOMusic 里直接和管家对话：配置自己的模型端点后，在任意页面的右侧面板或整页里发消息，
看到流式回答和工具调用过程，管理自己的会话（父任务 S1、S16、S17、R15、R16）。

## 背景与约束

- 已确认的静态原型在 `temp/steward-design/`（`index.html`：面板、整页、设置里的 Agent 栏目），父任务 S16 规定以它为准。
  本任务规划时补了它没有的状态（`c4.html` 与 `c4-*.png`）：运行中、出错、未配置、手机端对话与列表、本任务范围内的 Agent 栏目。
- C2 已提供的接口（规范 `.trellis/spec/backend/steward-runtime-contracts.md` 第 4、5、10 节）：设置读写与探测、会话的增删改查、
  发消息（响应是 SSE：`text`、`tool_started`、`tool_finished`、`usage`、`done`）、取消、管理员的成员开关与出站放行名单。
- 后端目前的边界：
  - 会话只有 `assistant` 模式，只登记了 16 个只读工具。
  - 一次运行绑定在发消息的那个请求上：客户端断开即取消运行；刷新页面后只能看到已落库的步骤。
  - 模型请求失败时用户消息已落库、该步回答不落库；没有“不追加用户消息、从现有历史继续”的接口。
  - 可选模型来自设置里探测结果的 `probe_result.models`；会话的模型用 `PATCH` 改。
  - 系统提示词是固定常量（`backend/internal/steward/runtime/run_content.go:11`），不含显示名字。
- 前端现状：`frontend/src/features/steward` 只有访问令牌（C3）；设置页有独立的“访问令牌”栏目（C3 的 K3 决定在本任务并入 Agent 栏目）。
  布局 token `--layout-steward-width`（390px）已预留。现有 SSE 用法是 `fetch` 加按行解析（`features/player/zones/event-stream.ts`）。
  底部标签栏是“概览、专辑、艺人、我的”四项（`app/shell/tab-bar.tsx`）。前端没有 Markdown 渲染依赖。
  C2 的接口样例在 `src/test/api-contract.test.ts` 里记为 `unconsumedContracts`。
- `frontend/DESIGN.md`：不伪造没有后端的能力；没有管家运行能力时不呈现聊天外壳。

## 需求

- R1 入口：桌面侧栏“聆听”分组里加一项，显示用户起的名字（默认“管家”），点击打开或收起右侧面板（D5）；
  手机底部标签栏加第五项（D4）。成员开关关闭时成员看不到入口。
- R2 面板与整页是同一个会话的两种显示：面板有新对话、展开到整页、收起；整页左边是会话列表（按今天、本周、更早分组，
  可新建、改名、删除），右边是对话。手机上整页的对话与列表分两屏，标题栏左侧按钮切换。
- R3 发消息后流式显示：工具调用按条目列出（中文名称、主要参数、结果数量或失败原因、进行中的状态），回答文字逐步出现；
  运行结束后过程收成一行摘要（查了几处、用时），可展开。运行中发送按钮变成停止按钮。
- R4 回答按 Markdown 渲染（D2）。
- R5 运行没有正常结束（模型接口出错、达到步数或用量上限、已停止、内部错误）时，在对话里说明原因；
  模型接口出错时可以“重试”（不重复追加用户消息）和“检查模型设置”。
- R6 在页面之间切换不打断正在进行的回答；面板和整页显示同一个进度。刷新页面会中断回答，重新打开后显示已保存的部分。
- R7 输入框下的模型按钮列出探测到的模型，切换只影响当前会话；菜单里有去设置的链接。
- R8 未配置模型时，面板和整页显示配置引导和去设置的按钮，不显示输入框。
- R9 设置页的 Agent 栏目（所有用户可见，取代“访问令牌”栏目，`/settings/tokens` 转到新地址）：
  名字；模型（接口地址、密钥、检测、检测结果与手动修改接口类型和工具能力、对话模型）；访问令牌（沿用 C3 的功能）。
  管理员另有“成员”一段：成员开关、成员可以连接的内网地址（列表、添加、移除）。
  成员开关关闭时成员只看到说明和访问令牌（D6）。
- R10 后端：系统提示词带上显示名字（D3）；新增“从现有历史继续运行”的接口，供重试使用。
- R11 名字在侧栏、标签栏、面板标题、输入框提示里一致，改名后不刷新页面即生效（父任务 S17）。

## 验收

- A1 配置好端点的用户在面板里发一句话，能看到工具条目逐条出现、回答流式显示，结束后过程收成摘要。
- A2 运行中切到别的页面再切回来（或从面板展开到整页），回答仍在继续且内容一致。
- A3 点停止后运行结束，对话里显示已停止，可以继续发下一条。
- A4 模型接口出错时显示原因与接口返回的状态；点重试后从已有历史继续，历史里没有重复的用户消息。
- A5 回答里的表格、列表、加粗、代码能正常显示；回答里的 HTML 标签按文字显示，`javascript:` 链接不可点击。
- A6 会话列表能新建、改名、删除、切换；正在回答的会话有标记，删除它时提示先停止。
- A7 切换模型后，下一条消息用新模型；别的会话不受影响。
- A8 未配置时看到引导；按引导配置并检测通过后可以直接开始对话。检测失败时显示每一步失败的原因，原设置不变。
- A9 改名字后侧栏、面板标题、输入框提示立刻变化；问“你叫什么”时回答这个名字（用假模型端点核对系统提示词里有名字）。
- A10 成员在开关关闭时看不到入口，直接打开地址看到说明；管理员关开关、增删放行地址后立即生效。
- A11 手机宽度（390px）下从标签栏进入，能完成对话、切换会话、新建会话；没有横向滚动。
- A12 `/settings/tokens` 的旧地址能到达 Agent 栏目；C3 的令牌功能不变。
- A13 契约测试里 C2 的管家样本由解码器消费，`unconsumedContracts` 里不再有本任务用到的接口。

## 不做

- 模式切换、方案确认卡片、审查结果、上下文标签、联网搜索设置、审查模型（D1，随 C5–C8）。
- 刷新页面或断线后接回正在进行的回答。
- 对话历史的长度控制（截断或摘要）：仍待用户决定，另行安排。
- 展开工具条目查看原始输入输出。
- 中窄桌面（768–1099px）上面板与内容并排：这个宽度下面板盖在内容上。

## 规划结论

路线：用户选择。D1–D5 由用户在 2026-11-16 的选择框里选定；其余细节按主代理的建议。
qlqq 于 2026-11-16 批准最终规划摘要并要求开始执行，同时指定前端可以交给 Opus 5.5（high）子代理实现。
