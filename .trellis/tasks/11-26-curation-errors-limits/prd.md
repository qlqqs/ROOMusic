# 出错、限流与提前查声纹

父任务：`.trellis/tasks/11-26-curation-chain-review`。每条决定的现状、依据和代码位置见父任务 `prd.md` 的对应段落（下表“出处”一栏）；规则汇总见 `docs/architecture/adr/0009-curation-chain-review.md`。

本任务只实现下面列出的决定，不改其他段的行为。实施中发现某条决定做不到或需要改，先停下报告，由主代理回父任务问用户。

## 目标

按父任务 A2.4、A3、A2.7 最后一行和“运行时哪些是并行的”的决定，改查询出错时的处理、限流先后，并提前查 AcoustID。

## 范围

| 事项 | 出处 | 要做的 |
| --- | --- | --- |
| 出错不算结论 | A2.4 表 | 出错时不跳到更弱的一步，也不记未匹配 |
| 来源暂停 | A2.4 表 | 5 秒起翻倍，最长 3 分钟，成功一次清零；对方用 Retry-After 要求更久时按对方的；长时间不可用就按 3 分钟一轮反复试，整理进度提示该来源不可用，不给每张专辑累计失败次数（`backend/internal/sources/queue.go:91-116`） |
| 专辑等多久 | A2.4 表 | “稍后重试”最长 3 分钟（`backend/internal/curation/program/pass.go:260-278`）；因来源暂停而等的，来源一恢复就排回队列，从出错的那一步接着查，前面的结果走缓存；界面显示“等待重试”和来源（界面由主代理做） |
| 只和这张有关的错误 | A2.4 表 | 按专辑计次，间隔最长 3 分钟，连续 3 次记“查询出错”并停下；本地变了或规则升级再查 |
| 声纹来源关掉、密钥失效 | A2.4 表 | 照旧跳过这一步；临时出错则等它恢复 |
| 去掉放慢发送 | A3 表 | 去掉来源失败后的发送间隔翻倍（`backend/internal/sources/limiter.go:116-127`） |
| 抢来源的先后 | A3 表、A2.7 | 界面上的操作 → 专辑识别 → 艺人资料 → 本地齐全的专辑；艺人资料排到所有专辑识别之后（`backend/internal/curation/model_queue.go:11-13` 等） |
| 提前查 AcoustID | 运行时哪些是并行的 | 本地声纹那条队列提前替后面的专辑算好声纹、查好 AcoustID，只对 S8 前 5 步都没有线索、会走到声纹一步的专辑；识别时直接用结果 |
| 空等 | A3 | 子任务 1 查出的原因在本任务范围内的，一并修 |
| 规范 | 文档 | `.trellis/spec/backend/sources-contracts.md` 和整理合同里改到的段落 |
