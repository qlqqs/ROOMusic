## 发现

- 回跳行为与设计一致，并且比 e2e 里更完整地被验证：会话被撤销后刷新，登录页带 `redirect`，登录后回到原页面；在页面里主动退出，登录页不带 `redirect`；重新载入后没有“刚退出”的记忆，直接访问受保护页会带 `redirect`。这是预期的区别，规范里要写清楚：“不带回跳”只适用于同一个文档内的退出。
- 终态在开始扫描后约 2 秒才被界面观察到，这是 2 秒的详情轮询间隔，不是后端慢：合成素材的扫描几乎立即完成。
- 概览每次加载请求两次 `GET /release-groups`（每次只取一项，用 `pagination.total` 得到专辑数与需要关注的专辑数）。写请求与操作一一对应，没有重复发送：目录新增 4 次（含一次重复新增，后端按路径返回已有目录）、停用 1 次、恢复 1 次、开始扫描 2 次、创建成员 1 次（另有一次 409）、成员停用与重新启用各 1 次（另有一次 409）、撤销会话 1 次、退出 2 次。
- 后端与前端的错误信封、状态码、字段名与样本一致，没有出现 decoder 拒绝响应的情况（`invalid_response`）。

## 没有覆盖及原因

- 取消扫描、运行中扫描的轮询与“取消请求中”：合成素材的扫描在毫秒内结束，真实后端上无法稳定停在运行中。这些由 Vitest（假定时器）与 Playwright（受控后端）覆盖。
- 会话在页面打开期间过期（中途 401）与跨标签页广播：Step 3 在真实后端上手动验证过，e2e 与单元测试覆盖。
- 结果不确定（网络中断）后的同键重试：需要在请求途中断开连接，真实后端上不能稳定复现，由单元测试与 e2e 覆盖，幂等重放本身由后端集成测试覆盖。
- 这次冒烟不进入 CI：它需要 Docker 与 PostgreSQL，且步骤依赖本机环境；后端的 API 契约由样本与集成测试在 CI 中守住。
