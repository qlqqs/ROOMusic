# 我的评分页与管家评分工具

父任务：`11-25-opensubsonic-api`。依赖 `11-25-subsonic-rating`（评分表、`SetRating`、`LookupRatings`、星级控件），必须在它合入后开工；不依赖 Subsonic 的其他子任务。用户于 2026-11-25 决定加入第一版。

## 目标

- 网页端能按评分找东西：列出本人评过分的曲目、专辑、艺人，按星级筛选，按评分高低或评分时间排序；曲目可以一键播放筛选结果，比如“播放所有 4 星以上的曲目”。
- 管家能读写本人评分，和收藏工具对等。

## 已确认的事实（仓库调查）

- “我的音乐”导航组下已有“我喜欢的音乐”（`/me/liked`，收藏曲目加“播放全部”）、“我的收藏”（`/me/favorites`，专辑与艺人两栏）、历史、歌单（`app/router.tsx:542`，`app/routes/favorites-page.tsx`）。
- 个人列表的做法：`personal` 只读自己的表，再调用曲库的公开投影拼出摘要。例如收藏专辑读 `favorite_albums`，再调 `catalog.LoadReleaseGroupSummaries`（`personal/favorite_reads.go:108`）。曲库的列表查询不读个人表。
- 专辑组可能变得不可用（没有可见版本）。收藏在收藏时保存了 `saved_title`/`saved_artist`，用于这时的显示（`personal/projection.go:49`）。评分专辑也要同样保存，这一点已写进 `11-25-subsonic-rating` 的表结构。
- 专辑页的排序白名单只有 `title`、`added_at_desc`（`catalog/recent_additions.go:10`），带搜索词时另走按相关性的搜索路径（`catalog/search_lists.go:54`）；艺人页的排序是 `name`、`album_count`。
- “播放全部”用 `GET /me/favorites/tracks/queue` 的模式：一次给出最多 10,000 首的播放队列（`personal-contracts.md` §3）。
- 管家已有 `list_favorites`（read）和 `set_favorite`（personal）两个工具（`personal/stewardtools/tools.go:108`、`:128`）。新增工具的规则见 `steward-runtime-contracts.md`“新增一个工具”。管家另有 `play_tracks` 工具，拿到曲目 ID 就能播放。

## 需求

- R1 评分列表（`personal`）：
  - 曲目、专辑、艺人三类，每类一个分页列表；只列本人评过分的；
  - 筛选：`min_rating` 1–5，表示“N 星及以上”，默认 1；
  - 排序：`rating`（评分高到低，同分按评分时间新到旧，默认）或 `recent`（评分时间新到旧）；
  - 艺人按解析后的艺人合并，取最近一次评分，和查询规则一致；
  - 专辑不可用时用保存的名字显示，做法同收藏；缺失的曲目照样列出，并标明缺失。
- R2 曲目队列：按同样的筛选和排序，返回最多 10,000 首可播放的曲目，供“播放全部”使用。
- R3 “我的评分”页（`/me/ratings`）：
  - 放在“我的音乐”导航组，紧挨“我的收藏”；
  - 曲目、专辑、艺人三栏；
  - 星级筛选用五颗星的单选组，选中第 N 颗表示“N 星及以上”，再点一次回到全部；
  - 排序是一个图标切换（评分 / 最近评分），文字放进提示和读屏名；
  - 曲目栏有“播放全部”，播放当前筛选的结果；每行的动作同收藏页；
  - 每项显示本人星级，可以直接改；改完后列表按新值刷新，跨标签页同步；
  - 栏、筛选、排序、页码都写进地址，刷新或分享地址后状态不丢；
  - 空状态按筛选条件说明，比如“还没有 4 星以上的专辑”。
- R4 管家工具（`personal/stewardtools`）：
  - `list_ratings`（read）：`kind`（必填，track/album/artist）、`min_rating`、`sort`、分页（默认 20、最大 50）；
  - `set_rating`（personal）：`kind`、`target_id`、`rating`（0–5，0 表示清除）；
  - 身份和标记与收藏工具相同：成员可用，输出含不可信文字。

## 验收标准

- AC1 列表：给 3 首曲目分别评 5、4、2 星，`min_rating=4` 只返回前两首且 5 星在前；`sort=recent` 按评分时间排；没评过分的不出现；另一个用户的评分不出现。
- AC2 艺人合并后，评分列表里只出现一行，显示最近一次评的分；拆分后两个锚点各自出现。
- AC3 专辑组变得不可用后，评分列表仍显示保存的名字，并标为不可用；缺失曲目出现在列表里，但不进入播放队列。
- AC4 “播放全部”播放的正是当前筛选和排序下的可播放曲目；超过 10,000 首时截断并告诉用户。
- AC5 页面：
  - 只用键盘就能切换栏、选择星级筛选、切换排序、播放全部；
  - 读屏能读出当前筛选，比如“筛选：4 星及以上”；
  - 在列表里改评分后，这一项按新值重新排位或被筛掉，其他标签页同步更新；
  - 地址带上栏、筛选、排序和页码，刷新后状态不变；
  - 320px 宽度下不溢出。
- AC6 管家：
  - 让管家“列出我 5 星的专辑”会调用 `list_ratings`，结果与网页端一致；
  - `set_rating` 设置与清除后，网页端和 Subsonic 客户端看到同样的值；
  - `page_size=51` 被拒；目标不存在返回 `not_found`；输出不含路径、歌词和他人的数据。

## 不做

- 在专辑页和艺人页的现有排序里加“按我的评分”：曲库的列表查询会因此读取个人表，越过 `personal` 的表归属，还要和搜索相关性、`attention` 筛选组合。评过分的东西都已经在“我的评分”页里，第一版不改曲库列表。
- 按评分自动生成歌单、智能歌单。
- 平均评分、半星（理由见 `11-25-subsonic-rating`）。

## 规划决定记录

- 路线：主代理按用户 2026-11-22 的长期授权（规划完直接实现，能定的自己定）选定，交付时列出。
- 关键取舍：
  - 排序和筛选放在新的“我的评分”页，而不是改曲库列表：不破坏表的归属，曲目也有了地方（网页端没有全库曲目列表）；
  - 独立成子任务，不并进 `11-25-subsonic-rating`：评分核心本身已涉及整理事务，列表、页面和管家工具可以单独验证和回退；
  - 管家的列表工具也放在这里，因为它复用 R1 的列表读取。
