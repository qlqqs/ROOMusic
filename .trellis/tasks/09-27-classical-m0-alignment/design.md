# M0 文档设计

## 文档职责与依赖

沿用现有项目文档职责，不新增与 Trellis 并行的治理体系：

| 文档 | 本任务的职责 |
| --- | --- |
| `frontend-desgin/` | 不修改的原始设计证据；保留来源，不把示例交互当作已实现合同 |
| `frontend/DESIGN.md` | Classical 落地设计锚点，记录布局、组件、状态和原型差异 |
| `.trellis/spec/guides/product-goals.md` | 保留 Core 0 永久约束，明确区分 Core 1 范围提案与已批准范围 |
| `.trellis/spec/frontend/` | 同步当前事实、设计引用、状态/路由责任、数据边界和可复用队列语义 |
| `docs/architecture/architecture-decisions.md` | 修正过时实现树并链接本轮 ADR，不将目标目录宣称为现状 |
| `docs/architecture/adr/` | 四份简体中文 ADR；用明确状态防止“建议”被误读为“已采纳” |
| 父/子任务文档 | 保存需求映射、能力矩阵、阶段门禁和待确认事项 |

只修改与本轮冲突相关的规范段落；不为语言统一翻译所有历史文档，不重写 Canvas。
共享工程规范中的过时事实和运行合同中的前端现状也应纳入定位，而非只清理视觉规范。

## 原型落地差异

下列调整在获批 M0 中记录为落地差异或候选，不直接修改原型，也不把需要新增能力的建议宣称已获业务实施批准：

| 原型或上轮建议 | 文档需要说明的边界 |
| --- | --- |
| Bit-perfect、未重采样、硬件 DAC/音量 | 信号路径只描述可核实的源文件、传输/转码与浏览器环节；不作端到端硬件保证 |
| 扫描日志的恢复点 | 扫描观察与管理变更分开，扫描记录不等同于可撤销检查点 |
| 删除重复文件、回收站 | 保留源目录只读；若提议“从资料库排除”，必须列为尚待实现的数据库操作 |
| 监听后 30 秒入库、扫描暂停 | 当前只有启动/取消；定时或增量扫描是后续方案，不作为 M1 现有能力 |
| 外部参照、候选封面、编辑笔记 | 没有批准的数据来源时隐藏或延期，不伪造内容 |
| Steward、版本合并/拆分与审批 | 未具备后端能力前隐藏或明确禁用；不能只实现可点击外壳 |

字体、字号和布局尺寸从原型核对后提炼成变量；字体自托管方式是待评估决策，不在 M0 安装包。
保留立即播放替换上下文、下一首插入当前项之后、加入队列不中断等语义，剥离旧模拟时钟和本地数据假设。

## ADR 写作合同

每份 ADR 记录：状态、当前证据、待解决问题、推荐与替代方案、影响范围、失败/回退策略、
验收方法及仍待确认的决定。方案依赖外部库或媒体实现时，使用官方文档/原始资料核实，
记录查阅日期；不得凭记忆填写“最新版本”或全浏览器兼容结论。

四个主题的讨论范围见[父任务架构候选](../09-27-classical-core-1/design.md)。具体表结构、
端点 payload 和模块移动补丁由未来子任务设计，M0 不用猜测型接口代替研究。

## 兼容与回退

- 不改变任何当前 API、表结构、依赖或运行行为。
- 不修改原始设计资产，差异由落地文档表达；目录改名另行批准。
- 不覆写旧任务的历史批准记录，不将“被替代”伪写为功能验收通过。
- 文档修改可独立撤回；如研究推翻候选方案，修订 ADR 和路线，再请求相应决策批准。
