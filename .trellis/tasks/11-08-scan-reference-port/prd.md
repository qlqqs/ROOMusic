# 扫描子系统对标：复刻参考设计的扫描架构与文件/文件夹规则

## 目标

用户上传了一份媒体库扫描子系统的设计说明（[research/reference-design.md](./research/reference-design.md)），要求把其中核心且对 ROOMusic 有好处的内容复刻进来。重点是扫描系统架构，以及扫描文件夹和文件时对文件夹名、文件名的处理规则（2026-11-08 用户明确）。

本任务是父任务，只管范围、顺序、边界与跨项验收；每一项作为子任务分别立项、规划与验收。

## 背景

完整对照见 [research/gap-analysis.md](./research/gap-analysis.md)（含参考设计章节行号、ROOMusic 现状 `file:line` 与取舍理由）。要点：

- 两边的架构思路一致：扫描只产出文件级记录，归组是独立的纯函数；名字的语义推断都带 inferred 或来源标记。
- 增量方式不同：参考设计按时间戳比对，没变的文件不再处理，解析 4 路并发；ROOMusic 每次全量解析，全程串行（`backend/internal/library/scanner.go:454`）。
- ROOMusic 没有路径过滤；不支持的格式和解析失败会把整个根目录标成不完整，missing 对账和移动后保留曲目 ID 都不再执行（`scanner.go:447-460`）。`._*` 伴生文件或一个 `.ape` 就会触发。
- 碟目录只认以 disc/cd/disk 开头、后面除数字外没有别的字的名字（`backend/internal/catalog/ingest/organizer.go:272-293`）；分组只在 scope 内进行（`scope.go:9-22`），所以 `Disc 1 - 副标题` 这类目录会被拆成多张同名专辑。
- 不从文件名推断编号，轨号缺失时按字节序补位（`organizer.go:655-721`）。
- folder_metadata 的目录名解析比参考设计强，保留不动。
- 八号机真实库 `/vol2/1001/ROOMusic` 与本机 `music/` 的文件清单（相对路径与大小）完全相同（2026-11-08 比对，106 个目录、399 个文件：199 FLAC、84 M4A、1 MP3、8 CUE、44 个 `Zone.Identifier`、没有 APE/WavPack/AIFF）。各子项的“真实库 smoke”在本机隔离实例上对 `music/` 跑即可。生产库的只读统计见 [research/m8-production-stats.md](./research/m8-production-stats.md)：没有人工意图、专辑收藏、艺人收藏与发行修正，所以 ⑥ 的“人工意图对不上清单”和 ② 的收藏转移在现有数据上都为空，部署前后不需要再到生产库对比。

### 一次规划、四线并行（2026-11-08 用户裁决）

13 个子任务的需求与各线接口合同一次定完，再按共享文件分四条线，各在独立的 git worktree 里实现，主会话逐线审阅后合入 `main`（沿用 M5 做法）。线内后面的子项可在前一项合入线分支后微调设计。

| 线 | 子项（线内顺序） | 共享文件 |
| --- | --- | --- |
| S 扫描流程 | ① → ⑫ → ④ → ⑤ → ⑪ | `library/scanner.go`、扫描协调、目录接口 |
| O 归组规则 | ② → ③ | `catalog/ingest/organizer.go`、碟号解析器 |
| T 标签与署名 | ⑥ → ⑦ → ⑧ → ⑬ | `parser/` 标签读取、`catalog/metadata`、artistgraph、搜索规范化 |
| M 格式与分析 | ⑩ → ⑨ | `parser/` 新格式、`playback/` |

- 每条线一个 git worktree（从规划提交后的 `main` 分出）。线内分工按 `~/.claude/CLAUDE.md`：后端实现 `codex/gpt-6-astra`（2026-11-08 用户批准规划后改定），前端实现 `claude/claude-opus-5-5`，写测试与跑测试另开 `codex/gpt-6.1-sol`（`modeId: full-access`），均 high；前后端有接口依赖的子项按各自 design 的接口合同并行。子 agent 不提交，主会话逐步审阅后在该线 worktree 里按步提交。
- 测试数据库按线隔离：Compose 项目 `roomusic-test-scan-s`、`-o`、`-t`、`-m`（`--env-file /dev/null`、绝对 compose 路径、空闲端口、随机库名、用完 `down -v`）；Playwright（4173 端口）与 `scripts/playback-e2e.sh` 在 `flock /tmp/roomusic-scan-e2e.lock` 下运行。
- 同一条线的前后端同批合入 `main`（前端解码器是严格枚举，⑦ ⑧ 的新字段只上后端会让页面解码失败）。

### 合入顺序与版本号约定（2026-11-08 设计审阅定稿）

推荐合入顺序（各设计对两种顺序都写了处理，实际以各线完成先后为准，但守住下面两条约束）：

1. **S1 = ① ⑫**：S 线前两项完成后先合入一次。① 把扩展名表移到 `library/scan_filter.go`，并让不支持的格式只记诊断，⑩ 依赖它。
2. **M = ⑩ ⑨**、**O = ② ③**、**T = ⑥ ⑦ ⑧ ⑬**：按完成先后合入；M 必须在 S1 之后。
3. **S2 = ④ ⑤ ⑪**：最后合入。④ 以合入时 `main` 上的全部解析与归组规则为基线（`parser.CommonVersion`、`formatVersions`、`ingest.GroupingVersion` 都从 1 起），其他线因此都不用升这三个版本；若某条线晚于 S2 合入，按该线 design 里“④ 先合入”的规则升版本（④ design 第 8 节有全表）。

与合入顺序无关、每条线合入 `main` 时各自升一次的版本：

| 版本 | 谁升 |
| --- | --- |
| `artistgraph.Version` | O（③ 让文件名拆出的艺人进艺人页）、T（⑥ ⑦ 的拆分、合辑、角色、括号排除词） |
| `searchindex.ProjectionVersion` | T（⑦ 角色、⑧ 作品、⑬ 去标点键，同一次回填） |
| `analysis.Version` | M（⑨，1 → 2，旧结果在重算前继续可用） |
| `textnorm.Version` | 不升（升了会让所有人工意图与艺人收藏失联，⑬ 用独立的去标点键） |

迁移：各线在自己的基线上用下一个空号开发（暂定号互相重叠：S ① 0034、⑫ 0035、④ 0036、⑪ 0037；O ② 0034；T ⑦ 0034、⑧ 0035、⑬ 0036；M ⑨ 0034）。主会话合入时按合入顺序重新编号（文件名、`.down.sql`、`migrations_rollback_integration_test.go` 的版本表一起改），线分支 rebase 到 `main` 后重跑迁移上下行与该线的集成测试。

共享文件的协调：`parser/`（⑥ ⑦ ⑧ 改 `tags.go`、`mp3.go`、`m4a.go`，⑨ ⑩ 只加新文件并改分派）、`ingest/observation.go`（② ④ 加字段，按字母序合并）、`artistgraph/facts.go`（③ 一处条件，⑥ ⑦）、封面候选列举函数（② 扩充、④ 签名共用）、`catalog/read.go`（② ③ 种类白名单、⑧ 作品、⑨ 时长视图）。各子任务 implement.md 的共享文件表列出了具体改动。

## 复刻原则（2026-11-08 用户裁决）

参考设计里对 ROOMusic 有益的规则逻辑，默认按原文复刻（判定顺序、正则、回退层级、阈值、边界处理）。只有在有把握改写后效果相同或更好时才改写，例如原文自认的缺陷、与 ROOMusic 已有合同冲突、对中文库不适用。每个子任务的 `design.md` 必须附一张复刻对照表：参考设计的规则（附章节与行号）→ 照搬 / 改写 / 不采用，改写与不采用都写明理由。主会话审阅时以这张表为准。

## 不复刻（理由见 research/gap-analysis.md §4）

成员集合摘要做专辑 ID、三点采样替换现有指纹、碟号一识别就上提、根目录散文件归一组、`艺 - 专` 兜底名、子串式忽略规则、大小写自动探测、逐目录即时删除、降精度时间戳比较、实时文件监听、内存目录树缓存、外部资料库导入、列表文件、SMB/卷管理、导入整理、云存储、设备协议、DSP。

## 跨项裁决

各子项的裁决都记在子任务 PRD 的“已裁决”一节（用户裁决与主会话在设计审阅中的裁决分开标注）；目前没有待裁决项。跨子项的裁决如下。

- **落选 Release 的数据**（2026-11-08 用户裁决：专辑收藏自动转过去）：规则变化导致重新归组、某个旧 Release 的曲目全部被另一个 Release 沿用而变空时，指向旧 Release 所在 ReleaseGroup 的专辑收藏自动转到接收曲目最多的那个 Release 的 ReleaseGroup（已收藏的不重复）；听歌历史、歌单、曲目收藏跟着曲目，本来不受影响；旧 Release 上的修正、认领、默认版本不自动搬。该规则对用户自己整理目录导致的合并同样生效。由 ② 实现（O 线第 1 项），③、⑥ 复用。背景：现状：没有 present 曲目的 Release 在读取侧隐藏（`backend/internal/catalog/read.go:188`）；专辑收藏引用 `release_groups`（`backend/migrations/0021`，RESTRICT），修正、默认版本、认领挂在 Release 上；没有 Release 重定向机制。这与用户自己整理目录导致合并时的现状相同。影响 ②、③、⑥。


## 跨项验收

- **每个子项**：满足子任务 PRD 的验收；新增或改变的规则有对应单测；只跑与改动直接相关的最小测试集（按 `~/.claude/CLAUDE.md` 与项目 `AGENTS.md`，不跑全量、不做额外演练）。
- **每次合入 `main` 后**：迁移上下行通过；该线的集成测试在 `main` 上通过。
- **全部合入后（父任务收尾，一次）**：在本机隔离实例上以规划前的 `main`（`ef463ce`）扫一遍 `music/` 作基线，再以收尾时的 `main` 扫一遍，对比并逐条确认：
  - 已有曲目 UUID 按来源身份全部不变；Release 沿用仍按严格过半；扫描为 `succeeded`；
  - 发行数、曲目数、艺人名字集合、诊断类别分布的变化都能对应到某个子项的规则（预期：⑦ 新增作词、编曲、制作人署名与对应艺人；其余子项在样本库上基本不变）；
  - 第二次增量扫描解析 0 个文件、跳过全部未变候选（④）；
  - 界面：涉及界面的子项（① ③ ④ ⑦ ⑧ ⑨ ⑩ ⑪ ⑫）宽 1440、窄 375 截图复核，文案按 `~/.claude/CLAUDE.md` 的前端文案规则。
- **合同**：`.trellis/spec/backend/library-scan-contracts.md` 等子项列出的合同随子项同步更新，收尾时复查没有互相矛盾的描述。
