# 自动整理 I：曲目级字段修正

## 目标

曲目标题与曲目艺人可以修正：人工一层、自动一层，人工优先，扫描值垫底；都可撤销（U9）。所有读取处读有效值；署名、搜索、队列、歌词匹配跟着变。程序层在匹配上之后补空着或占位的曲目标题与艺人，模型层与管家对话能修正它们。曲序与碟号不动。

依据：ADR 0006 U9、第 4 节表（第 112 行）、第 15 节验收（第 389 行）；父任务 `implement.md` 的 I 一节；调研 `research/track-fields-current.md`（下文 R§n）。

## 决定（主代理按 qlqq 的授权取定，规划子代理审阅；随交付列出）

| # | 决定 | 理由 |
| --- | --- | --- |
| I1 | 新表 `track_corrections`（人工）与 `track_auto_values`（自动），主键 `(track_id, field)`，`field ∈ {title, artist}`，只有 `set`（两个字段都必填，不能设空；与发行的必填字段同规则）；有效值用视图 `track_effective`（人工 → 自动 → 扫描），读取处从 `tracks` 换成视图 | 扫描与 artistgraph 都会写 `tracks.title/artist`（R§8.1）；分表加视图与发行级同形，结构上保证各写各的 |
| I2 | 人工层的版本号给每首曲目单独一个（`tracks.edit_revision`），不占发行的 `edit_revision`；自动层沿用发行的 `auto_revision` | 共用发行版本会让修正一首曲目挡住同发行更早修正的撤销（R§5） |
| I3 | 操作类型新增 `track_correction`、`track_auto_correction`，目标仍记为所属发行（同 `track_external_lyrics`），记录里带 `track_id` 与曲目标题；不新增 `track` 目标类型 | 操作记录、按发行筛选、按批与按来源撤销都现成可用 |
| I4 | 曲目艺人修正后，署名事实按人工 → 自动 → 扫描三选一生成（`refreshFacts`/`refreshEffective` 的曲目分支），搜索索引刷新这首曲目 | 验收“署名事实随曲目艺人修正更新”（父任务 I 验证）；重扫时事实会被重建（R§8.2） |
| I5 | 程序层的输入（`CurationTrack`）只叠加人工层、不叠自动层（§15.2 不变量）；人工修正直接覆盖已有的 `Title`/`Artist`，不加字段，避免全库摘要变化 | R§8.4 |
| I6 | 接入 C：匹配上之后，曲目标题是占位或曲目艺人是占位（且没有人工或自动值）时，用外部曲目的标题与署名补上（只补空缺，查“不再提出”）。不升规则版本；已匹配的发行按 B3 的做法只在满足条件时重开一次（结果里记 `track_fields` 已做） | 不让全库重做；存量里占位曲目多的是流媒体下载与标签差的文件 |
| I7 | 接入 D：新工具 `correct_track{track_id, expected_revision, changes{title?, artist?}, basis}`，对话与 MCP 写人工层，后台写自动层（只限本批发行的曲目）；审查证据加曲目的有效值、扫描值与外部对应；后台白名单、例外表 `tool` 约束与前端解码器放开；例外的采纳走人工层，不采纳写曲目字段的“不再提出”。审查策略版本不变 | 与 `correct_release` 对称；字段类工具不需要强证据规则 |
| I8 | 界面：专辑详情的曲目行给管理员“修正曲目信息…”（标题、艺人两个字段，照发行的编辑对话框）；被修正或自动补全的曲目在行内标“人工修正”/“自动补全”（同发行字段的标签形态）；操作记录、例外、撤销对话框认识两种新类型 | 编辑入口与标记与发行级一致 |
| I9 | 同一路径换了文件会产生新曲目，旧修正留在不在库的曲目上——记为已知限制（同发行级 G8） | R§6 |

## 需求与验收

| # | 需求 | 验收 |
| --- | --- | --- |
| R1 | 数据与读取 | 迁移往返；没有任何修正时现有接口样本逐字不变；所有读取处（专辑详情曲目、曲目摘要、队列与播放、搜索、歌词匹配、最近播放、收藏与歌单、艺人页、管家目录工具）读有效值 |
| R2 | 人工层 | `GET/PATCH /api/v1/tracks/{id}/corrections`（检查顺序与错误码照发行修正）；版本冲突 409；撤销恢复前值；修正后重扫仍保留；署名事实与艺人页随曲目艺人修正更新；搜索能按新标题与新艺人找到 |
| R3 | 自动层 | `Writer.ApplyTrack`（人工优先、`OnlyEmpty`、不再提出、`unchanged`）；单条、按批、按来源撤销；撤销写不再提出标记 |
| R4 | 接入 C | 匹配上的发行补占位的曲目标题与艺人（外部源 MusicBrainz、来源 source）；有人工或自动值的不动；存量已匹配的发行只重开一次 |
| R5 | 接入 D | 后台 `correct_track` 落自动层、对话落人工层；审查证据带曲目字段；例外的采纳与不采纳；白名单与约束放开 |
| R6 | 界面 | 曲目行的修正对话框（版本冲突与校验提示）；曲目标记；操作记录与撤销对话框的文案；例外里曲目修正的前后值 |

## 不做

- 曲序、碟号、时长等其他曲目字段。
- 作曲、指挥等署名角色的修正（只改曲目艺人那一行）。
