# Subsonic 鉴权与协议骨架

父任务：`11-25-opensubsonic-api`，共用约定见父任务 `design.md`。

## 目标

客户端能用 ROOMusic 的用户名和登录密码连上服务器、通过连接测试；管理员能开关这个功能；用户在账号页能看到连接方式与当前状态。

## 需求

- R1 `/rest/` 路由、外壳与错误码，XML/JSON 两种格式，`.view` 后缀与 POST 表单都可用。
- R2 鉴权：
  - `p=` 明文与 `p=enc:<hex>` 按 bcrypt 校验；
  - `t`+`s` 按加密保存的登录密码副本校验；
  - 失败计入现有限流。
- R3 登录密码副本：
  - 实例开启 Subsonic 时，以下时机按“用户 + 用途”加密保存一份：网页登录成功、本人修改密码、管理员创建用户或重置密码、账号页确认密码；
  - 实例关闭时删掉全部副本。
- R4 接口：`ping`、`getLicense`（`valid=true`）、`getOpenSubsonicExtensions`、`getMusicFolders`、`getUser`（仅本人；`username` 参数是别人时返回 50）。
- R5 实例开关：管理员可开关，默认开启（用户 2026-11-25 指定），升级的实例同样开启；关闭时所有 `/rest` 请求返回错误 40，不提示原因。
- R6 账号页“第三方客户端”一行（实例开启时才显示）：
  - 显示服务器地址与用户名，可复制；
  - 状态分两种：“已就绪”，或“需要确认一次登录密码”，后者附确认入口，确认后保存副本；
  - 说明“用登录密码连接”。
- R7 管理设置里的开关：
  - 说明开启的后果：会加密保存一份可还原的登录密码；已有成员需要在网页登录一次，或在账号页确认密码；
  - 关闭时提示会删除这些副本。

## 验收标准

- AC1 开启后，用正确的用户名和密码，以 `p=`、`p=enc:`、`t+s` 三种方式请求 `ping.view` 都返回 `status="ok"`；XML 与 JSON 的结构符合协议示例。
- AC2 密码错误、用户停用、实例关闭、缺少参数，分别得到协议错误码 40、40、40、10。连续失败触发限流后返回 40，限流状态与网页登录共用。
- AC3 开启前已存在、开启后还没在网页登录过的用户：`p=` 可用；`t+s` 返回 40。在账号页确认密码或重新登录后，`t+s` 可用。
- AC4 关闭开关后，数据库里没有任何登录密码副本；再开启时需要重新登录或确认。
- AC5 修改密码后，旧密码以任何方式都失败，新密码以 `t+s` 立即可用。
- AC6 日志和诊断导出中找不到请求里的 `p`、`t`、`s` 值。
- AC7 前端：管理员开关和账号页一行可以用键盘操作，有读屏名；成员看不到管理开关。
- AC8 `routes_test.go` 覆盖 `/rest/` 路由；`/rest` 以外的路由不变。

## 不做

- `apiKey` 扩展、用户管理类接口、`jsonp`。
