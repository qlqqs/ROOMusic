# 自动整理 E2：例外与用量界面

父任务 `.trellis/tasks/11-22-auto-curation-sources`。前置 D（`38b2c7a5`）已合入：接口齐全（`curation-contracts.md` §17.5），前端解码器与端点已写好（`features/curation/api`、`features/steward/api/endpoints.ts` 的 `fetchCurationConversations`），界面没有。

## 目标

管理员在“自动整理”页上看得到模型层在做什么、用了多少、还剩多少；能设整理用的模型与每日上限；能处理审查没通过或转人工的例外（采纳或不采纳）；能点开后台的会话看模型查了什么。

## 需求

| 编号 | 需求 |
| --- | --- |
| E2-R1 | 新增“模型判断”一组（放在“进度”之后）：状态与不可用原因；整理用的模型（行内改，空 = 对话模型）；每日上限（行内改，单位万 token，可设不限）；今天的用量（输入、输出、合计，有上限时带比例条）；各状态的项数（等模型、处理中、等你处理、搁置）；最近的后台会话（至多 3 个，链接到管家会话页，“全部 N 个”时不另做列表页） |
| E2-R2 | 审查模型与整理用的模型相同时（当前管理员就是开启者、他的审查模型为空或等于有效的整理模型），在“整理用的模型”一行下提示另选一个审查模型，链接到 Agent 设置（U11） |
| E2-R3 | 新增“例外”一组（放在“模型判断”之后）：待处理的例外分页列表（地址参数 `exception_page`），每项写发行（链接到这个发行的操作记录）、提出的修改（匹配：对应到哪个 MusicBrainz 发行、曲目对应数、补哪些字段；字段修正：各字段前值 → 后值）、审查的结论与理由、提出的时间；“采纳”“不采纳”都先确认；有会话且属于当前管理员时给“查看过程”链接 |
| E2-R4 | 采纳：确认框列出将要写入的改动，说明“记为你的人工确认”；成功后行消失、进度与操作记录失效；`409 exception_stale` 在框内写“提出之后内容变了，这一项没有执行，请查看过程或等模型重新判断”并刷新列表；`409 exception_decided` 写“已经被处理了”并刷新 |
| E2-R5 | 不采纳：确认框说明“以后程序与模型都不再提出这个值，可以在‘不再提出’里清除”；成功后行消失，“不再提出”列表失效 |
| E2-R7 | 管家会话页打开 `kind=curation` 的会话时：不显示模式菜单（后端会 409），标题区标“自动整理”，输入框提示写“接着对话纠正时，这些消息按你本人的对话处理（写人工修正）”；会话列表本来就不含它们 |
| E2-R6 | 没有例外时只写一句“没有等你处理的例外。”；从未打开过总开关时“模型判断”与“例外”两组都收成一行说明，不显示控件 |

## 验收

- AC1 模型状态八种、原因六种都有文案；`unavailable/not_configured` 时，当前管理员是开启者则链接 Agent 设置，否则写“开启者还没有配置模型接口”。
- AC2 改模型、改上限即改即存，失败回到服务器的值并就近提示；上限输入只接受 1 到 10⁸ 的整数万（等于 10¹² token），“不限”是一个开关；保存后设置与进度都更新。
- AC3 用量比例条的数值来自服务器；`limit_reached` 时写“今天的用量到了上限，明天继续”。
- AC4 例外列表分页、页码越界回到最后一页（照“不再提出”）；外部来的文字按不可信文本显示（`styles.untrusted`）。
- AC5 采纳与不采纳的成功、`exception_stale`、`exception_decided`、网络失败各有页面级测试；进行中不能重复提交。
- AC6 Vitest 页面级测试；Playwright 冒烟（桌面与 390 宽，axe、无横向溢出）；截图附在交付说明。
