# 自动整理 A：自动写入的地基

父任务：`.trellis/tasks/11-22-auto-curation-sources`（需求 R1、R2、R3、R10）。规则依据：
[ADR 0006](../../../docs/architecture/adr/0006-auto-curation-and-sources.md) 第 4、5、10 节。
前置：X0（已完成，`89467ce6`）。后续：B1、C、D、I、G、H 都建立在本任务之上。

## 目标

给“后台自动整理”准备好写入、记录与撤销的地基：外部源与模型的产出有独立的一层可写，写进去不会盖掉人工修正，
每条自动修改有来源与批次，可以单条、按批、按来源撤销，撤销过的不再自动应用；自动整理有一个默认关闭的总开关，
记着是哪位管理员打开的。

本任务没有任何自动写入的调用方（匹配与模型判断在子任务 C、D）。交付的是后端的能力与管理员可用的读取、撤销、开关接口，
用测试里的调用验证。用户在界面上暂时看不到变化；没有打开总开关、也没有自动层数据的实例，行为与现在逐项相同。

## 已确认的事实

- 元数据两层：扫描值在 `releases` 的列，人工修正在 `release_corrections`（主键 `(release_id, field)`，八个字段，
  `mode` 为 `set` 或 `null`，值在 `text_value`、`year_value`、`list_value`，`operation_id` 指向写入它的操作）；
  视图 `release_effective` 在读取时叠加（`backend/migrations/0017_governed_operations.sql:44-61`、`backend/migrations/0032_release_genres.sql:21-64`）。
- 所有读取的发行来源是常量 `ReleaseSource = "release_effective releases"`（`backend/internal/catalog/internal/releasesql/release.go:7`）。
- `operations` 表：`actor_id` 非空并引用 `users`；`expected_revision`、`result_revision` 非空，约束 `result = expected + 1`；
  操作类型与目标类型有 CHECK；一条操作至多被撤销一次（`backend/migrations/0017_governed_operations.sql:7-32`）。`origin` 是可空 JSONB，
  代码里 `source` 只有 `chat` 与 `mcp`（`backend/migrations/0054_steward_plans.sql:1`、`backend/internal/operations/operations.go:130-139`）。
- 撤销由按类型注册的 `Kind.Revert` 完成，通用守卫在 `RevertExecutor`（`backend/internal/operations/kind.go:67-95`）；
  字段修正的撤销要求发行的 `edit_revision` 等于记录的 `result_revision`，恢复前一个意图并把行的 `operation_id` 写成撤销操作
  （`backend/internal/catalog/governance/revert.go:82-145`）。
- 操作记录列表只能按目标与认领来源筛选，按页偏移分页（`backend/internal/operations/records.go:113-180`）。
- “需要关注”里拿不准的字段，定义是扫描决定为 `uncertain_apply` 且该字段没有修正行
  （`backend/internal/catalog/internal/releasesql/issues.go:21-28`）。
- 迁移成对提供升级与回退脚本，最新编号 0057（`backend/migrations/`）。

`research/auto-layer-coupling.md` 查清的耦合点：

- 除视图外，直接读写修正表的还有十多处；其中要同时看自动层的是：待关注字段的判定、专辑级署名里专辑艺人一行的替换
  （`backend/internal/catalog/read.go:333-345`）、署名事实与有效署名（`backend/internal/catalog/internal/artistgraph/facts.go:58-100`、
  `refresh.go:78-81`，按“有没有专辑艺人的修正行”整层切换）、回填成本估算（`backend/internal/catalog/maintenance/artist_batch.go:268-269`），
  以及三处把“没有修正”当成“显示扫描值”的预览。
- 修正与撤销之后的派生刷新只有一个入口 `refreshGovernedRelease`（艺人投影与搜索值），未导出，并且它依赖的包都在
  `backend/internal/catalog/internal/` 下，只有 `catalog` 子树能导入：自动层的执行器必须放在 `catalog/governance`。
- `artist_credits.layer` 只允许 `scan`、`correction`，`artist_names.origin` 只允许 `scan`、`correction`、`seed`
  （`backend/migrations/0026_artist_catalog.sql:20`、`:25`）。
- 认领只搬修正行与核对行；发行从不物理删除。
- 实例级设置的现成做法是单行表（`scan_schedule`、`steward_instance_settings`）。
- 管理员只在首次初始化时创建，代码里没有修改角色的入口，最后一位管理员不能被停用：目前实例里只有一位管理员，
  “开启者被停用”“另一位管理员接手”在现有功能下到不了。
- 前端对操作类型、改动摘要的 `kind`、`origin.source` 的解码是严格的，未知取值会让操作记录页解码失败
  （`frontend/src/features/governance/api/decoders.ts:208-291`、`:296-302`）。
- 接口样本在 `backend/internal/app/testdata/api-samples/`，由集成测试生成并逐字比对，前端的契约测试读同一批文件。

## 需求

| 编号 | 需求 |
| --- | --- |
| A-R1 | **自动层**：发行级八个字段各有一个可选的自动值，形状与人工修正相同（设值或设空，标题与专辑艺人不能设空），每个值记着写入它的操作 |
| A-R2 | **三层有效值**：`release_effective` 按 人工修正 → 自动层 → 扫描值 取，逐字段取第一个有值的。所有读取处不改就得到三层结果；依赖有效专辑艺人的派生数据（署名、搜索等）在自动层变化时同样刷新 |
| A-R3 | **结构隔离**：扫描不读写自动层；自动写入不读写人工修正与发行的 `edit_revision`；人工修正的写入与撤销不读写自动层。重扫、认领不清除也不破坏自动层 |
| A-R4 | **自动写入的入口**：后端提供一个只供程序内部调用的写入能力（没有 HTTP 写接口），一次写一个发行的一个或多个字段，经 `operations.Run`，带幂等键；操作者是开启自动整理的管理员，来源是“自动整理”，并带外部源或模型的标识、依据摘要与批次 |
| A-R5 | **写入的前提**：总开关开着，并且开启者仍是启用状态的管理员；否则拒绝写入并说明原因。判断在写入的事务里做 |
| A-R6 | **批次**：可以开一个批次、往里写、结束批次；批次记录起止时间、属于程序层还是模型层、改动数量。每条自动操作至多属于一个批次 |
| A-R7 | **单条撤销**：自动修改用现有的撤销入口撤销。规则是“这条操作写的每个值现在是否仍是它写的”：都是就恢复到它之前的自动层状态（之前的值及其写入者，或没有值）；任何一个已被更晚的自动修改改写就整条拒绝，返回冲突并指出是哪条操作改写的。不核对发行的 `edit_revision`，之后的人工修改不妨碍撤销 |
| A-R8 | **按批、按来源撤销**：按时间倒序逐条撤销范围内仍可撤的自动操作；每条独立成败；返回撤了多少、跳过了哪些及原因；范围大时分段进行，可以续做；同一请求重试不会重复撤销 |
| A-R9 | **撤销后不再应用**：撤销自动修改时记下“不再提出”的标记（哪个发行、哪个字段、哪个值）。自动写入遇到带标记的同一改动时不写入并在结果里说明；同一字段的其他值不受影响。管理员可以查看并清除标记 |
| A-R10 | **总开关**：实例级设置，默认关。只有管理员可以开关；打开时记下打开者，他成为开启者；关闭后保留已写入的自动层 |
| A-R11 | **读取**：管理员可以按来源、按批次筛选操作记录；可以列出批次并查看一个批次的改动；可以看到一个发行各字段的三层值（人工、自动及其来源、扫描）与哪一层生效 |
| A-R12 | **“需要关注”**：扫描拿不准、但自动层已经给出值的字段，不再计入“需要关注”；撤销自动值之后重新计入 |
| A-R13 | **前端的最小适配**：操作记录页的解码与标签接受自动整理的操作类型与来源，艺人别名接受新的名字来源；不新增页面与入口 |
| A-R14 | **合同与文档**：受治理操作合同补上自动层、来源、批次与撤销规则；ADR 0006 第 13 节补上任务与提交 |

## 主代理取的默认值（审阅时可改）

| 编号 | 默认值 | 理由 |
| --- | --- | --- |
| A-P1 | 自动值等于当前扫描值也可以写入（相当于外部源确认了扫描值） | 与人工修正“确认扫描值”一致；这样外部源能消掉“拿不准的字段” |
| A-P2 | 人工修正存在时仍允许写自动层，只是不生效 | ADR 0006 的验收场景要求“清除人工修正后显示自动层的值” |
| A-P3 | 单条撤销遇到被改写的值时整条拒绝，不做部分撤销 | 与认领的撤销一致；按批撤销按时间倒序进行，自然先撤后写的 |
| A-P4 | 按批、按来源撤销同样写“不再提出”的标记 | 撤销就应该撤得住；想重新允许时清除标记 |
| A-P5 | 任何管理员都可以开关，打开的人成为开启者。开启者失效的核对照 ADR 实现，但不为它做界面或接手流程 | 目前实例里只有一位管理员，并且不能被停用，这个状态到不了 |
| A-P7 | 自动修改的撤销不要求发行可见 | 已经不可见的发行上的自动值也要撤得掉，按来源整体撤销才完整 |
| A-P8 | 管理员的修正状态接口每个字段多一个 `auto`（三层值从这里读）；“清除修正后显示什么”的预览改为先看自动值 | 同一个编辑界面要同时看三层 |
| A-P6 | 普通成员的接口不增加任何自动层的信息；详情里“哪些字段是自动补全的”留给界面子任务 E1 决定怎么展示 | 本任务不改界面；避免先定下成员可见的字段再返工 |

## 验收标准

在隔离的 PostgreSQL 上用合成数据验证；除特别说明外都是集成测试。

- [ ] A-V1 三层优先顺序：同一字段有扫描值、自动值、人工修正时显示人工的；清除人工修正后显示自动的；撤销自动值后显示扫描的。八个字段逐个覆盖，含设空。
- [ ] A-V2 没有自动层数据时，现有接口的样本逐字不变；唯一的例外是管理员的修正状态接口，每个字段多一个值为 null 的 `auto`。现有的 EXPLAIN 与读取性能测试通过。
- [ ] A-V3 重扫（原样重扫与扫描值变化后重扫）之后自动值保持；扫描的写入语句不涉及自动层。
- [ ] A-V4 自动写入不改变发行的 `edit_revision` 与任何人工修正的行；自动写入之后，之前的人工修改仍然可以撤销。
- [ ] A-V5 自动写入之后，在同一发行上做人工修改（同一字段或其他字段），再撤销更早的自动修改，成功并回到自动写入之前的自动层状态。
- [ ] A-V6 同一字段先后两条自动修改：先撤销较早的一条被拒绝并指出改写它的操作；先撤销较晚的一条后，这个值回到较早那条写的值并仍记在它名下，再撤销较早的一条也成功。
- [ ] A-V7 专辑艺人的自动值生效后，艺人页的署名、搜索与排序反映新的值；撤销后恢复。
- [ ] A-V8 批次：开批次、写入多条、结束；按批次筛选操作记录只得到这一批的；批次详情的改动数量与实际一致。
- [ ] A-V9 按批撤销：全部可撤时全部撤销；其中一条已被更晚的批次改写时，这一条被跳过并说明原因，其余照常撤销；重试同一请求不产生新的撤销记录。
- [ ] A-V10 按来源撤销：只撤销该来源的自动修改，其他来源的不动；数量超过一段的上限时可以续做到完成。
- [ ] A-V11 撤销之后，再次以相同的值写入同一字段被拒绝并说明是“不再提出”；写入不同的值成功；清除标记后相同的值可以写入。
- [ ] A-V12 总开关关闭时自动写入被拒绝；打开后成功，操作记在开启者名下、来源是自动整理；测试里把开启者的用户行改成停用或普通成员后，写入被拒绝并说明原因。
- [ ] A-V13 开关、批次、按批与按来源撤销、标记的查看与清除、三层值的读取，普通成员一律被拒绝。
- [ ] A-V14 扫描拿不准的字段在自动层有值后不再计入“需要关注”，撤销后重新计入。
- [ ] A-V15 迁移的升级与回退脚本都能执行；回退后回到 0057 的结构。
- [ ] A-V16 前端：操作记录页能解码并显示自动整理的记录与它的撤销（Vitest，读后端生成的样本）；类型检查与相关用例通过。
- [ ] A-V17 包依赖规则测试覆盖新增的包；并发（同一发行的两次自动写入、写入与撤销同时发生）、权限与迁移三处做变异检查。

## 不在范围内

- 任何自动写入的调用方：外部源、匹配、模型后台运行（B1、B2、C、D）。
- 界面（E1、E2）：本任务只做解码与标签的最小适配，不新增页面、入口与编辑界面里的展示。
- 各外部源的开关、AcoustID 密钥、整理用的模型、每日用量上限（B1、B3、D）。
- 曲目级字段（I）；结构操作的自动使用（C、G、H）；外部封面、歌词与外部对应（B1、B2）。
- 待定项与例外（C、D）。
- 管家在对话里的写工具：仍然只写人工修正。

## 规划结论的确认方式
