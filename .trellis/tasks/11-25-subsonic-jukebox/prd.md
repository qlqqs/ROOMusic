# Subsonic 点唱机控制播放区

父任务：`11-25-opensubsonic-api`，共用约定见父任务的 `design.md`。依赖 `11-25-subsonic-foundation`。用户于 2026-11-25 决定加入第一版。

## 目标

支持点唱机模式的客户端（DSub、Ultrasonic、Symfonium 等）可以当遥控器，控制 ROOMusic 的一个播放区。声音从家里的音箱出来，多房间同步、均衡、房间校正照常生效。

## 需求

- R1 选择目标播放区：
  - 设置 › 账号的“第三方客户端”一行里，新增“点唱机控制”，可以选本人的任意一个播放区，包括局域网渲染器和编组；
  - 选择存在服务端；
  - 没有选过时，取本人最近一次播放过的播放区；一个都没有时，`jukeboxControl` 返回错误 0“没有可控制的播放区”。
- R2 `jukeboxControl` 的各个 `action` 对应到播放区现有的操作：

  | action | 对应操作 |
  |---|---|
  | `get` | 返回队列（`jukeboxPlaylist`），以及 `currentIndex`、`playing`、`gain`、`position` |
  | `status` | 只返回状态 |
  | `set` | 用 `id[]` 替换队列 |
  | `add` | 追加到队列末尾 |
  | `clear` | 清空队列 |
  | `remove` | 按 `index` 删除 |
  | `skip` | 跳到 `index`，并 seek 到 `offset` 秒 |
  | `start` / `stop` | 播放 / 暂停 |
  | `shuffle` | 打乱队列 |
  | `setGain` | 0–1，对应设备音量；编组时对应编组音量 |

- R3 写操作带播放区的 `revision`，由服务端读当前值后提交。并发冲突时重试一次，仍然失败就返回 0。
- R4 网页端与点唱机操作的是同一个播放区：一边的改动另一边能实时看到，用网页端现有的事件流。
- R5 权限：只能控制本人的播放区。成员看不到其他人的播放区，也控制不了。

## 验收标准

- AC1 选定一个播放区，`set` 三首后 `start`：播放区开始播放第一首，网页端显示同一个队列，状态为播放中。
- AC2 `skip index=2 offset=30`：播放区跳到第三首的 30 秒处，`status` 返回 `currentIndex=2`，`position` 约为 30。
- AC3 `setGain gain=0.5`：设备音量变为 0.5。编组时编组音量变为 0.5。
- AC4 `remove`、`clear`、`shuffle`、`add` 之后，`get` 返回的队列与网页端一致。
- AC5 没有选过播放区时，自动取最近播放过的那个；一个播放区都没有时返回错误 0。
- AC6 点唱机控制不了别人的播放区，即使把别人播放区的 ID 写进设置请求，也会被拒绝。

## 不做

- 一个客户端同时控制多个播放区。
- 点唱机模式下的流式输出（协议没有）。
