# Docker Compose 部署打包与上线演练

父任务：[部署上线](../11-05-deploy-launch/prd.md)（决定 D2、D3、D6 见父任务）。

## 目标

在本机用一条命令启动生产实例，崩溃或重启后自动恢复，每天自动备份，忘记密码和恢复数据都有说明可照做；
上线前在本机完整演练一次。

## 现状

- `scripts/prod.sh` 用 `go run` 现场编译，没有镜像与自动拉起；生产 `.env` 只有注释。
- `deploy/smoke/current.Dockerfile` 是仅供 smoke 的镜像（uid 1000、`/healthz` 健康检查），可参考。
- `scripts/ffmpeg-pinned.sh` 固定 ffmpeg 镜像 `mwader/static-ffmpeg@sha256:11a4…749c`（7.1.1）；应用启动时自检 ALAC 派生。
- 应用二进制有 `reset-password` 子命令；`/healthz`、`/readyz` 已有；迁移在启动时执行并加锁。
- 音乐在 `/home/qlqq/workspace/ROOMusic/music`（uid 1000，755），与开发工作区在同一目录下。
- 本机 Docker 默认地址池的下一个子网 `192.168.48.0/20` 会覆盖局域网 `192.168.50.0/24`（见父任务）。
- 开发用 Compose 项目名是 `roomusic`（`roomusic-postgres-1`），其数据卷不能被生产动到。

## 需求

| 编号 | 需求 |
| --- | --- |
| P1 | 生产镜像：多阶段构建，Go 版本与 `.mise.toml` 一致，基础镜像固定版本；内置 `scripts/ffmpeg-pinned.sh` 同一摘要的 ffmpeg；非 root（uid 1000）运行；带健康检查；前端用已提交的内嵌产物，构建镜像不需要 Node |
| P2 | 生产 Compose（与开发的 `compose.yaml` 分开，项目名与开发不同）：应用 + PostgreSQL 18；`restart: unless-stopped`；应用等数据库健康后再启动；PostgreSQL 端口不对外发布；网络**固定子网**，不与局域网和本机已有网络重叠 |
| P3 | 音乐目录只读挂载进容器；`ROOMUSIC_DATA_DIR`（派生缓存）与数据库各用独立数据卷；应用端口对局域网开放（外部反代也经这个端口访问） |
| P4 | 生产配置模板 `.env.prod.example`（与开发模板 `.env.example` 并列）：列出必填项（数据库密码、来源清单、音乐路径、端口等）与可选项，每项一句说明；实际 `.env.prod` 不提交 |
| P5 | 每日备份：随 Compose 一起启动的备份服务，每天 `pg_dump` 到宿主机目录，保留最近 14 天，失败要在日志里看得到；另提供一条手动立即备份的命令 |
| P6 | 恢复说明与脚本：从某个备份恢复到生产库（含停应用、恢复、再启动的顺序），以及恢复到临时库核对的做法 |
| P7 | 运维命令说明：首次部署、升级（提交到 `main` 后重建并启动）、回退到某个提交、查看日志、忘记密码、停止；生产镜像只用 `main` 分支已提交的代码构建（从 Git 导出，不用工作区文件），开发中未提交的改动或其他分支不会进入生产镜像 |
| P8 | README 的“开发环境”“生产环境”部分按两套配置重写；去掉 `go run` 方式的 `scripts/prod.sh`（生产只保留 Docker 一种方式）；`scripts/reset-password.sh`、`scripts/dev-reset.sh` 不再把根目录 `.env` 当配置文件 |
| P9 | 上线演练（由测试 agent 执行，在与生产不同的项目名、端口和数据卷上进行，演练后清理）：从零启动 → 初始化 → 添加目录并扫描 → 播放 FLAC 与 ALAC → http 局域网来源与 https 来源（本机临时 TLS 反代模拟）各登录一次并做写操作 → 限速触发（并确认容器看到的局域网连接来源是真实局域网 IP，而不是 Docker 网关地址；否则限速会退化为只按用户名，需要在设计里处理端口发布方式）→ `docker compose restart` 后恢复 → 手动备份 → 恢复到临时库核对 → 确认开发库未受影响 |
| P10 | 演练通过后启动正式生产实例并保持运行：端口 8090，来源清单先只有 `http://192.168.50.206:8090`（公网域名由用户日后写进 `.env.prod` 再 `make prod`，部署说明写明这一步）；数据库为空，由用户自己打开页面初始化管理员 |
| P11 | 两套配置（D7）：开发读 `.env.dev`，生产读 `.env.prod`，两套同时运行，端口、Compose 项目、数据卷、网络都分开；不设开关。生产命令：`make prod [REF=<提交>]`（构建、升级前备份、启动）、`make prod-stop`、`make prod-status`、`make prod-logs`、`make prod-backup`、`make prod-reset-password U=<名>`；开发保持 `make dev`、`make dev-reset`。根目录 `.env` 不再被任何脚本读取 |

## 规划裁决

设计稿（[design.md](./design.md)）提出，主会话 2026-11-05 按推荐裁决；端口由用户确认：

- 生产端口 **8090**（用户 2026-11-05 确认；8080 留给开发），演练用 18090 与 18443。
- 两套配置（P11）：用户 2026-11-05 提出两套配置，先后考虑过开关切换与“同时只跑一套”，最终定为直接部署两套、同时运行；具体文件名与命令由主会话定。
- 文件放在 `deploy/production/`；生产配置放在开发工作区根目录的 `.env.prod`（不再单独 clone 生产检出目录，原因见 P7 的导出构建）；备份目录 `/home/qlqq/roomusic-backups`。
- 生产只用被部署提交里的东西：应用镜像、装备份与恢复脚本的 tools 镜像都从 `git archive <提交>` 构建，`compose.yaml` 也取该提交里的版本（设计稿提出，主会话采纳）。
- 升级前备份总是做，失败就不换版本。
- 生产镜像默认从 `main` 构建，回退时可指定提交；`scripts/prod.sh`（`go run`）删除，`make prod` 改为 Docker 方式。
- 部署说明提醒：`.env.prod` 不在 Git 里，`git clean -x` 会删掉它，建议另存一份。
- 生产网络固定子网 `10.203.50.0/24`，演练 `10.203.51.0/24`；应用端口只发布在 IPv4 的 `0.0.0.0`。
- 入口脚本先等 PostgreSQL 可连接再启动应用（应用只在启动时连一次数据库，机器重启后容器顺序不保证）。
- 封面与转换缓存所在的 `/data` 卷不进每日备份，演练时确认重新扫描能补回封面。
- CI 只加生产 Compose 配置检查、脚本语法检查和固定版本一致性检查，不构建镜像。
- 演练第 8.3 步需要用户用手机或另一台电脑访问局域网地址输错一次密码，用来确认容器看到的是真实局域网地址。
