# 技术设计

## 组织与边界

采用单一任务：导航、个人库与队列共享曲目和会话身份，需联合验收，暂不拆为独立子任务。沿用 React、TypeScript、hash 路由和 CSS，生产仍由 Go 同源托管。

`main.tsx` 保留应用组合与既有会话协调；新增 `features/player/`、`features/personal-library/` 和 `features/demo/`。catalog 通过公开入口提供展示模型。真实数据继续走既有 REST decoder，不修改认证与管理权限合同。

## 状态合同

- 播放使用 reducer 与专用 hook；曲目身份用于收藏去重，队列条目身份用于定位与删除。队列上限沿用 500 项，历史上限 100 项。
- 立即播放歌曲/列表替换当前播放上下文；加入队列不打断播放；下一首播放插入当前位置之后。空队列追加后保持暂停，直到用户播放。
- 顺序模式末曲结束暂停；列表循环回首曲；单曲循环针对自然结束，手动下一首仍切歌；随机模式避免连续选中同曲，并记录历史以支持上一首。
- 时钟只在模拟播放且时长已知时推进；切歌清零、暂停停止，副作用卸载清理。未知时长禁用拖动和自动结束。
- 页面与筛选归 URL；浮层和表单归局部状态；个人库 hook 管理收藏、歌单、历史及存储。
- 持久化采用版本化结构和运行时校验，按真实用户或演示身份隔离；读取损坏数据可恢复，写入失败降级内存并反馈；恢复时不自动播放，注销清理当前内存。
- 仅保存必要展示快照和标识，不复制整个服务端目录，不保存路径、凭据或令牌。

## 界面与资产

按 qiaomu-design 打磨模式沿用既有设计锚，不重新选主题。视觉冒险度 4（熟悉结构）、动效 3（轻量过渡）、信息密度 6（便于扫读）。首屏辨识音乐库、当前页面和播放入口。

我的音乐采用标签与歌曲列表，歌单管理用明确对话框；播放器保留核心控制，队列和歌词按需展开。封面优先复用现有图片，演示使用许可可验证的本地位图，缺图提供一致回退。工具图标拟引入 lucide-react，以统一播放、队列、循环等命令图形，并同步记录依赖决定。

长标题可收缩，控件尺寸稳定，焦点可见，遵守减少动态效果设置。演示入口显式切换数据源，不能通过吞掉真实错误伪造成功。

## 回退

新增存储使用独立命名空间，无服务端数据迁移。主要回归边界为 `main.tsx`、全局 CSS 和旧队列 helper；迁移时同步调用点与测试，确保只有一个播放状态源。可按 feature 回退改动。
