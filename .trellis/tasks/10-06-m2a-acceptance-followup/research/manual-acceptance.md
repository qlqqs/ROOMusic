## 每组必测格式

短素材定位时在播放后立即拖动到中段，或暂停后定位再播放；确认进度、实际声音和结束行为一致。
不能只看按钮或 `canPlayType`。ALAC 由服务端无损转换成 FLAC 后交付（M2b），所有浏览器的行为应一致：先显示“正在准备”，完成后播放，
信号路径写明无损转换；不得伪装进度，也不得转成有损格式。

| 素材与参数 | Safari 播放/定位 | Chrome 或 Edge 播放/定位 | Firefox 播放/定位 |
| --- | --- | --- | --- |
| FLAC 16 bit / 44.1 kHz / 双声道 | 未执行 | 未执行 | 未执行 |
| FLAC 24 bit / 48 kHz / 双声道 | 未执行 | 未执行 | 未执行 |
| ALAC 16 bit / 44.1 kHz / 双声道（经服务端无损转换） | 未执行 | 未执行 | 未执行 |
| ALAC 24 bit / 48 kHz / 双声道（经服务端无损转换） | 未执行 | 未执行 | 未执行 |
| MP3 / 双声道 | 未执行 | 未执行 | 未执行 |

ALAC 在 M2a 收尾时移出直出格式表（提交 `13a9cfe`）；M2b 起由服务端无损派生为 FLAC 后交付（`delivery: derived`），不再要求 Safari 直出 ALAC。
测试实例没有可用的 ffmpeg 时 ALAC 仍显示“这种格式目前不能直接播放”，那是未启用派生，不是失败。
不能把缺少实播记录写成“兼容已确认”。AAC、16 bit WAV、Vorbis、Opus 以真实 Chromium 自动化证据批准；
24 bit extensible WAV 与 CUE 虚拟轨为应禁用的反例。
