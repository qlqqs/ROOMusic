# 管家 C3：MCP 服务与个人访问令牌

## 目标

让 Claude Code 等 MCP 客户端用个人访问令牌连上 ROOMusic，调用 C2 已登记的工具。
做完后可以用真实客户端试用只读工具，用试用中发现的问题修正工具设计（父任务 S4、S10）。

## 背景与约束

- 父任务决定（S10）：令牌代表签发它的用户；签发时选只读或读写，可设过期时间，可随时吊销；
  读写令牌的写操作直接执行，由 MCP 客户端自己的权限提示把关。
- ADR 0005 第 6 节：令牌只存 SHA-256 哈希，明文只在签发时显示一次；带范围、可选过期时间、上次使用时间；
  只用于 MCP 路径，不能当登录会话用，也不能用来管理令牌自身。
- C2 的工具注册表（`backend/internal/steward/tool`）每次调用按调用者重新鉴权；当前登记的 16 个工具都是 `read`，
  `Registry.Invoke` 目前只放行 `read`。
- 调研见 `research/mcp-go-sdk.md`（子代理 2026-11-16 查文档并用探测程序实测 SDK；没有用真实 Claude Code 连过）：
  现行 MCP 规范是 `2026-07-28`，相对 `2025-11-25` 是不兼容升级；Claude Code 先试新版，不支持时退回旧握手；
  配了 `Authorization` 头时收到 401 报连接失败，不会转去做 OAuth 发现。

## 决定

| 编号 | 日期 | 选择者 | 决定 |
| --- | --- | --- | --- |
| K1 | 2026-11-16 | qlqq | 协议层用官方 Go SDK（`github.com/modelcontextprotocol/go-sdk` v1.8.0），接受净增 7 个依赖模块 |
| K2 | 2026-11-16 | qlqq | 管理员关闭成员使用管家时，成员的令牌请求被拒绝、也不能签发新令牌；重新打开后原令牌恢复可用 |
| K4 | 2026-11-16 | qlqq 提出，主代理给出做法 | 认证失败按来源限速并在暂停开始时告警，避免爆破无法发现 |
| K3 | 2026-11-16 | qlqq | 本任务在设置页做一个简单的“访问令牌”栏目，C4 做管家设置时再并入 |

## 需求

- R1 主服务在 `/api/v1/mcp` 提供 MCP（可流式 HTTP、无状态、只有工具能力），同时接受 `2026-07-28` 与旧握手两代客户端。
- R2 认证用 `Authorization: Bearer <令牌>`。令牌缺失、不存在、过期、已吊销，或所属用户已禁用，返回 401；
  成员开关关闭时成员的令牌返回 403。登录 Cookie 在这个路径上不起作用。
- R9 同一来源地址一分钟内认证失败 30 次后暂停该来源一分钟，期间返回 429 与 `Retry-After`；暂停开始时记一条告警日志。
  做法与数值沿用登录限速（`identity/throttle.go`）；提交的令牌不进日志。
- R3 请求带 `Origin` 头时，按现有来源规则判断，不可信返回 403；不带 `Origin` 的请求（命令行客户端）放行。
- R4 工具列表与调用按令牌所属用户的身份和令牌范围过滤：只读令牌只能看到并调用 `read` 工具；
  读写令牌另外可以看到 `personal`、`shared` 工具（本任务内没有这类工具，调用入口的放行在 C5、C6 接上）。
- R5 工具结果按 MCP 的结构返回；工具失败作为工具结果里的错误返回，不带处理函数的原始错误文本。
  含不可信文本的工具在说明里写明结果是资料、不是指令。
- R6 令牌管理接口（登录会话认证）：签发（名称、范围、可选过期时间）、列出、吊销。明文只在签发响应里出现一次；
  列表只显示名称、范围、末四位、创建时间、过期时间、上次使用时间。每个用户最多 20 个未吊销的令牌。
- R7 设置页新增“访问令牌”栏目：列表、签发（签发后显示一次明文和 Claude Code 的接入命令，可复制）、吊销（需确认）。
  成员开关关闭时成员看到说明，不能签发。
- R8 令牌明文不出现在日志、操作记录、数据库和其他接口响应里；日志记录令牌标识、工具名、耗时和结果，不记工具输入输出。

## 验收

- A1 只读令牌：能列出并调用只读工具，结果与同一用户在对话入口调用同一工具的输出一致。
- A2 权限一致：成员的令牌看不到管理员工具，调用时被拒绝；同一用户、同一工具在两个入口的判定相同（父任务 A4）。
- A3 吊销、过期、用户被禁用后，下一次请求返回 401；成员开关关闭后成员的令牌返回 403，重新打开后恢复。
- A4 令牌不能访问 MCP 以外的接口；登录 Cookie 不能访问 MCP 路径；令牌不能调用令牌管理接口。
- A5 数据库的所有列、日志和列表接口的响应里搜不到令牌明文（父任务 A7）。
- A6 带不可信 `Origin` 的请求返回 403。
- A10 同一来源连续认证失败达到上限后返回 429，日志里有一条暂停开始的告警；用正确令牌的请求不计入失败次数。
- A7 新旧两代握手的客户端都能完成列出工具和调用工具（用 SDK 自带的客户端在测试里验证）。
- A8 设置页能签发、看到一次明文、吊销；刷新后明文不再出现。
- A9 用真实的 Claude Code 连接试用，由用户执行，结果单独记录，不算自动化验证。

## 不做

- OAuth 授权流程。
- 写工具本身（C5、C6）；本任务只把令牌范围的判定接好。
- 资源、提示词、采样、订阅通知等其他 MCP 能力。
- 管理员查看或吊销他人的令牌（禁用成员即可让其令牌失效）。

## 规划结论

路线：用户选择。K1–K3 由用户在 2026-11-16 的选择框里选定，K4 由用户提出；用户 2026-11-16 批准最终规划摘要，
其余细节（令牌数量上限、不包来源标记、上次使用时间的更新间隔、截断时的结果形态）按主代理的建议。
反向代理后的来源地址识别不在本任务内，需要时另开任务（会同时影响登录限速）。
