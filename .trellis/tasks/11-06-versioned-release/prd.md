# 版本化镜像发布与双向迁移

父任务：[部署体验改进](../11-06-deploy-ux/prd.md)（决定 D3–D6）。依赖：迁移前备份来自 [builtin-backup](../11-06-builtin-backup/prd.md)；
发布附带的 compose 来自 [config-trim](../11-06-config-trim/prd.md)。现状依据：[后端调研](../11-06-deploy-ux/research/backend-facts.md) §1、§2、§5、§7。

## 目标

把 compose 里的镜像版本号改大就升级、改小就降级，`docker compose up -d` 后数据库结构自动跟着走，不需要手动恢复备份。

## 需求

### 版本与发布

- **R1 版本号**：语义化版本 `vX.Y.Z`，来自 git 标签；首个版本 `v0.1.0`。版本号与提交号在构建时写进二进制，启动日志输出；
  管理接口提供给“系统 › 备份”页显示（字段由 builtin-backup 接入）；非标签构建显示“开发版”。
- **R2 发布流程**：推送 `v*.*.*` 标签触发 GitHub Actions：先通过与现有 CI 相同的门禁，再分别在 amd64 与 arm64 原生构建，
  合并为多架构镜像推到 `ghcr.io/qlqqs/roomusic`，标签为 `X.Y.Z`、`X.Y` 和 `latest`；镜像带 OCI 版本、提交、源码仓库标签。
  同时创建 GitHub Release，附上已写好该版本号的 compose 文件和示例配置。镜像包设为公开。
- **R3 发布权限**：只有用户说“发布”时，主会话才打标签并推送；推送前做只读检查：远端 main 是本地 HEAD 的祖先、新增内容没有密钥类文件或令牌、标签版本号大于已有标签。

### 双向迁移

- **R4 回退 SQL**：从下一个新迁移起，每个迁移都附带回退 SQL（与正向 SQL 分开存放，不改变已发布迁移的校验和）；
  确实无法回退的迁移必须显式标记。缺少回退 SQL 又没有标记的迁移在加载阶段就失败（测试和 CI 能发现）。现有 0001–0030 不需要回退 SQL。
- **R5 存库**：执行正向迁移时，把对应的回退 SQL 与其校验和一并写进 `schema_migrations`。
- **R6 自动降级**：启动时库里有本版本不认识的、连续的更新迁移，且它们都带回退 SQL：先做一次迁移前备份（builtin-backup R5），
  然后在一个事务里按版本倒序执行库里的回退 SQL 并删除对应记录，再走正常启动流程。其中任何一条不可回退、记录不连续或回退失败：
  整体回滚，不改库，app 不进入就绪，日志写明数据库来自哪个版本、哪条迁移无法回退，以及应改用哪份迁移前备份恢复。
- **R7 回退后再升级**：降级后再次升级，正向迁移照常重新执行。
- **R8 数据语义**：回退会丢掉新版本新增的表和列里的数据，这是降级的预期代价；回退 SQL 还要处理新版本写进旧表、但旧版本不认识的取值
  （如放宽过的 CHECK 取值），保证旧版本能正常读写。`/data` 下的封面与派生缓存目录格式变化也必须让旧版本可用或可自动重建。
- **R9 规范更新**：`.trellis/spec/backend/core0-runtime-contracts.md:124`（“不提供 down migration”）与 `database-guidelines.md`
  的迁移合同改为新规则，写明每个新迁移的回退要求和测试要求。

## 验收标准

- [ ] A1 二进制 `--version`（或等价方式）和管理接口返回版本号与提交号；开发构建返回“开发版”。
- [ ] A2 执行器单元与集成测试（PG 18）：正向迁移写入回退 SQL；未知新迁移全部可回退时自动倒序回退且先产出迁移前备份；
      有不可回退、不连续或回退报错时整体回滚、库不变、`/readyz` 503、日志含版本与备份提示；回退后再升级成功。
- [ ] A3 每个带回退 SQL 的迁移都有自动测试：升级 → 回退后的表结构与升级前一致 → 再升级成功。
- [ ] A4 发布工作流通过 `actionlint` 检查；本机构建一次 amd64；arm64 在 GitHub 原生 arm64 runner 上用手动触发的只构建不推送运行验证（本机不装 binfmt）。首次真实发布在用户说“发布”后进行，
      发布后 `docker manifest inspect ghcr.io/qlqqs/roomusic:0.1.0` 显示 amd64 与 arm64，匿名可拉取。
- [ ] A5 升降级演练（隔离演练项目，不碰生产）：用本地构建的版本 A（含本机制）与版本 B（A 加一条带回退 SQL 的测试迁移，仅演练用、不发布）
      做 A → B → A → B，每次改版本号后 `docker compose up -d --wait` 都 healthy，账号、专辑、曲目、收藏数量不变，
      每次迁移前都有一份迁移前备份。
- [ ] A6 规范文档已更新，`git grep "不提供 down migration"` 无残留。

## 不做

- 发布 main 尝鲜镜像、自动生成更新日志之外的发布说明、跨大版本的数据格式转换工具。
