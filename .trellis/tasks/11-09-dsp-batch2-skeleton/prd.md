# 第二批公共骨架：多节点处理链与格式拆分

父任务：[音频算法对标](../11-08-audio-dsp-reference-port/prd.md)。代码核对：[research/code-reconciliation.md](./research/code-reconciliation.md)。

## 目标

第二批的采样率转换、降混、PEQ、卷积、DSD 都要往渲染链里加节点、给播放区加设置。第一批的代码只按“链上只有 Headroom 和量化、格式不变”实现，各子项直接接入会在同一批文件上反复冲突，并且有几处会出错（见核对 A、F、H）。本子项先把这些共同的地方改好，**不加任何新的处理算法**，合入后对用户无可见变化。

## 需求

- **K1 多节点处理链**：处理链能按父设计 §6.1 的顺序接入任意数量的节点（②采样率、③降混、⑤用户处理项等），节点可以改变采样率和声道数；chain 包不导入具体的算法包。
- **K2 格式拆分**：渲染会话区分“源格式”（解码与混音）和“链输出格式”（编码与交付）。播放头、位置事件和时间换算在格式变化时依然正确。
- **K3 统一的“有处理”判定**：抖动步骤与“能否出 16 位”只看一个判定函数，任何节点启用都算有处理。
- **K4 延迟**：处理链能汇报总延迟；换轨与重建判定改用“已送入链的帧数”，使有延迟的节点（卷积）不会让已移出队列的曲目播出来。
- **K5 声道布局**：声道布局从来源一路传到渲染（`RenderSource` → 渲染器 → `render.Track` → 协商格式）。按声道数取标准默认布局，WAV 用文件头里的声道掩码。
- **K6 设置表示**：播放区设置能容纳切片和可空字段，判断“有没有变化”正确，读出时不共享底层数据；读到坏值时按默认处理并记日志，不让整个用户的播放区加载失败（Headroom 一起改）。新增一个设置键时要改的地方尽量收拢。
- **K7 公共包与规则**：建立第二批共用的空包或基础包并登记依赖规则（`dsp/internal/fft`、`dsp/internal/refdata`、`dspsettings` 等，归属在设计里定）；第二批各子项的迁移编号在设计里预留。

## 验收

- 不开任何处理时，无损档流与源逐位相同（第一批的会话 MD5 测试照常通过）。
- 用一个测试用的改变采样率/声道数的节点，渲染流的格式、位置事件与时长正确。
- 用一个测试用的带延迟节点，移出已预取的下一首会触发重建。
- 设置坏值时播放区仍能加载，用默认值。
- 对用户无可见变化：现有 real e2e 与 mock e2e 通过。

## 依赖

第一批已合入 main（v0.5.0）。第二批其余子项的“接入”部分都在本子项之后；各自的纯算法包不依赖本子项。

## 范围外与验收映射

本次公共骨架不添加新算法、用户设置键或数据库迁移，不改变第一批 ffmpeg 适配路径；后续分别由对应子项替换。现有文档仍未实现的接入假设由本任务 design.md 的合同取代。

| 需求 | 最小验收 |
| --- | --- |
| K1、K2 | 多节点变率/变声道，零帧输出及流尾冲刷，流格式、位置事件与时长；复用第一批无处理 MD5 |
| K3 | 同一处理判定覆盖启用节点、0 dB 电平化、16 位能力上限；量化仍按块的 Exact |
| K4 | 下一首已送入带延迟链但尚未输出时移出队列，触发重建；只预缓冲则重选 |
| K5 | WAV 显式掩码传递；默认 4.0 与 6.1 |
| K6 | 规范 JSON 比较、取出切片不共享；坏 Headroom 仅回退本键并有脱敏日志 |
| K7 | 实际新增包有依赖规则，无虚构空规则；迁移号按 design §8 预留 |

日常只跑受影响最小集；合入 main 前额外按父 implement §5 整组跑 real e2e、mock e2e，这是第一批合入时得到的教训，不扩成每一步全量测试。
