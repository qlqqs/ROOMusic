# 自动整理 B1：外部源接口与 MusicBrainz

状态：规划完成，待启动。父任务 `11-22-auto-curation-sources`，前置子任务 A 已完成（`d079f44c`）。
技术设计见 `design.md`，执行计划见 `implement.md`。调研在 `research/`：

- `research/musicbrainz-api-and-tags.md`：MusicBrainz 接口的用法与限制、光盘目录查询的核实、各格式标签里外部标识的键名。
- `research/scan-tag-identifiers.md`：解析器的键入口、解析缓存与版本、落库链路、候选签名、实例设置与密钥、包依赖规则。

决策依据：[ADR 0006](../../../docs/architecture/adr/0006-auto-curation-and-sources.md) 第 4、6、8、10 节。

## 目标

给后面的程序自动整理（子任务 C）准备好两样东西：能向 MusicBrainz 做专用查询的外部源，以及本地曲库里可以拿去比对的标识。

用户价值：本任务没有界面，也没有自动写入的调用方，用户看不到新功能。它决定了之后自动匹配能覆盖多少种曲库——
用 Picard 打过标签的文件凭标签里的 ID 直接对上，整轨抓的 CD 凭光盘目录对上，其余凭条码、编号与 ISRC。

## 背景

- 出站请求的客户端在 `backend/internal/steward/egress`，只有管家使用；它不依赖管家的其他包。
- MusicBrainz 只有管家的两个对话工具在用（`backend/internal/steward/web/musicbrainz.go`）：自由查询串加按 MBID 读取，
  每次请求新建客户端，没有缓存，503 不重试，进程内每秒一次的限速器是包内私有的。
- 标签里的 MusicBrainz ID、AcoustID 没有解析；标签 ISRC 解析了但在 `backend/internal/library/scanner.go:557` 被丢掉。
- 标签键有三个互不相通的入口：Vorbis 与 APEv2 全量经过 `setAudioTag`；ID3 有帧白名单（`mp3.go:84`）与 `TXXX` 描述白名单
  （`mp3.go:449-454`）；M4A 有自由格式名单（`m4a.go:638-649`）。`UFID` 帧没有解析代码。
  **MP3 的 `TXXX:BARCODE`、`TXXX:CATALOGNUMBER` 与 M4A 的 `----:BARCODE`、`----:CATALOGNUMBER`、`----:ISRC` 现在读不到**，
  而这正是 Picard 与 Mp3tag 写条码和编号的位置。
- 没有保存外部 ID 与本地对象对应关系的表；子任务 A 的 `curation_settings` 只有总开关与开启者，没有各源的开关。
- 调研核实的外部事实：
  - 一次读取能拿全发行的曲目表、时长、录音 ID、ISRC、厂牌编号、条码、release group 与署名。
  - 搜索结果没有曲目表，`score` 只是本次结果内的相对排名；条码与 ISRC 在 MusicBrainz 里都不唯一。
  - 由曲目数与各轨时长可以重建光盘目录，实测与库里的 disc ID 逐位一致；模糊查询只能缩小到“这张专辑的若干 CD 版本”。
  - 限速是每 IP 平均每秒 1 次；遵守限速仍会遇到全局繁忙的 503（带 `Retry-After`），重试是必需的。
  - 标签里叫 “Track Id” 的键装的是录音 ID，曲目 ID 用带 “Release Track” 的键；各打标工具的大小写、空格与下划线不一致。

| 编号 | 需求 |

| B1-R6 | 扫描解析并保存标签里的外部标识：MusicBrainz 的 release、release group、recording、release track、artist、album artist、work ID 与 disc ID，ISRC，AcoustID |
| B1-R7 | 外部对应的存储：本地的发行、专辑、曲目、艺人与外部 ID 的对应，带匹配方式、把握程度与写下它的操作；一个本地对象在一个源里至多一个；扫描不动它 |
| B1-R8 | 合同文档：新增外部源合同，同步管家联网、扫描标签、增量扫描、自动整理等合同 |

## 规划时取的默认值

用户在规划过程中指示“规划完后直接开始实现”，以下各项由主代理按推荐取定，交付时在验收摘要里逐条说明。

| 编号 | 默认值 | 理由 |
| --- | --- | --- |
| B1-P1 | 外部对应在本任务只建存储（表、约束、事务内的读写函数）。把它写成受治理操作、撤销与“不再提出”放到子任务 C | 一次匹配产生的对应怎样分成操作（按发行、按对象）、与补字段是不是同一条记录，取决于匹配流程；现在定下来是猜 |
| B1-P2 | 总开关与各源开关只管后台自动整理。管家对话里的两个 MusicBrainz 工具不受它们影响 | ADR 0006 第 13 节要求“没有开启自动整理的实例行为不变”；对话里的查询是用户本人发起的请求。开关默认是关的，让它管对话工具等于把 M6 已有的功能关掉 |
| B1-P3 | MusicBrainz 的源开关默认开；没有记录时按声明的默认值 | U8 |
| B1-P4 | 查询缓存是数据目录下的文件，不进数据库。有效期：有结果 30 天，空结果 1 天；失败只在进程内记 10 分钟 | ADR 0006 默认 7：缓存放数据目录，可以重新获取，不进备份 |
| B1-P5 | 后台调用遇到 503、429 或网络错误按 `Retry-After` 等待（没有时从 2 秒起指数退避加抖动，单次至多 60 秒），至多重试 4 次，之后报“稍后再试”；对话调用不重试、排队至多 10 秒 | 后台不赶时间但不能丢结果，也不能把断网当成“没匹配上”；对话保持现在的响应时间与错误码 |
| B1-P6 | Cover Art Archive 的封面清单仍留在管家包里，本任务不接入共用限速器 | 它属于子任务 B2 的封面源，届时一并迁移 |
| B1-P7 | 不保存标签里的 AcoustID 指纹 | 上千字符，可以由音频重算，Picard 默认也不写 |
| B1-P8 | 同时补上 MP3 的 `TXXX` 与 M4A 自由格式里的条码与厂牌编号；这两处的 ISRC 只进标识 | 这是 Picard、Mp3tag 写这些值的位置；读不到就没有“条码、厂牌加编号”这条匹配依据。**后果：现有实例重扫后，这类文件所在发行的条码与编号会从空变成有值**，这是对“未开启时行为不变”的一处有意例外 |
| B1-P9 | 现有接口不新增字段：发行详情不显示这些标识，曲目的 `cue.isrc` 不变 | 展示属于界面子任务 E1；标识先只供程序读取 |
| B1-P10 | 能力接口只定义 MusicBrainz 实现的三种（发行、录音、艺人查找）；指纹、封面、歌词的接口随 B2、B3 加 | 没有实现的接口无从验证 |
| B1-P11 | 管家的两个工具直接使用适配器的实体级读取与查询，不经能力接口 | 它们是 MusicBrainz 专用工具，自由查询串与 include 列表表达不成中立的能力；程序层只面向能力接口 |
| B1-P12 | 光盘目录这条匹配依据保留：适配器提供“按光盘目录查发行”，本地算出 disc ID 做精确查询，未命中时同一请求转模糊，结果标明精确还是模糊 | ADR 0006 第 6 节要求在本任务规划时核实；核实结果是可行 |
| B1-P13 | User-Agent 沿用 `ROOMusic/<版本> ( <项目地址> )` | 已符合 MusicBrainz 的要求，不含实例信息 |

## 验收标准

用合成数据与受控的本地服务验收，不请求真实的 MusicBrainz。

- [x] B1-V1 出站客户端在平台层；管家的模型端点、联网搜索、网页读取的现有用例不改断言全部通过。
- [x] B1-V2 管家两个音乐资料工具的工具级现有用例（请求、输出、错误码、每用户额度、日志）只改注入方式、不改断言，全部通过；
  工具定义与输出逐字节不变。直接读写限速器内部字段的几条白盒用例随限速器搬到 `sources` 包，断言的内容不变。
- [x] B1-V3 限速：任意两次发往 MusicBrainz 的请求间隔不小于 1 秒（对话与后台合计）；两者同时排队时对话先发；
  对话排队超过 10 秒返回 `rate_limited`，后台一直等到轮到或被取消。
- [x] B1-V4 缓存：同一请求在有效期内第二次不出站；有结果、空结果、失败三种有效期各自生效；缓存文件在数据目录下，过期的被清理；
  缓存目录不可写时请求照常完成。
- [x] B1-V5 重试与错误：后台调用遇 503 按 `Retry-After` 等待后重试；达到上限返回“稍后再试”，不落盘、不被当成空结果；
  后台遇到断网也是“稍后再试”，不是“没有结果”；对话调用遇 503 不重试；结构不对的 200 不进缓存。
- [x] B1-V6 专用查询：按 ID 读取发行（曲目表、时长、录音 ID、ISRC、厂牌编号、条码、release group、署名）、录音、艺人（含别名）；
  按条码（12 位与前补 0 的 13 位两种写法）、厂牌编号、ISRC、光盘目录、标题艺人曲目数查找。对受控服务断言请求的路径与参数、
  查询词的转义与返回值的解析。
- [x] B1-V7 光盘目录：由各轨帧数算出的 disc ID 与调研核实的例子一致；精确命中与模糊命中在返回值里可区分。
- [x] B1-V8 闸门：总开关关闭、MusicBrainz 源关闭、开启者不是启用状态的管理员，三种情况下经闸门的调用都被拒绝
  （前后两种是 `curation_disabled`，中间一种是 `source_disabled`），受控服务收到的请求数为 0，缓存里有结果也不返回；
  调用已经在排队或等待重试时关掉开关，之后不再出站。同时管家的两个工具照常可用。
- [x] B1-V9 源开关接口：管理员可读可改，默认 MusicBrainz 为开；成员 403；未知的源 404。
- [x] B1-V10 标签标识的解析：FLAC、OGG、Opus、MP3（ID3v2.3 与 v2.4，`UFID` 与 `TXXX` 两种写法）、M4A、APE、WavPack、
  WAV 内嵌 ID3、AIFF、DSF、DFF 都能读出各类标识；“Track Id” 读成录音 ID；多值全部保留；非法值丢弃；大小写、空格与下划线的变体等价。
- [x] B1-V11 落库：扫描后 `track_identifiers` 与标签一致；改标签后重扫随之更新，删掉标签后清除；多轨 CUE 的虚拟轨只带专辑级标识；
  候选没有变化时不重写。
- [x] B1-V12 升级：解析器版本升高后，下一次增量扫描重新解析全部文件，曲目与发行的 ID 不变；没有这些标签的合成曲库，现有接口样本逐项不变。
- [x] B1-V13 MP3 的 `TXXX` 与 M4A 自由格式里的条码、厂牌编号被读到发行字段，这两处的 ISRC 进了标识（B1-P8）；
  同一文件里 `TPUB`、`TSRC` 的现有取值不变。
- [x] B1-V14 外部对应的存储：一个对象在一个源里至多一个；能按对象读取、按外部 ID 反查；重扫、认领与改名移动之后保持。
- [x] B1-V15 迁移升级与回退往返通过。
- [x] B1-V16 包依赖规则覆盖新包；外部源的请求日志不含查询词、路径与响应内容。
- [x] B1-V17 前端接口合同测试通过（新增样本已登记）。
- [x] B1-V18 合同文档与路线图已同步（B1-R8）。

## 不在范围内

- 任何匹配逻辑、把握规则、后台循环与自动写入（子任务 C）。
- 把外部对应写成受治理操作、它的撤销与“不再提出”（子任务 C，见 B1-P1）。
- Cover Art Archive 的图片下载、LRCLIB、外部封面与歌词的存放（子任务 B2）；AcoustID 与声学指纹（子任务 B3）。
- 设置界面与标识的展示（子任务 E1）。
- 用标签里的 release ID 改变扫描的归组。
- ASF/WMA、文件尾部的 APEv2（MP3）与 ID3v2.2：解析器现在就不支持这些，本任务不新增格式。
- 出站代理的配置。

审阅记录（2026-11-22，审阅者：规划审阅子代理，只读）：结论是“改完必须改的再启动”。五条必须改的与六条建议已全部采纳并写入文档：

| 意见 | 处理 |
| --- | --- |
| 迁移版本必须连续，两条线各带一个迁移号时都无法单独验证 | `implement.md` 增加步骤 P0：两份迁移与回退夹具先落到任务分支，再分工作目录 |
| 管家的限速器白盒用例迁出包后不可达，缓存会改变“同一查询出站两次”的断言 | 缓存目录为空即不缓存；客户端工厂形状不变；限速器可注入；B1-V2 改为工具级断言不变、白盒用例搬到 `sources` |
| `web.New` 还有两处调用点不在允许范围内 | 签名不变，增加 `WithMusic` |
| 闸门只在调用前核对一次，排队与重试期间关掉开关仍会出站 | 后台标记带放行回调，每次出站前调用；B1-V8 增加这一条 |
| 失败缓存没有存放位置；对话的失败会让后台把断网记成没匹配上 | 失败只在进程内记；后台一律得到“稍后再试”；写明只有“没有”与空结果算没匹配上 |
| 与 ADR 0006 第 8、10、13 节的措辞冲突（B1-P2、P8、P11） | 交付时在 ADR 里补充说明，随验收摘要交用户确认 |
| `TPUB` 是无条件赋值；`TXXX:ISRC` 会覆盖现有的 ISRC 字段 | 不新增 `TXXX:LABEL`；这两处的 ISRC 只进标识 |
| 对话的读取上限会从 2 MiB 变成 8 MiB | 对话保留 2 MiB，后台 8 MiB |
| 结构不对的 200 会被缓存 30 天 | 写缓存放在适配器校验之后 |
| 闸门的三种拒绝用同一个错误码 | 总开关与开启者沿用 `curation_disabled`，源开关用 `source_disabled` |
| 集成测试脚本有全局互斥锁；数据目录为空的装配 | 执行计划写明两条线的集成测试不能同时跑；数据目录为空时不缓存 |

记录在案的风险：外部对应不设外键（艺人合并靠重定向，子任务 C 反查时解析）；有结果的缓存 30 天内对话读不到新编辑；
封面清单在子任务 B2 之前仍不限速。
