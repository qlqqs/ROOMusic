# 外部数据源与自动整理：执行计划

父任务不实施代码。本文件给出子任务的顺序、依赖、里程碑与各自的验证要点；每个子任务创建后单独规划
（自己的 `prd.md`，跨包或有迁移时加 `design.md` 与 `implement.md`），经用户批准后再启动。
按路线图的约定，只为下一个获批的独立交付创建任务。

## 各子任务的范围要点与验证要点

子任务规划时以此为起点；确切范围、接口与测试名由子任务自己的文档给出。

### X0 裁决与文档

- 范围：`design.md` 第十节列出的 ADR、架构原则与产品合同里属于“决定”的部分；路线图加入本阶段并补记未记录的已交付项。
  各合同文档的细节随对应子任务更新，不在 X0 里预写。
- 验证：Markdown 链接、ADR 状态与决定索引一致；不跑业务测试。

### A 自动写入的地基

- 范围：发行级字段的自动层与三层有效值；操作记录的来源取值与批次；自动层的撤销规则；按批与按来源撤销；
  “不再提出”的标记；自动整理的实例级设置（总开关、开启者）与停止条件；操作记录按来源与批次筛选。
  本子任务没有任何自动写入的调用方，用测试里的调用验证。
- 验证：隔离 PostgreSQL 上的集成测试，覆盖三层优先顺序、重扫后保持、人工修改之后仍可撤销自动层、
  批量撤销的部分成功、撤销后的标记、开启者被停用后拒绝写入；没有自动层数据时现有接口样本逐项不变。
- 关键逻辑（权限、并发、迁移）做变异检查。

### B1 外部源接口与 MusicBrainz

- 范围：能力接口与源的声明；出站客户端迁到平台层；MusicBrainz 适配器（专用查询、缓存、重试、限速共用）；
  管家的两个音乐资料工具改走适配器；外部对应的存储；扫描解析并落库标签里的 MusicBrainz 各类 ID、ISRC、AcoustID；
  源的实例级开关。
- 规划时先核实：由曲目时长推出光盘目录查询 MusicBrainz 是否可行；MusicBrainz 各查询接口当前的用法与限制。
- 验证：受控的本地服务代替 MusicBrainz；限速、缓存、重试、关闭后不发请求；各格式标签的解析用例；
  管家工具的输出样本不变；包依赖规则测试覆盖新包。

### B2 外部封面与歌词

- 从 B1 接过来的：管家包里的封面清单读取迁到封面源，并接入与 MusicBrainz 共用的限速器（现在不限速）。
- 范围：Cover Art Archive 的图片下载与校验（沿用现有封面的校验与内容寻址存储）、LRCLIB 适配器；
  外部封面与外部歌词的存储；读取时本地优先、外部补空缺；扫描不清除外部封面与外部歌词。
- 验证：受控服务；图片大小与格式上限、重定向目标、下载失败；本地封面出现后改用本地的；重扫后保持。

### C 程序自动整理

- 范围：匹配状态与后台循环；匹配依据的顺序与“把握足够”的规则；补空缺与取封面、歌词；强证据下的专辑归组；
  待定项的生成；批次的切分与统计；存量曲库进队列、暂停与进度。
- 从 B1 接过来的：把建立外部对应做成受治理的操作（记录、撤销、不再提出）。B1 只建了存储与事务内的读写函数；
  闸门 `curation.Sources` 的第一个生产调用方也在这里。按外部 ID 反查艺人时要解析合并产生的重定向。
- 验证：合成曲库覆盖 U7 的各种形态；每条把握规则有正例与反例（相反证据必须降为拿不准）；
  扫描进行时让路；规则版本或输入变化才重新处理；总开关与各源开关。
- “把握足够”的规则做变异检查。

### E1 整理记录与设置界面（第一版）

- 范围：设置里的自动整理一组（总开关、各源开关、进度与暂停）；整理记录页（批次列表、每批的改动、来源与依据、
  单条与按批、按来源撤销）；详情页上被自动补全的字段可辨认；首次扫描完成后的一次性提示。
- 先出原型给用户确认布局，再实现。
- 验证：Vitest 页面级测试、Playwright 冒烟（桌面与 390 宽）、真实服务用例一条；界面改动截图复核。

### B3 AcoustID 与声学指纹

- 范围：生产镜像与开发环境增加 Chromaprint；指纹计算的后台任务（照音频分析的形状，结果按内容指纹缓存）；
  AcoustID 适配器与密钥设置；接入 C 的匹配依据。
- 规划时先核实：Alpine 的 `chromaprint` 包是否带命令行工具；AcoustID 当前的限速与使用条款。
- 验证：受控服务；没有 Chromaprint 或没填密钥时源显示未启用且其余功能正常；指纹只在音频内容变化后重算；
  部署改动验证 Compose 配置与容器启动流程。

### D 模型后台判断

- 范围：由调度启动的管家运行与“自动整理”类型的会话；停止条件检查；自动整理的运行里字段类写工具落到自动层；
  审查策略第 2 版与证据里的外部对应；待定项的状态流转与例外；每日用量上限与用量统计；整理用的模型设置；
  审查不可用时的有限重试。
- 验证：用受控的模型服务（现有管家测试的做法）；审查通过、转人工、没通过、不可用四条路径；
  每日上限的达到与次日恢复；开启者被停用、清除密钥、关开关后的停止；对话里的 `steward` 模式行为除证据外不变；
  权限与审批矩阵做变异检查。

### E2 例外与用量界面

- 范围：例外列表与采纳、不采纳；当天用量、上限设置、排队项数；自动整理会话的入口。
- 验证：同 E1。

### I 曲目级字段修正

- 范围：曲目标题与曲目艺人的人工修正层、自动层与有效值；撤销；所有读取处改读有效值；界面上的编辑入口；
  管家的写工具与审查证据；接入 C 与 D。
- 验证：没有修正时现有接口样本逐项不变；署名事实随曲目艺人修正更新；搜索、队列、歌词匹配读到有效值。

### G 艺人操作可撤销

- 范围：合并与改名的撤销（按记录的前态恢复）；忽略候选的撤销；登记审查证据；接入 C（同一外部艺人自动合并）与 D。
- 验证：合并后撤销回到操作前原样的逐项断言（名字绑定、作用域归属、链式重定向、收藏解析）；
  合并之后有新的人工修改时拒绝撤销。

### H 发行的合并与拆分

- 范围：先调研与失败用例清单，再定方案；成员归属意图、重扫保持、修正与核对的去向、撤销；界面入口；接入 D。
- 验证：重扫、增删文件、改名移动之后合并与拆分保持；撤销回到操作前原样；与认领、归组、默认版本的相互作用。

## 派工与验证的约定

- 后端实现与测试按全局约定交给 Codex 子代理，实现与测试由不同的子代理执行；前端由主代理实现。
- 每个子任务的验证命令只覆盖本次改动涉及的包与用例；复用已有结果，不重复跑没改动的部分。
- 外部服务在自动化测试里一律用受控的本地服务，不请求真实服务；真实服务只在收尾的试用里使用。
- 集成测试使用隔离的 PostgreSQL 与合成数据，不读取现有实例。

## 回退点

- 每个子任务合入后，没有开启自动整理的实例行为不变，可以在任一子任务之后停下。
- 里程碑一之后停下：有程序自动补全，没有模型兜底。
- 关掉总开关即停止全部后台活动；已写入的自动层可以按来源整体撤销。
