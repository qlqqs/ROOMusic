# 整理链重构：本地优先、模型兜底、不等人处理

状态：规划中（父任务）。本文件记录需求、决定、子任务划分与跨子任务验收；总体技术设计见 `design.md`，
子任务顺序见 `implement.md`。父任务本身没有实现工作，不启动；每个子任务单独规划、实施、验收和归档。

调研在 `research/`：

- `research/current-chain.md`：现在的整理链，带代码位置。
- `research/external-services.md`：MusicBrainz 限流与接口能力、实测结果、Roon 的做法、用户提供的设计稿的取舍。
- `research/review-2026-11-25.md`：对本规划的独立审查，25 条发现与处理结果。

## 目标

用户打开自动整理后不需要手动整理，也不需要确认任何东西：本地标签能定的由程序即时定，
外部源在后台按预算补，程序定不下来的由模型兜底。

用户价值：

- 没有待处理事项。任何一环定不下来，结果都是保持本地原样。
- 别名（Jay Chou 与周杰伦）、错别字、乱标签由程序与模型发现并处理。
- 大曲库第一次整理时，最有价值的结果先出现；MusicBrainz 限流只影响后台补全的快慢，不影响使用。
- 模型只用在程序定不了、而它的产出又能被核对的地方。

边界（写进用户文档）：没有标签、没有声纹、文件名与目录名也没有信息的文件，自动整理无能为力，仍需手动整理。
外部库没有收录的专辑保持本地标签不变。

## 背景

现在的链路是“程序逐张查 MusicBrainz → 定不下来的全部交给模型 → 审查拿不准的转人工”。问题（位置见 `research/current-chain.md`）：

| 编号 | 问题 | 位置 |
| --- | --- | --- |
| P1 | 文字搜索的结果程序从不判定，一律交给模型；专辑与散放单曲都是。没有条码、目录号、ISRC，也没配声纹密钥的曲库，几乎每张专辑都进模型 | 第 5、6 节 |
| P2 | 候选为零、候选被撤销过、发行已有别的对应，这些模型无法解决或很难解决的项也交给模型 | 第 5、6 节 |
| P3 | 不看信息是否完整，每张专辑走同一条查询链；按加入时间排，没有按收益排 | 第 1 节 |
| P4 | 所有来源排成一条队：全部发行 → 全部歌词 → 全部艺人。封面清单占用 MusicBrainz 的限速额度 | 第 1、3 节 |
| P5 | 被限流时只按单个请求地址暂停，其余请求继续发出 | 第 3 节 |
| P6 | 模型每批带全套工具，可以自己查 MusicBrainz 与联网；每次写入另起一次审查调用；只有每日上限 | 第 8 节 |
| P7 | 审查拿不准的转成例外，等管理员处理 | 第 8 节 |
| P8 | 艺人对应要求名字相同，不认别名；艺人搜索的写法查不到别名 | 第 4、7 节 |
| P9 | 程序只补空，标签里的错字没有纠正的路径（模型的字段修正工具只在待定项里可用） | 第 7 节 |
| P10 | 无标签文件的占位判断疑似失效，会拿占位值去搜索 | 第 6 节疑点 |
| P11 | 自动值疑似不随标签变化而作废 | 第 10 节疑点 |
| P12 | 规则版本升级会让全库重查 | 第 2 节 |
| P13 | 文件没拷完就开始整理；首次整理期间新入库的专辑要等一轮结束 | 第 1、11 节 |
| P14 | 模型提交外部编号时，后端只核对碟数与曲目数，不比时长与文字；现在靠那次审查把关 | 第 5 节 |

MusicBrainz 每个 IP 平均每秒 1 个请求（`research/external-services.md` 第 1 节）。

| D14 | 推断值与模型整理的值可以用来搜索，但这类输入的结果只接受带时长的结构判定；占位值不进入搜索（审查新增） | 让无标签专辑走得通，同时不拿不可靠的文字做认定 |
| D15 | 发行组级对应可以作为版本归组与艺人对应的依据，不作为发行合并的依据（审查新增） | 归组与艺人对应可撤销且影响小；发行合并改变曲目归属 |

| D17 | 没有佐证的模型发现，在“网络搜索”可用时先交联网兜底去找带引用的佐证，找不到才记为未采用的建议（按 U10 新增） | D2 要求佐证；多花一次联网调用换来能写入的依据 |

## 原则

在 ADR 0006 第 3 节的基础上修订第 1、2 条，其余不变：

1. **结局只有三种**：自动写入（可撤销）、保持本地原样、稍后自动重试。没有“等人处理”这个去向。
2. **本地能定的不联网，程序能定的不用模型，模型只做可核对的事**。程序定不了、模型可能解决的，都交给模型；不以省 token 为由放弃（U10）。
3. **核对代替确认**：模型的产出写入前由后端核对，依据是结构、外部源、库内写法或带引用的网页；核对不了的经独立审查，审查不通过即结束。
4. 安全靠事后可撤；人工修正永远优先；音乐文件只读；能力由宿主分配（不变）。
5. **中断安全**：每条队列按状态取下一项；做完一项存一项；“来源不可用”与“查无结果”分开记。
6. **错了要看得见**：每次自动写入记录核对方式，整理记录可以按核对方式筛选并整批撤销。

## 需求

| 编号 | 需求 | 对应 |
| --- | --- | --- |
| R1 | 真实性标记：发行与曲目的每个字段值，在整理环节能一致地读出它是标签给的、推断的还是占位的。占位值不进入外部搜索；交给模型的证据带这个标记 | P10 |
| R2 | 本地分类：每张发行有一个分类——带外部编号、有缺口、本地完整、信息不足。分类决定排队的先后；信息不足指标题与艺人都只有占位值且没有任何标识，这类只在声纹可用时识别。分类的数量在界面可见 | P3 |
| R3 | 队列：每条队列每次按状态与优先级取下一项，不记翻页位置。优先级：用户手动触发的 → 新入库的 → 带外部编号、条码、ISRC 的 → 有缺口的（缺口大的在前）→ 本地完整的（艺人尚无外部对应的在前）。扫描观测到仍在变化的专辑不进入整理（D7） | P3、P13 |
| R4 | 多来源并行：MusicBrainz、封面、歌词、艺人资料、声纹各自一条队列，同时进行。封面清单不占 MusicBrainz 的限速额度。某个来源被限流或不可用时只停这一条队列，等待时间逐步延长，其它队列继续 | P4、P5 |
| R5 | 专辑的程序匹配：条码、目录号、标题加艺人合并成一次搜索；搜索结果先按曲目数与碟结构在本地筛选，再按需读取完整曲目；碟片 ID 查询一次带回曲目。判定分级见 `design.md` 第 3 节，要点：发行组唯一可以直接认定到发行组一级，但只在输入是真实值、结果没有被截断、不是合辑或古典、曲目多于 4 首时适用；其余用曲目数与时长判定；同一发行组内多个版本都通过时不算歧义。搜索优先使用巡检给出的规范名 | P1 |
| R6 | 艺人对应认别名：专辑已对上时，本地署名与外部署名人数相同、位置对应，名字相同或是外部登记的别名，即建立对应。艺人搜索改用能查到别名的写法。名字对不上的交模型判断是否同一身份；只有署名人数不同、或属于合辑与古典里角色错位的不交 | P8 |
| R7 | 终止状态与零候选（D13）：候选都被撤销过或发行已有别的对应的，标为无可用候选，不产生模型调用。候选为零的先由程序放宽重试，再查艺人是否在外部库；艺人在外部库的进识别第二档，不在的直接进联网兜底；各档都没有结果、或没有配置模型的，标为未收录。未收录的按 D6 重查 | P2 |
| R8 | 模型巡检：扫描稳定后，模型查看新出现的艺人名与各艺人的专辑名，给出规范身份与问题清单（同一身份的不同名字、错字、同一专辑的不同写法）。只处理新出现或变化的名字；结果持久化，带模型与提示词版本；提示词限定只报告身份与明确的错字，不翻译标题，不统一风格。开工前先用带标注的别名集验证可行性 | U4 |
| R9 | 核对与写入：巡检与兜底的产出按 D2 核对后写入，每次写入记录核对方式。无佐证的按 D17 先联网求证，仍无佐证的记为未采用的建议。合并艺人另有硬条件：两个名字从未在同一首曲目上并列署名 | U1、U4 |
| R10 | 纠正：纠正已有的真实值与补空分开。条件是身份已由结构确认、外部源或库内给出不同的值、判断为错字而不是写法或译名差异。规范化后相同的不改。写在自动层，原值可见，可撤销 | P9 |
| R11 | 识别兜底按 D11 分三档，写入规则按 D4。第一档：候选的完整曲目由程序取好写进首条消息，同类型的项打包，不带工具，输出是选定某个候选或升级。第二档：第一档升级的项与符合 R7 的零候选项，按艺人打包，模型带查询 MusicBrainz 的工具，可提交任何编号；每项上限按 D16。第三档是联网兜底（R13） | P6、P14 |
| R12 | 不等人处理：审查拿不准或不通过的项不写入并结束；例外改为“未采用的建议”，可查看、可手动采纳，界面不显示待办数量；已有的待处理例外迁移过去 | P7 |
| R13 | 联网兜底：开放库里没有的艺人与专辑，联网找身份、图片、简介，带引用；按艺人在库专辑数排先后；单独的每日 token 上限；每项上限按 D16 | P6 |
| R14 | 自动层规则：自动层内部固定先后——程序依据外部源写的 → 模型依据外部源写的 → 模型依据库内或网页写的 → 模型从本地文字整理的，低的不替换高的。自动值记录它依据的扫描值，扫描值变化后作废并重新判断 | P11 |
| R15 | 合并后的艺人显示名按 D5 | U4 |
| R16 | 中断与恢复：做完一项存一项，重启、暂停、被扫描打断后不重复写入、不丢结果；来源不可用不计失败次数；token 上限在项与项之间检查；模型任务按项提交；更换模型不重做巡检；根目录暂时不可用时不清除整理结果 | U7 |
| R17 | 规则版本拆分：本地规则、外部匹配规则、巡检提示词各自计版本。本地规则升级不发外部请求；外部规则升级先用已保存的候选与缓存重新判定，只对结论会变的专辑重新请求；巡检提示词升级默认不重做全库。证据摘要只包含识别用到的字段。这一条在任何改变判定结果的子任务之前完成 | P12 |

## 成本说明

- 程序的外部请求与曲库规模成正比，这一点改不掉：每张专辑至少 1 个识别请求，每个新艺人至多 1 个艺人读取。改的是先后与并行，以及不再有多余的请求。
- 模型用量由三部分组成：巡检（与新名字的数量成正比，一次性）、识别兜底（与“程序定不下来且有出路”的项数成正比）、联网兜底（与开放库没有的艺人数成正比，有单独上限）。
- 模型用量不是优化目标（U10）。外部库没有收录的专辑多的曲库，模型用量会与未收录的数量成正比：艺人在外部库的进第二档，不在的进联网兜底。花费由管理员设的每日上限控制，用完次日继续。
- 具体数字没有实测，审查给出的估算见 `research/review-2026-11-25.md`；以子任务 M 的度量为准。

## 跨子任务验收

用合成曲库验收；外部源与模型在自动化测试里用受控的本地服务代替。“队列排空”指所有队列都没有可处理的项。

- [ ] V1 标题与艺人是真实值、曲目多于 4 首、不是合辑或古典的专辑（没有条码、目录号、ISRC），搜索结果未截断且同属一个发行组：不配置模型也由程序对上，只用 1 个识别请求；之后能取到封面，并与同一发行组的其它本地版本归为一组。
- [ ] V2 由程序定案的专辑：发行组级 1 个识别请求，版本级不超过 2 个，每个新艺人另加至多 1 个艺人读取；封面清单不经过 MusicBrainz 的限速器。
- [ ] V3 占位值（“未知艺术家”“未知专辑”）不进入搜索条件；输入含推断值或模型整理值的搜索，只有曲目数相等且时长吻合才认定。
- [ ] V4 无可用候选的项不产生模型调用。候选为零的项：程序先放宽重试；仍为零且艺人不在外部库的，不进第二档，联网可用时进联网兜底；没有配置模型的标为未收录。
- [ ] V5 队列排空后没有等人处理的事项：审查拿不准或不通过的项没有写入且已结束，界面没有待办数量；已有的待处理例外出现在“未采用的建议”里。
- [ ] V6 库里同时有“Jay Chou”与“周杰伦”，两边的专辑都能对上外部源：不经过模型合并为一个艺人，两个名字都能搜到，显示名符合 D5；撤销后恢复为两个，之后不再自动合并。
- [ ] V7 专辑名有错字、外部源有这张专辑：整理后显示正确的名字，原值可见，可撤销。写法差异（繁简、大小写、标点）不改。外部源本身就是特殊写法的不改。
- [ ] V8 没有佐证的模型判断不写入，出现在“未采用的建议”里：凭记忆给出的事实类字段、没有外部库内或网页佐证的艺人合并与名字纠正。没有结构或外部佐证的发行合并不发生。
- [ ] V9 整理进行中重启服务：重启后不重复写入、不丢结果，已经取回的外部响应不重新请求。MusicBrainz 被限流时歌词与艺人资料的队列继续推进。
- [ ] V10 首次整理未完成时加入新专辑：新专辑在下一次取项时排到存量之前。拷贝过程中被扫到的专辑，在它不再变化之前不进入整理。
- [ ] V11 自动值写入后，文件标签里的对应字段改了：重新扫描后显示新的标签值，旧的自动值作废。
- [ ] V12 模型用量：回归曲库里标注为“程序可定”的项，进入模型的数量为 0；没有新名字的再次扫描，巡检 token 为 0；各档每项的用量不超过 D16 的上限。
- [ ] V13 既有验收不回退：人工修正优先、按批与按来源撤销、撤销后不再应用、文件只读、总开关关闭时不发外部请求与模型调用（沿用归档任务的 V1、V3–V5、V9、V11 对应的测试）。
- [ ] V14 真实环境试用一轮：用真实专辑的标签与时长制作的合成曲库、真实的 MusicBrainz 与一个真实模型端点，跑到队列排空，记录请求数、耗时、token、完成比例、各档解决的项数、错误数，与 M 的基线对比。
- [ ] V15 候选里没有正确答案的专辑（例如要用原文标题才搜得到）：模型在第二档查到，通过完整结构核对后写入。模型提交曲目数相同但时长不符的编号：不直接写入，经独立审查；审查不通过即结束。第二档在识别队列里高于“本地完整”的项排空之前不启动。
- [ ] V16 没有标签、文件名形如“01 - 艺人 - 曲名”的专辑：由扫描解析出艺人与曲名，不调用模型做本地整理；据此搜索并经时长核对后补全。扫描解析不了、但文件名里有信息的专辑：模型整理出的值里没有本地文字以外的内容。
- [ ] V17 正确率：回归曲库的反例集里错连、错并、错改的数量为 0。反例至少包括：同名的不同专辑、外部库未收录但有近似候选、曲目数相同的不同合辑、结构相符的错误编号、不该合并的两个艺人名、搜索结果被截断的常见标题。
- [ ] V18 散放单曲（标题与艺人是真实值）：时长吻合且唯一的由程序建立录音对应；多个候选署名同一艺人的只建立艺人对应；都不进模型。

## 不在范围内

- 按艺人取作品列表的补救路径（专辑按规范名仍搜不到时用），留作后续。
- 自建 MusicBrainz 镜像的地址与限速设置。
- 全库曲名逐首巡检（D9）。
- 新增外部数据源。
- 写回文件标签、移动或改名文件。
- 曲序与碟号的修正。
- 同目录归组改用曲号连续性（扫描归组的改动，另行评估）。
- 手动“识别专辑”向导的新界面：现有的手动修正与指定条目保留，本任务不新增。
- 一个本地艺人实际对应两个不同的外部艺人（同名的不同人）时把它拆开：由子任务 D 核实现状后记为已知局限。
