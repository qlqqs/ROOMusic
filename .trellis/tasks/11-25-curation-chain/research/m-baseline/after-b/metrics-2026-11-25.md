## 度量驱动与可比性

- 每个样本仍按原顺序写入同一个模式的独立库，沿用前面样本的对应和来源缓存。首扫后将待确认的观测时间前移 60 秒，再走管理员的普通增量扫描入口。此处只推进整理稳定门槛所用的数据库时间，不修改标签、候选、上游计数或打分。
- 仍在程序每轮处理完后才允许受控模型返回，再等待模型排空和数据库检查点稳定。新增检查五队列都没有可领项或在跑的项。所有由本次增量触发的出站仍归当前样本。
- 样本、模型脚本、上游场景、AcoustID 关闭状态和所有记分逻辑沿用 F。双扫增加了本地扫描工作，测试墙钟用时不能直接当作与 F 的吞吐比较。

## 度量命令与结果

两次均用 `ROOMUSIC_TEST_RUN='^TestPostgreSQLCurationMetrics$'`，用独立 Compose 项目和不同的 JSON 输出路径。

```bash
ROOMUSIC_TEST_COMPOSE_PROJECT=roomusic-compose-test-b-oracle \
ROOMUSIC_TEST_RUN='^TestPostgreSQLCurationMetrics$' \
ROOMUSIC_CURATION_METRICS_MODEL=oracle \
ROOMUSIC_CURATION_METRICS_OUT="$PWD/temp/curation-b-oracle/metrics-oracle.json" \
sg docker -c 'mise exec -- ./scripts/test-integration.sh'

ROOMUSIC_TEST_COMPOSE_PROJECT=roomusic-compose-test-b-first-candidate \
ROOMUSIC_TEST_RUN='^TestPostgreSQLCurationMetrics$' \
ROOMUSIC_CURATION_METRICS_MODEL=first_candidate \
ROOMUSIC_CURATION_METRICS_OUT="$PWD/temp/curation-b-first-candidate/metrics-first-candidate.json" \
sg docker -c 'mise exec -- ./scripts/test-integration.sh'
```

Oracle 通过，用时 418.10 秒。First candidate 通过，用时 421.80 秒。两份输出位于父任务的 `research/m-baseline/after-b/`。
