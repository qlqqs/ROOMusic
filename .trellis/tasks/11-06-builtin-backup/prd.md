# 备份内置到应用

父任务：[部署体验改进](../11-06-deploy-ux/prd.md)（决定 D1、D2、D7）。现状依据：[后端调研](../11-06-deploy-ux/research/backend-facts.md) §3、§8、§9，
[前端调研](../11-06-deploy-ux/research/frontend-facts.md)。

## 目标

部署时不再需要单独的 backup 服务和 tools 镜像：app 自己按时备份 PostgreSQL，管理员能在页面上看到备份是否正常、立即备份、下载备份；
升级或降级迁移前 app 自动先备份一次。

## 需求

- **R1 镜像带 PG 18 客户端**：app 镜像里有与数据库主版本一致的 `pg_dump`、`pg_restore`、`pg_isready`（现在的 `postgresql17-client` 导不了 PG 18）。
  CI 继续保证数据库镜像与客户端主版本一致。
- **R2 定时备份**：沿用 `deploy/production/backup.sh` 的语义——每天在 `ROOMUSIC_BACKUP_HOUR`（默认 3）点后备份一次，
  按 `ROOMUSIC_TIMEZONE`（默认 `Asia/Shanghai`）计时；启动时 24 小时内没有成功备份就立即补一次；失败一小时后重试；
  每次成功后删除超过 `ROOMUSIC_BACKUP_KEEP_DAYS`（默认 14）天的备份，失败时不清理。
- **R3 写入安全**：先写隐藏的临时文件，用 `pg_restore --list` 校验通过后再原子发布为 `.dump`，不覆盖已有文件；失败不留下看起来完整的文件；
  备份文件权限 600。日志只记事件、阶段、退出码、文件名与大小，不含连接串、密码或 pg_dump 原始错误。
- **R4 四种来源**：定时、手动、迁移前、恢复前。文件名能区分来源，迁移前备份的文件名带上迁移前的版本号，降级被拒时日志能直接指出该用哪份；现有 `/home/qlqq/roomusic-backups` 中的 `roomusic-YYYYmmdd-HHMMSS.dump`
  与 `-manual.dump` 必须被识别并列出、计入保留清理。
- **R5 迁移前备份**：库里已有业务表、且这次启动要执行升级或降级迁移时，先备份再迁移；备份失败就不迁移，app 不进入就绪，
  日志说明原因。全新空库不备份。降级回退本身由 [versioned-release](../11-06-versioned-release/prd.md) 实现，本任务只提供被调用的备份能力。
- **R5a 开发与测试**：本机开发和集成测试经与生产相同版本的 docker 包装 pg 工具运行（`ROOMUSIC_PG_BIN_DIR`），开发库遇到新迁移也照常先备份；包装不创建新的 Docker 网络。
- **R6 并发**：定时、手动、迁移前备份互不重叠；手动备份进行中再点一次不会生成两份。
- **R7 管理接口**（仅管理员；写请求同源校验）：查询备份状态（最近一次成功时间、最近一次失败的时间与阶段、下次计划时间、是否正在备份）与备份列表
  （时间、大小、来源）；触发立即备份；下载单个备份（附件形式，流式传输，文件名不可被用来访问备份目录以外的文件）。
- **R8 系统 › 备份页**：管理员导航新增“系统”组，“备份”页显示当前版本号（版本号来源由 versioned-release 提供，本任务先接入字段，开发构建显示“开发版”）、
  最近一次成功备份时间、立即备份按钮、备份列表与下载。最近一次备份失败时用一句日常话提示。界面文案遵守 `~/.claude/CLAUDE.md`
  “前端界面文案”三条：不写防御性说明、不写多余说明、必要说明简短人性化。
- **R9 恢复命令**：`roomusic restore <备份文件>` 在 app 停止时运行（如 `docker compose run --rm app restore /backups/<文件>`）：
  先显示备份的时间、大小、其中的迁移版本与当前库的迁移版本，要求输入确认词；再对当前库做一次安全备份，失败不继续；
  然后重建数据库并恢复所选文件；失败时打印用安全备份恢复的完整命令。有其他 app 连接时拒绝运行并提示先停 app。
  另提供 `roomusic backup` 命令立即备份一次，供脚本使用。
- **R10 移除旧组件**：生产 compose 去掉 `backup`、`restore-check` 服务与 tools 镜像；删除 `deploy/production/backup.sh`、`restore.sh`
  以及 `scripts/production.sh` 中依赖它们的部分；更新部署说明与 CI 中的相关检查。为保证每个提交的部署文件都完整可用，
  删除与改写统一在 [config-trim](../11-06-config-trim/prd.md) 的 compose 改写提交里执行，A9 也在那时核对。
- **R11 备份目录**：应用配置 `ROOMUSIC_BACKUP_DIR`，容器内默认 `/backups`；开发默认在数据目录下。目录不存在或不可写时，
  备份失败并在页面和日志里显示，但不影响 app 正常使用。

## 验收标准

- [x] A1 app 镜像内 `pg_dump --version` 主版本与数据库一致；生产 compose 只有 app 与 postgres 两个常驻服务。
- [x] A2 定时逻辑的单元测试覆盖：到点备份、当天已备份不重复、启动补备份、失败一小时后重试、成功后按天数清理、失败不清理、时区。
- [x] A3 集成测试（PG 18）：备份成功产出可被 `pg_restore --list` 读取的文件；人为让 pg_dump 失败时不留下 `.dump`；并发触发只产出一份。
- [x] A4 旧命名的 `.dump` 文件出现在列表中且来源正确。
- [x] A5 迁移前备份：有待执行迁移时先产出“迁移前”备份再迁移；备份失败时迁移不执行、`/readyz` 返回 503；空库不备份。
- [x] A6 接口：非管理员 403、未登录 401、跨源写 403；下载返回附件头与正确字节；构造的路径穿越文件名返回 404。
- [x] A7 页面：Vitest 覆盖状态、空列表、正在备份、失败提示、下载链接；mock Playwright 冒烟 1440 与 375 宽度截图经主会话审阅无布局问题、无多余说明。
- [x] A8 恢复：在隔离演练项目中恢复一份备份后行数一致；有其他数据库连接（正常运行的 app）时命令拒绝；恢复失败时打印的命令可直接执行。
  （降级模式的 app 已关闭数据库连接，恢复不受影响；日志里的恢复命令包含先停 app 与重新启动，见父任务实施记录 2026-11-06 P4。）
- [x] A9 旧 `backup.sh` / `restore.sh` 与 tools 镜像相关文件、CI 检查和文档引用都已清理，`git grep` 无残留引用。
