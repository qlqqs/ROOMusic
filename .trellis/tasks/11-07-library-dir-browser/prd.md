# 音乐目录浏览器

## 目标

添加扫描目录时，在界面上逐级点选文件夹，不用手动输入路径。

对应用户反馈 8（见 [父任务](../11-07-ui-minimal-and-catalog-fixes/prd.md)）。

## 依赖

后端可以和 [ui-minimal](../11-07-ui-minimal/prd.md) 并行；前端在 ui-minimal 之后实施。接口合同和裁决见 [design.md](./design.md)，执行步骤见 [implement.md](./implement.md)。

## 已确认事实

- **新增目录表单**在 `frontend/src/features/library/components/add-root-form.tsx`：一个“目录路径”文本框（说明“服务器上的绝对路径，例如 /music/classical”），加“添加”按钮。
- **后端校验** `backend/internal/library/roots.go` 的 `ValidatePath`：
  - 要求绝对路径，不跟随目录符号链接；
  - 必须是真实目录，并且在 `ROOMUSIC_ALLOWED_LIBRARY_ROOTS` 之内；
  - 错误信息不暴露允许目录的位置。
- **允许目录**：生产 compose 设为 `/music`（`compose.prod.yaml:20`）。
- **接口位置**：目录和扫描的管理接口在 `backend/internal/library/httpapi`，只给管理员。

## 需求

- R1 **自动展开**：点击路径框时，下方自动展开目录浏览器。按 Esc、点外面或选好之后收起。
- R2 **起点**：
  - 只有一个允许目录时，直接显示它里面的内容；
  - 有多个时，先列出这几个允许目录。
- R3 **浏览**：
  - 列出当前文件夹的子文件夹，按名字排序；不列文件、隐藏文件夹和符号链接；
  - 点文件夹名进入下一级；
  - 顶部显示当前路径，可以返回上一级，但不能越过允许目录；
  - 已经添加为扫描目录的文件夹标“已添加”，仍然可以选；
  - 一个子文件夹都没有时，显示一句简短的话。
- R4 **选择**：
  - 每一行右侧有“选择”，点它把这个文件夹的路径填进路径框；
  - 当前所在的文件夹本身也能选；
  - 选好以后照常点“添加”。
- R5 **手动输入**照样可用，校验和现在一样。
- R6 **接口**：
  - 新接口只给管理员，只列允许目录之内的子文件夹；
  - 越界、不存在、不是目录、是符号链接时返回错误；
  - 管理员能看到允许目录本身（这一点与 `ValidatePath` 的“错误不暴露允许目录”不同，只对管理员开放）。
- R7 **文件夹很多**（上千个）时，界面可以滚动；最多列 2000 个，超过时提示“文件夹太多，没有全部列出，可以直接输入路径。”
- R8 **路径框**只留标签“目录路径”，删掉原来的说明句。

## 约束

- 界面文案不写防御性说明。
- 测试只补改动直接影响的行为：接口的范围限制、鉴权、符号链接、前端的浏览和选择；只跑受影响的包和用例。

## 验收

- [ ] A1 从允许目录开始逐级进入，选择一个子文件夹，添加成功。
- [ ] A2 越界路径（如 `/etc`、带 `..` 的路径）被接口拒绝；普通成员调用返回 403。
- [ ] A3 符号链接目录不出现在列表里，和 `ValidatePath` 一致。
- [ ] A4 受影响的 Go 测试和前端测试通过；截图里浏览器在 1440 和 375 宽度下都可用。

## 不做

- 在浏览器里新建、重命名或删除文件夹。
- 显示文件，或预览文件夹里的音乐。
