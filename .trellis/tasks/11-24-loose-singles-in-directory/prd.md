# 同一目录里的零散单曲不归成一张专辑

## 背景

V12 真实环境试用（`.trellis/tasks/archive/2026-11/11-22-auto-curation-sources/v12-trial.md` 问题 3）：
`Singles/` 里 4 首、`Downloads/` 里 2 首单曲都没有专辑标签，艺人各不相同，扫描后各自归成一个以目录名为标题的发行。
自动整理按专辑去匹配，对不上任何发行，模型也只能搁置；AcoustID 单曲模式的判定（`ambiguous`、`too_many`）因此走不到。
流媒体下载的单曲常这样存放。

现状：没有专辑标签的观察，整理范围按目录划分（`backend/internal/catalog/ingest/scope.go` 的 `OrganizationScope`），
标题退回目录名。

## 目标

同一目录里看得出是零散单曲的文件，各自成为单曲发行；自动整理对它们走单曲模式（ISRC、声学指纹）。

## 要求

- 先调研再定规则：怎样区分“零散单曲”和“没有标签的整张专辑”（例如 V12 的《U87》：没有任何标签、同一艺人、文件名带曲序）。
  可参考的信号：艺人是否一致、曲序或文件名编号、ISRC、有无专辑标签。规则写进 `design.md`，先给 qlqq 确认。
- 拿不准时保持现状（按目录归成一个发行），不为猜测拆分。
- 发行 ID 稳定性按阶段 I 的规则：同样的文件重扫，ID 不变。规则上线后，已存在的“目录名专辑”如何变成单曲（重扫时拆开、ID 怎么分配、已有修正与收藏怎么办）要在设计里写明。
- 根目录下没有专辑标签的散曲现已按路径区分，行为不变。

## 验收标准

- [ ] 合成曲库：一个目录放几首不同艺人、没有专辑标签、带 ISRC 的单曲，扫描后各成一个发行；一个目录放同一艺人、没有标签、按曲序命名的一组文件，仍是一个发行。
- [ ] 自动整理对拆开后的单曲走单曲模式，ISRC 能直接匹配的匹配上。
- [ ] 重扫后发行 ID 不变；既有的接口样本在不涉及零散单曲时逐项不变。
- [ ] 与 `11-24-reopen-shelved-on-new-evidence` 的关系写明：拆分改变发行的输入，已搁置的旧项如何处理。

## 不做

- 物理移动文件或写回标签。
- 用外部源结果反过来决定扫描的归组。
