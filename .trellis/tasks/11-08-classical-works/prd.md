# ⑧ 古典作品与乐章

父任务：[扫描子系统对标](../11-08-scan-reference-port/prd.md)，T 线第 3 项。参考设计 21.4（作品/乐章键）、22.1–22.7、22.9 章；不用作曲家配置表与古典性打分（22.6、22.11，依赖外部数据）。

## 目标

古典专辑在专辑页上按作品分组显示乐章，例如“交响曲第 5 号 c 小调，Op. 67”下面列四个乐章；作品编号（Op.、BWV、K. 等）能被认出来，用于显示和搜索。

## 现状（`B/` = `backend/internal/`）

- 后端、迁移、前端都没有作品、乐章概念；ID3 `TIT1`、`MVNM`、`MVIN`，M4A `©grp`、`©wrk`、`©mvn`，Vorbis `WORK`、`MOVEMENT*` 都不读。
- 专辑页曲目列表（`frontend/src/features/catalog/components/release-media.tsx`）：单碟直接列表，多碟每张一节（`:187-213`）；每行是序号、标题、播放标记、CUE 标签、操作、时长、曲目艺人、署名（`:66-100`）。
- 唱片编号只来自 folder_metadata 与标签（`B/catalog/ingest/folder_metadata.go:53`，`organizer.go:383`）；搜索的 `CatalogNumber` 规范化只用于唱片编号字段（`B/catalog/textnorm/textnorm.go:23-41`）。
- 设计文档没有古典作品或乐章的展示规则（`frontend/DESIGN.md` 的 Classical 是视觉风格名）。

## 需求

- **R1 读取作品与乐章标签**：Vorbis `WORK`、`MOVEMENTNAME`、`MOVEMENT`、`MOVEMENTNUMBER`、`MOVEMENTTOTAL`；ID3 `TIT1`（作品）、`MVNM`、`MVIN`；M4A `©wrk`、`©mvn`、`©mvi`、`©mvc`。按参考设计 21.4 的回退顺序。
- **R2 无标签时从标题拆分**：同一专辑相邻曲目的标题形如 `作品名: I. 乐章名`、`作品名 - 2. 乐章名`时，按参考设计 22.7 的段切分与公共前缀算法拆出作品与乐章；只在多首相邻曲目形成同一作品时拆，单曲不拆（22.12 第 13 条）。拆分结果标 inferred，标签优先。只对流派含古典（Classical、古典及其常见写法）的专辑从标题拆；有作品标签的曲目不受此限制。
- **R3 作品编号**：内置常见编号体系的解析（至少 Op./Opus、WoO、BWV、K./KV、Hob.、D.、RV、HWV），从作品名中认出编号，用于排序规范化与搜索。不引入作曲家数据表。
- **R4 存储**：作品与乐章作为曲目的结构化字段保存（作品名、作品编号、乐章序号、乐章名、来源），重扫替换，不随扫描次数累积。
- **R5 专辑页**：有作品信息的专辑，曲目按作品分组显示：作品名作小标题（右侧显示该作品总时长），下面列乐章行，乐章行只显示乐章名，序号与时长照常；作品名不在每一行重复。没有作品信息的曲目与专辑显示不变。不加单独的作品页面与筛选。
- **R6 搜索**：作品名与作品编号进搜索投影，`BWV 1007`、`op67` 能搜到对应曲目。
- **R7 合同同步**：新增作品与乐章的数据合同，更新 `catalog-rest-contracts.md`、`search-contracts.md`。

## 验收

- 单测：R1 各容器读取；R2 拆分对照表（以参考设计 22.7.9 的演算样例为基础，补中文常见写法）；R3 编号解析与排序规范化；单曲不拆、相邻同名乐章按 22.7.8 处理。
- 前端：古典专辑按作品分组显示，非古典专辑不变，截图复核。
- 真实库只读 smoke：列出被拆分出作品的专辑，逐条确认没有误拆流行专辑。

## 不做

- 作曲家配置（3023 位）、古典性打分、乐器编制推导（22.8）、流派树。

## 已裁决

- 2026-11-08 用户裁决：没有作品标签时，只在古典流派的专辑里从标题拆（R2）。
- 2026-11-08 用户裁决：专辑页用“作品小标题 + 乐章行”，不加作品页面与筛选（R5）。
- 2026-11-08 主会话裁决（设计审阅）：是否从标题拆只看扫描得到的流派，人工修正流派不触发重算；生产库与样本库都没有古典流派，古典正例靠单测覆盖。
- 2026-11-08 主会话裁决（实现验收）：作品编号原文按原样保存，超过 256 字节时触发约束、该候选失败；真实标签不会出现这种长度，不截断、不放宽约束，也不为它写测试。

T 线第 3 项，在 ⑦ 之后。有前后端接口依赖，先由设计 agent 起草接口合同。
