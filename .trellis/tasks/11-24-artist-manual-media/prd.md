# 艺人手动资料与指定对应

父任务 `11-24-artist-web-search`（需求 R1–R9、决定 D1–D6）。现状调研：`../11-24-artist-web-search/research/repo.md`（下文“调研 A–H”）。
技术设计见 `design.md`，执行顺序见 `implement.md`。

## 目标

管理员在艺人页直接补图片、简介，或指定这个艺人对应的 MusicBrainz / Wikidata 条目，让现有的有许可来源接着补；任何来源的资料都能标记“不对”。

## 需求

- M1 上传图片：管理员上传一张图片（JPEG、PNG、WebP，≤16 MiB，沿用现有图片校验），成为这位艺人的图片，来源记为“管理员提供”。再次上传替换。
- M2 编辑简介：管理员写纯文本简介（1–4000 个 Unicode 字符，语言 zh 或 en），来源记为“管理员提供”。
- M3 人工层：管理员提供的图片与简介单独存放，遮住自动层但不删除；读取时人工层优先。合并艺人时随有效身份走（与自动层同一套家族解析）。
- M4 指定对应：管理员粘贴 MusicBrainz 艺人链接或 MBID、Wikidata 链接或 Q 号：
  - 先预览：返回条目的名字、简介短语、MBID 与 Q 号（Wikidata 条目有 P434 时给出 MBID），以及名字是否与本地艺人的任一名字一致；
  - 确认后写入艺人的外部对应（MusicBrainz 和/或 Wikidata），替换已有的同源对应；
  - 写入后自动整理按新对应补有许可的图片与简介（只有 Wikidata 对应时也能走 Commons 与维基百科）。
  - 手动对应不作为自动合并艺人的证据。
- M5 标记不对：一个接口按“当前显示的是哪一层”处理——人工层则清除人工资料；自动层则撤销那条自动写入并写抑制标记（现有撤销语义）。图片与简介分别处理。
- M6 每次写入、替换、清除、指定对应都是一条操作记录，可在整理记录里撤销；撤销恢复之前的状态。
- M7 读取：艺人详情的 `image`、`bio` 的 `source` 增加 `manual`；详情新增 `links`（MusicBrainz 与 Wikidata 的当前对应，可为空）。
- M8 权限：写入接口只有管理员可用（同源检查、幂等键），普通账号 403。

## 验收

- A1 上传、替换、清除图片；写入、清除简介；人工层遮住自动层，清除后自动层重新显示；图片文件引用计数正确（人工与自动共用同一内容键时撤销任一方不误删文件）。
- A2 预览：MusicBrainz 链接、裸 MBID、Wikidata 链接、裸 Q 号四种输入；无效输入 400；条目不存在 404；名字一致标志正确；源开关关闭时返回对应错误。
- A3 指定对应后，下一轮 `artist_media` 用新对应补上资料；只有 Wikidata 对应（无 P434）时走 Commons 与维基百科；替换已有的自动对应后，撤销旧的发行对应操作不会删掉人工写的对应行。
- A4 标记不对：人工层 → 清除；自动层 → 撤销并抑制，下一轮不再写回同一条目。
- A5 撤销：每种操作单条撤销恢复原状；前态已变返回 `revert_conflict`。
- A6 权限、同源、幂等键、请求体限制的错误码与现有艺人治理接口一致。
- A7 迁移往返；接口样本更新。

## 不做

- 前端（由 `11-24-artist-media-ui` 做）。
- 模型与插件相关的写入（由 `11-24-artist-web-search-model` 做）。
- 裁剪图片、多张图片挑选。
