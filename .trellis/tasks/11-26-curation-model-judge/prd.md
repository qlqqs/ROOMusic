# 识别判断与名字核对

父任务：`.trellis/tasks/11-26-curation-chain-review`。每条决定的现状、依据和代码位置见父任务 `prd.md` 的对应段落（下表“出处”一栏）；规则汇总见 `docs/architecture/adr/0009-curation-chain-review.md`。

本任务只实现下面列出的决定，不改其他段的行为。实施中发现某条决定做不到或需要改，先停下报告，由主代理回父任务问用户。

## 目标

按父任务 B2、B3 的决定：程序定不了的专辑，模型一次给出线索，由程序去查；去掉巡检、第二档、联网档和整理链里的审查；名字差异和艺人身份按新规则判断。

## 范围

| 事项 | 出处 | 要做的 |
| --- | --- | --- |
| 识别判断 | B2 表 | 未匹配、有冲突的交模型，只调用一次，不用工具循环。输入：本地信息（标签、注释、文件名、目录名、曲目和时长）、程序找到的候选和详情、程序搜过什么、冲突在哪。回答：可以选一个候选，再按把握从大到小给 0 到 n 组线索，或回答“定不了” |
| 五种线索 | B2“模型能给的线索” | 名字；同名艺人选哪一位；本地内容里的编号（必须能在本地内容、含注释里原样找到）；版本线索；专辑类型。程序怎么用见该表 |
| 程序按线索查 | B2 表 | 先核对选中的候选，再按顺序逐组查，哪一组查到一张、并通过 A2.3 的核对就停；每张最多多发 6 次请求；某一组查出几张都对得上、分不出是哪张，记“有冲突”并停下，不再交模型 |
| 让用户挑 | B2 最后一条 | “有冲突”的列出这几张候选，用户点一下就能定，选中的照样过结构核对。本任务提供接口，界面由主代理做 |
| 定不了 | B2 表 | 保持原样，没有下一档；本地变了、规则升级、90 天重查时，先由程序查 |
| 去掉 | G2、B2、B3.2 | 巡检（含 `PatrolPromptVersion`，`backend/internal/curation/program/worker.go:17-25`）；第二档，即模型自查 MusicBrainz（含 `LookupTierReady`）；联网档；整理链里的审查（含审查不可用的退避，`backend/internal/curation/model/scheduler.go:642-706`）；“未采用的建议”。整理链的模型会话不再挂 MusicBrainz 和网页工具 |
| 升级清理 | B4.2 最后一行 | 清掉巡检项、联网项、“未采用的建议”；已经写进曲库的保留；以前的模型结论保留 |
| 名字差异 | B3 表 | 中日韩文对拉丁字母、只多后缀、差很多的，程序直接保留本地写法；同一种文字只差一两个字的交模型：是错字就改用 MusicBrainz 的写法（自动层，可撤销，人工改过的不动），不是就保留本地写法，不留建议；名字核对不拖专辑；专辑页显示 MusicBrainz 的写法、一键改用（接口由本任务做，界面由主代理做） |
| 艺人是不是同一人 | B3.2 | 程序定不了的交模型：是同一人就建对应或合并两个本地艺人（可撤销，注明“由模型判断”）；不是就记住结论，同一对名字不再问；不审查 |
| 规范 | 文档 | 整理合同里改到的段落；`.trellis/spec/backend/steward-review-contracts.md` 里关于整理链的部分 |

- 管家对话的审查，以及设置里的“审查模型”，不动。
