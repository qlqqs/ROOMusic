# 自动整理 C：程序自动整理

父任务：`.trellis/tasks/11-22-auto-curation-sources`（M7 外部数据源与自动整理）。前置 A（`d079f44c`）、B1（`32c1a8d6`）、B2（`c1daf591`）已合入。
技术设计见 `design.md`，执行计划见 `implement.md`，现状调研见 `research/program-curation-current.md`。

## 目标

打开自动整理之后，不需要任何人工操作：后台按缺口把曲库里的发行与外部源对上；有把握的直接建立外部对应、补空缺字段、
取封面与歌词、在强证据下归组；拿不准的形成待定项留给模型层（子任务 D）。每一项改动都在整理记录里有来源、依据与批次，可以撤销，
撤销过的不再自动应用。

用户价值：里程碑一的核心（父任务 V2）。扫描进来的内容自动补全，人只在偶尔查看整理记录时撤销错的。

## 背景与约束

- 判定原则来自 ADR 0006 第 6、7 节：匹配依据按可靠程度排列、前面的命中就不再用后面的；“把握足够”= 唯一候选 + 至少一项独立佐证 + 没有相反证据；
  宁可多交给模型，不可错判。强证据 = 已保存的外部对应。
- 写入只经 A、B2 已有的受治理写入口（`Writer.Apply`、`ApplyArtwork`、`ApplyLyrics`）与本任务新增的两个入口；外部源只经闸门 `curation.Sources` 取能力。
- B1 交给本任务：建立外部对应做成受治理的操作（记录、撤销、不再提出）；闸门的第一个生产调用方；按外部 ID 反查艺人时解析重定向。
- B2 交给本任务：“外部封面的行在、文件不在”算缺口；下载前先查按外部身份的不再提出标记；LRCLIB 的时长筛选与写法差异的容忍。
- 现状要点（详见调研）：标签里的 MusicBrainz 各类 ID 与 ISRC 在 `track_identifiers`，CUE 的 ISRC 在 `tracks.cue_isrc`；条码与编号在发行上；
  整轨抓取的 CUE 有每轨帧偏移；根目录的零散单曲是 `candidate_kind='loose_unknown'` 的单曲发行；没有逐发行的输入版本可以复用；
  归组执行器可以在进程内带来源与批次调用，但它的撤销不写不再提出标记；“需要关注”的模型不能承载待定项。

## 需求

| 编号 | 需求 |
| --- | --- |
| C-R1 | 后台循环：单线程，扫描进行时让路；总开关关闭、开启者失效或暂停时不发任何外部请求；按缺口处理（没处理过、输入变了、规则版本升级）；进程重启后从持久状态继续 |
| C-R2 | 匹配：专辑形态的发行对 MusicBrainz 发行，零散单曲对 MusicBrainz 录音；依据顺序与每一步的把握规则见 `design.md` 第三节，规则有版本号 |
| C-R3 | 外部对应是受治理的操作：一次匹配是一条记录（发行、它的曲目、必要时它所在的专辑），可以单条、按批、按来源撤销；撤销后同一个对应不再建立，发行重新判定 |
| C-R4 | 补空缺：匹配有把握时，把发行上真正空着的字段（年份、厂牌、编号、条码、专辑艺人，以及占位的标题）补到自动层；有人工修正或已有自动值的字段不动 |
| C-R5 | 封面：发行对上之后，本地没有封面、外部封面没有或文件不在时，从 Cover Art Archive 取主封面；下载前先查外部身份的不再提出标记 |
| C-R6 | 歌词：曲目本地没有歌词、外部歌词也没有时，按曲目标题、艺人、专辑与时长向 LRCLIB 查询；按时长与写法规则筛选，结果唯一才写入。不依赖发行是否对上 |
| C-R7 | 归组：两个发行的外部对应指向同一个外部专辑时，把发行归入已对应到这个外部专辑的本地专辑；撤销后不再自动归入同一个专辑 |
| C-R8 | 待定项：拿不准、没匹配上但有候选的，形成持久的待定项（本地证据、候选、冲突点），状态为等模型；之后判定有把握时自动结束 |
| C-R9 | 批次：程序层的一段连续工作是一批，按数量与时间切分，空批不建；进程重启时收掉上次没关的批 |
| C-R10 | 进度与暂停：管理员能读到后台状态与进度（已处理、已对上、拿不准、没对上、稍后再试、待定项数）；能暂停与继续；重新打开总开关时自动解除暂停 |
| C-R11 | 外部服务不可用、限流、超时一律记为稍后再试并退避，不算一次失败的尝试；某个源的开关关着时跳过与它有关的工作，不留下“已尝试”的状态 |

## 验收标准

- [ ] AC1 总开关关闭、开启者失效、暂停三种情况下，受控外部服务收到的请求数为零；打开后存量曲库全部进入处理，进度接口的数字随之变化（V1）。
- [ ] AC2 合成曲库覆盖 U7 的形态：Picard 打过标签的专辑、只有条码的专辑、只有厂牌与编号的专辑、带 ISRC 的流媒体单曲与专辑、整轨抓取的 CD（CUE）、
  多碟、华语、没有标签的文件。每种形态的预期结果（对上 / 拿不准 / 没对上）用测试固定（V2）。
- [ ] AC3 每一步把握规则有正例与反例：每一种相反证据都让结果降为拿不准，候选不唯一时拿不准；搜索与按时长的模糊目录查询从不直接判定。规则做变异检查。
- [ ] AC4 对上之后：外部对应一条记录；只有真正空着的字段被补上，人工修正过的字段、已有自动值的字段、被标记不再提出的值不动；本地没封面的取到封面；
  有人工修正时显示仍是人工的值（V3）。
- [ ] AC5 撤销外部对应：对应删除（或恢复成被替换的那条），写下不再提出标记，发行重新判定且不再对上同一个外部发行；被更晚的匹配替换过的拒绝撤销。
  按批撤销把这一批的对应、字段、封面、歌词、归组都撤掉（V4、V5）。
- [ ] AC6 归组：两张对上同一外部专辑的发行归到一起；撤销后不再自动归入；没有已保存的对应时不归组；人手动移出或归入过的发行不再自动归组；
  被人工改过的归组撤销被拒绝（V9 的归组部分）。
- [ ] AC7 歌词：时长差超过容差、标题或艺人对不上、纯音乐、多个不同的候选时都不写；写法差异（大小写、全半角、空白、标点）能容忍。
- [ ] AC8 扫描进行时不发外部请求（处理到一半开始扫描，下一次出站即被挡）；规则版本不变、输入不变时重扫后不重复请求；输入变化（标签、曲目、人工修正、不再提出标记的增删）后重新判定。
- [ ] AC9 外部服务返回 503 或超时后记为稍后再试，退避之后重试，尝试次数不增加；关闭某个源后与它有关的工作跳过，再打开后继续。
- [ ] AC10 进程在一个发行处理到一半时重启：不产生重复的记录（幂等键重放），批次被收掉，继续处理；撤销后清除标记再对上时是新的记录，不是回放。
- [ ] AC11 操作记录页能显示“建立外部对应”与它的撤销；归组记录的来源显示为自动整理；接口样本与前端合同测试一致。
- [ ] AC12 迁移 0062 升级与回退往返；没有开启自动整理的实例行为与之前相同，现有接口样本除自动整理设置多出 `paused` 外逐项不变。

## 范围外

- 艺人的外部对应与同一外部艺人的自动合并：随子任务 G（艺人操作可撤销）一起做。按外部 ID 反查艺人与重定向解析也在那时接入，本任务不建艺人对应。
- 曲目标题与曲目艺人的补全：随子任务 I（曲目级修正）。
- 流派、版本说明的补全：MusicBrainz 发行没有可直接对应的值。
- 声学指纹的匹配依据：子任务 B3 接入。
- 待定项的模型处理与状态流转（处理中、已解决之外的状态）、例外：子任务 D；待定项与进度的界面：子任务 E1、E2。
- 一次撤销“这次匹配及它带来的全部改动”的界面入口：E1 用按批或按发行筛选的操作记录实现；本任务后端不做级联撤销。
- 对已有外部对应的发行，新的判定拿不准时删除旧对应：保留旧对应并记入待定项的冲突点，由模型判断。

## 主代理代为决定的事项（按“优先使用和操作舒适”）

用户 2026-11-22 授权“很多都可以自己决定，除非实在无法决定的，再问我”，以下由主代理决定，交付时列给用户：

1. 专辑形态与零散单曲分两种匹配方式；零散单曲只建立曲目到录音的对应，不补发行字段、不取封面（单曲属于很多外部发行，挑一张是猜）。
2. 歌词不依赖发行是否对上：曲目有可信的标题、艺人与时长就按 LRCLIB 的精确查询取，覆盖流媒体单曲。
3. 封面先取对上的外部发行的主封面，没有时退到它所属外部专辑的主封面。
4. 匹配的输入只用人工修正与扫描值，不用自动层：自动层是匹配的产出，不能拿来证明自己。
5. 标题只在扫描给的是占位“未知专辑”时补；专辑艺人在扫描值为空时补；流派与版本说明不补。
6. 时长容差：每首 max(3 秒, 外部时长的 1%)；歌词的时长容差 2 秒（LRCLIB 自己的精确查询容差）。
7. 一次匹配（发行、曲目、专辑的对应）是一条受治理的记录；撤销是整条撤。
8. 增加“暂停”：与总开关分开，暂停只停后台循环，不影响已写入的内容与撤销；重新打开总开关时自动解除暂停。
9. 处理顺序：没处理过的发行按加入曲库的时间从新到旧，用户最近加的先补。
10. 没有任何可用信息（占位标题、未知艺人、没有标识）的发行不建待定项，只记“没对上”：模型也无从判断。
11. 歌词在发行匹配之后另起一轮：整库歌词按 LRCLIB 的限速要几十个小时，不能把专辑的匹配推迟。
12. 人做过的归组优先：最近一次归组是人做的，程序不再动这个发行的归组。
13. CUE 的 `CATALOG`（MCN）是条码，不当编号比较。

## 规划结论的确认方式

路线：子代理审阅（用户 2026-11-22 的常设授权：规划后直接实施，能自己定的自己定）。

审阅者：规划子代理（Plan，2026-11-22）。结论：改完必须改的 8 项后可以实施。主代理全部采纳，并采纳了建议改的 12 项：

| 审阅意见 | 处理 |
| --- | --- |
| M1 幂等键取自摘要，清除标记后会回放已撤销的操作 | 改为代次（design 第四节） |
| M2 归组的强证据读的是单元结束才写的状态 | 改为读 `external_link` 记录的后态（6.2） |
| M3 自动归组会覆盖人做的归组 | 最近一次归组来源是人时不归组，`manual_structure`（4.3、6.2） |
| M4 ISRC 结果被截断、没有曲目数 | 截断即拿不准；曲目数在读取完整发行后核对（3.2） |
| M5 条码一步的佐证同义反复 | 增加第二项佐证与 `title_artist_mismatch`（3.2、3.3） |
| M6 推断曲号与重复曲号下的配对不可靠 | `position_conflict`、`inferred_positions`（3.3） |
| M7 循环会在现有测试里真实出站 | 装配选项，测试夹具默认关掉（7.5） |
| M8 改签名让现有测试编译失败、验证命令不对 | `SetPaused` 新增不改旧签名；允许改归组测试的调用处；修正命令（implement.md） |
| 建议：CUE 的 MCN、缺少的相反证据、事务顺序、不替换已有对应、`OnlyEmpty`、闸门挡暂停与扫描、变化标记含操作记录、键集分页、歌词单独一轮、只算可见发行、空键不相等、证据入口在 `catalog`、标记列表含曲目与专辑、夹具与样本的先后 | 全部并入 |

审阅列为“可以不改”的（命中即定的代价、分轨不重建目录、外部专辑封面可能是别的版本、整条撤销、归组撤销沿用版本号）接受，代价写在 design 第十一节。
