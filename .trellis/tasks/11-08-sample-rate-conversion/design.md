# 技术设计：采样率转换（SRC）

需求见 [prd.md](./prd.md)；父任务 [音频算法对标](../11-08-audio-dsp-reference-port/design.md)（下称“父设计”）。参考稿章节：§6.2、§6.1（第 ② 步）、附录 A（处理量子）。
本文只记章节号、我们自己整理的规格参数和公开方法；参考核系数不进仓库、不在文档里出现。

## 0. 结论

- 纯包 `backend/internal/dsp/src`：**核目录 + 多相有理数重采样器 + 规划器**（策略、兼容性回退、分级）。重采样器按父设计 §3.1 实现 `Process`/`Latency`/`Reset`，延迟补偿与流尾冲刷由 `chain.Wrap` 负责（父设计 §3.2）。FFT 用 `dsp/internal/fft`（父设计 §1）。
- **smooth、precise 运行时生成**（Kaiser 窗 sinc，闭式公式）；**2s 离线生成后入库**（极小化最大误差的线性规划，生成器 `scripts/dspgen/src2s.py`）。最小相位核一律在运行时由对应的线性相位核做倒谱变换得到。
- **验收按“不劣于参考”**（§8.2）：每组核的阻带最差衰减 ≥ 参考 − 0.5 dB，通带偏差 ≤ 参考，核长与相位类型相同，线性相位群延迟精确相等，最小相位低频群延迟相差 ≤ 0.5 个输入样本。2026-11-08 用 Python 原型按最终参数重跑全部 76 组，全部满足（§8.3）。
- **2s 只用在本级输入的有用内容 ≤ 0.113 × 本级奈奎斯特的地方**：DSD256/512 解出后降到 352.8 kHz 的前一级，以及以后 PCM→DSD 升频的第二级。普通 PCM 转换一律单级（§4.4）。
- 第二批合入后，第一批由 ffmpeg 临时做的兼容性转换（解码 `aresample`、编码前的 48 kHz）全部换成链上 ② 节点（§6.3）。
- 147/20、147/40、147/80 的 smooth 核照参考规格把截止固定在 22.05 kHz（§2.2）；76 组都按同一口径对照，没有偏离。

## 1. 包与接口

```go
package src // backend/internal/dsp/src

type Phase int   // Linear, Minimum
type Quality int // Smooth, Precise, Stage2（即 2s）

type Stage struct {
	Phase   Phase
	Quality Quality
	L, M    int // 本级升、降因子，已约分；升采样 M=1、降采样 L=1 或互质的 L/M
}

// Kernel 返回原型滤波器（Σh = 1），首次调用时生成并进程内缓存。
func Kernel(phase Phase, q Quality, L, M int) []float64

// Resampler 是一级或多级串联的有理数重采样器，满足父设计 §3.1 的 Processor。
func New(stages []Stage, channels int) *Resampler
func (r *Resampler) Process(in [][]float64) [][]float64 // 块长任意；输出帧数按相位累加器精确累计，总计 floor(总输入 × 比率)
func (r *Resampler) Latency() int                       // 按最终输出率计，§3.3
func (r *Resampler) Reset()

// ResampleAll 一次性重采样整段信号（开头去掉延迟、尾部补零冲刷），输出 ceil(len·to/from) 个样本。给卷积 IR 用。
func ResampleAll(x []float64, from, to int, phase Phase, q Quality) []float64
```

没有 `Drain`、`Ratio`：流尾冲刷与增益区域的比率换算由适配器按输入输出格式完成（父设计 §3.2、§4）。

## 2. 核

### 2.1 目录（76 组）

- 比率 L/M：2、3、4、6、8、16、32、64 倍，3/2，160/147、320/147、640/147、1280/147，147/20、147/40、147/80，共 16 种。
- smooth、precise 各 16 种比率 × 线性/最小相位 = 64 组；2s 只有 2、4、8、16、32、64 倍 × 两种相位 = 12 组；合计 76。
- 每相抽头 T：smooth 20、precise 166、2s 19；核长 `n = L·T + 1`；Σh = 1。
- 归一化频率：`x = f / (min(fs_in, fs_out)/2)`，x = 1 是**下侧奈奎斯特**，对应中间采样率上的 `π / max(L, M)`。
- 147 为分子的三种比率是 48/96/192 kHz → 352.8 kHz（DSD 与 DXD 方向）。

### 2.2 smooth 与 precise：Kaiser 窗 sinc（运行时）

```text
N = max(L, M)
h[k] = sinc(x_c · (k − (n−1)/2) / N) · kaiser(k; n, β)     k = 0 … n−1
h ← h / Σh
```

| 质量 | T | 截止 x_c（−6 dB 点） | β | 规格（由参考核频响测出，我们的核按此验收） |
| --- | --- | --- | --- | --- |
| smooth | 20 | 1.0；147/20、147/40、147/80 为 0.91875、0.459375、0.2296875（即 22.05 kHz） | 20 | x = 0.9·x_c 处下垂约 2.4–4.1 dB；x ≥ x_c + 0.6 衰减约 136 dB |
| precise | 166 | 1/1.05 | 18.68 | x < 0.9 偏差约 0.003 dB；x ≥ 1.06 衰减 ≥ 180.8 dB（参考约 180.0 dB） |

- smooth 的公式与参数和参考核在数值误差内重合（每组阻带差 ≤ 0.11 dB）。147/M 三种比率把截止固定在 22.05 kHz：同一原型也用于 352.8 → 48/96 kHz 的降采样（DSD 解出后），这样正好去掉 DSD 的超声噪声，照参考复刻。precise 在同样长度下比参考阻带深 0.9–1.3 dB、通带偏差小约 0.0002 dB。
- 2 倍 smooth 按此公式就是半带滤波器：中心抽头 0.5，偶数偏移处为 0（C3）。
- 线性相位核是毫秒级的计算；不入库的理由：公式十几行、可复现，入库反而要审几十万个数。

### 2.3 2s：极小化最大误差的线性规划（离线）

参考 2s 的特点是通带很缓（约 x = 0.41 处 −3 dB、x = 0.476 处 −6 dB），有用通带只到 x ≈ 0.11，阻带从 x = 0.99 起。规格化为下面的线性规划（I 型线性相位，`A(ω) = c₀ + 2Σ c_k cos kω`，k = 1…(n−1)/2）：

```text
最小化 δ
约束   |A(x) − 1| ≤ 1e−4       x ∈ [0, 0.113]          （通带）
       A(0.4758) = 0.5                                  （−6 dB 点与参考同位）
       |A(x)| ≤ δ             x ∈ [0.99, L]            （阻带）
网格密度：每个余弦系数 8 个点；结果按 Σh = 1 归一
```

- 求解器：HiGHS（scipy `linprog(method='highs')`），原始与对偶可行性容差都设 1e−10（默认容差会让阻带卡在约 −140 dB）。最长一组（64 倍，n = 1217，609 个变量）约 90 秒。
- 为什么不用其他方法：本机试过加权最小二乘（各种权重）、Chebyshev/DPSS 等其他窗函数，阻带都比参考差 4 dB 以上；Parks–McClellan（scipy `remez`）在 32、64 倍不收敛。线性规划在同样长度下阻带比参考深 18–31 dB（§8.3）。
- **入库**：生成器 `scripts/dspgen/src2s.py`（numpy + scipy，头部写明版本，用 `uv run --with numpy==… --with scipy==…` 运行，不进项目依赖）输出 `backend/internal/dsp/src/kernels2s_gen.go`：6 组线性相位核，只存一半（对称），约 1200 个数；文件头注释写每组的阻带、通带、−6 dB 点。CI 不重新生成；测试检查入库核的规格（§8.1）。改方法时重新生成并在 PR 里对比注释里的指标。
- Go 标准库没有线性规划，自己在 Go 里写一个 600 变量、近万条约束、容差 1e−10 的单纯形不值得；离线一次生成、结果入库与父设计 §9 的“生成脚本与结果可以入库”一致。

### 2.4 最小相位：倒谱法（运行时）

对同一线性相位核 h（长度 n）：

```text
nfft = max(2²⁰, next_pow2(8n))
H = |FFT(h, nfft)|，下限钳到 1e−14 · max|H|
c = Re IFFT(log H)                            实倒谱
c'[0] = c[0]; c'[1 … nfft/2−1] = 2c; c'[nfft/2] = c[nfft/2]; 其余 0
h_min = Re IFFT(exp(FFT(c')))[0 : n]，再按 Σ = 1 归一
```

- 倒谱长度：只取 8n 时，短核（2、4、8、64 倍 precise）的倒谱混叠会让通带偏差超过参考（最多超出约 0.0015 dB）；下限 2²⁰ 消除了这个问题，长核取 8n 已经足够。
- 最大的一组（1280/147 precise，n = 212481）需要 2²¹ 点的复数 FFT，临时内存约 100 MB（用完即释放），Python 实测 1.2 s；只在第一次用到时付出，之后缓存。
- 最小相位核按 C4 申报延迟 0。

### 2.5 缓存

- `Kernel` 以 `(phase, quality, L, M)` 为键，进程内缓存，同键并发只生成一次。
- 不同 CPU 架构的浮点末位可能不同（arm64 会融合乘加），测试比较频响规格，不比较系数哈希。
- 实际只会用到少数几组，不设淘汰。

## 3. 多相重采样器

### 3.1 单级

```text
多相分解：E_p[j] = L · h[p + jL]，p = 0 … L−1，j = 0 … T_p−1，T_p = ceil((n − p)/L)
第 m 个输出：t = m·M；p = t mod L；i = floor(t / L)
y[m] = Σ_j E_p[j] · x[i − j]
```

- 每声道一个长度 `max T_p` 的历史缓冲，相位累加器用 int64 跨块延续；输入块长任意（父设计的量子是 `采样率/5`）。
- 直流增益：Σh = 1，多相系数乘 L 后每相之和约 1。
- 成本：每个输出 T_p 次乘加。44.1→48 precise 约 166 次；2 倍 precise 降采样约 333 次。

### 3.2 降采样复用原型（C3b）

L/M 转换的原型工作在中间采样率 `L·fs_in = M·fs_out`，截止 `π/max(L,M)`。反方向的中间采样率与截止完全相同，所以同一个原型两个方向通用：48→44.1（147/160）用 160/147 的原型、插值因子 147；2 倍降采样用 2 倍原型、L = 1；352.8→48 kHz 用 147/20 的原型。
增益归一统一为：原型 Σh = 1，多相系数乘本方向的插值因子 L。升降两个方向的直流增益都是 1。

### 3.3 延迟

- 线性相位一级：中间采样率上的群延迟 (n−1)/2，换到本级输出是 `(n−1)/(2M)` 个样本。最小相位记 0（C4）。
- 多级：各级延迟换算到最终输出率后相加，最后四舍五入一次，`Latency()` 返回这个整数。剩下的不到半个样本的偏差不补偿。
- 延迟补偿与流尾冲刷归 `chain.Wrap`：流头丢 `Latency()` 帧，流尾喂零直到输出帧数达到 `总输入 × 比率`（父设计 §3.2）。DSD 来源段里的降采样同样经适配器包装（§6.2）。

## 4. 规划器：策略、回退与分级

### 4.1 输入与输出

```go
type Request struct {
	SourceRate int
	Strategy   string // none | max_sample_rate | power_of_2 | dsd | custom
	CustomRate int
	Filter     Filter // linear_precise | minimum_precise | linear_smooth | minimum_smooth
	Supported  func(rate int) bool // 输出端能力（协商结果；Opus 只有 48000）
	MaxRate    int
}
type Plan struct {
	From, To      int
	Stages        []Stage // From == To 时为空
	Compatibility bool    // 命中兼容性回退（C2），或用户策略为 none 但源率不受支持
}
func Choose(req Request) (Plan, error)
```

标准采样率集合：44.1 与 48 kHz 两族各 ×1、×2、×4、×8、×16（最高 705.6 / 768 kHz）。源采样率可以是任意常见值（含 8、11.025、16、22.05、32 kHz），目标只取标准集合。

### 4.2 策略（C1）

| 策略 | 目标 |
| --- | --- |
| `none` | 源采样率 |
| `max_sample_rate` | 输出端支持的最高标准采样率，不超过 768 kHz |
| `power_of_2` | 源 × 2ᵏ，取不超过上限且受支持的最大 k |
| `dsd` | 本批不可用（PCM→DSD 只做库，M5）；`Choose` 返回 `ErrStrategyUnavailable`，处理链按 `none` 处理，界面不显示 |
| `custom` | 用户指定的标准采样率 |

### 4.3 兼容性回退（C2）

目标 r 不受支持时按顺序找第一个受支持的：r 本身 → 换族（44.1 族 ×480/441、48 族 ×441/480）→ 从 r 起逐次减半到 44.1（或 48）kHz → 从 r 起逐次倍增到 768 kHz。
命中第 2–4 步时 `Compatibility = true`。全部失败返回错误，由协商层处理（播放区线的 `no_stream_format`）。例：DSD64 解出 352.8 kHz、浏览器上限 192 kHz → 352.8 ✗、384 ✗、176.4 ✓。

### 4.4 分级

2s 的通带只平到 x ≈ 0.11，所以它只能放在“本级输入里的有用内容 ≤ 0.113 × 本级奈奎斯特”的位置。规则：

| 转换 | 级 |
| --- | --- |
| L/M 或 M/L 在目录里 | 单级，用户滤波器 |
| 不在目录里的跨族比率（如 44.1→768 = 2560/147） | 跨族目录核 + 一级 2 的幂，两级都用用户滤波器（例：1280/147 + 2 倍）；选使 2 的幂部分最小的组合 |
| 2ᵏ 倍降采样且本级输入 ≥ 8 × 基础率（DSD256 解出的 1.4112 MHz、DSD512 的 2.8224 MHz 降到 352.8 kHz） | 先 2s 降 2^(k−1)，再 precise 降 2。2s 级的输出奈奎斯特 352.8 kHz，0–20 kHz 落在 x ≤ 0.057；它的过渡带（约 168–349 kHz）不折叠，由后一级去掉；折叠进 0–20 kHz 的只有 x ≥ 0.99 的成分 |
| 以后 PCM→DSD：升到 2ᵏ × 基础率（k ≥ 6） | 先用户滤波器升到 8 × 基础率（352.8 kHz），再 2s 升剩下的倍数。2s 级输入的奈奎斯特 176.4 kHz，20 kHz 正好在 x = 0.113 |

- DSD512 的 8 倍降采样：每个最终输出的乘加从单级约 1329 次降到约 2×77 + 333 ≈ 490 次。
- 其他 2 的幂转换（2–64 倍升降）目录里都有单级核，不分级：插值的单级成本与倍数无关（每输出 T 次），而且保住 precise 的 180 dB 阻带。

## 5. FFT

`backend/internal/dsp/internal/fft`（父设计 §1 已记）：只支持 2 的幂长度，迭代基 2 复数 FFT + 实数输入打包成 N/2 点复数 FFT，约 250 行，零新依赖。双精度基 2 的误差 O(log N · ε)，满足 180 dB 指标。不用 gonum 的理由：只为两处 2 的幂用法引入整个模块及间接依赖不划算。本子任务实现，卷积复用。

## 6. 接入

### 6.1 链上 ② 节点

- 位置：父设计 §5.2 第 ②（初始采样率转换）。规划结果为空时不插节点。
- 装配：`chain.Wrap(src.New(plan.Stages, ch), in, out, step, true)`；会话内不变（父设计 §5.3）。

### 6.2 DSD 来源段里的降采样

DSD128 以上解出后降到 352.8 kHz（DSD 子任务 §4）在每曲来源段里、电平化之前，同样用本包的 `Resampler`，由来源段的适配器补偿延迟并按流内绝对帧号搬运增益区域（父设计 §4）。滤波器固定 linear precise（不随用户设置），分级按 §4.4。

### 6.3 替换第一批的 ffmpeg 临时转换（父设计 §6）

| 第一批 | 第二批 |
| --- | --- |
| 解码 ffmpeg 带 `-af aresample=resampler=soxr:precision=28` 与 `-ar <链采样率>`（源超过输出端上限时“同族减半”） | 解码命令去掉 `aresample` 与 `-ar`，按源采样率输出；规划器按 §4.3 选目标，② 节点转换 |
| Opus 编码进程里 `aresample=48000` | 去掉；协商为 Opus 时 `Supported` 只接受 48000，② 把链转到 48 kHz，编码进程只编码 |
| AAC 链采样率高于 96 kHz 时编码前 `aresample` | 去掉；`MaxRate` 取 96000，② 降到同族的 88.2/96 kHz |
| 信号路径 `convert` 步骤（`by: "ffmpeg"`） | 不再产生，换成 `sample_rate` 步骤（§6.5） |

dsp-pipeline 的解码命令、design-delivery 的编码命令随本子任务合入时同步改（只删上表这几项参数）；解码端换转换器后，两首高采样率曲目无缝相接处的边缘效应也随之消失（链跨曲目连续）。

### 6.4 设置

按父设计 §7 加在 `playback_zones` 上，用一列 jsonb（与 Headroom 同形）：

```sql
-- 00NN_playback_zone_sample_rate.sql，编号接在 dsp-pipeline 的 Headroom 迁移之后、按第二批合入顺序顺延；带 .down.sql
ALTER TABLE playback_zones
  ADD COLUMN sample_rate jsonb NOT NULL
  DEFAULT '{"strategy":"none","custom_rate":null,"filter":"linear_precise"}';
```

- 字段：`strategy` ∈ `none | max_sample_rate | power_of_2 | dsd | custom`；`custom_rate` 为标准集合里的值或 null；`filter` ∈ `linear_precise | minimum_precise | linear_smooth | minimum_smooth`。`dspsettings` 提供编解码与校验（坏值按默认处理，与 Headroom 一致），`zones` 的 `set_settings` 接受键 `sample_rate`，改动由 zones 去抖重建。
- `custom` 而 `custom_rate` 为空按 `none`。兼容性转换也用 `filter`。

### 6.5 信号路径步骤

按 dsp-pipeline §9.1 的 `SignalStep`：

| 情况 | kind | params | 评级 |
| --- | --- | --- | --- |
| 用户策略要求的转换 | `sample_rate` | `{from_rate, to_rate, filter}` | `enhanced`，`compat: false` |
| 兼容性回退或输出端只收某些采样率（含 Opus 48 kHz） | `sample_rate` | 同上 | `high`，`compat: true` |

DSD 来源段里降到 352.8 kHz 的那一步并进 `dsd_to_pcm` 步骤（DSD 子任务 §4.3），不单独列。

### 6.6 使用方（C5）

卷积 IR 重采样调用 `ResampleAll(…, Linear, Precise)`；DSD 来源段的降采样（§6.2）；链上 ②；以后的 DAC 输出与 PCM→DSD。

## 7. 界面

在“设置 › 播放”的播放区设置里加一组（Opus 实现）：

- “采样率转换”：下拉“不转换 / 设备最高采样率 / 2 倍升频 / 指定采样率”；选“指定采样率”时出现采样率下拉（44.1 kHz … 768 kHz）。
- “转换滤波器”：下拉“精确 · 线性相位 / 精确 · 最小相位 / 平滑 · 线性相位 / 平滑 · 最小相位”。策略为“不转换”时仍显示（兼容性转换会用到）。
- 不加说明文字；`dsd` 策略不显示。
- 信号路径组件加 `sample_rate` 步骤的显示（“采样率转换 44.1 → 48 kHz”，兼容性时带“兼容转换”标记）。

## 8. 测试与对照

### 8.1 CI（最小集）

1. **FFT**：长度 8 … 1024 的随机输入与 DFT 定义比较，最大误差 ≤ 1e−12；逆变换往返。

### 8.3 Python 原型的对照结果（2026-11-08，本机）

余量 = 我们 − 参考（阻带：正数为我们更深；通带：负数为我们偏差更小）。每族取最差的一组：

| 族（组数） | 阻带余量最差 | 通带余量最差 | 群延迟差最大（输入样本） | 我们的阻带最差 |
| --- | --- | --- | --- | --- |
