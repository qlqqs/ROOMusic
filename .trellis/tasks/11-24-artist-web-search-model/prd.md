# 网络搜索：模型联网认人与模型整理

父任务 `11-24-artist-web-search`（R1–R9、D1–D6）。调研：`../11-24-artist-web-search/research/repo.md`。设计 `design.md`，计划 `implement.md`。
前置：`11-24-artist-manual-media` 合入（复用其 `artist_link` 操作、人工层与入口放宽）。

## 目标

打开“网络搜索”后，没有 MusicBrainz / Wikidata 对应的主署名艺人由自动整理的模型层联网处理：认出身份就写对应、交给有许可来源；认不出但搜到资料就写入“模型整理”的图片与简介；拿不准的转人工。插件也能按名字给这些艺人补资料。

## 需求

- W1 来源设置里新增一个“网络搜索”来源（默认开）。它依赖开启者的管家对话模型与搜索来源（SearXNG、Tavily 或模型自带的搜索）；缺搜索时不可用并给出原因，接口同时给出两项依赖各自是否就绪。
- W2 范围：没有任何 MusicBrainz / Wikidata 艺人对应、有专辑艺人或曲目艺人署名、图片或简介至少缺一项的有效艺人。
- W3 插件按名字查：对 W2 范围的艺人，启用的插件（有 `artist_image` / `artist_bio` 能力）按名字查询，结果写入自动层（来源 `plugin:<id>`）。不受“网络搜索”开关控制。
- W4 插件补完仍有缺口、且网络搜索与模型层可用时，建一个艺人身份待定项交给模型；证据是艺人名、别名、若干专辑名与曲目名，以及缺哪一项。
- W5 模型提交身份（MusicBrainz MBID 或 Wikidata Q 号，附依据与引用网址）：程序复查条目确实是个人或音乐团体、名字或别名与本地一致；独立审查通过后写入对应（`artist_link`，模型来源），之后由有许可来源补全。审查转人工的进入例外，同一艺人可有多个候选，管理员采纳一个后其余关闭。
- W6 模型提交“模型整理”的资料：图片（图片地址 + 所在网页，网页须在引用中）与/或简介（纯文本 20–4000 字，附 1–5 个引用网页）。不经独立审查，直接写入自动层，来源 `web_search`，读取时带引用列表。
- W7 来源等级：有许可来源 > 插件 > 网络搜索。自动层遇到等级更低的已有资料时替换它（记录 Before，撤销新操作不恢复旧资料）；同级与更高级不覆盖。
- W8 标记不对（父任务 R5 / 手动子任务 M5）对新来源同样有效：插件按条目抑制；网络搜索的图片按图片地址抑制，简介按艺人整体抑制（以后不再写模型整理的简介）；拒绝的身份候选写抑制，模型不能再提交同一条目。
- W9 管理员可查看单个艺人的网络搜索状态（排队、处理中、搁置、等你确认）与待确认的候选，采纳与不采纳走现有例外接口。
- W10 外发数据与额度：只发艺人名、别名、少量专辑与曲目名；用量计入模型层每日额度；后台会话在网络搜索可用时才挂联网工具。
- W11 mock 服务器能离线走通三条路（认出身份、模型整理、转人工），以及插件按名字查。

## 验收

- B1 W1：开关、默认值、依赖缺失时的 `inactive_reason` 与依赖状态。
- B2 W2–W4：范围筛选正确（有对应的、只是合作者的、资料齐全的不进）；插件先查；仍有缺口才建项；输入摘要不变不重复建项。
- B3 W5：复查不过（不是人物或团体、名字不一致、已被拒绝）时工具返回错误不写入；审查通过写对应并在下一轮补上有许可资料；转人工 → 例外 → 采纳写对应、其余候选关闭；不采纳写抑制。
- B4 W6：图片地址不是公网、网页不在引用中、图片太小或不是图片、简介超长或无引用时拒绝；合法时写入并在读取接口带引用；不经审查。
- B5 W7：有许可来源替换网络搜索与插件资料；插件替换网络搜索资料；撤销替换操作后不恢复旧资料。
- B6 W8：三种抑制生效。
- B7 W9：状态接口在各阶段返回正确；普通账号 403。
- B8 W10：网络搜索关闭或依赖缺失时后台会话不挂 `web_search`、`fetch_page`、不设模型自带搜索；token 计入每日额度。
- B9 迁移往返；接口样本；mock 三条路走通。

## 不做

- 前端（`11-24-artist-media-ui`）。
- 网络搜索用于发行匹配（后台会话挂了联网工具后模型也可能用于发行，不额外设计）。
- 定期复查已写入的模型整理资料。
