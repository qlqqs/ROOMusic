# SlimProto 跳帧的录音与测量

Squeezelite 2.0.0-1613 两台同组，主设备时钟为 0 ppm，成员为 +800 ppm。93 秒内共记录 7 次 `strm a`，三段素材均有覆盖。时钟较快的成员持续领先，ROOMusic 按最超前设备对齐，每次向落后的主设备发送 10 ms 修正。在 44.1 kHz 下，7 次均从主设备实录中量得恰好丢了 441 个源帧，成员实录完整。

正弦和和弦的 4 次切点，跳变幅度比同段相邻样本差 p99 高 12.713–25.275 dB；切点高频能量相对各自很低的基线上升 74.171–90.797 dB。白噪声段的 3 次样本跳变均在该段 p99 以内，高频能量变化介于 −0.277 与 +0.403 dB。下面的两台录音可供试听，表中记录的是数字输出测量。

## 测量方法

- 运行 `sg docker -c scripts/test-slimproto-skip.sh`，退出码 0。使用生产 Dockerfile 的固定提交 `b02a9ac77794c9914fa2b70caa98010e9f23cc2d`。两台通过同一条 ROOMusic 编组 FLAC 流播放合成素材，Squeezelite 的 32 位双声道标准输出接限速 FIFO。把成员从 +100 ppm 提高到 +800 ppm，使每段 31 秒的素材能覆盖多次修正。
- 三段依次为峰值约 −12 dBFS 的 437 Hz 正弦，220、277.183、329.628 Hz 各加二次泛音的和弦，以及固定种子的白噪声。右声道叠加峰值约 −96 dBFS 的位置标记，以区分相同相位的各个周期；指标均取左声道。
- 扫描整段实录双声道 PCM 与源逐帧对齐，在不连续处用后续连续 16 帧唯一定位新的源位置。前后源帧号之差减一给出实际丢帧数。再按每台播放器的日志顺序和单调钟时间与 `strm a` 一一配对。预计帧数等于 `floor(指令毫秒 × 44100 / 1000)`。
- 跳变幅度取修正两侧相邻样本差的绝对值，以 32 位 PCM 满量程为 0 dBFS。p99 取该段完整源信号所有相邻样本绝对差的第 99 百分位。对切点前后各 220 帧及中心样本施加 441 点 Hann 窗，求 DFT 中严格高于 8 kHz 的频点能量和；与该段每秒中点相同窗的平均能量取比，再换算为 dB。
- WAV 为 44.1 kHz、24 位、双声道。截取端点分别映射到两台录音上，同一时段内 +800 ppm 设备会多输出少量帧。
