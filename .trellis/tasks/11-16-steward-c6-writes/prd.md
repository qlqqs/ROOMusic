# 管家 C6：写操作确认、目录整理工具、operator 模式

## 目标

管家能提出并执行曲库的整理修改：默认把修改合成一份方案给用户逐项确认，确认后经现有的受治理写入执行，
每一项都有操作记录并可撤销；用户可以把会话切到直接执行（父任务 R3、R8、S12）。

## 背景与约束

- 受治理写入的入口是 `operations.Run`（`backend/internal/operations/operations.go:182`）。`Spec` 只有执行者、类型、
  幂等键、指纹和请求 ID，没有来源或模式字段；规范写明“模式字段在 M6 引入”（`governance-contracts.md:65`）。
- 已登记的操作类型：专辑字段修正、归组、默认版本、问题核对、认领（可撤销）；艺人合并、拆分、改名、忽略候选
  （不可撤销，靠反向操作恢复）；撤销本身。HTTP 写接口都要求管理员（`catalog/httpapi/handlers.go:69-84`）。
  问题核对与认领需要先读一次得到的令牌。没有艺人别名接口。
- 会话表已有 `mode` 列（`assistant`、`steward`、`operator`，默认 `assistant`），但创建时写死 `assistant`，
  接口拒绝其他值，`PATCH` 只改标题和模型。
- 循环没有挂起：`ReleaseConversation` 会把还在 `running` 的工具调用标成 `interrupted`，重放时没有结果的调用
  也按 `interrupted` 伪造结果。工具调用状态只有 `running`、`succeeded`、`failed`。
- 调用入口在 `steward/tool/registry.go:89-92` 留了接确认路径的位置。SSE 没有方案事件。
- 产品合同：确认绑定方案内容摘要与过期时间，内容变化要重新确认；模型不能靠在输出里写批准字段通过；
  `operator` 只跳过审批，不跳过鉴权、revision、幂等和记录（`agent-and-operation-guidelines.md:34-42,65-86`）。
  合同里“Operator non-admin principal → permission_denied”一条已被父任务 S12 取代，随本任务改写。
- ADR 0005：方案每一项标明依据来自本地证据还是外部资料（4.3）；`operator` 下外部内容可能促成直接写入，
  是已接受的风险，模式菜单要写明（4.5）；MCP 读写令牌没有服务端确认（4.6）。
- 原型：方案卡片逐项列出字段、旧值、新值、依据说明和勾选框，按钮“应用 N 项修改”“不修改”，
  复选框“这次对话里，<这类修改>不再问我”；输入框下的模式按钮与 Shift+Tab（`temp/steward-design/index.html:308-315,384-395`）。

## 需求

- R1 目录整理工具（`shared`，管理员）：修正专辑字段、加入或脱离版本组、设默认版本、问题核对与取消核对、认领
  （含只读的认领预览）、艺人合并、拆分（含只读的拆分预览）、改名、忽略候选、撤销一条操作。全部经 `operations.Run`。
- R2 `assistant` 模式：模型在一步里要求的 `shared` 调用不执行，合成一份方案落库，运行以“等待确认”结束；
  界面显示方案卡片。用户可以逐项取舍后应用，或全部不修改。
- R3 应用时后端校验方案摘要与有效期，逐项执行；每一项各自经过 revision 与幂等校验，单项失败不影响其他项；
  结果（成功、失败原因、未选、被拒绝）作为工具结果回给模型，运行继续。
- R4 “这次对话里这类修改不再问我”仅适用于可撤销工具：该工具在本次方案中至少有一项被接受，才可按工具名记在会话上，之后同一会话里该工具直接执行。不可撤销工具在 assistant 模式每次确认。
- R5 `operator` 模式：`shared` 工具鉴权后直接执行。模式可以在新建会话时选，也可以对已有会话切换；
  新会话默认 `assistant`。普通成员可以选任何模式，但 `shared` 工具本来就不在他的工具列表里。
- R6 操作记录带来源：入口（对话或 MCP）、会话、模式、方案；操作记录页与 `list_operations` 能看到。
- R7 MCP 读写令牌可以调用 `shared` 工具，直接执行；只读令牌拒绝。
- R8 方案每一项显示旧值与新值、是否可撤销、模型给的依据说明（标明来自本地证据还是外部资料）。
- R9 刷新页面后未处理的方案仍然显示，可以继续确认。
- R10 产品合同与后端规范同步：`operator` 对所有用户开放；新增的错误码与事件。

## 验收

- A1 管理员在 `assistant` 模式要求修正一张专辑的标题和年份：出现方案卡片，旧值新值正确；只勾一项应用后，
  只有那一项生效，操作记录里有这一条且带来源，能撤销。
- A2 不点应用时曲库没有任何变化；点“不修改”后模型得知用户拒绝并继续对话。
- A3 方案落库后目标被别处改过：应用时该项失败并说明版本冲突，其他项正常。
- A4 用篡改过的摘要、过期的方案、别的用户的方案 ID 调确认接口都被拒绝，没有副作用。
- A5 模型在自己的文字或工具参数里写“已批准”不能让方案执行。
- A6 接受可撤销工具的至少一项修改并勾“不再问我”后，同一会话里同类修改直接执行，别的会话仍然要确认；不可撤销工具或未接受任何项的工具不能加入免确认名单，确认接口返回 `400 invalid_input`，取舍与名单更新均回滚。
- A7 `operator` 模式下管理员的修改直接执行并有操作记录（来源标明直接执行）；新会话回到确认模式。
- A8 普通成员在任何模式下工具列表里没有 `shared` 工具，直接调用被拒绝。
- A9 MCP 读写令牌能完成 A1 的修改，记录来源为 MCP；只读令牌被拒绝。
- A10 标签或歌词里的指令文本在 `assistant` 模式下不会造成未经确认的修改（假模型端点模拟被注入的模型输出）。
- A11 Shift+Tab 只在输入框里轮换模式；切到 Operator 时菜单与提示写明直接执行的含义。

## 不做

- `steward` 模式与审查（C7）；应用配置类工具（C9）。
- 一次对一批专辑的批量操作类型；艺人别名（后端没有这个能力）。
- 给不可撤销的艺人操作补撤销。

## 规划结论

路线：用户选择。qlqq 于 2026-11-16 要求 C5–C11 一次规划完后直接执行，不逐个子任务再问；
标“主代理”的决定按建议取值，用户验收时可以改。
