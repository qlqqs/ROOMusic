# 管家 C8：联网

## 目标

管家能查外部资料：结构化的音乐数据、通用网页搜索、读取网页正文（父任务 R4、S8、S11）。

## 背景与约束

- ADR 0005 已定：管理员填的端点与 SearXNG 地址不限；成员填的必须是公网地址或在管理员的放行名单里；
  网页抓取对所有人只允许公网地址；程序固定的地址（商业搜索、音乐数据源）允许。抓取的限制（D5）：只用 GET，
  不带 Cookie、认证和实例标识，固定的通用 User-Agent，只收 HTML、纯文本、JSON、XML，正文最多读 2 MiB，
  给模型的文字最多 100 KiB 并说明截断，总时长 20 秒，最多 5 次重定向。搜索密钥按用户加密存放（D2）。
  外部内容是不可信文本。这些限制尚未实现，出站客户端（`steward/egress/client.go`）已有地址规则与重定向复核。
- 探测（`steward/provider/probe.go`）目前只判断协议和是否支持工具调用，没有自带搜索的判断。
- 2026-11-16 查到的接口现状（来源见 `research/web-sources.md`）：
  - SearXNG：`GET /search?q=&format=json`；实例默认不开 JSON，未开时返回 403。
  - Tavily：`POST https://api.tavily.com/search`，Bearer 密钥，每月 1000 次免费。
  - Messages 协议的服务端搜索工具（`web_search_*`）：结果块含 `encrypted_content`，回传历史时必须原样带回；
    有 `pause_turn` 停止原因；按次计费。
  - OpenAI 的 `web_search` 工具只在 Responses 接口上，Chat Completions 上没有。
  - MusicBrainz：平均每秒 1 次请求，要求 User-Agent 写明应用名、版本和联系地址；核心数据 CC0。
  - 纯 Go 的正文提取：`golang.org/x/net/html`（项目已允许的依赖范围）。

## 决定

| 编号 | 日期 | 选择者 | 决定 |
| --- | --- | --- | --- |
| D1 | 2026-11-16 | qlqq | 模型自带搜索除 Messages 协议外，也接 OpenAI 官方的搜索接口（Responses） |
| D2 | 2026-11-16 | 主代理 | 商业搜索 API 用 Tavily（用户在选择框里没有点选，按建议取值） |
| D3 | 2026-11-16 | 主代理 | 新增第三种模型协议 Responses，作为完整的对话协议（含工具调用），探测到端点支持时可选；这修改父任务 S3“只支持两种协议” |
| D4 | 2026-11-16 | 主代理 | 音乐数据源本任务只做 MusicBrainz 与 Cover Art Archive 的封面清单；Discogs（官方文档未能核实）与歌词库不做 |
| D5 | 2026-11-16 | 主代理 | MusicBrainz 请求用写明应用名、版本和项目地址的 User-Agent（对方的使用条款要求），不含实例信息；ADR 0005 的 D5 相应补一句，网页抓取仍用通用 User-Agent |
| D6 | 2026-11-16 | 主代理 | 抓取不读 robots.txt（单次、由用户发起的读取），写进 ADR；只允许 80 与 443 端口，拒绝带用户名密码的地址 |

## 需求

- R1 设置增加搜索来源（按用户）：不用、SearXNG（地址）、Tavily（密钥，加密存放，接口只回末四位）、模型自带。
  “模型自带”只在探测确认端点支持时可选。
- R2 工具 `web_search`（read）：来源是 SearXNG 或 Tavily 时登记给模型；返回标题、地址、摘要。未配置时不出现。
- R3 来源是模型自带时：Messages 协议下把服务端搜索工具加进请求，Responses 协议下加 `web_search` 工具；
  搜索过程作为条目显示在对话里，引用的来源在回答下面列出。
- R4 工具 `fetch_page`（read）：按 ADR D5 的限制读取一个公网网页并提取正文文字。
- R5 工具 `search_music_metadata`、`get_music_metadata`（read）：查 MusicBrainz 的艺人、专辑（release、release-group）、
  录音；封面清单。全实例共用每秒 1 次的限速。
- R6 Responses 协议：对话、流式、工具调用、用量；探测能识别并列出模型；设置里可以手动选。
- R7 探测增加自带搜索的判断，结果显示在设置页的检测结果里，可以手动改。
- R8 所有外部内容带来源标记进入模型；工具条目显示查询词和访问的域名。
- R9 密钥、搜索词之外的个人数据不发给搜索服务；日志不记录搜索词和网页内容。

## 验收

- A1 配好 SearXNG 或 Tavily 后问一个需要查资料的问题，对话里出现搜索与读取网页的条目，回答引用了来源。
- A2 Messages 端点开启自带搜索后，多轮对话不报错（历史里的搜索结果块原样回传），回答下面有来源。
- A3 OpenAI 官方端点用 Responses 协议能对话、调用本地工具、用自带搜索。
- A4 `fetch_page` 对内网地址、回环地址、重定向到内网、非 80/443 端口、超大响应、非文本类型分别拒绝或截断，并说明原因。
- A5 整理专辑时能从 MusicBrainz 查到候选并对比；连续多次查询时间间隔不小于 1 秒。
- A6 成员填内网的 SearXNG 地址被拒绝，管理员放行后可用。
- A7 SearXNG 没开 JSON 时提示“这个实例没有开启 JSON 输出”；Tavily 密钥错误或额度用完时说明原因。
- A8 网页里的指令文本在确认模式下不会造成未经确认的修改（与 C6 的 A10 同一类用例，来源换成网页）。
- A9 搜索密钥在接口响应、日志、操作记录里查不到。

## 不做

- Brave、Exa、Serper 等其他商业搜索；Discogs；外部歌词库；下载封面图片入库。
- OpenRouter 的 `:online`、xAI、Gemini 等其他服务商的自带搜索。
- 抓取需要执行脚本的页面、PDF。

## 规划结论

路线：用户选择。qlqq 于 2026-11-16 要求 C5–C11 一次规划完后直接执行，不逐个子任务再问；
标“主代理”的决定按建议取值，用户验收时可以改。
