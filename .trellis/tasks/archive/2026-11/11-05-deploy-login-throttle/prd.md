# 登录限速

父任务：[部署上线](../11-05-deploy-launch/prd.md)（决定 D4、D5 见父任务）。

## 目标

开到公网后，别人不能对某个账号无限次试密码；家里人偶尔输错不会被为难。

## 现状

- `backend/internal/identity/httpapi/handlers.go:137-162` 登录：用户不存在或停用时直接返回 401，不调用 bcrypt，
  密码错误时调用一次 bcrypt。两种失败的耗时不同，可以据此探测用户名是否存在。
- 自助改密码 `POST /auth/password` 核对当前密码，错误返回 `403 current_password_incorrect`（[身份与成员合同](../../../../spec/backend/identity-contracts.md)），只有已登录的会话能调用。
- 经外部反代时，后端看到的对端地址是反代的地址，不能按 IP 区分用户；但能区分“经反代”和“局域网直连”（D5）。
- 前端请求层把 `401 unauthorized` 当作会话结束（同一合同第 49 行附近），新的限速错误不能复用 401。

## 需求

| 编号 | 需求 |
| --- | --- |
| T1 | 按“用户名（按原样字节，与 `users.username` 的精确查询一致，不折叠大小写）+ 连接来源地址（IPv6 按 /64 聚合）”分别记录连续登录失败。来源地址取 TCP 对端（`RemoteAddr` 的 IP），不读任何请求头。连续失败 5 次后这一组合需等 1 分钟，之后每再失败一次等待翻倍，最长 15 分钟；等待期内的登录直接被拒绝，不核对密码。经反代的请求共用反代的地址，所以公网上的试探不会挡住局域网直连的登录（用户 2026-11-05 选定） |
| T2 | 来源上限：同一来源地址 1 分钟内允许 30 次失败，第 31 次尝试起这个来源的登录暂停 1 分钟，防止换着用户名批量试；其他来源不受影响 |
| T3 | 被限速时返回新的错误码（不用 401），提示一句日常的话，例如“登录失败次数太多，请过几分钟再试。”；前端登录页显示这句话 |
| T4 | 登录成功后只清零这一“用户名 + 来源”组合的失败计数（局域网登录成功不替公网上的试探清零）；用户不存在与密码错误同样计数、同样提示、耗时相近（不存在时也做一次等价的 bcrypt） |
| T5 | 限速状态放在进程内存（单实例部署），重启清空；条目有上限并定期清理过期项，不能被大量随机用户名撑爆内存；不新增表或迁移 |
| T6 | 管理员在服务器上执行 `reset-password` 后，这个用户名的限速随新密码失效（若状态在进程内存里无法跨进程清除，需在说明里写清等多久或重启服务） |
| T7 | 限速事件写结构化日志（不含密码与完整用户名以外的敏感信息），便于查看是否有人在试 |
| T8 | 更新身份合同、错误码表与前端提示文案映射 |
| T9 | 自助改密码核对当前密码也限速：按用户 ID 计数，规则同 T1，复用同一错误码；对话框显示“当前密码输错次数太多，请过几分钟再试。” |
| T10 | 登录时查用户遇到数据库错误返回 `503 database_unavailable`，不计为失败（现在返回 401） |

## 验收

- [x] B1 同一用户名从同一来源连续输错 5 次后，正确密码在 1 分钟内也被拒绝，返回限速错误码；之后可以登录；继续输错时等待翻倍到最长 15 分钟。
- [x] B1b 一个来源被限速时，同一用户名从另一个来源地址仍可正常登录。
- [x] B2 输错少于阈值后成功登录，计数清零。
- [x] B3 同一来源 1 分钟内换着用户名失败超过 30 次后，这个来源暂停 1 分钟，其他来源不受影响。
- [x] B4 不存在的用户名与密码错误的提示相同，计数规则相同。
- [x] B5 登录页在限速时显示那一句提示，不跳转、不当作会话结束。
- [x] B5b 改密码时连续输错当前密码 5 次后被限速，对话框显示那一句提示，会话不结束。
- [x] B5c 管理员重置密码（网页或命令行）后，被限速的用户名用新密码可以立即登录（来源暂停最多仍需 1 分钟）。
- [x] B6 后端单元测试（可注入时钟）、identity 相关集成测试、前端登录相关的 Vitest 通过。

## 规划裁决

- 限速计数方式（T1、T2 的数值）：用户 2026-11-05 选定。
- 清零范围、来源上限边界、用户名不折叠、改密码一起限速、数据库错误改 503、T6 用密码哈希指纹解除：设计稿（[design.md](./design.md)）提出，主会话 2026-11-05 按推荐裁决。
