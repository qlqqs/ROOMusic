# 界面按钮布局与设置页整理

## Goal

用户反馈页面按钮布局不够优雅、用起来不顺手，设置页布局乱。参考主流音乐应用（Spotify、Apple Music、Roon、系统设置）的长处，整理专辑详情与曲目行、底部播放栏与信号路径、全屏播放器、设置页、侧栏与列表页的按钮布局和视觉层次，并加入让操作更顺手的交互：常用操作一眼可见、主次清楚，设置项分组对齐。

视觉依据为用户认可的对照稿（2026-11-14 定稿） [research/mockup-v5.html](research/mockup-v5.html)；参考取舍见 [research/reference-apps.md](research/reference-apps.md)；改前截图在项目 `temp/ui-review/shots/`（mock 数据，桌面 1440、手机 390，不提交）。技术设计见 [design.md](design.md)，执行计划见 [implement.md](implement.md)。

## Decisions

- D1（用户，2026-11-14）：允许增加新交互，数量不限；目标是优雅美观、用着顺手。
- D2（用户，2026-11-14）：设置页保留左侧分栏，内容改为分组卡片。
- D3（用户，2026-11-14）：参考其他音乐应用的长处，不完全自行设计。
- D4（用户，2026-11-14）：认可对照稿的整体方向，包括随机与循环拆成两个按钮且互斥（不改服务端四选一模式）。
- D5（规划）：单个任务、按区域分阶段提交，不拆子任务——共用控件（菜单分组、设置行、曲目行显隐）跨区域使用，拆开会产生依赖链；每阶段仍可单独回退。
- D6（用户，2026-11-14）：认可信号路径改版方案（R3.5）。
- D7（用户，2026-11-14）：侧栏“我的歌单”展开列表的歌单名前要有封面（R5.3）。
- D8（用户，2026-11-14）：侧栏歌单项不缩进，封面与一级导航图标同一列，歌单名与一级文字基本对齐（对照见 research/sidebar-align.html）。
- D9（用户，2026-11-14）：全屏播放器纳入本次范围（R6），按对照稿方案。
- D10（用户，2026-11-14）：信号路径入口为“圆点＋格式文字”胶囊；播放中圆点平缓呼吸（用户选定：4 秒节奏，亮度下限 55%，内核呼气时缩得更小，重点是动效自然），削波时更明显（对照见 research/signal-entry.html、research/breathe-levels.html）。

## Requirements

### R1 专辑详情头部

现状：操作分三行、行距大、主次不清——“播放整张专辑”“加入队列”（`frontend/src/features/player/components/album-playback-actions.tsx:35`），心形与“添加到歌单…”（`frontend/src/app/routes/album-detail-page.tsx:39`），管理员的五个纯图标按钮（`frontend/src/features/governance/components/release-admin-actions.tsx:66-83`）；概况排在按钮下面（`frontend/src/features/catalog/components/album-header.tsx:52`）；“返回专辑列表”远在标题对面。

- R1.1 标题、专辑艺人、概况进入封面右侧并底对齐封面；“返回专辑列表”改为标题上方的“‹ 专辑”链接。
- R1.2 一条操作行：圆形播放整张（唯一主操作）、随机播放（新增）、收藏、添加到歌单、“更多”。
- R1.3 “更多”菜单：下一首播放（新增）、加入队列；管理员另有“管理”分组：编辑发行信息、设为默认版本 / 改回自动选择、归入其他专辑、移出为独立专辑（多版本时）、查看问题。
- R1.4 版本导航改为标签，“对比版本”留在版本导航行尾。

### R2 曲目行

现状：每行常驻播放、心形、“更多”三个图标（`frontend/src/app/routes/track-actions.tsx`，规范 `frontend/DESIGN-components.md:36`），列表视觉噪声大。

- R2.1 精确指针设备上平时只显示序号、标题、署名、时长；悬停或键盘聚焦时序号位显示播放按钮，心形与“更多”显现；已收藏心形常驻。
- R2.2 双击行从这首开始播放（新增），在链接、按钮上或拖选文字时不触发。
- R2.3 正在播放的曲目序号换成音柱（减少动态时静止），标题用强调色。
- R2.4 触屏与窄屏不依赖悬停，动作常驻；窄屏心形进“更多”。
- R2.5 收藏、历史、歌单、搜索、艺人页的曲目行用同一规则。

### R3 底部播放栏与信号路径

现状：右侧挤着信号路径与格式、播放模式、静音与音量、设备、队列（`frontend/src/features/player/components/player-bar.tsx:50-56`），模式按钮离传输键远，进度时间只在右侧。

- R3.1 三段式：中间为随机、上一首、播放、下一首、循环，下方进度两端写时间并保留波形。
- R3.2 随机与循环两个按钮，互斥（D4）；启用时强调色加小圆点；全屏播放器同样处理。
- R3.3 右侧固定顺序：格式与信号路径、设备、队列、分隔线、音量；状态文字只在加载、缓冲、出错时显示。
- R3.4 窄屏为浮起的迷你栏（封面、标题＋设备名、播放、下一首、队列、底边进度线）。
- R3.5 信号路径（D6；`frontend/src/features/player/components/signal-path.tsx`，现为 280px 弹层：彩色波形图标与格式文字分开、步骤与响度/处理速度/设备混在一列，看不出哪一步拉低质量）：
  - 入口合并为一个胶囊按钮（质量色圆点＋格式文字）（D10）：播放中圆点约 4 秒一次自然呼吸（吸气约 1.5 秒、呼气约 2 秒、末尾停顿约 0.5 秒；内核 78%↔100% 与透明度 55%↔100% 同步；另一层柔光在吸气后稍晚绽开再散去；对照见 research/breathe-levels.html），暂停、缓冲、出错时静止；削波时圆点变警示色并约 0.9 秒一次脉动，削波结束（服务端约 450 ms 后报告）即恢复；`prefers-reduced-motion` 时不做动画，只变色；
  - 弹层头部为质量词与“来源格式 → 输出设备”，削波时下方一条“正在削波”；
  - 步骤画成从来源到输出设备的竖向链，每步“步骤名＋取值”，决定整体质量的最差一步加粗；“有损”“兼容转换”标签保留；
  - 响度、范围、峰值、处理速度移到底部测量格，缺项不显示；宽 340px，全屏用深色面，窄屏底部弹出；不加解释句。

### R4 设置页

现状：应用侧栏＋设置分栏＋内容三列，内容挤在左半边（`frontend/src/app/routes/settings-layout.tsx`）；播放设置十几个控件平铺、标签位置不一致、下拉宽度不一（`frontend/src/features/player/components/playback-settings-form.tsx:186-238`）；扫描目录页内容堆叠，表格操作只有图标。

- R4.1 保留设置分栏（D2），标题加大，管理员栏目归入“管理”小标题；窄屏为胶囊标签。
- R4.2 内容区限宽，分组卡片，每行左侧名称与说明、右侧控件右对齐；从属项缩进，所属开关关闭时隐藏。
- R4.3 播放设置分“播放、输出、音效处理”三组，页首显示设置作用于哪台设备；纯图标按钮改为文字按钮。
- R4.4 扫描目录分扫描卡、音乐目录卡（“添加目录…”对话框、行尾“更多”）、记录。
- R4.5 成员、备份、账号、操作记录按同样布局整理。

### R5 侧栏与列表页

- R5.1 搜索入口浅底并显示快捷键；待办入口在已有数据时显示数量，不为此新增接口。
- R5.3 “我的歌单”展开列表每个歌单名前显示 26px 封面（D7）：数据用侧栏已在读取的歌单摘要 `cover_groups`（`frontend/src/app/shell/primary-nav.tsx:80-90`，最多 4 张），规则与歌单页的 `PlaylistCover` 一致——4 张拼方格、不足 4 张用第一张；空歌单或第一张没有封面时显示歌单图标（小尺寸不显示标题文字版面）；当前打开的歌单高亮；歌单项不缩进（D8），封面与一级图标同列，“全部歌单”与歌单名左对齐。不新增请求。
- R5.2 列表页工具条（搜索、筛选、排序）同一行同一高度，每页最多一个主要按钮。

### R6 全屏播放器

现状（`frontend/src/features/player/components/fullscreen-player.tsx`）：桌面所有控件挤在底部一条，收起按钮在左下角、播放键偏左、进度条极长；标题在上、心形在最右，相距很远；歌词小字堆在左上，右侧与下方大片留空；不显示信号路径与设备；窄屏要点唱片才能看歌词，底部三个图标孤立靠右。

- R6.1 桌面左栏为“唱机＋控制台”：唱片（封面作标签、唱臂保留）下依次是标题＋心形＋更多、专辑 · 艺人、信号路径胶囊＋设备按钮（点开选择设备）、进度（两端时间、波形）、传输键（随机、上一首、大播放键、下一首、循环）、音量。
- R6.2 桌面右栏为“歌词 / 接下来”切换：歌词大字号，当前行最亮最大、已唱过更暗，自动滚动使当前行保持在中间偏上，上下边缘渐隐，点行跳转沿用现有功能；“接下来”列出队列随后若干首（`upNext`），点一首播放（`playEntry`，新增），随机模式下写明“随机播放中”；没有歌词时默认显示“接下来”。
- R6.3 收起在左上角，队列在右上角；Esc、返回键收起与焦点归还不变。
- R6.4 窄屏：顶部为收起、“正在播放 · 专辑名”、更多；唱片视图下方是标题、信号路径、进度、传输键，底部一排是设备名按钮（左）与歌词、队列（右）；歌词有明确按钮，歌词视图把唱片换成一行小封面与标题，控制区位置不变。
- R6.5 背景仍为封面放大、模糊、压暗，没有封面时为深色底。

## Acceptance Criteria

- [ ] AC1（R1）桌面 1440 下专辑详情的标题、概况与全部常用操作位于封面右侧一个区块内，操作只有一行；管理员动作只在“更多”的“管理”分组中出现，普通成员看不到该分组。
- [ ] AC2（R1.2）“随机播放”以随机模式播放整张可播放曲目；“下一首播放”把整张可播放曲目插到当前曲目之后；队列已满与跳过不可播放曲目的提示与现有“播放整张专辑”一致。
- [ ] AC3（R2.1、R2.4）精确指针下未悬停的普通曲目行不显示播放、心形、“更多”，已收藏的心形可见；Tab 聚焦到行内控件时它们可见且焦点环可见；触屏模拟（`hasTouch`、`pointer: coarse`）下动作常驻。
- [ ] AC4（R2.2）双击曲目行开始播放该曲目；双击行内链接或按钮不触发。
- [ ] AC5（R3.2）随机与循环按钮的 `aria-pressed` 与当前模式一致，开启一个时另一个关闭；循环依次为关、列表循环、单曲循环。
- [ ] AC6（R3）播放栏在 768–1440 宽度下右侧控件不重叠、不换行；窄屏迷你栏不遮挡页面最后一行。
- [ ] AC7（R4）设置各页在 1024 及以上宽度显示分栏与分组卡片，控件右对齐；交叉渐变、Headroom 关闭时其从属行不出现；窄屏无横向溢出。
- [ ] AC8（R4.4）添加音乐目录通过对话框完成，目录行的暂停、恢复、移除等动作在行尾“更多”中可用。
- [ ] AC9 现有按钮的读屏名不变（design.md 第 8 节清单）；axe 无严重问题；375、768、1024、1280、1440 宽度下页面无横向溢出。
- [ ] AC10 `npm run lint`、`typecheck`、`test`、`build` 与全量 e2e 通过；`frontend/DESIGN-components.md` 及相关前端规范已按新布局更新。
- [ ] AC11（R3.5）信号路径入口是一个含格式文字的按钮，可访问名含可见文字与“信号路径：质量”；播放中圆点有呼吸动画、暂停时没有，`clipping` 为真时切换为削波脉动，减少动态时都没有动画；弹层按服务端步骤顺序显示链，最后是输出设备；`clipping` 时显示“正在削波”；没有分析结果时底部不显示响度格，没有处理速度时不显示该格。
- [ ] AC12（R5.3）侧栏歌单列表每项前有封面：4 张时为方格、1–3 张为第一张、空歌单为图标；封面左边缘与一级导航图标的左边缘对齐（误差不超过 4px）；展开侧栏歌单不产生额外的网络请求。
- [ ] AC13（R6）桌面 1280 与 1440 下全屏播放器的传输键、进度与音量都在唱片下方的左栏内，收起按钮在左上角；右栏可在“歌词”“接下来”间切换，没有歌词时默认“接下来”，点“接下来”中的一首开始播放该条目；窄屏有可见的“歌词”按钮，切换后控制区位置不变。

## Out of Scope

- 后端接口与播放区协议改动（包括“随机＋循环”同时生效）。
- 新的颜色、字体或设计变量；深色主题。
- 概览页、登录与初始化页的改版；唱片与唱臂的动画本身不改。
- 为侧栏计数或歌单封面新增接口。

## Planning Route

规划定稿路径：route a（用户审阅最终规划摘要后批准，选择人：用户）。理由：本任务的取舍主要是视觉与交互偏好，只能由用户决定。状态：已批准（2026-11-14，用户回复“开始实施”）。

## Constraints

- 设计规范以 `frontend/DESIGN.md`、`frontend/DESIGN-components.md` 为准，改动后同步更新。
- player 与 personal 互不导入，由 app 组合。
- 不新增依赖，不加载网络字体。
