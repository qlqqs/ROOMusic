# 技术设计：无缝换轨与淡化曲线

需求以 [prd.md](./prd.md) 为准。本子项只在渲染会话内部工作：实现 dsp-pipeline 取帧入口 `player.read` 里的“格式检查、淡化截断、混音、短读换轨”几步（[dsp-pipeline design.md](../11-08-dsp-pipeline/design.md) §5.2，下称“管线设计”），
以及纯包 `backend/internal/dsp/fade`。跨子项的架构见[父任务 design.md](../../../11-08-audio-dsp-reference-port/design.md)（下称“父设计”）。参考稿只引章节号，写作“参考稿 §N”。

## 0. 结论

- 下一首在“当前曲目剩余 10 秒 + 淡化时长”时取来并打开（管线设计 §5.3）；取来时就判定这次换轨是**无缝**、**交叉淡化**、**间隔**还是**格式边界**，之后只在 `NextChanged` 时重判。
- 无缝按参考稿 §4.6 的短读换轨：当前曲目读不满时切到下一首补读，两首的样本原样拼接，逐位不变。等下一首就绪最多 5 秒，超时就在边界结束本流，交给 zones 开接续流。
- 交叉淡化在“有效结尾 − 淡化时长”处截断当前曲目，截断点向下对齐到 8 帧；淡入 `sqrt(sin(πx/2))`、淡出 `cos⁴(πx/2)`，按公式逐点计算。
- “只在下一首是另一张发行时才交叉淡化”保留为淡化条件之一；同一发行内照常无缝。
- `NextChanged`：下一首的样本还没进入链就悄悄换掉；已进入就发 `rebuild_needed`。

## 1. 换轨方式的判定

取到下一首 B（当前是 A）时，按顺序判定：

| 顺序 | 条件 | 方式 | `track_started.transition` |
| --- | --- | --- | --- |
| 1 | A、B 的**源格式**不同（G1） | 格式边界：本流在 A 末尾结束，立即发 `format_boundary{next_entry_id: B, reason: "format"}` | （B 在接续流里由 zones 开始，不经本流） |
| 2 | 交叉淡化的条件全部满足（§3.1） | 交叉淡化 | `crossfade` |
| 3 | 播放区 `gapless` 为真 | 无缝 | `gapless`（即参考稿 §4.4 的 OnToNext） |
| 4 | 其余 | 间隔：A 放完后插 0.5 秒静音再接 B（§4） | `gap` |

**源格式**（G1，参考稿 §4.6）：采样率、位深、声道数、声道布局、样本类型（整数/浮点）都相等。来自扫描记录（管线设计 §4.1 的 `Track`）；第一批扫描没有声道布局，按声道数的默认布局比较。
参考稿还比较 DTS 与 MQA 子类型，ROOMusic 不支持这两种，不需要。格式相同的两首推导出的流格式必然相同（design-delivery.md §2.2），所以能放进同一条流。

- 格式边界时 B 的来源段立即关闭（zones 会为 B 开接续流，那边自己解码），本流读到 A 的末尾后冲刷链、关闭编码器；不登记 `stream_ended`（流没有放完队列，zones 靠 `next_stream` 接上）。
- B 准备失败（打不开、不可渲染）：在 A 的末尾帧登记 `track_failed{B, reason}`，再 `Cursor.Next(B)` 取下一首重判；连续 5 首失败就不再取，本流在 A 末尾结束并登记 `stream_ended`（zones 按派发的 5 条失败停下）。
- `Cursor.Next` 返回 false（没有下一首）：A 放完就结束，登记 `stream_ended`。

## 2. 短读换轨与等待超时（G2、G3）

`player.read(n)` 的换轨部分（参考稿 §7.1 的“短读 → 无缝换轨 → 递归补块”）：

```text
read(n):
  got = current.read(dst[0:n])                       # 来源段：已施加电平化
  if got == n or current 还没到结尾: return got 帧
  # 当前曲目读完（解码 EOF，或 CUE 数满帧数，或淡化截断点）
  switch 已判定的方式:
    无缝 / 间隔:
      wait = 等待 next 就绪（预缓冲 ≥33% 或已 EOF），最多 5 秒
      if 超时:
        立即发 format_boundary{next, reason: "not_ready"}；关闭 next；return got（本流到此为止）
      间隔时先补 0.5 秒静音（可能跨多次 read）
      登记 track_started{next, transition}，帧号 = 流内当前帧 + got（或静音之后）
      current = next；next = 空
      return got + read(n − got) 拼进 dst[got:]       # 递归补读，对调用方永远是整块
    格式边界 / 没有下一首:
      return got                                     # 短块，渲染循环据此冲刷并结束
```

- **逐位不变**：拼接只是把 B 的样本接在 A 后面写进同一个缓冲，没有任何运算；两段的 `Exact` 都为真时整块为真。链跨曲目连续运行，不复位。
- **递归只有一层**：B 本身不可能在补读里又读完（B 至少有 3.3 秒预缓冲，补读最多一个量子 200 ms）；遇到不足一个量子的极短曲目时循环处理，不靠递归深度。
- **等待超时 5 秒**（偏离参考稿 §4.6 的“无上限”，理由是参考稿自己的建议）：渲染领先播放头最多 20 秒，局域网本地文件打开解码通常在 100 ms 内，5 秒还没就绪说明出了问题；在边界结束本流后，zones 立即为 B 开接续流，输出端在本流放完时换上，听感是一次普通换曲。等待时间不计入处理速度。
- 下一首是 `repeat_one` 给出的同一条（`Cursor` 返回自己）：按普通的下一首处理，同源格式必然相同，无缝接上。

## 3. 交叉淡化（G5、G6，参考稿 §4.7）

### 3.1 条件（全部满足才淡化）

1. 源格式相同（不同时已是格式边界）。
2. 播放区 `crossfade` 为真（时长取 `crossfade_seconds`，3/5/8/12 秒，G7）。
3. **A 与 B 不是同一张发行**（`ReleaseID` 不同）。保留现有前端规则（`player-engine.ts` 的淡化计划）：同一发行内的曲目本来就该连着听，照常无缝。`repeat_one` 时 A、B 是同一首，也因此不淡化（现有前端单独判了 `repeat_one`，这里自然覆盖）。
4. 两首都允许淡化：A 的有效时长、B 的有效时长都大于淡化时长的 3 倍（参考稿“时长 ×3 小于有效素材时长”；现有前端只判了 A，这里两首都判）。
5. 本流的起点（定位、续流开的流）早于 A 的截断点；否则 A 已经过了淡化点，按 §1 的第 3、4 行换轨。

**有效范围**沿用现有前端：A 的有效结尾 `E_A` = 分析给出的结尾静音起点（有且大于 0 时），否则曲目时长；B 的有效起点 `S_B` = 开头静音长度（大于 0 且不超过 10 秒时，同前端 `MAX_LEADING_SKIP_MS`），否则 0。
有效时长：A 为 `E_A`，B 为 `时长_B − S_B`。参考稿在“结束前淡化时长”处截断；我们把“结束”取作有效结尾，是现有行为（淡进一段静音没有意义），不算退化。

### 3.2 截断点与窗口

```text
D    = round(淡化秒数 × 链采样率)                 # 窗口帧数
cut  = floor((round(E_A × 链采样率) − D) / 8) × 8   # A 的曲目内帧号，向下对齐到 8 帧
```

- 8 帧对齐来自参考稿（DSD 的字节边界）；PCM 不需要，但照做没有代价，以后 DSD 直通时也成立。`cut + D ≤ E_A`，窗口不会越过 A 的有效结尾。
- A 的来源段读到 `cut` 就当作“读完”（§2 的截断点），窗口里的 A 样本另外从 A 的来源段读出；窗口之后 A 的剩余样本丢弃，A 的来源段关闭。
- B 的来源段从 `S_B` 开始解码（输入侧 `-ss`；不要求逐位，淡入本身就改了样本）。

### 3.3 曲线

窗口内第 `k` 帧（`0 ≤ k < D`）：

```text
x        = k / D
淡入 g_in  = sqrt(sin(π·x/2))
淡出 g_out = cos⁴(π·x/2)
输出      = A[cut + k] · g_out + B[S_B 起第 k 帧] · g_in      # 两者都已施加各自的电平化增益
```

- `dsp/fade` 提供 `FadeIn(x)`、`FadeOut(x)`、`AlignDown8(frames)` 与 `Mix(dst, a, b [][]float64, start, total int)`（按窗口内的起始帧与窗口长度计算曲线，可以分多次调用跨量子混音），纯函数，不导入任何包。曲线每次现场按公式计算（不查表），保证与公式逐点一致。
- 窗口内的块 `Exact = false`，所以会按需加抖动（dither T3）。
- **“预热段 30%”**：参考稿只给了数字，没有定义它作用在哪里。我们的解释：它是参考稿平台层为“新曲目自己的处理（如每曲重采样）”预先跑一段、让滤波器进入稳态用的；ROOMusic 的共享链在混音之后跨曲目连续运行，每曲来源段里第一批没有滤波器（兼容性转换在 ffmpeg 里，ffmpeg 自己处理起始），所以**不需要单独实现**，曲线按上面的公式作用于整个窗口。
  `dsp/fade` 保留常量 `Warmup = 0.3` 与注释说明这一解释；若以后确认它是“旧曲目在窗口前 30% 保持原电平、之后再按 cos⁴ 淡出”，只改 `Mix` 里 `g_out` 的自变量一处。
- 交叉淡化不进信号路径（瞬时；信号路径只描述稳态，管线设计 §9）。

### 3.4 事件与分段

- `track_started{B, transition: "crossfade"}` 登记在窗口起点（流帧号 = A 的段起点 + `cut` − A 的曲目内起点）。
- B 的分段 `{entry_id: B, stream_start_seconds: 窗口起点, track_start_seconds: S_B}`；位置因此从窗口起点算 B 的第 `S_B` 秒，与现有前端“重叠部分只算新曲目”一致（计次在 zones，规则不变）。
- `time` 事件在窗口内报 B 的位置（分段表已切到 B）。

### 3.5 何时计划

取到 B 时（A 剩余“10 秒 + 淡化时长”）判定 §3.1 并算好 `cut`、`D`、`S_B`。B 必须在渲染位置到达 `cut` 前就绪；到 `cut` 时还没就绪就**放弃这次淡化**（不在 `cut` 处等待）：A 继续读到 `E_A` 之后的真实结尾，再按 §2 的无缝/间隔路径处理（这时 B 多半已经就绪；仍不就绪就走 `not_ready`）。这样淡化只是“锦上添花”，不会因为 B 慢而把流截断。

## 4. 设置与“关闭无缝”（G4、G7）

- 设置都在 `playback_zones`（zones 迁移已建）：`gapless`（默认 true）、`crossfade`（默认 false）、`crossfade_seconds`（3/5/8/12，默认 5）。会话开流时从 `RenderSpec.Settings` 读，会话内不变；改设置由 zones 去抖重建。
- **关闭无缝**时在曲间插入 0.5 秒静音（`transition: gap`），仍在同一条流里，锁屏不受影响；0.5 秒接近旧的双元素轮换在曲间的停顿。交叉淡化的条件满足时优先淡化（淡化本身就不是无缝）。
- 静音样本是精确的 0，不影响 `Exact`。

## 5. `NextChanged` 的处理

zones 在队列变化使“已取走的下一首”失效时调用 `NextChanged()`（不阻塞，只置标志）；渲染循环在下一个量子前处理：

| B 的状态 | 处理 |
| --- | --- |
| 还没取（离结尾还远） | 无事；到时候 `Cursor.Next` 自然取到新的下一首 |
| 已取、来源段在准备，但 B 的样本**还没进入链**（无缝时 A 还没读完；淡化时还没到 `cut`） | 悄悄换掉：关闭 B 的来源段，`Cursor.Next(A)` 重取并按 §1 重判（可能变成淡化、无缝、间隔、边界或没有下一首）；不发任何事件 |
| 已宣布格式边界或 `not_ready`、本流还没结束 | 本流仍在 A 末尾结束（边界已经交给 zones，不收回）；重取下一首并**再发一次** `format_boundary`（新的 `next_entry_id`），zones 以最新一条替换接续流（父设计 §8 第 3 条） |
| B 的样本**已进入链**（拼接点或淡化窗口已经写进编码器） | 发 `rebuild_needed`（立即事件），由 zones 按当前播放位置重建 |

- “进入链”以渲染循环为准，而不是播放头：已经编码发出的字节收不回来。渲染最多领先 20 秒，所以只有在曲目结尾前约 20 秒内改了下一首才会重建。
- 一次 `NextChanged` 期间又来新的，只处理一次（标志合并）。

## 6. 测试范围（只测改动直接影响的行为）

合成素材都由 ffmpeg `lavfi` 现场生成（44.1 kHz/16 bit 立体声），不进仓库；假 `TrackSource` 提供曲目信息，不需要数据库。

- **逐位拼接**（prd 验收 1）：10 秒 997 Hz 正弦切成两半（切点不在 200 ms 网格上），两首无缝渲染成 FLAC 流，解码后的 PCM MD5 等于整段的 MD5。电平化关。
- **格式边界**（验收 2）：44.1 kHz 后接 48 kHz：取到下一首时发出 `format_boundary{reason: "format"}`，流在第一首末尾结束，流的帧数等于第一首的帧数，没有错误。
- **曲线与截断**（验收 3）：`dsp/fade` 在 x = 0、0.25、0.5、0.75 处的 `FadeIn`/`FadeOut` 与公式相差 < 1e−12；`AlignDown8` 的结果是 8 的倍数且 `cut + D ≤ E_A`；两个常数信号（1.0 与 0.5）分三次调用 `Mix` 跨量子混音，抽查窗口内几个帧的输出等于公式值。
- **淡化条件**：同发行 → 无缝；不同发行 → 淡化，`track_started` 带 `crossfade` 且帧号在窗口起点；A 时长不足 3 倍 → 无缝；`crossfade` 关 → 无缝；`gapless` 关 → 0.5 秒静音与 `gap`。
- **超时**（验收 4）：下一首的假解码一直不出数据，5 秒后（时钟注入）发 `format_boundary{reason: "not_ready"}`，流正常结束。
- **`NextChanged`**：A 读完前调用 → 用新的下一首拼接、没有 `rebuild_needed`；拼接点已写进编码器后调用 → 发一次 `rebuild_needed`。
- 不测：曲线的听感、不同淡化时长的组合、极短曲目的各种排列。
