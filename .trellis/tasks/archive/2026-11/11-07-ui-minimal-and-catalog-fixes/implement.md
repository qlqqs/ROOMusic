父任务本身不改代码，只负责：排定子任务的顺序和并行方式、跨子任务验收、收尾。

## 顺序与并行

所有工作都在同一个工作区的 `main` 上进行，不开 worktree。

**并行规则**：
- Sol 测某一层时，这一层不能有别的改动正在进行：测前端（Vitest、Playwright、构建）时没人改前端；跑 DB 集成测试时没人改后端。另一层可以照常改。
- 接口样本只由 Sol 录，实施者不录。
- 有接口变化的子任务，后端、前端和样本放在同一个提交里。前端契约测试要求“每个样本都有契约”，`genre` 改名后旧解码器又会报缺字段，所以分开提交会让中间那个提交测试失败。
- 提交时只暂存本项的文件。工作区里另一层正在进行的改动留在暂存区外；`git status` 出现说不清来源的改动时，先停下来核对。

## 每项的验收门

1. 实施者回报改动文件、typecheck、vet 和已跑测试的结果。
2. Sol 补改直接相关的测试，只跑受影响的用例，回报命令和结果。
3. 主会话审阅 diff：对照 PRD 验收，看有没有多余的说明文字、多余的测试和兜底。不通过就写明问题打回原 agent。
4. `git diff --cached --check` 干净后，用中文信息提交。

## 收尾（父任务）

1. 跑一次现有的真实服务用例（`scripts/playback-e2e.sh` 和 `frontend/e2e/real/`），由 Sol 执行（X2），不另加用例。运行前先停掉其他 `roomusic-test` DB。
2. Sol 拍 1440 和 375 截图，放 `research/after/`，与 `research/baseline/` 对照。主会话先自己审一遍布局，再交用户确认（X1）。
3. 核对规范与实现一致（X3）。
4. 在各子任务 PRD 里写实施结果，依次归档 5 个子任务，最后归档父任务（`task.py archive <name> --skip-branch-validation`）。
5. 归档后修正相对链接，和 journal 放在同一个提交里。

不另做演练或预演；只有局部验证失败需要定位时才扩大测试范围。
