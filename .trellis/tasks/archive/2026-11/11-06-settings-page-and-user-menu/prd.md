# 设置页、侧边栏用户菜单与删除备份

## 目标

1. 管理员可以在界面上删除不再需要的备份文件（单份或批量），并在界面上设置自动保留规则（保留天数、保留份数），不必登录服务器或改环境变量。
2. 新增独立的设置页，把账号（修改密码）和配置类的管理页面（扫描目录、成员、操作记录、备份）收进去，侧边栏只留日常要用的入口。
3. 侧边栏底部的当前用户区改成 ChatGPT 左下角那种样式：一行头像 + 用户名，点开向上弹出菜单（设置、退出登录）。

## 已确认的事实（代码现状）

- 备份：后端 `backend/internal/backup/httpapi/handlers.go` 只有 `GET/POST /api/v1/system/backups` 与 `GET /api/v1/system/backups/{name}`（下载）；文件名由 `FileNamePattern`（`backend/internal/backup/files.go:19`）约束，`OpenBackup` 用 `os.OpenRoot` + `O_NOFOLLOW` 防目录穿越与符号链接；`retain()` 会按 `KeepDays` 自动清理过期备份；正在进行的备份是 `.partial` 临时文件，不在列表里。备份操作不进“操作记录”，只写 slog。
- 前端备份页：`frontend/src/app/routes/backups-page.tsx`（状态区段 + 文件区段 `frontend/src/features/system/components/backup-files-section.tsx`，表格每行只有“下载”）。
- 侧边栏：`frontend/src/app/shell/app-shell.tsx` 宽屏底部、窄屏菜单对话框里都渲染 `IdentityPanel`（`frontend/src/app/shell/identity-panel.tsx`：用户名、角色标签、修改密码按钮、退出登录按钮，退出失败显示 FailureNotice）。
- 导航：`frontend/src/app/shell/nav-items.ts`，“资料库”分组有扫描目录、元数据问题、待认领、可能是同一位、成员、操作记录；“系统”分组只有备份。
- 修改密码：`ChangePasswordButton` + `ChangePasswordDialog`（`frontend/src/features/auth/components/change-password-dialog.tsx`），所有角色可用。
- 已有共享组件：`MenuButton`（`frontend/src/shared/ui/menu-button.tsx`，门户浮层菜单）、`ConfirmDialog`、`ModalDialog`。
- 站内多处链接指向旧地址：`/library`、`/library/scans/$scanId`、`/members`、`/operations`（含 `artist`/`release`/`group`/`page` 查询参数）、`/system/backups`，见 `member-summary.tsx`、`scan-detail.tsx`、`scan-summary.tsx`、`root-summary.tsx`、`scan-section.tsx`、`scan-history-section.tsx`、`active-scan.tsx`、`artist-admin-actions.tsx`、`release-history.tsx`、`operations-view.tsx`、`album-list-view.tsx`。

## 已定决策（用户 2026-11-06 选择）

- D1 设置页形式：独立页面 + 左侧分栏，每栏有自己的地址，刷新、返回不丢位置。
- D2 放进设置的范围：配置类进设置（扫描目录、成员、操作记录、备份）；元数据问题、待认领、可能是同一位这类待办留在侧边栏“资料库”分组。
- D3 “重置密码”指当前账号自己的修改密码（截图里的“修改密码”），放在设置的“账号”栏；管理员给成员重置密码仍在“成员”栏里。
- D4 批量删除与保留规则界面纳入本任务（用户 2026-11-06 追加）。
- D5 保留规则：“保留天数”与“保留份数”都是上限——超过 N 天的删，多于 M 份时删最旧的；两项都可设为“不限”；最新一份永远不自动删除。
- D6 生效时机：保存时立即按新规则清理；若会删掉已有备份，保存前确认框说明将删除几份，确认后清理；不会删时直接保存。
- D7（主会话按易用性默认，用户可在摘要审阅时改）：界面保存过的规则优先，环境变量 `ROOMUSIC_BACKUP_KEEP_DAYS` 只在从未保存时作为默认天数；份数默认“不限”，天数默认 14，升级后行为不变；四种来源的备份都计入规则；批量删除用行勾选 + 表头全选 + “删除所选（n）”，部分失败时列出没删掉的几份。

## 需求

### R1 删除备份（后端 + 前端）

- 管理员可以删除列表里的任意一份备份（定时、手动、迁移前、恢复前均可）。
- 需要同源校验 + 管理员鉴权；文件名必须符合 `FileNamePattern`，只能删备份目录下的普通文件，拒绝符号链接与目录穿越。
- 文件已不存在（被自动清理或重复删除）时按“备份不存在”处理，前端刷新列表即可，不当成严重错误。
- 删除成功写一条 slog 日志；不进操作记录。
- 前端每行在“下载”旁加“删除”，点了弹确认框，确认框说明一句“删除后不能恢复。”；删除中按钮忙碌；成功后列表刷新；失败（如目录不能写入）在确认框里提示，可重试或取消。
- 文件已经不在（404）不算失败：关闭确认框、刷新列表即可，界面不显示错误。
- 删除最新一份会让“上次成功”退回到剩下最新的那份；若当天备份时刻已过，调度器会在 10 分钟内自动补做一份（与在服务器上手工删文件一致）。

### R1b 批量删除

- 备份表每行一个勾选框；表格上方一行“全选”勾选框（表头在窄于 640px 的容器里会隐藏，所以不放表头）；有选中时旁边出现“删除所选（n）”。
- 点后弹确认框：“删除 n 份备份？”，正文“删除后不能恢复。”；确认后逐份删除，删除中按钮忙碌。
- 全部成功：对话框关闭、列表刷新、勾选清空。部分失败：对话框不关，列出没删掉的几份（时间），再点“删除”只重试剩下的；其余已删的从列表消失。已不存在的算成功，不列为失败。
- 列表刷新（如轮询）后，已经不在列表里的勾选自动去掉。

### R1c 保留规则

- 设置 › 备份页增加“自动清理”区段：保留天数（1–3650 或“不限”）、保留份数（1–1000 或“不限”），两项都是上限（D5）；最新一份永远不自动删除。
- 保存：后端先算出按新规则会删除的备份数；为 0 时直接保存；大于 0 时前端确认框“将删除 X 份旧备份。删除后不能恢复。”，确认后保存并立即清理（D6）。确认期间若文件变化，以保存时实际清理结果为准，并刷新列表。
- 自动清理仍在每次备份成功后执行，按当前规则。
- 规则保存在备份目录里的规则文件（`.roomusic-backup-retention.json`），重启或恢复数据库都不改变规则；换备份卷后回到默认值。从未保存时用环境变量 / 默认值（D7）。
- 规则文件损坏时跳过自动清理，界面显示“没能读取当前设置。”，重新保存即可覆盖修复。
- 保存成功但个别旧备份删不掉时，界面提示“有 n 份旧备份没能删除。”
- 降级风险：旧版本不认识规则文件，只按环境变量清理；设过“不限”的，降级前要先调大 `ROOMUSIC_BACKUP_KEEP_DAYS`。写进部署文档。
- 保存与立即清理写 slog；不进操作记录。

### R2 设置页

- 新地址前缀 `/settings`，`/settings` 默认进“账号”。视口 ≥1024px 用左侧分栏；<1024px 改为内容上方一行横向分栏链接（768–1024 之间外壳已有主侧栏，再放分栏内容区太窄）。各栏：
  - 账号（所有人）：用户名、角色、修改密码。
  - 扫描目录（管理员）：现 `/library` 页面内容；扫描详情 `/library/scans/$scanId` 一并迁到设置下。
  - 成员（管理员）：现 `/members`。
  - 操作记录（管理员）：现 `/operations`，保留全部查询参数。
  - 备份（管理员）：现 `/system/backups`，含 R1 的删除。
- 成员访问管理员栏目时与现在一样被拦（AdminGate）；成员的设置页只看到“账号”。
- 旧地址（`/library`、`/library/scans/$scanId`、`/members`、`/operations`、`/system/backups`）重定向到新地址，查询参数与 hash 原样带过去，旧书签不失效；重定向在登录检查之前发生，所以未登录时登录页记住的回跳地址就是新地址。
- 站内所有指向旧地址的链接改指新地址。
- 侧边栏去掉扫描目录、成员、操作记录、备份四项和“系统”分组；“资料库”分组保留元数据问题、待认领、可能是同一位。
- 用户文档同步：`README.md`（备份可删除、可设保留规则）、`deploy/production/README.md`（“系统 › 备份”改为“设置 › 备份”，补删除与保留规则；`ROOMUSIC_BACKUP_KEEP_DAYS` 改为“网页上从未设置过时的默认天数”；降级提示）、`deploy/production/example.env` 该变量注释同步。

### R3 侧边栏用户菜单（ChatGPT 式）

- 宽屏侧栏底部固定一行：圆形头像（用户名首字）+ 用户名，旁边小字角色；整行是一个按钮。
- 点击后在按钮上方弹出菜单：设置、退出登录（带图标）。键盘可打开、上下移动、Esc 关闭并回到按钮。
- 当前在设置页时，这一行有“当前”样式提示。
- 退出失败仍要提示并可重试，不假装已退出。
- 窄屏菜单对话框里同样用这一行用户按钮，选“设置”后关闭对话框并进入设置页。
- 原来侧栏里的“修改密码”按钮去掉（入口移到设置 › 账号）。

## 界面文案约束

- 不写防御性说明（权限、隔离、安全、实现细节）；标题、按钮和数据已经说清楚的不加描述段落。
- 必要说明一句日常话：如删除确认框“删除后不能恢复。”
