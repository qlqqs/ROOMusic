# 记录真实音乐目录长期事实

## Goal

将项目根目录下的 `music/` 包含真实音乐资产这一事实写入 Trellis 项目长期记忆，避免后续开发、测试或自动化任务把它误当作可随意清空的 fixture 目录。

## Background And Confirmed Facts

- 已通过仓库检查确认：`music/` 下存在大量真实音频文件，当前可见格式包括 `.flac` 和 `.m4a`，并包含专辑封面、CUE 等配套文件。
- 根目录 `.gitignore` 已将 `/music/` 排除在版本控制之外；这不改变其在本地工作区中的真实资产属性。
- 现有项目规范要求音乐目录默认只读，CI 不读取真实音乐目录，测试使用小型合成或专用 fixture。

## Requirements

- 在 `.trellis/spec/guides/` 增加项目级长期记忆文档，明确 `music/` 是本地真实音乐资产目录，而不是测试 fixture、构建产物或可删除缓存。
- 在共享规范索引中增加该长期记忆文档的入口，确保后续会话能从 Trellis 指南索引发现它。
- 记录最低限度的操作边界：默认不得移动、改名、覆盖或删除 `music/` 内容；测试和 CI 不应依赖或扫描该目录；需要真实媒体验证时必须显式、只读并避免泄露完整路径或媒体内容。
- 本任务只修改 Trellis 文档，不修改产品代码、扫描逻辑、CI 工作流或音乐资产本身。

## Out Of Scope

- 不清点、重命名、整理、转码、删除或复制 `music/` 内的任何文件。
- 不把真实音乐目录接入自动化测试、CI、演示数据或生产默认配置。
- 不建立音频播放、媒体索引或版权管理能力。

## Acceptance Criteria

- [x] `.trellis/spec/guides/` 中存在中文长期记忆文档，并明确写出 `music/` 包含真实音乐资产。
- [x] `.trellis/spec/guides/index.md` 提供该文档的可发现入口，且文档链接有效。
- [x] 长期记忆文档明确只读、测试/CI 隔离和敏感信息不泄露边界。
- [x] `music/` 文件内容未发生变化；任务 diff 仅包含任务规划及 Trellis 文档变更。
- [x] 通过 Markdown 链接检查或等价的仓库级文档校验。

## Planning Decision

- 路线：human selection
- 选择者：用户
- 选择结果：批准按上述最小范围写入项目级长期记忆（2026-09-02）。
- 选择理由：项目事实需要进入可被后续会话加载的 `.trellis/spec/`，同时保留明确的只读和测试隔离边界；不扩大为代码或媒体管理任务。

- `prd.md`：已完成轻量任务规划，包含目标、确认事实、范围、边界和验收标准。
- `design.md` / `implement.md`：不需要；本任务为 PRD-only 文档记录。
- 当前状态：实现与质量检查完成，准备提交并归档任务。
- 验证记录：索引 12 个相对链接均有效；`git diff --check` 通过；`music/` 无 Git 状态变化；应用 lint/typecheck/测试不适用，因为本任务仅修改 Markdown 文档。
