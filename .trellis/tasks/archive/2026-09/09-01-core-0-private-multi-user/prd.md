# Core 0 私有多用户管理

## Goal

在单管理员闭环之上增加普通用户创建禁用、会话撤销和只读权限矩阵

## Requirements

- 前置依赖：首个纵向切片的单管理员 setup、session 和管理端点合同已稳定。
- 管理员可以创建普通用户、禁用/启用普通用户并撤销其活跃会话。
- 所有用户共享同一音乐库；普通用户只能登录、浏览、查看非敏感扫描状态和搜索。
- 普通用户不能注册目录、触发扫描、查看敏感路径诊断或执行持久化管理操作。
- 禁用用户与会话撤销必须在下一次请求立即生效；前端角色状态只影响展示，不承担授权。

## Acceptance Criteria

- [ ] 管理员创建的普通用户可以登录并浏览共享音乐库。
- [ ] 普通用户对所有管理端点的越权请求均被后端拒绝。
- [ ] 用户禁用和会话撤销在下一次请求生效，并具有自动化权限矩阵验证。
- [ ] 普通用户 DTO 和日志不泄露完整服务器路径或敏感诊断。

## Out of Scope

- 细粒度 ACL、独立用户音乐库、邀请系统、密码重置邮件、SSO 和播放偏好。

## Confirmed Facts

- 当前 `users` 只有用户名和密码哈希，没有角色或禁用状态；`sessions` 只有撤销时间和过期时间。
- `authenticatedUser` 只返回用户 ID，目录、扫描和诊断端点目前统一按“已登录”放行。
- 前端会话 DTO 只有 `username`，主页面默认按管理员展示目录注册、扫描和目录列表操作。

## Key Decisions

- 角色模型采用 `admin` / `user` 两级，首个 setup 用户为管理员；普通用户共享同一只读音乐库。
- 授权以后端会话中的用户状态和角色为准；禁用用户在认证查询阶段立即失效，撤销会话通过现有 `revoked_at` 机制立即生效。
- 管理员用户管理使用版本化 REST 端点和稳定错误码；普通用户只保留登录、登出、会话查询、库浏览、Release 详情、封面读取和搜索。

## Open Questions

无阻塞问题。密码最小长度沿用现有 12 字符规则；用户管理界面保持 Core 0 的最小可用形态。
