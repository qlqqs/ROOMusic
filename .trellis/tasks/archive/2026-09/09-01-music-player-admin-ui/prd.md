# 音乐播放器管理界面

## 目标
将现有 ROOMusic 单列原型重构为可直接使用的音乐库管理与播放工作台。管理员能管理用户、音乐目录和扫描；所有用户能搜索发行版本、查看详情，并通过固定底部播放器获得清晰的播放状态反馈。

## 背景与已确认事实
- 前端技术栈为 React + TypeScript + Vite，入口为 `frontend/src/main.tsx`，样式为 `frontend/src/styles.css`。
- 后端已有 setup/login/logout、用户、library roots、扫描、发行版本列表/详情与 artwork REST 接口。
- 用户选择保留现有 API 工作流并进行界面重构；不新增后端协议。
- Core 0 产品约束：工作型私有音乐库、后端负责权限、前端只做展示与交互状态。

## 范围内
- 登录/首次设置视图的视觉重构，保持原有提交行为。
- 登录后的应用壳层：侧栏导航、顶部搜索、用户信息与退出操作。
- 媒体库浏览：发行版本网格/列表、结果计数、加载/错误/空状态、详情抽屉或主面板。
- 播放工作区：当前播放条、播放/暂停、上一首/下一首、进度展示、队列摘要（前端本地状态，不持久化音频）。
- 管理员工作区：用户管理、目录注册/停用/恢复、扫描启动与状态、操作历史；沿用现有请求与反馈。
- 响应式布局，桌面三栏收敛为移动端上下堆叠；键盘可操作和语义标签。

## 范围外
- 真实音频文件播放、音频流服务、收藏/播放历史持久化。
- 新增 REST endpoint、数据库迁移、GraphQL、PWA 或第三方搜索服务。
- 多页路由系统；继续使用单个 React 应用与 URL 查询参数搜索。

## 验收标准
1. 已登录用户首屏可见导航、搜索、媒体库结果和底部播放控制；管理员可进入管理区。
2. 发行版本列表、详情、封面、搜索、加载/错误/空状态继续由现有 API 驱动，操作失败有可见且可恢复反馈。
3. 管理员可完成用户创建/启停/撤销会话、目录注册/停用/恢复、扫描启动，且原有请求参数与权限边界不变。
4. 播放控制在无音频后端时以本地演示状态工作，点击歌曲可更新当前曲目和进度显示，不声称已播放真实音频。
5. 视口宽度 375px 与桌面宽度下无横向溢出，控件文字不重叠；表单、按钮、列表具备可访问名称与焦点状态。
6. `npm run typecheck`、`npm run lint`、`npm run build` 通过；现有 API 测试继续通过。

## 风险与延期
- 真实播放能力延期为后端音频服务接入时的独立任务；当前通过“演示播放状态”明确边界。
- artwork 可能缺失，封面区域必须提供稳定占位，不影响列表扫描。
- 管理数据量较大时暂不引入分页 UI，沿用现有 page_size=50。
