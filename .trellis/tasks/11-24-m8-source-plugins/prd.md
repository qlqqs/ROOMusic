# 第三方数据源插件

父任务 `11-24-m8-devices-artists-plugins`，决定 W7（插件只扩展数据源）。调研：`research/wasm-hosting.md`。
技术设计见 `design.md`，执行顺序见 `implement.md`；裁决写成 `docs/architecture/adr/0007-source-plugins.md`（本任务新增，修订 ADR 0006 的 U4）。

## 目标

管理员可以安装第三方写的数据源插件，给自动整理补充内置来源没有的资料：封面、歌词、艺人图片、艺人简介。
插件在沙箱里运行，只拿到宿主分配的能力：不能自己联网、读文件或拿到别的密钥；所有外部请求经宿主转发，照常受开关、限速、缓存、mock 替换与出站策略约束。

用户价值：内置来源覆盖不到的地区与语种（例如某个只有中文资料的站点）可以由社区补上，不必等 ROOMusic 发版。

## 现状

- ADR 0006 U4：外部源是编进程序的适配器，不建插件宿主；架构决策摘要“扩展边界的两步走”的第二步是把稳定接口升级为类型化合同并建宿主。
- 外部源已有统一的声明（能力、密钥、限速、默认开关）、设置页开关与密钥行、请求器（限速、缓存、重定向逐跳检查、mock 替换）、自动整理的写入与撤销。
- 能力接口以 MusicBrainz ID 为入口：封面（发行或发行组 MBID）、歌词（标题、艺人、专辑、时长）、艺人图片与简介（艺人 MBID 与链接）。

## 需求

- R1 运行时：插件是 WebAssembly 模块，进程内用 Extism（go-sdk）+ wazero 运行；不需要 CGO；所有 Extism 类型封在一个适配层里。
- R2 沙箱：插件没有文件系统、环境变量、套接字；Extism 内置的 HTTP 一律拒绝；唯一的出网通道是宿主函数 `upstream_fetch`。每次调用新建实例，内存上限 64 MiB，单次调用 10 秒超时，每个插件同时最多 2 个调用。
- R3 出网：插件在清单里声明上游（标识、基础地址、请求间隔）与密钥（名字、放在请求头还是查询参数）。插件只传上游标识、方法（GET）、路径与查询；宿主拼地址、按 `PublicOnly` 出站、限速、缓存、设 UA、注入密钥（插件看不到密钥的值），设了 `ROOMUSIC_UPSTREAM_MOCK_URL` 时改指 mock 的 `/plugins/<插件>/<上游>` 前缀。
- R4 能力：第一版支持封面、歌词、艺人图片、艺人简介四种；插件按导出的函数声明能力。插件给出的图片只返回地址，宿主下载并校验。返回值按大小与字段校验，简介去 HTML。
- R5 接入自动整理：每个启用的插件就是一个外部源，出现在“设置 › 自动整理 › 外部源”里，有开关与密钥行；在各能力的优先级里排在内置来源之后。写入、记录、撤销、抑制与内置来源完全相同，来源记为 `plugin:<插件标识>`。
- R6 安装：管理员在设置里上传插件包（zip：`manifest.json` + `plugin.wasm`），看到名称、作者、版本、能力、要访问的上游地址与密钥后确认安装；默认不启用。包存到数据目录的 `plugins/`，记 SHA-256；文件被替换（哈希变化）时自动停用，需要重新确认。可以停用、删除；删除时撤销它写入的内容由管理员另选（按来源撤销已有）。
- R7 示例插件：仓库带一个用 Go（`GOOS=wasip1`）写的示例插件，访问 mock 服务器上的一个示例上游，提供歌词与艺人简介；附插件开发说明（清单格式、导出函数与 JSON 约定、宿主函数）。
- R8 ADR 0007 写明上述裁决，修订 ADR 0006 的 U4 与架构决策摘要的“两步走”。

## 验收

- A1 安装示例插件 → 设置页出现、默认关；打开后自动整理用它补上内置来源没有的歌词与简介，整理记录的来源是插件，可按来源撤销。
- A2 沙箱：测试插件尝试 Extism 内置 HTTP、WASI 文件与套接字、访问未声明的上游、超大返回、死循环、超内存，都被拒绝或终止，宿主不崩、其他插件不受影响。
- A3 出网：插件请求经宿主限速与缓存；密钥只出现在发往上游的请求里，插件拿不到；mock 变量设了时插件的上游改指 mock。
- A4 完整性：替换 `plugin.wasm` 后插件自动停用并提示重新确认；清单与包格式错误时安装被拒并说明原因。
- A5 总开关或插件开关关闭时，插件不被调用、不发请求。
- A6 生产镜像（只读根文件系统、`cap_drop: ALL`）里插件能运行（wazero 编译器或解释器模式），编译缓存放在数据目录或内存。
- A7 前端：安装（上传、确认页）、列表、开关、删除、哈希变化后的提示；390 与 1440 两种宽度。

## 不做

- 发行与录音匹配类插件（匹配规则与外部 ID 体系牵涉太广，另议）。
- 插件仓库、在线目录、签名校验（第一版只记哈希，手动安装）。
- 界面扩展、输出设备、格式解析器类插件（W7）。
- 插件自己的定时任务、键值存储、配置界面（第一版只有密钥）。

## 规划决定

路线：人工选择，qlqq 于 2026-11-24 预先授权“规划完直接实现”（父任务 W1）；W7 由 qlqq 选定，其余默认值由主代理取定，交付时列出。

| 编号 | 决定 | 理由 |
| --- | --- | --- |
| K1 | WebAssembly 沙箱（Extism + wazero），不用独立进程 | 独立进程与宿主同等系统权限，能自行联网读文件，不满足“能力由宿主分配”；Navidrome 生产使用同一组合；PDK 覆盖 Rust、Go、JS |
| K2 | 只开放 `upstream_fetch`，关掉 Extism 内置 HTTP | 内置 HTTP 不防 SSRF、不复核重定向、失败会弄坏实例（Navidrome 因此出过两次漏洞） |
| K3 | 密钥由宿主注入请求，插件看不到 | 插件代码不可信；即使插件只能访问声明的上游，也不该能读出密钥 |
| K4 | 第一版只做封面、歌词、艺人图片与简介 | 输出简单、可校验，与内置来源的写入完全复用；匹配类能力牵涉外部 ID 与强证据规则 |
| K5 | 插件排在内置来源之后 | 内置来源经过审查；插件补的是内置来源没有的 |
| K6 | 手动上传安装，只记哈希，不做签名 | 同类项目（Navidrome、Jellyfin）也没有签名；先把沙箱做扎实 |
| K7 | go-sdk 停更的风险由适配层承担 | 需要时可以换成 fork 或直接用 wazero 实现同一套 ABI |
