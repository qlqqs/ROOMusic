# 整理链 E · 模型兜底设计

本设计已审阅，并按 D16 计数与 0091 回退的两项约定实施。依据是父任务的[决定与验收](../11-25-curation-chain/prd.md)、[设计第 6、7 节](../11-25-curation-chain/design.md)及 ADR 0006 第 9、16.6 节。路径以仓库根目录为准。程序先给结论，模型处理仍有出路的项。一次处理可以产生可撤销的写入、保持本地原样或因暂时故障稍后重试。管理员设每日预算；模型用量本身不作优化指标（U8、U10）。

## 2. 领取、输入与提交

调度器先取种类，再取该种类下的目标。同批默认沿用 5 项上限。领取只预留行；后台指定当前项，查询、提交、审查和用量都归到它。多步任务按批内次序处理，共享艺人资料和来源缓存，只让提交工具处理当前项。同艺人分组用已解析的署名身份；合辑或没有确定艺人的项按发行单独处理。多步批在同一后台会话开始每项时向管家交付该项的消息，完成或放弃就结束这一项的循环，再开始下一项，避免一组用完同一份步数。已经落库的结果保留，停止时释放尚未开始的项。每次转路线都在事务内核对原领取会话、路线和证据摘要，清除领取与本档重试信息；重启仍按行上的路线恢复。

| 任务 | 领取、打包与首条消息 | 工具、结论与去向 |
| --- | --- | --- |
| 第一档选择 | 领取有可用候选的 `release_match` 或 `recording_match`，发行与录音分批。程序复用现有候选快照、来源缓存及后台 Finder 按编号补齐详情。每项列本地真实性、标题、艺人、逐碟曲序与时长、冲突、搜索是否截断；每个可选编号列标题、署名和**完整**逐碟曲目（位置、曲名、录音编号、时长或缺失）。录音候选列相应的单曲资料。失效编号剔除，暂时读失败按来源退避。先缩批使消息装得下，单项仍无法完整呈现则升级 | 用开启者的同一 provider 发**一次**主模型请求，关闭所有工具和原生搜索，按严格 JSON 收 `items:[{item_id,decision:"select",external_id} 或 {item_id,decision:"upgrade"}]`。提示模型比较整张结构、指出没有合适候选时升级。校验本批、每项唯一、集合完整，只接受发给该项的编号。选定交第 3 节；升级进 `waiting_route/lookup`。一批只有一次主调用、零工具，另需审查的项独立送审。格式错误按无有效提交收尾，不从自由文本提取编号 |

| 核对判断 | C 的有效署名提案、身份已结构确认后产生的真实值差异，及 D 将提交的问题清单。按同一判断类型打包。首条消息逐项列目标、角色与位置、原值和拟改值、结构依据、后端取到的外部值或库内样本。原有 `release_merge` 仍属 verify，单独打包，沿用它的双方对应、录音集合与合并后曲序预览 | 管家仅开放提交判断，发行并入批仅开放既有并入提案/放弃。提示只判断身份或明确的错字，不统一风格、不翻译标题。每个判断返回 `item_id, verdict, reason`；身份取“同一、不同、拿不准”，纠正取“错字、写法差异、译名差异、拿不准”。说明特殊原名应保留。一次提交后即结束该项主判断，沿用管家单次运行 24 步、400000 token 的总保护，不套 D16 的检索额度。不同、写法或译名差异不改；有具体修改主张但证据缺失时按 D17 转 web，其余按第 4、5 节处理。模型同意只产生可审的提案 |

`FinishUnlisted(itemID, identityDigest, conversation, reason)` 要求发行或录音项仍处于相应路线的 `in_progress`，在同一事务校验当前识别摘要、结束待定项并把发行工作状态置为 `unlisted`。由 C 负责 90 天后仅程序重查一次及手动重查。核对、艺人资料或被否决的具体修改用各自的终态，不把有对应的专辑标成未收录。

新增核对项沿用待定表的领取和恢复。以提案编号或“目标、字段、拟改值、证据摘要”派生稳定项键，核对项单独按键唯一，调整原先按发行与种类唯一的部分索引，允许同发行多条署名或纠正。C 的提案只在 `open`、摘要匹配且原外部对应操作仍生效时转为可领项；提交前再核对角色、人数、位置与当前对象。确认同位身份且证据成立时写艺人对应，两个本地身份确实满足第 4 节时再合并；逐项记录 `accepted/declined/stale`，交 web 的保留原提案引用直到结清。D 可用相同入口交目标及候选值。冻结该项证据键，相同输入的程序重判跳过已结清项，输入或佐证变化才产生新判断。

## 3. D4 由 ModelMatcher 决定免审

`program.ModelMatcher.Plan/readMatch` 已校验编号与读回类型、发行摘要、碟数、位置、曲数、已有对应和抑制。当前调用 `comparison.compareTracks` 后只取配对、曲数及位置，丢掉了时长反证；单曲读回编号就建立配对。两个识别档共用一次 Plan，返回写入预览和后端生成的核对结果，包含本地/外部曲数、可比及命中数、超差曲位与差值、文字与硬冲突。该结果也供审查证据读取器独立重算。

- 专辑按碟和位置一一配对，外部明细完整、总数及各碟曲数相等、总数大于 4。至少一对有可比时长，**所有可比对**均在 `compareLength` 的容差内（含边界，取 3 秒与外部时长 1% 的较大值）。零可比进审查。复用比较循环暴露计数，区分 D4 与程序识别已有的“至少半数可比”规则。保留识别出的反证，如标签编号与真实文字全面矛盾。1–4 首的专辑走审查；散放单曲按录音核对。
- 单曲必须确为一条本地录音，逐项通过时长、标题和艺人规范化相等。缺失、占位、无法配对或三者之一不合均不能免审。编号不合法、已有不同生效对应、撤销抑制、目标失效等继续由写入口拦截；审查不能授予无法执行的配对。
- 完整通过时，由后端直接调用已校验的 `ModelMatcher.Apply → writeMatch`，复用建对应、补缺、强证据归组、目录锁内摘要复核与派生幂等键。结论及受治理操作记模型、来源、选定编号、`verification=album_structure|recording_duration_text` 和计数。直接执行的权限绑定到该项和该版 Plan。
- 未完整通过时，把逐曲反证及其它独立依据送现有独立审查，记录 `verification=independent_review` 与审查编号。短专辑、时长资料不全仍可能凭独立标识获批。批准后后端再次核对：明确时长或真实文字反证仍在且没有独立正证解释该候选时，策略拒绝；“模型选了它”和“审查也同意”不能互相佐证。拒绝或拿不准直接结项留建议。核对与审查均在首个对应、厂牌或归组写入之前，避免先产生衍生错连再否决。

## 4. 哪些佐证可以用于哪种写入

| 佐证 | 后端取得与核实 | 可写范围 |
| --- | --- | --- |
| 外部 | 读取生效的外部对应及未撤销的来源操作，经来源闸门按准确对象 ID 取发行、录音或艺人详情，比较具体字段、署名位置及别名。来源带对象、字段、原值和本次核对方式。艺人身份继续核验 MB/Wikidata 的对象类型 | 模型选取且核实的外部字段为 3 级；程序强证据写入为 4 级。事实类字段（年份、厂牌、目录号、条码等）只收该外部对象实际给出的值 |
| 库内 | 从真实标签或人工确定的有效事实重读本地 ID、署名与曲目数。两艺人各有规范化同名且曲目数相等的发行，或同一发行的不同曲目中两名出现在同一署名位置，才有库内合并依据。名字纠正按同一外部对象或同一艺人名下的独立记录统计多数写法（过半，平票无结论），排除待改记录及模型自己写过的派生值 | 同一身份或错字还须模型判断及独立审查。字段 2 级，受治理艺人合并单列来源 |
| 带引用的网页 | 绑定本项实际搜索结果或原生引用，后端经现有安全取页路径读取最终 URL 和正文，存来源、可定位摘录与内容摘要。核对摘录确实在页中；合并需页面明确说两个名字是同一人，简介、图片及姓名分别核对其内容和所属艺人。独立审查看后台取得的摘录、目标、前后值。仅通过 URL 格式、公网检查或模型自填标题不足以写入 | 身份、名字和媒体可使用，字段 2 级。图片仍验证页面出处、内容格式/尺寸。模型记忆或网页里的年份、厂牌等不能替代结构化外部源值 |

**艺人合并。** 在 `curation/artist_merge.go` 增加受核实提案驱动的模型写入口。原 `MergeArtists` 的 MB 程序路径仍核对两个本地身份各自生效的发行或录音署名指向同一外部艺人，排除特殊 ID。两个入口均经 `operations.Run` 和现有 `CurationMergeExecutor`；在目录锁及双方身份锁内重读证据、重定向闭包、撤销标记、人工分开决定。**两名字曾在同一首曲目并列署名就拒绝合并**，以留存的逐曲署名事实按曲目、同一层和实际署名位置查双方名字及其成员，避免只看两个艺人的摘要或只看当前显示名。相同发行的不同曲目不能触发此否决。网页或库内路径携带经核实的提案、证据、版本及审查，不制造 MB 号码。投影、别名搜索、保留身份、撤销和不再合并沿用治理执行器；显示名策略由 D 负责。

**纠正与补空。** 补缺沿用 `missingFields`、曲目补缺及 `OnlyEmpty`。外部身份本身尚未由结构确认时，不能纠正真实名字。有结构身份后，将原艺人署名、专辑或曲名与外部或库内不同值组成候选。规范化相同即收尾，翻译、繁简、大小写、标点及艺人刻意的特殊写法均保留。只对模型判断为错字、拟改值符合后端所取证据且审查通过的字段写自动层。网页可为错字及姓名提供引用，仍须满足 R10 的结构身份与外部或库内差值前提。艺人名纠正落对应的发行/曲目署名，避免把一条错字写成全库人工改名。原扫描值及写入前值可见、可撤销。F 的 1 级用于从文件名等本地文字整理（D），手动优先；级别在后端预览和提交时一致，事务内执行逐字段优先级与 `scan_basis` 检查。

**来源与求证。** 操作记录的 `origin` 保留模型身份或会话，`basis` 记录核对方式和证据引用。建议以固定的 `provider=library_evidence`、`provider=web_search` 区分库内及网页，后者沿用媒体来源；实际模型名单独存于会话/证据。复用 `scope.kind=provider` 与批次撤销，并保留对同值、同一艺人对的抑制。发行并入或改变曲目归属仍限结构或外部强证据，不接受库内名字相似或网页单独授权。无佐证且存在可核实的主张时，搜索已开先存主张及目标转 web；无可用搜索或联网后仍无佐证，存未采用建议。日额度耗尽及来源暂时故障走等待，不当作“没有佐证”。

## 5. 未采用的建议、旧数据与接口

复用 `curation_model_exceptions`。一条具体建议包含原待定项、拟执行的工具与输入、前后值预览、依据及理由、实际审查（若有）、模型/会话、人工决定及操作编号。新增 `reason_code`（如 `review_rejected`、`review_uncertain`、`no_evidence`）和核实摘要。审查之前就失败的允许方案项与审查字段成组为空；以待定项、主张与输入证据摘要派生唯一建议键，原有方案项唯一键保留。单纯查无发行且没有拟改值时只结清未收录。无佐证的事实值作为建议存档，自动字段表不产生行。

新增一对 0091 迁移，在同一事务为已有例外补理由，把相关 `waiting_human` 原项设为 `resolved`，记录 `suggestion_recorded` 与结束时间，清掉调度时间。继续用 `open` 表示建议尚可手动采纳，旧 ID、预览、原决定及历史操作不变；`accepting` 行保留操作者、幂等键、原快照，供继续采纳。新建议写入、原项结清及相关署名提案结清同事务；同项多候选逐条存唯一建议（先锁原项，再一次结清），重放已有行不复制。程序再次见到相同输入时不重排，管理员显式不采纳才写原来的抑制标记。

手动入口复用 `model.ExceptionResolver.Accept/Decline`、领取、预览、执行、部分成功后的 `ResumeConfirmation` 及 `FinishException`。把 `CheckMatchItem`、采纳各分支与发行并入预览中“必须 waiting_human”改为校验**这条**建议的状态、操作者、终态原因以及当前目标、摘要/版本、预览相等。旧的字段采纳继续写人工修正，身份、匹配、并入走对应受治理路径，记确认人及操作编号。新类型登记到同一分派，手动决定可以确认具体提案，但仍受治理的目标、结构硬条件及陈旧检查约束。无法形成可执行修改的观察只展示理由。采纳同项互斥身份后将其它候选置 `superseded`；任何决定都不把原项送回 `waiting_model`。

前端交接沿用管理员接口前缀 `/api/v1/admin/curation`：

| 接口 | 拟定形状 |
| --- | --- |
| `GET /exceptions?status=open\|all&page=…&page_size=…` | 仍返回 `{items,total,page,page_size}`，默认 open。每项沿用 `id,pending_item_id,kind,release,artist,track,tool,input,preview,status,conversation_id,operation_ids` 等，增加 `reason_code,reasons,evidence,can_accept`，`review` 可空。列表标题“未采用的建议”，total 仅用于分页 |
| `POST /exceptions/{id}/accept`、`/decline` | 保留响应 `{exception,operation_ids}`、`{exception}`，保留已决定、过时、来源不可用等错误映射。新建议也走这两个入口 |
| `GET /progress` | `pending.waiting_model` 和模型进度的 `items.waiting_model` 均含等待处理的路线，`items.waiting_human` 过渡期固定 0。建议不计入待办或剩余项；G 消费建议列表和分页 |
| `GET/PUT /settings`、`GET /progress` | 设置顶层增 `web_daily_token_limit`（正整数，null 不限，PUT 缺省保留）。进度的模型块增 `web_daily_token_limit,web_today`，后者与 `today` 同形，并给出联网额度是否用尽和次日恢复时间；总额度字段沿用 |

## 6. 提示词与独立审查

后台系统段按第 2 节的任务生成，去掉“交由人工确认”和泛用的“搁置”。同名多人不能区分时逐一记录候选及歧义；无法确信就使用本档的升级、放弃或提交建议。直接选择的一次调用也要求来源包装、仅处理本批、无工具、严格解析；在后台会话记录输入、输出及用量，方案由后端据结果构造，不让模型伪造工具执行记录。

`runtime.ReviewPolicyVersion` 从 4 升到 5。保留隔离审查的单次 `submit_review`、逐项决策、高风险复判、20 项、政策/模型来源、15 分钟有效期、方案及证据摘要绑定、执行前重取预览。增加后台结构比较与反证、外部字段、库内计数或网页摘录的证据读取方式；审查依据由后端形成，排除主模型自述。拒绝或 `needs_human_confirmation` 在后台均记录建议并关闭，不再发送等待管理员的结论。按项的不确定判定与整次服务不可用分别处理。版本变化使旧批准失效，按原机制重审；策略全文、证据字段与合同逐字同步由主代理在集成时处理。只有后台来源启用任务白名单、D4 分流及新结项逻辑，对话里的 steward 继续使用原有人工确认语义和工具授权。

## 7. 预算、停止与恢复

- `BeforeModelItem` 继续按服务器本地日期检查管理员的总日限（默认 1000 万，null 不限），web 在同一项开始边界再查联网子额度。在 `curation_model_usage` 的同一日行增加 web 输入、输出两列，联网用量同时原子计入总量和子量；主模型、独立审查、摘要均按已有 usage 回调记一次。旧数据不推算联网用量。联网日限拟默认 null，升级后保留已有实例的用量安排，由管理员独立设定。
- 已领和已开始要分开。多步组按项串行，下一项先过额度闸门才进入提示词和工具上下文。选择批的各项在同一主调用开始，构造消息前对每项执行 B 的检查，发送前再次检查并固定本次同时准入的集合；这次调用可以完成已准入各项及其审查，下一批再读实耗。多步批即使设了日限也可同艺人领取多行，每次仅开始其中一项。用尽总额则下一项等次日本地零时，仅联网子额度用尽仍可跑离线任务。已开始项可完成本项审查、重审和写入，不能把开关/身份检查也延后到下一项。
- 自查和联网每次模型请求完成后，将实际报告的输入、输出和实际工具调用次数累计到当前项；含查询、读取、提交及上游报告的原生搜索调用。审查与摘要计 token，独立审查内部提交决定不占主模型工具次数。当前项同路线恢复或重审时续计，进入下一档清零。超过 D16 即停止该项的新调用，按本档放弃；保留已完成的写入。沿用上游输出设置，原生搜索按请求实际报告记账。多项按当前项归属整次请求。对自查与联网放宽后台原有 24 步限制以容纳正常的逐次查询和提交。第一档和核对不新增 D16 限额。
- 若等待中的 web 路线遇到管理员永久关闭网络搜索，在总开关开启且未暂停时，以 C 的无联网分支结清发行或保存未证实的建议；在途关闭先按停止释放，暂时故障保留路线。日限只挡新项；来源开关、开启者资格、暂停、扫描、取消、模型配置及当前项归属仍在每步和写前复核。运行中关开关按停止处理、释放领取，不记放弃或未采用；调度重启关闭旧批、清理遗留方案，仅恢复未结项。审查不可用保留方案，5 分钟、30 分钟、2 小时有限重审，仍失败延迟 24 小时回原队；模型服务错误释放领取，10 分钟起倍增至 6 小时。MB 暂时失败走来源退避。旧的“三次未处理后搁置”只用于运行未给有效结果；明确放弃或 D16 触限当次转去下一档或结束。
