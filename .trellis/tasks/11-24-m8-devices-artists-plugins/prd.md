# M8 局域网设备、艺人资料、数据源插件与测试设施

状态：规划中（父任务）。父任务本身没有实现工作，不启动；每个子任务单独规划、实施、验收和归档，按下表顺序进行。

## 目标

M7 之后的五项交付：两项测试设施（中文字体、外部接口 mock 服务器）与三项功能（艺人图片与简介、UPnP/DLNA 设备串流、
第三方数据源插件）。测试设施先做，后面三项的浏览器截图与集成试用都用得上。

## 决定记录（2026-11-24，选择者 qlqq）

| 编号 | 决定 | 理由 |
| --- | --- | --- |
| W1 | 五项放在一个父任务下，各成一个子任务；按“规划完直接实现、本地合并、不推送”进行 | 沿用 M7 的做法 |
| W2 | 顺序：中文字体 → mock 服务器 → 艺人图片与简介 → U3 → 第三方插件 | 设施先行；插件要等前几项的数据源接口稳定后再抽成合同 |
| W3 | 中文字体装在用户目录（Noto Sans CJK SC，`~/.local/share/fonts`），不用 sudo，不改系统 | 本机没有任何中文字体；之前截图用的文泉驿是临时解压进 `temp/` 的，已不在 |
| W4 | mock 服务器模拟外部 API 端点的响应：替代 MusicBrainz、Cover Art Archive、LRCLIB、AcoustID、艺人资料来源与 OpenAI 兼容的模型端点；可切换正常、超时、503、坏数据等场景 | 开发与试用实例不连真实服务、不发外部请求 |
| W5 | 艺人资料来源分两层：默认 Wikidata、Wikimedia Commons、维基百科（不要密钥）；管理员填入密钥后启用 Fanart.tv、TheAudioDB | 不要密钥的来源覆盖不全：小众、华语与日韩艺人常没有自由许可的照片；Last.fm 已不提供艺人图片；Spotify、网易云没有开放接口 |
| W6 | U3 首批只做 UPnP/DLNA 渲染器 | 标准公开、设备普遍支持、可直接拉无损渲染流；Chromecast、AirPlay 没有官方开放接口 |
| W8 | U3：生产默认改为 host 网络；账号间是否共享局域网设备做成开关（默认共享） | qlqq 2026-11-24 追加决定 |
| W7 | 第三方插件只扩展数据源（元数据、封面、歌词、艺人资料提供方）；需要新 ADR 修订 ADR 0006 的 U4 | 按架构决策摘要“扩展边界的两步走”的第二步；输出设备、格式解析、界面扩展不在范围 |
