# 自动整理 B2：外部封面与歌词

父任务：`.trellis/tasks/11-22-auto-curation-sources`（需求 R4；决定 U8、默认 3、默认 7）。前置：A（`d079f44c`）、B1（`32c1a8d6`）。
技术设计见 `design.md`，执行计划见 `implement.md`。现状与外部接口的调研在 `research/`：

- `research/covers-and-lyrics-current.md`：封面与歌词的表、扫描、读取点、可复用的函数、管家的封面清单、出站与限速的现状。
- `research/caa-and-lrclib-api.md`：Cover Art Archive 与 LRCLIB 的接口、重定向、限速、内容特点（含对真实服务的少量只读核实）。

## 目标

给后台自动整理准备好“补封面、补歌词”需要的全部零件：能从 Cover Art Archive 取到封面图片、从 LRCLIB 取到歌词；
外部来的封面与歌词有自己的存放位置，读取时本地优先、外部只补空缺；写入有记录、能撤销、撤销后不再提出；扫描不清除它们。

用户价值（在子任务 C 接上匹配之后体现）：没有封面的专辑自动有封面，没有歌词的曲目自动有歌词；补错了可以撤销，之后不会再补同一张图或同一份歌词。
本任务合入后、C 之前，没有任何生产代码会写入外部封面与外部歌词；没开自动整理的实例行为不变。

## 背景（现状事实，锚点见调研文档）

- 封面只有 `release_artworks` 一张表，一发行一行，来源只允许 `embedded`、`folder`；全量扫描选不出本地封面时删除这一行。
  文件平铺在 `<数据目录>/artwork/`，内容寻址；孤儿清理只按这张表计引用。读取处全部经 `releasesql` 的两个片段与 `artwork.Lookup`。
- 歌词是 `tracks.lyrics`、`tracks.lyrics_source` 两列，来源只允许五种本地来源，扫描每次整体覆盖。
  歌词接口的 `source` 现有两个取值：`embedded`、`external`（后者指音频旁的同名 `.lrc` 文件）。
- 管家的 `get_music_metadata` 带 `cover-art` 时自己请求 Cover Art Archive 的清单：不限速、不缓存。
- `sources.Requester` 只有 `GetJSON`，不跟随重定向；Cover Art Archive 的每个端点都是三跳（`coverartarchive.org` → `archive.org` → `*.archive.org`）。
- 受治理操作的目标只有发行、专辑、艺人三种；`Run` 没有提交后的回调。

## 主代理取的默认值

用户已授权“规划完直接实现，能自己定的自己定”（2026-11-22）。以下是我替用户做的决定，随交付说明列出，可在验收后改：

| 编号 | 决定 | 理由与另一种做法 |
| --- | --- | --- |
| B2-P1 | 封面与歌词的**写入操作与撤销在本任务做**，不留给 C | B1 把“建立外部对应”的写入留给了 C，是因为匹配方式与把握程度的取值要由 C 定义；封面与歌词没有这个依赖，存放、读取优先顺序与撤销规则放在一起才能一次验清。C 只需要调用 |
| B2-P2 | 存放层面就是“只补空缺”：一个发行已有外部封面、一首曲目已有外部歌词时不再写第二份；要换先撤销 | 这样前态恒为“没有”，撤销就是删除，不存在“恢复上一张图但文件已被清理”的问题。放弃的做法：允许替换并保存前一份 |
| B2-P3 | 本地已有封面或歌词时拒绝写入外部的（跳过原因 `local_present`） | 不下载不会显示的图片。放弃的做法：照样写、等本地的消失后显示 |
| B2-P4 | 下载封面取 1200 档缩略图；没有时依次取 500、250，都没有才取原图（原图是 PDF 时放弃） | 缩略图恒为 JPEG、体积可预期（样本 40–215 KB）；原图不限大小且可能是 PDF。界面最大显示尺寸不超过 1200 |
| B2-P5 | 选图：清单里 `front` 为真的那张；没有时取第一张类型含 Front 的；都没有就是没有封面 | 与 Navidrome 示例一致；`front` 就是社区选定的主封面 |
| B2-P6 | 限速：清单请求用 MusicBrainz 的限速器（每秒 1 次、对话优先）；图片下载用 Cover Art Archive 自己的限速器（每秒 1 次）；LRCLIB 每秒 1 次 | 父任务 V8 要求清单与 MusicBrainz 合计每秒 1 次。图片的第一跳也经过 MetaBrainz 的网关，所以对网关合计每秒 2 次；Cover Art Archive 的文档写明目前没有限速规则，图片另算可以不拖慢匹配。LRCLIB 文档的上限是每分钟 90 次 |
| B2-P7 | 两类操作的目标都是**发行**（歌词操作的目标是曲目当时所在的发行，曲目记在状态里） | 不为歌词新增“曲目”这种操作目标：一张发行的字段、封面、歌词的改动在同一个目标下能一起看到。曲目级目标留给子任务 I 按需要引入 |
| B2-P8 | 歌词一首曲目一条操作；封面一张发行一条操作 | 一份歌词补错只撤这一首，不连累同一张发行的其他曲目 |
| B2-P9 | 歌词接口的 `source` 增加第三个取值 `online`，表示外部源取来的 | `external` 已被“音频旁的 .lrc 文件”占用，不改它的含义。歌词面板不显示来源，界面没有变化 |
| B2-P10 | LRCLIB 同时给出同步与纯文本时存同步的；标记为纯音乐的不存任何东西 | 同步歌词包含全部文本；纯音乐“已尝试”的记忆属于 C 的匹配状态 |
| B2-P11 | 封面摘要（`artwork` 对象）不加来源字段 | 现有 150 份样本与前端解码器不变；“哪些是自动补的”由 E1 从操作记录取 |
| B2-P12 | “同一个改动”按内容与外部身份两样判定：内容是图片字节或规范化后歌词文本的 SHA-256，外部身份是“源加外部编号”。撤销时两条都记，写入时命中任一条就不写 | 同一张图换个来源再来、或同一张图换一档缩略图（字节不同）再来，都不会被再次提出 |
| B2-P13 | 恢复数据库备份而数据目录没有恢复时，外部封面的行还在、文件不在：之后对这个发行的新写入视同没有外部封面，替换旧行 | 数据目录不进备份（默认 7）。发现文件丢失并重新获取由子任务 C 的缺口查询负责 |

## 验收

外部服务一律用受控的本地服务；集成测试用隔离的 PostgreSQL 与合成数据。写入没有 HTTP 入口，测试直接调用 `curation.Writer`。

- [x] B2-V1 Cover Art Archive：清单经三跳取到并解析（`id` 是数字或字符串都接受）；重定向到非官方主机，或从 HTTPS 降到 HTTP 时拒绝，不再继续也不重试；404 是“没有封面”。
- [x] B2-V2 选图与下载：`front` 为真的优先，其次类型含 Front 的第一张；1200 档 404 时依次回退；原图是 PDF 时放弃；超过 16 MiB、不是四种格式之一、宽高读不出的图片被拒绝且不落盘。
- [x] B2-V3 限速：清单请求与 MusicBrainz 的请求合计不超过每秒 1 次（同一个限速器）；图片下载不占 MusicBrainz 的许可。
- [x] B2-V4 LRCLIB：精确查询的参数与解析；404 是“没找到”；搜索返回带各自标题、艺人、专辑、时长的候选；纯音乐的记录能辨认；429 与 503 在后台按 `Retry-After` 重试。
- [x] B2-V5 管家工具：带 `cover-art` 的 `get_music_metadata` 输出与原来逐项相同，现有用例不改断言（入参换成合成的 UUID、注入方式改为经适配器）；清单请求经过限速器。
- [x] B2-V6 源开关接口列出三个源，两个新源默认开；关闭某个源或总开关后，经闸门的调用被拒绝且零出站。
- [x] B2-V7 读取优先：只有外部封面时各摘要与图片接口返回它；本地封面出现后返回本地的；本地的被扫描删除后回到外部的。歌词同理，外部的 `source` 为 `online`。
- [x] B2-V8 全量重扫、改名移动、认领之后外部封面与外部歌词的行与文件都在；扫描的孤儿清理不删除仍被外部封面引用的文件。
- [x] B2-V9 写入：记录的操作者是开启者，来源与批次正确；本地已有、外部已有、已标记不再提出时分别以对应原因跳过且不产生记录；总开关关闭或开启者失效时拒绝。
- [x] B2-V10 撤销：单条撤销后行消失、文件在没有其他引用时被删除、写下不再提出，同一内容或同一外部编号（内容不同）再次写入都被挡；按批与按来源撤销覆盖这两类操作；撤销前后发行的人工修改版本号不变，之后的人工修改不妨碍撤销。
- [x] B2-V11 同一张图片被两个发行引用（一个本地、一个外部，或两个外部）时，撤销其中一个不删文件；一个发行写入与另一个发行撤销同一内容交叠时，结束后行与文件一致。
- [x] B2-V12 操作记录列表给出两类改动的摘要与是否仍可撤销；前端能解码并显示。
- [x] B2-V13 没有外部封面与外部歌词时，现有接口样本逐项不变（`curation/sources` 除外，它多出两个源）。
- [x] B2-V14 迁移升级与回退往返；包依赖方向测试覆盖新包。
- [x] B2-V15 关键逻辑的变异检查：重定向主机限制、读取优先顺序、跳过条件、撤销的归属判断、文件引用计数。

## 不在范围内

- 什么时候取封面与歌词、用哪个外部 ID、匹配是否可靠：子任务 C。本任务没有后台循环，也没有生产调用方。
- 用外部的替换本地已有的；多张封面、封底与内页；艺人图片。
- 界面上标出“这是自动补的”、整理记录页：E1。本任务的前端只做解码与现有操作记录列表里的摘要文字。
- 曲目作为操作目标、曲目级字段：子任务 I。
- LRCLIB 的逐字歌词文件（`lyricsfile`）与上传接口。
