# Music Steward 执行计划

父任务不启动、没有实现工作。下面是子任务的顺序、依赖和每一步的评审点。每个子任务创建后先走自己的规划
（PRD、设计、执行计划），用户批准后才 `task.py start`。

## 顺序

- [x] C1 ADR：数据外发、提示注入、出站请求、密钥与令牌
  - 只有文档（`docs/architecture/adr/0005-*`）。用户批准 ADR 后才开始 C2。
- [x] C2 运行时与只读工具
  - 依赖 C1。后端为主。这是地基，工具合同在这里定下来，之后的子任务只加工具。
  - 评审点：工具注册表的字段与调用入口，在加第二批工具之前由用户确认。
- [x] C3 MCP 服务与个人访问令牌（真实客户端试用待用户执行）
  - 依赖 C2。做完后可以用 Claude Code 连上真实实例试用只读工具，用使用中的问题修正工具设计。
- [x] C4 对话页（真实模型端点未试用）
  - 依赖 C2，与 C3 可并行（前端由主代理实现，后端交 Codex 子代理）。
  - 评审点：布局由用户确认。
- [x] C5 播放与个人库工具、页面上下文（未在浏览器与真实模型上试用）
  - 依赖 C2、C4。
- [ ] C6 写操作确认流程、目录整理工具、`operator` 模式
  - 依赖 C2、C4。完成后 MCP 的读写令牌才有写工具可用。
  - 评审点：确认卡片的交互由用户确认。
- [ ] C7 审查子代理与 `steward` 模式
  - 依赖 C6（复用方案的持久化与摘要绑定）。
  - 评审点：审查的提示词、证据摘要的内容和策略由用户确认。
- [ ] C8 联网
  - 依赖 C1、C2。规划时先查三种搜索来源的当前接口文档，并请用户指定商业搜索 API。
- [ ] C9 应用配置工具、诊断与只读查询
  - 依赖 C6。逐项列出未走 `operations.Run` 的写操作，由用户决定补记录还是标为不可撤销。
- [ ] C10 记忆与后台任务
  - 依赖 C4、C6。
- [ ] C11 跨子任务验收与文档同步
  - 按父任务 PRD 的验收标准逐项验收；同步路线图 M6 行、产品合同与后端规范
    （含“operator 仅管理员”改为所有用户可选）。

## 验证

各子任务在自己的执行计划里写验证命令，只覆盖本次改动涉及的包和用例；已通过且相关代码没改过的不重跑。
集成测试使用独立临时目录、唯一 Compose 项目名和合成数据；模型端点用本地的假服务，不调用真实模型。
需要真实模型的验收由用户提供端点，并在记录里与自动化测试分开写。

## 分工

- 后端实现与测试交给 Codex 子代理，实现与测试由不同的子代理执行；C2、C3、C6、C7 属于复杂任务。
- 前端由主代理实现。
- 子代理不提交 Git；主代理审阅后合入。每个子任务用独立任务分支。
