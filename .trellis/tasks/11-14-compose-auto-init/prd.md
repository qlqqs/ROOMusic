# 生产部署自动初始化与目录持久化

## 目标与范围

首次安装只填写音乐目录，直接运行 Docker Compose。初始化服务自动生成数据库密码并持久保存；后续启动复用。数据库、应用数据、备份与密码全部使用部署目录的 bind mount，不创建命名卷或匿名卷。

支持首次手动指定密码。应用启动、备份、恢复、账号密码重置统一读取凭据。保留独立使用 ROOMUSIC_DATABASE_URL 的既有方式。更新安装与停机目录迁移流程。

## 约束

不操作现有实例，不迁移旧卷，不发布镜像。项目文档使用简体中文；不添加防御性说明，不为假想场景增加兜底。仅校验真实输入、文件与依赖状态。

开发工具由用户目录 mise 管理。使用独立分支和工作目录；测试使用 temp 下合成数据、唯一 Compose 项目名、独立网络和动态端口（0.0.0.0）。

## 验收

- 不设置数据库密码即可启动，密码文件权限受限，两端使用同一密码。
- 重新创建容器后密码和数据库记录不变；提供不同手动密码时报错而不替换已有密码。
- 数据库目录已有内容但密码文件缺失时停止初始化。
- 密码中的 URL 特殊字符可用于应用连接及备份恢复。
- 应用以 UID 1000 写入 data 与 backups；无命名卷和匿名卷。
- 停止服务后复制整个部署目录，重启后数据和密码不变。
- 备份与恢复命令可用；说明不把在线复制 PostgreSQL 文件当作日常备份。
