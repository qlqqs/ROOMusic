# 自动整理 E1：整理记录与设置界面（第一版）

父任务：`.trellis/tasks/11-22-auto-curation-sources`。前置 C（`b96d8ea3`）已合入：后端接口齐全，前端还没有任何 `/api/v1/admin/curation/*` 的界面。
设计见 `design.md`，执行计划见 `implement.md`，现状调研见 `research/frontend-current.md`（下文“调研 §n”）。

## 目标

管理员在应用里就能打开、暂停、查看和撤销自动整理：知道它在做什么、做到哪了、改了什么、依据是什么，错的能单条、按批、按来源撤销，撤销过的标记能清掉。
成员在专辑详情里能分辨哪些信息是自动补全的。里程碑一（父任务 V2–V5、V8、V11）从此可以不靠接口直接使用。

## 需求

| 编号 | 需求 |
| --- | --- |
| E1-R1 | 设置里新增“自动整理”栏（管理员）：总开关（打开前确认会向外部服务发送什么）、开启者与生效状态、暂停（总开关开着时出现） |
| E1-R2 | 进度：后台状态、已处理/总数、对上、拿不准、没对上、稍后再试、等模型的待定项数、当前批次；工作时自动刷新 |
| E1-R3 | 外部源：每个源的开关、能力、不生效的原因；按来源撤销这个源的全部自动修改 |
| E1-R4 | 批次：倒序分页列表（时间、层、改动数、已撤销数）；查看这一批的改动（跳到按批次筛选的操作记录）；撤销这一批（分段续做直到完成，结果就近显示） |
| E1-R5 | 不再提出：标记列表（目标、类别、值、时间）与逐条清除 |
| E1-R6 | 操作记录：支持按来源（自动整理）、外部源、批次筛选，筛选说明与“查看全部”；自动整理的记录显示依据 |
| E1-R7 | 专辑详情：自动补全的字段带“自动补全”标签（与“人工修正”并列的位置）；编辑对话框里有自动值时说明当前显示的是自动补全的值 |
| E1-R8 | 一次性提示：管理员在概览上、曲库里有发行而自动整理从未打开过时，看到打开自动整理的提示，可以前往设置或不再提示；概览的“资料库状态”增加自动整理一行 |

## 验收标准

- [ ] AC1 总开关从关到开要先确认，确认框写明发送给外部的内容（ADR 0006 第 8 节的表）；关掉不需要确认。开着时出现暂停开关，关着时不出现。失败时回到服务器的值并就近提示。
- [ ] AC2 进度在后台工作或等待扫描时每 10 秒刷新，空闲、暂停、关闭时不轮询；数字与接口一致；`unavailable` 时说明“后台整理没有运行”。
- [ ] AC3 各源开关即改即存；总开关关着时各行写出不生效的原因。
- [ ] AC4 撤销这一批、撤销这个来源：确认后分段调用同一个幂等键直到 `next_cursor` 为空；进行中不能重复提交；结果写出撤了多少、跳过多少与跳过的原因；结果不确定时可以用同一个键重试。
- [ ] AC5 标记列表能分页、能清除（封面与歌词的一对标记一起清除），清除后列表刷新，后台可以再次写入同一个值。
- [ ] AC6 操作记录的 `source`、`provider`、`batch` 地址参数生效，筛选说明正确，“查看全部记录”清掉筛选；自动整理的记录显示“依据：…”。
- [ ] AC7 专辑详情：只有自动层取值的字段带“自动补全”标签，人工修正的字段仍是“人工修正”；没有自动补全时界面（含编辑对话框）与之前完全相同。
- [ ] AC8 一次性提示只对管理员、只在“曲库里有发行且总开关从未打开过”时出现；“不再提示”之后在这个浏览器上不再出现；打开过总开关之后不再出现。
- [ ] AC9 新的十个 `curation/*` 样本由解码器往返无损；页面级 Vitest、Playwright 冒烟（1440、375、390，axe、无横向溢出）与一条真实服务用例（总开关保持关闭）通过。
- [ ] AC10 后端：发行详情在有自动补全的字段时带 `auto_fields`，没有时省略；现有接口样本逐项不变。

## 范围外

- 待定项的列表与处理、例外、用量：E2（与 D 一起）。
- 封面与歌词的来源标记（摘要里没有封面来源，B2 决定；歌词面板按 player 规范不显示来源）：从整理记录看。
- 曲目级字段（I）、艺人合并（G）的界面。
- 一次撤销“这次匹配带来的全部改动”的单独按钮：用按批次筛选的操作记录与按批撤销实现。

## 主代理代为决定的事项

用户 2026-11-22 授权能自己定的自己定（父任务原计划“先出原型给用户确认”，按授权改为主代理按现有设计规范决定，交付时附截图）：

1. 一个“自动整理”栏，放在“操作记录”之前；里面依次是开关、进度、外部源、批次、不再提出五组。批次的明细复用操作记录页（按批次筛选），不另做明细页。
2. 打开总开关要确认（这是 ADR 规定由人做的一步），关闭、暂停、各源开关不确认。
3. 按来源撤销放在外部源那一行的菜单里；按批撤销放在批次那一行。
4. “自动补全”标签用与“人工修正”相同的位置与形态，图标不同（`Sparkles`），色调 `neutral`（不扩新颜色）。
5. 一次性提示的“不再提示”存在浏览器本地（按用户），属于每个查看者自己的便利；打开过总开关后由服务器状态决定不再出现。
6. 概览的“资料库状态”加一行自动整理（管理员），写状态与已处理比例，链接到设置。
7. 后端两项：发行详情与对比的 `auto_fields`（省略空值，避免改动现有样本）；清除封面或歌词的标记时一并清除成对的另一条。
8. 歌词来源不在界面上显示（沿用 player 规范）。

## 规划结论的确认方式

路线：子代理审阅（用户 2026-11-22 的常设授权）。审阅者：规划子代理（Plan，2026-11-22）。结论：必须改的 10 项改完后可以实施。主代理全部采纳，并采纳了建议改的大部分（只省掉按来源撤销的“做完这一段后停止”）；修订写在 design.md 第九节，与前文冲突时以它为准。
