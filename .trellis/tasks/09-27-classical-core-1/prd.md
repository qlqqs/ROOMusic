# Classical 重设计 / Core 1

## 目标与用户价值

以 `frontend-desgin/` 中的 Classical 原型为设计输入，先恢复可用的音乐资料库客户端，
再分阶段交付真实播放、可审计整理和版本管理，避免界面承诺超过后端能力。
父任务负责需求总表、阶段映射、安全约束和最终集成验收，不直接承接业务代码实施。

## 阶段任务映射

下表保留上一轮建议的完整路线，不代表所有阶段已获批准或全部属于 Core 1。
Core 1 截止范围由 M0 提案并经用户确认；只为当前交付创建 M0，其余阶段尚未创建任务。

M0 的交付提案见 [Core 1 能力矩阵与路线](../../../docs/architecture/core-1-roadmap.md)：推荐截止 M4，
M5/M6 后续；也列出先交付 M1+必要 B0+M2 的较小替代。该切分仍待用户确认。

| 阶段 | 内容 | 前置与边界 | 任务状态 |
| --- | --- | --- | --- |
| M0 | 设计定稿、规范清理、阶段范围、四类 ADR 草案 | 仅文档与规划，不改业务代码 | [已创建](../09-27-classical-m0-alignment/prd.md)，`in_progress` |
| M1 | 应用外壳、认证、目录浏览、详情、现有管理界面、恢复真实构建门禁 | M0 审阅通过；只消费现有 API，不等待 B0 完成 | 待创建 |
| B0 | 后端按解析器、平台、身份、目录/扫描、catalog 边界分步重构 | M0 审阅通过；可与 M1 并行，不夹带业务变更 | 待创建 |
| M2 | 串流、ALAC 转码/CUE 分轨缓存、播放引擎、歌词和服务端播放历史 | M1 和相关播放决策；个人历史接口不必等 M5 的历史页面 | 待创建 |
| M3 | 修正覆盖层、变更集、审批、检查点和编辑者角色 | 写路径决策与所需模块边界就绪；不以 M2 完成为逻辑前提 | 待创建 |
| M4 | 元数据问题、ReleaseGroup、版本对比/默认版本、合并拆分、扫描反馈 | M3；强证据或用户确认才能形成权威分组 | 待创建 |
| M5 | 搜索体验、艺人实体/别名、收藏/歌单/历史页面 | 按子功能依赖排期；版本化检索依赖 M4，个人数据不强行依赖全部 M4 | 待创建 |
| M6 | Steward 只读问答、受控提案、独立审查 | M3/M4 的工具与操作合同；外部元数据源另立项 | 待创建 |

M1 的“只读客户端”指不新增元数据整理写路径，不禁止恢复已有的初始化、登录、
目录配置、扫描启动/取消和成员管理操作。暂未实现的播放、整理和 Steward 入口不得伪装可用。

## 跨阶段约束与范围外

- 延续 Go 模块化单体、版本化 REST、同源 HttpOnly Cookie 和 PostgreSQL 权威边界。
- 音乐源文件只读；本路线不授权写标签、重命名、移动、删除或回收真实音频。
- 路径安全、鉴权、事务、revision、幂等和回滚有效性始终由后端决定。
- 不凭弱标题/艺人相似度自动跨目录合并版本；不把失败、取消或不完整扫描当作缺失证据。
- 个人数据与资料库治理区分：前者按用户隔离，后者按授权与操作合同执行。
- 不承诺浏览器可验证硬件级 Bit-perfect 或 DAC 状态；兼容范围由播放子任务实际验证。
- 不将 Redis、Meilisearch、GraphQL、Agent 运行时、外部元数据服务或 PWA 变成早期交付的隐含前置。
- 不延续生产演示模式；测试数据通过受控测试边界提供，不静默兜底真实 API 错误。
- 文档使用简体中文，公开仓库不写入私有音乐路径、凭据或真实媒体资产。

## 父任务完成条件

- M0 交付范围提案后，由用户明确 Core 1 的已批准阶段集合；集合外的路线项显式标记为后续工作。
- 纳入集合的子任务逐项通过自身验收，父任务可追溯每条源需求的交付或批准延期记录。
- 集成复核覆盖已交付的真实登录、浏览、播放或整理主路径及相关权限/数据边界。
- 文档、API 合同与实际交付一致；不以子任务创建、文档写完或占位页通过 CI 代替功能完成。
