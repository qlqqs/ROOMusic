## 验证策略

当前只验证任务结构、上下文路径和文档一致性：

```bash
python3 .trellis/scripts/task.py validate .trellis/tasks/09-27-classical-core-1
python3 .trellis/scripts/task.py validate .trellis/tasks/09-27-classical-m0-alignment
python3 .trellis/scripts/task.py list
python3 .trellis/scripts/task.py current --source
git diff --check
```

实现阶段的精确测试命令由各子任务依据实际文件/测试名称记录，优先最小相关测试集；
不预先以全仓测试作为每个子任务的默认门禁，也不把数据库测试跳过视作通过。
最终集成验证的范围随实际批准的功能确定。

## 风险与回退点

- M0 未形成一致依据前，不安装依赖、不拆包、不编写迁移、不迁移设计资产。
- 旧任务仅作为历史证据，是否按“已取代”归档需保留真实交付状态并另行确认。
- 文档规划可单独修订；每个业务阶段必须有独立验收与回退说明，不能用父任务一次性批准替代。
