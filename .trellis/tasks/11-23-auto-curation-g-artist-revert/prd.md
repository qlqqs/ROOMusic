# 自动整理 G：艺人操作可撤销

## 目标

艺人的合并、改名与忽略候选可以撤销，恢复到操作前原样（ADR 0006 第 312 行修订 ADR 0003 的 R4；第 389 行验收）。程序层在匹配上的发行里把本地艺人对上 MusicBrainz 艺人；两个本地艺人对上同一个外部艺人时自动合并（强证据，ADR 第 180 行），可撤销，撤销后不再提出。

依据：ADR 0006 U6、第 4、7 节；父任务 `implement.md` 的 G 一节；调研 `research/artist-ops-current.md`（下文 R§n）。

## 决定（主代理按 qlqq 的授权取定，规划子代理审阅；随交付列出）

| # | 决定 | 理由 |
| --- | --- | --- |
| G1 | 合并、改名、忽略候选三种可撤销；拆分不可撤销（它就是纠正错误合并的手段，撤销合并覆盖它） | ADR 第 182、312 行 |
| G2 | 不改记录形状：现有记录的前态已足够恢复（R§1），历史记录按新规则判定能不能撤；撤销记录带原操作的 `changes`（kind 为原类型）、前后态对调、目标艺人相同 | 避免迁移历史；按艺人筛选与说明照常可用 |
| G3 | 能撤销的条件：①这次操作写下的每一项（名字绑定、作用域、重定向、显示名、忽略对）现在仍是它写的样子；②涉及的艺人之后没有别的生效中的操作（被撤销的不算）。不用版本号核对（会挡住链式撤销，R§2）。不满足 `409 revert_conflict`；列表里的“能否撤销”用同一判定 | 链式合并 A→B、B→C 时可以倒序撤销；之后有人工修改时拒绝（父任务 G 验证） |
| G4 | 恢复要逐项还原：绑定有原行则恢复原 `(artist_id, operation_id)`、无原行则删；作用域逐行恢复；源艺人与扁平化旧身份的 `redirect_artist_id/redirect_operation_id` 恢复原值（merged-sources 依赖它，R§3）；之后刷新艺人图、搜索与收藏解析 | 回到操作前原样 |
| G5 | 艺人外部对应：`ApplyLinks` 放开 `object_type='artist'`。程序层在匹配上（certain）的发行里，本地专辑艺人与曲目艺人的署名与外部署名逐位一一对应、松比较名字相等时，或扫描标签 `mb_artist`/`mb_album_artist` 与外部艺人 ID 相同时，写艺人对应（外部源 MusicBrainz，来源 source）。只用扫描与人工修正层的署名 | 自动合并要有强证据；标签与匹配结果都是程序能保证的 |
| G6 | 自动合并：两位本地艺人（解开重定向后不同）都有生效中的对应指向同一个 MusicBrainz 艺人，且没有“不再提出”的 `artist_merge` 标记、两者之间没有人工拆分或人工忽略记录 → 经新的 `curation.Writer.MergeArtists` 合并（来源 curation/musicbrainz、批次、幂等键）。合并方向：保留署名多的一方，平局按 ID。撤销来源是自动整理的合并时写 `artist_merge` 标记 | ADR 第 180 行；人做过的决定优先 |
| G7 | 管家的三个工具改为可撤销：Steward 模式下走审查（不再因不可撤销直接转人工），审查策略升到第 3 版（策略文本同步）；Assistant 模式可以把它们加进免确认名单。后台运行不开放艺人工具：现在的待定项只有发行，后台模型没有处理艺人的入口；“模型在后台处理艺人候选”另立后续任务 | 工具可撤销后对话行为随之改变；后台需要新的工作队列，不在 G 内 |
| G8 | 界面：操作记录与艺人页上三种操作可以撤销（撤销入口支持艺人目标、标题与说明）；拆分仍写“需要时可以再合并” | 与发行级撤销一致 |

## 需求与验收

| # | 需求 | 验收 |
| --- | --- | --- |
| R1 | 撤销合并 | 撤销后名字绑定、作用域归属、重定向（含链式）、收藏解析、merged-sources、搜索与艺人页逐项回到合并前；之后有人工修改时 409；链式 A→B、B→C 能倒序撤销 |
| R2 | 撤销改名与忽略候选 | 显示名与名字操作恢复；只恢复这次改动的忽略对；之后有修改时 409 |
| R3 | 艺人对应 | 程序层按 G5 写艺人对应；位置或名字对不上不写；对应可撤销 |
| R4 | 自动合并 | 同一外部艺人的两位本地艺人被合并（来源 curation、在批次里）；有标记、人工拆分或忽略时不合并；撤销后写标记、不再合并 |
| R5 | 管家工具 | 三个工具 `Revertible=true`；Steward 模式送审；策略第 3 版；对话里合并后能从操作记录撤销 |
| R6 | 界面 | 撤销入口、标题、确认文案；拆分不变 |

## 不做

- 后台模型处理艺人候选（需要艺人级的工作队列，另立任务）。
- 拆分的撤销。
