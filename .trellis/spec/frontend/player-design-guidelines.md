# Classical 浏览与播放器规范

## 当前状态与设计依据

2026-09-27 基线没有 `frontend/src/` 或真实音频服务；本规范描述恢复客户端时的要求，
不宣称已实现。唯一落地视觉依据是 [frontend/DESIGN.md](../../../frontend/DESIGN.md)，
原始设计位于 `frontend-desgin/`。旧月刊布局、朱红主色、大圆角和生产演示播放器不再适用。

M1a/M1b 仅接入既有认证、目录/扫描、成员 API 与阶段 I 的按组只读接口；真实播放从 M2a（直出）开始，
M2b 补派生与歌词。未完成阶段的控件隐藏或明确禁用，不能用模拟状态充当功能。具体阶段与未决方案见
[Core 1 路线](../../../docs/architecture/core-1-roadmap.md)。

## 视觉与布局

- 使用 DESIGN 中的 Classical 色彩、排版、间距、细线和小圆角规则；不复制原型散落的内联数值作为第二套 token。
- 私有资料库工作流优先，保持 Release/Medium/Track、版本事实和证据的可扫描性，不做营销首屏或装饰性大卡片。
- 桌面采用原型的侧栏与独立主内容；仅在真实播放器交付后提供有效的持续播放区域。路由形式另经 ADR/M1 决定，不强制旧 hash 路由。
- 窄屏布局按 DESIGN 的落地约束验证，不把原型桌面固定宽高当作移动端适配证据。
- 固定底部区域必须预留内容空间与触屏安全区；长标题、错误文本、按钮状态变化不能遮住最后一行或造成控件抖动。
- 布局子项需要时设置 `min-width: 0`；长文本可截断但有可访问完整名称。验收包含超过 1000 字的合法标题。
- 信号路径只显示已核实的源、直出/转码与浏览器环节；不把“无损编码/传输”提升为系统输出或 DAC 的 Bit-perfect 保证。

## M1 真实能力边界

- 没有音频服务时不推进播放时钟、不记录播放历史，不把假进度/假音量/示例歌词显示为用户数据。
- 目录新增、停用、恢复，扫描启动/取消，以及成员管理是已有写操作，不因“只读客户端”称呼而被误禁；源音频始终只读。
- 扫描状态来自后端 `running | succeeded | failed | canceled | incomplete`，诊断计数不是进度百分比。
- 页面/区域必须具备加载、空、错误、无权限、冲突与适用的恢复路径；正常成功提示不长期占据主要阅读空间。
- 版本聚合、问题处理、通用审批和 Steward 未交付时不提供虚假可点击操作。原型示例不是服务器事实。

## 真实播放器交互合同（M2 及以后）

以下从旧任务保留行为语义，实施仍待对应子任务批准：

- 同一播放生命周期跨页面存续；具体 `PlayerEngine` 实现方式由 M2 确定。真实状态由媒体事件驱动，而不是模拟定时器。
- 立即播放歌曲或列表替换当前上下文；加入队列不打断当前项；下一首播放插在当前项之后。
- Track ID 表达曲目身份；队列条目 ID 表达同曲多次入队的独立位置，排序和移除不能混用两者。
- 顺序模式末曲结束后暂停；列表循环返回首曲；单曲循环处理自然结束，手动前后切歌仍切换；随机模式避免无意义连续重复并支持返回上一项。
- 当前项移除、清空队列、播放失败、未知时长和末项结束都有明确可测状态，不允许越界或静默播放另一版本。
- 拖动仅在对应媒体实际可 seek 且时长有效时启用；音量、静音等控件应明确实际能力限制，不能声称控制硬件音量。
- 刷新后如批准恢复队列，应保持暂停；切换账号或会话失效停止旧媒体并清空用户范围状态。
- 歌词有真实数据才显示，缺失展示空态；来源、时间轴和不支持格式不伪造。
- 历史只记录实际开始的播放；最低有效播放标准、重试去重和多端语义由 M2 确定，不在 M1 生成记录。

## 组件、权限与可访问性

- 延续 React 组件责任与边界 decoder；图标可复用已声明的 lucide-react，但不能因包存在而假定控件已有。
- 命令用 `button`，导航用链接，标题层级、列表/表格和 landmark 保持语义。
- 图标按钮必须有可访问名称；非通用图形提供 tooltip 或等价说明，不能只依赖 hover。
- 键盘支持核心导航、表单和队列操作；如采用拖拽，必须有等价非拖拽入口。
- 对话框有名称、焦点约束、安全的 Esc/取消和关闭后焦点恢复；异步状态用节制的公告，不按每个扫描文件播报。
- 权限、错误和证据等级不能只用颜色区分；焦点清楚，字体缩放和窄屏下操作仍可触达。
- UI 角色判断只控制展示；后端仍决定会话、角色、资源、路径、revision/幂等和恢复能力。

## 禁止事项

- 不在展示组件直接 `fetch`、强转原始 JSON 或构造主机文件路径。
- 不在 URL、播放器状态或浏览器持久层保存 session token、绝对源路径或凭据。
- 不静默把真实 API 错误替换为演示成功；测试受控响应不得进入生产运行路径。
- 不把扫描事件当作可撤销检查点，不向用户承诺未实现的硬件输出、删除源文件、暂停扫描或外部元数据。
- 不新增独立生产前端服务；生产资产继续由 Go 同源提供。

## 后续实现验收清单

- [ ] 桌面与窄屏无内容/固定区域遮挡，长标题和放大字体不覆盖操作热区。
- [ ] 真实 API 的认证、浏览、目录和扫描主路径可用，错误/冲突可恢复。
- [ ] 所有可见动作与已交付后端能力匹配，未交付能力不伪装成功。
- [ ] 播放子任务覆盖队列身份、播放模式、切页连续性、seek 限制、失败与会话清理。
- [ ] 键盘完成核心操作，焦点可见、名称明确、弹层关闭后恢复正确。

M0 只核对文档合同；以上界面与播放验收不因写完本规范而视为通过。
