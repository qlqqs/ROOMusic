# Classical 浏览与播放器规范

## 当前状态与设计依据

2026-09-27 基线没有 `frontend/src/` 或真实音频服务；M1 已恢复浏览客户端，
M2a 已增加后端鉴权直出并接入播放器，M2b 增加 ALAC 的服务端无损派生（转换成 FLAC 后交付）与内嵌歌词的同步显示。三组手工实播尚待执行，不能宣称全部兼容性已验收。唯一落地视觉依据是 [frontend/DESIGN.md](../../../frontend/DESIGN.md)，
原始设计位于 `frontend-desgin/`。旧月刊布局、朱红主色、大圆角和生产演示播放器不再适用。

M1a/M1b 仅接入既有认证、目录/扫描、成员 API 与阶段 I 的按组只读接口；真实播放从 M2a（直出）开始，
M2b 补派生与歌词（均已实现）。未完成阶段的控件隐藏或明确禁用，不能用模拟状态充当功能。具体阶段与未决方案见
[Core 1 路线](../../../docs/architecture/core-1-roadmap.md)。

## 视觉与布局

- 使用 DESIGN 中的 Classical 色彩、排版、间距、细线和小圆角规则；不复制原型散落的内联数值作为第二套 token。
- 私有资料库工作流优先，保持 Release/Medium/Track、版本事实和证据的可扫描性，不做营销首屏或装饰性大卡片。
- 桌面采用原型的侧栏与独立主内容；仅在真实播放器交付后提供有效的持续播放区域。路由形式另经 ADR/M1 决定，不强制旧 hash 路由。
- 窄屏布局按 DESIGN 的落地约束验证，不把原型桌面固定宽高当作移动端适配证据。
- 固定底部区域必须预留内容空间与触屏安全区；长标题、错误文本、按钮状态变化不能遮住最后一行或造成控件抖动。
- 布局子项需要时设置 `min-width: 0`；长文本可截断但有可访问完整名称。验收包含超过 1000 字的合法标题。
- 信号路径只显示已核实的源、服务端环节与浏览器环节；服务端环节按交付方式写明“原文件直出”，或“无损转换”（ALAC 解码后重新编码为 FLAC，
  位深、采样率与声道不变，发布前核对两者解码后的 PCM 一致，播放前仍核对来源与权限）。格式表还没取到时写“读取中”，不替 ALAC 曲目说“原文件直出”。
  不把“无损编码/传输”提升为系统输出或 DAC 的 Bit-perfect 保证。

## M1 真实能力边界

- 没有音频服务时不推进播放时钟、不记录播放历史，不把假进度/假音量/示例歌词显示为用户数据。
- 目录新增、停用、恢复，扫描启动/取消，以及成员管理是已有写操作，不因“只读客户端”称呼而被误禁；源音频始终只读。
- 扫描状态来自后端 `running | succeeded | failed | canceled | incomplete`，诊断计数不是进度百分比。
- 页面/区域必须具备加载、空、错误、无权限、冲突与适用的恢复路径；正常成功提示不长期占据主要阅读空间。
- 版本聚合、问题处理、通用审批和 Steward 未交付时不提供虚假可点击操作。原型示例不是服务器事实。

## 真实播放器交互合同（M2 及以后）

以下行为已纳入用户批准的 M2a；具体实现与验证记录见[M2a 任务](../../tasks/archive/2026-10/10-03-classical-m2a-direct-playback/prd.md)：

- 同一播放生命周期跨页面存续；具体 `PlayerEngine` 实现方式由 M2 确定。真实状态由媒体事件驱动，而不是模拟定时器。
- 立即播放歌曲或列表替换当前上下文；加入队列不打断当前项；下一首播放插在当前项之后。
- Track ID 表达曲目身份；队列条目 ID 表达同曲多次入队的独立位置，排序和移除不能混用两者。
- 顺序模式末曲结束后暂停；列表循环返回首曲；单曲循环处理自然结束，手动前后切歌仍切换；随机模式避免无意义连续重复并支持返回上一项。
- 当前项移除、清空队列、播放失败、未知时长和末项结束都有明确可测状态，不允许越界或静默播放另一版本。
- 拖动仅在对应媒体实际可 seek 且时长有效时启用；音量、静音等控件应明确实际能力限制，不能声称控制硬件音量。
- 刷新后如批准恢复队列，应保持暂停；切换账号或会话失效停止旧媒体并清空用户范围状态。
- 歌词有真实数据才显示，缺失展示空态；来源、时间轴和不支持格式不伪造。面板规则见下文“M2b 歌词面板”。
- 历史只记录实际开始的播放；最低有效播放标准、重试去重和多端语义由 M2 确定，不在 M1 生成记录。

## M2b 歌词面板

数据、提取与解析规则见[歌词合同](../backend/lyrics-contracts.md)；面板（`features/player/components/lyrics-panel.tsx`）只显示接口返回的真实歌词。

- 位置：正在播放页首屏按**容器宽度**（不是视口）分两种布局。宽于 760px：左为封面、右为歌词面板（与封面同高，至少 280px，内部滚动，上下渐隐），
  标题、艺人、专辑、状态与控制在两栏下方，再往下是信号路径与队列；窄于 760px 单栏：封面（最大 280px）、标题与控制、歌词（最高 60vh）。
  没有当前曲目时不显示面板。DOM 顺序是宽屏的阅读顺序（封面、歌词、标题与控制）。
- 状态：加载中、读取失败（带请求 ID 的错误与“重试”）、没有歌词（“这首曲目没有内嵌歌词”，不是错误）、纯文本、同步。404 是错误，不当成没有歌词。
- 纯文本：空行分段，静态显示，不高亮、不可点；可滚动区域可聚焦，键盘用户能滚动阅读。
- 同步：每个时间点一组（同一时间戳的多行是主行加对照行）；当前组 `aria-current="true"`，用强调色加左侧标记，已唱过的组用次要文字色，未到的组用主文字色，
  三种颜色对背景的对比度都不低于 4.5:1，状态不只靠颜色。高亮只改颜色，不改字号、字重与行高（左边框常驻，状态变化不挪动文字）；
  间奏（空文本）不显示文字，也不暴露给读屏。
- 跟随：默认开启；当前组变化时滚到面板中部（第一次直接到位，之后平滑；`prefers-reduced-motion` 下不平滑）。用户的滚轮、触摸、滚动键或拖动滚动条即暂停跟随，
  并出现“回到当前行”按钮；程序触发的滚动不算用户滚动。点“回到当前行”或点任一行都恢复跟随。当前组是间奏时视图停在上一句。
- 点击与键盘：媒体可拖动时每组是按钮，点击或 Enter 调用 `engine.seek(start_ms / 1000)`；Tab 只停在当前组的按钮上（没有当前组时是第一句），
  方向键、Home、End 在各句之间移动焦点，不让上百句各占一个 Tab 停靠点。不可拖动时各组是普通文本。
- 公告：不设 `aria-live`，当前行变化与播放时间不进入读屏公告；加载中用普通文字，不用 `role="status"`（每次切歌都会出现）。
- 性能：面板只订阅“当前组下标”与“可否定位”，约每秒 4 次的进度事件在组没变时不重绘整份歌词。
- 底部来源说明：“内嵌歌词 · 逐行同步 · 点任一行跳到该处”（可拖动时）、“内嵌歌词 · 逐行同步”、“内嵌歌词 · 纯文本”。

## 组件、权限与可访问性

- 延续 React 组件责任与边界 decoder；图标可复用已声明的 lucide-react，但不能因包存在而假定控件已有。
- 命令用 `button`，导航用链接，标题层级、列表/表格和 landmark 保持语义。
- 图标按钮必须有可访问名称；非通用图形提供 tooltip 或等价说明，不能只依赖 hover。
- 键盘支持核心导航、表单和队列操作；如采用拖拽，必须有等价非拖拽入口。
- 对话框有名称、焦点约束、安全的 Esc/取消和关闭后焦点恢复；异步状态用节制的公告，不按每个扫描文件播报。
- 权限、错误和证据等级不能只用颜色区分；焦点清楚，字体缩放和窄屏下操作仍可触达。
- UI 角色判断只控制展示；后端仍决定会话、角色、资源、路径、revision/幂等和恢复能力。

## 禁止事项

- 不在展示组件直接 `fetch`、强转原始 JSON 或构造主机文件路径。
- 不在 URL、播放器状态或浏览器持久层保存 session token、绝对源路径或凭据。
- 不静默把真实 API 错误替换为演示成功；测试受控响应不得进入生产运行路径。
- 不把扫描事件当作可撤销检查点，不向用户承诺未实现的硬件输出、删除源文件、暂停扫描或外部元数据。
- 不新增独立生产前端服务；生产资产继续由 Go 同源提供。

## M2a 可执行入口与错误矩阵

- 入口：`PlayerProvider(userId)`、`usePlayer()->{engine,snapshot}`、`usePlayerProgress()`、`usePlayerEngine()`（只发命令）、
  `usePlayerSelector()`（只订阅选出的基本值）、`usePlayerProgressSelector()`（只订阅进度里选出的基本值）、`useCurrentTrackMarker()`、`usePlaybackCapabilities()`；
  曲目由 catalog 的已解码详情经 `playerTrackOf/playerTracksOf` 转换。
- 命令：`playTracks/playNext/enqueue/playEntry/removeEntry/moveEntry/clearQueue/setMode/play/pause/togglePlayback/stop/next/previous/seek/setVolume/setMuted/retry`。
  三种入队动作返回 `added|queue_full`，上限 10,000；拒绝超限并提示，不静默截断或部分替换。
- 能力：服务端格式表（每项带 `delivery`）+ `canPlayType` + 可选 `decodingInfo.supported`；询问的是浏览器实际拿到的表示（派生项是转换后的 `audio/flac`），
  API 缺失/抛错时只采用可获得的能力。虚拟 CUE、非白名单（含派生不可用时的 ALAC）与浏览器不支持各有明确原因，整张播放仅加入可播项并提示跳过数量。
- 预检成功后使用返回的同源音频路径；媒体错误再次预检以区分来源/权限与解码问题。
- 派生：预检收到 202 进入“正在准备”并立即再次预检（服务端把预检挂起约 20 秒，两次之间仍至少间隔 1 秒，防止异常的立即 202 被高速重试），
  从第一次 202 起超过 11 分钟按转换失败；切歌、暂停、停止与会话结束放弃等待。音频请求失败后的再次预检得到 202 同样回到“正在准备”。
  当前曲目第一次出声后，为下一首派生曲目预先发一次预检（单曲循环与随机不预取），结果被丢弃、不改变状态；队列或当前项变化时中止。

| 事件或失败 | 可观察处理 |
| --- | --- |
| 404/409 | 标记失败条目、显示固定安全原因（含 `derivation_failed`：无损转换失败）、按模式前进；全部失败时停止，不无限循环 |
| 网络或503 | 当前项暂停、可重试，不连续跳歌 |
| 503 `derivation_busy` | 与网络失败共用重试入口，文案为“服务器正忙于转换，请稍后重试”，底栏与公告同样说明 |
| 202 正在准备 | 状态“正在准备”，按钮写“暂停”；公告只说一次；转换完成后进入加载 |
| 401 | 会话边界同步结束并清理，不保留旧账号媒体 |
| play被策略拒绝 | 暂停并提示请按播放，不伪装已出声 |
| 未知时长或seekable为空 | 显示未知值，禁用无依据定位 |
| 源版本变化 | 提示重新扫描；不能通过重复音频请求绕过核对 |

正常案例：下一首插入当前项后且不打断，按条目ID移除单个重复项。
边界案例：自然结束时单曲循环，手动下一首仍切曲。
失败案例：全部项不可播时停止并提供原因，不用定时器或假时间维持播放状态。

必需验证：API样本与decoder、纯队列四模式、持久数据边界、引擎媒体事件/异步竞态与会话结束、
媒体键、底栏与正在播放组件、键盘菜单与队列、五种宽度布局与axe、隔离真实服务解码/定位。
手工实播另见[验收表](../../tasks/10-06-m2a-acceptance-followup/research/manual-acceptance.md)。
错误做法：忽略`queue_full`、退出时只卸载provider、凭浏览器能力宣称格式已实测。
正确做法：显式提示容量失败、订阅会话结束同步清理、逐项区分自动化结果与手工证据。

### 恢复错误与公告的审查约束

恢复失败可能同时是“队列为空 + 可重试故障”。错误/重试入口必须放在空队列与非空队列的共同区域，
不能只在有当前曲目时展示；至少用一个空队列恢复503的组件回归测试证明重试可达。
选中项/开始预检仅可公告“已选择/正在加载”，收到真实`playing`才可称“正在播放”。
随机历史按本次访问是否实际出声判断，而不是按某条目在其生命周期中是否曾经播放过判断；
预检中跳走的旧条目不能污染实际返回路径。随机“上一首”把离开的条目放回本轮袋子，之后的“下一首”不会跳过它。
暂时无法读取与自动播放被拒同样进入外壳常驻的公告区域，不只在正在播放页提示；公告区域本身常驻，按事件序号换内容。
`loading/preparing/playing/buffering` 共用一个“要播放”判定：按钮写“暂停”，按下即暂停（加载或准备中则放弃，并取消在途的预检）。
只有 `waiting` 进入缓冲，`stalled` 不改变状态（已缓冲的音频照常出声，之后不保证有 `playing`）。
专辑页当前曲目在任何状态都有文字与图标标记，文字是真实状态，不只在出声时出现。
