# Classical 浏览与播放器规范

## 当前状态与设计依据

2026-09-27 基线没有 `frontend/src/` 或真实音频服务；M1 已恢复浏览客户端，
M2a 已增加后端鉴权直出并接入播放器，M2b 增加 ALAC 的服务端无损派生（转换成 FLAC 后交付）与内嵌歌词的同步显示。三组手工实播尚待执行，不能宣称全部兼容性已验收。唯一落地视觉依据是 [frontend/DESIGN.md](../../../frontend/DESIGN.md)，
原始设计位于 `frontend-desgin/`。旧月刊布局、朱红主色、大圆角和生产演示播放器不再适用。

M1a/M1b 仅接入既有认证、目录/扫描、成员 API 与阶段 I 的按组只读接口；真实播放从 M2a（直出）开始，
M2b 补派生与歌词（均已实现）；2026-11-08 正在播放页改为全屏播放器，队列改为抽屉，信号路径改为弹层，并增加波形进度、音量均衡与交叉渐变。未完成阶段的控件隐藏或明确禁用，不能用模拟状态充当功能。具体阶段与未决方案见
[Core 1 路线](../../../docs/architecture/core-1-roadmap.md)。

## 视觉与布局

- 使用 DESIGN 中的 Classical 色彩、排版、间距、细线和小圆角规则；不复制原型散落的内联数值作为第二套 token。
- 私有资料库工作流优先，保持 Release/Medium/Track、版本事实和证据的可扫描性，不做营销首屏或装饰性大卡片。
- 桌面采用原型的侧栏与独立主内容；仅在真实播放器交付后提供有效的持续播放区域。路由形式另经 ADR/M1 决定，不强制旧 hash 路由。
- 窄屏布局按 DESIGN 的落地约束验证，不把原型桌面固定宽高当作移动端适配证据。
- 固定底部区域必须预留内容空间与触屏安全区；长标题、错误文本、按钮状态变化不能遮住最后一行或造成控件抖动。
- 布局子项需要时设置 `min-width: 0`；长文本可截断但有可访问完整名称。验收包含超过 1000 字的合法标题。
- 信号路径只显示已核实的事实，规则见下文“全屏播放器、队列抽屉与信号路径”；界面上没有任何解释句（不写“原样发送，不转码”“ALAC 转成 FLAC……”“由浏览器解码……”之类），
  不把“无损编码/传输”提升为系统输出或 DAC 的 Bit-perfect 保证。

## M1 真实能力边界

- 没有音频服务时不推进播放时钟、不记录播放历史，不把假进度/假音量/示例歌词显示为用户数据。
- 目录新增、停用、恢复，扫描启动/取消，以及成员管理是已有写操作，不因“只读客户端”称呼而被误禁；源音频始终只读。
- 扫描状态来自后端 `running | succeeded | failed | canceled | incomplete`，诊断计数不是进度百分比。
- 页面/区域必须具备加载、空、错误、无权限、冲突与适用的恢复路径；正常成功提示不长期占据主要阅读空间。
- 版本聚合、问题处理、通用审批和 Steward 未交付时不提供虚假可点击操作。原型示例不是服务器事实。

## 真实播放器交互合同（M2 及以后）

以下行为已纳入用户批准的 M2a；具体实现与验证记录见[M2a 任务](../../tasks/archive/2026-10/10-03-classical-m2a-direct-playback/prd.md)：

- 同一播放生命周期跨页面存续；具体 `PlayerEngine` 实现方式由 M2 确定。真实状态由媒体事件驱动，而不是模拟定时器。
- 立即播放歌曲或列表替换当前上下文；加入队列不打断当前项；下一首播放插在当前项之后。
- Track ID 表达曲目身份；队列条目 ID 表达同曲多次入队的独立位置，排序和移除不能混用两者。
- 顺序模式末曲结束后暂停；列表循环返回首曲；单曲循环处理自然结束，手动前后切歌仍切换；随机模式避免无意义连续重复并支持返回上一项。
- 当前项移除、清空队列、播放失败、未知时长和末项结束都有明确可测状态，不允许越界或静默播放另一版本。
- 拖动仅在对应媒体实际可 seek 且时长有效时启用；音量、静音等控件应明确实际能力限制，不能声称控制硬件音量。
- 刷新后如批准恢复队列，应保持暂停；切换账号或会话失效停止旧媒体并清空用户范围状态。
- 歌词有真实数据才显示，缺失展示空态；来源、时间轴和不支持格式不伪造。面板规则见下文“M2b 歌词面板”。
- 历史只记录真实出声的播放，计次规则见下文“计一次播放（阶段 P）”。

## M2b 歌词面板

数据、提取与解析规则见[歌词合同](../backend/lyrics-contracts.md)；面板（`features/player/components/lyrics-panel.tsx`）只显示接口返回的真实歌词。

- 位置：全屏播放器里（布局见下节）：宽屏在右栏标题下方占满剩余高度、内部滚动、上下渐隐；窄屏与唱片占同一块，点唱片切到歌词。没有当前曲目时不显示面板。
- 状态：加载中、读取失败（带请求 ID 的错误与“重试”）、没有歌词（“这首曲目没有内嵌歌词”，不是错误）、纯文本、同步。404 是错误，不当成没有歌词。
- 纯文本：空行分段，静态显示，不高亮、不可点；可滚动区域可聚焦，键盘用户能滚动阅读。
- 同步：每个时间点一组（同一时间戳的多行是主行加对照行）；当前组 `aria-current="true"`，用强调色加左侧标记，已唱过的组用次要文字色，未到的组用主文字色，
  三种颜色对背景的对比度都不低于 4.5:1，状态不只靠颜色。高亮只改颜色，不改字号、字重与行高（左边框常驻，状态变化不挪动文字）；
  间奏（空文本）不显示文字，也不暴露给读屏。
- 跟随：默认开启；当前组变化时滚到面板中部（第一次直接到位，之后平滑；`prefers-reduced-motion` 下不平滑）。用户的滚轮、触摸、滚动键或拖动滚动条即暂停跟随，
  并出现“回到当前行”按钮；程序触发的滚动不算用户滚动。点“回到当前行”或点任一行都恢复跟随。当前组是间奏时视图停在上一句。
- 点击与键盘：媒体可拖动时每组是按钮，点击或 Enter 调用 `engine.seek(start_ms / 1000)`；Tab 只停在当前组的按钮上（没有当前组时是第一句），
  方向键、Home、End 在各句之间移动焦点，不让上百句各占一个 Tab 停靠点。不可拖动时各组是普通文本。
- 公告：不设 `aria-live`，当前行变化与播放时间不进入读屏公告；加载中用普通文字，不用 `role="status"`（每次切歌都会出现）。
- 性能：面板只订阅“当前组下标”与“可否定位”，约每秒 4 次的进度事件在组没变时不重绘整份歌词。
- 面板底部没有来源说明行（2026-11-08 起删除），只在暂停跟随时出现“回到当前行”按钮。

## 全屏播放器、队列抽屉与信号路径（2026-11-08）

正在播放页（`/now-playing`）已取消：旧地址在根路由下跳到概览并替换历史项（不保留路径后缀与 `#queue`），侧栏不再有“正在播放”。
组件都在 `features/player`：`FullscreenPlayer`、`PlayerBar`、`QueueButton`/`QueueDrawer`、`SignalPathButton`、`WaveformSeek`、`PlayerFaultInline`；
心形与“存为歌单”仍由 app 经插槽交给播放栏、全屏与队列抽屉（`AppShell` 里的模块级函数，引用不变；播放栏的心形只给读屏说失败，全屏完整提示）。

**全屏播放器**
- 打开：点播放栏封面（按钮，名称与悬停提示“打开全屏播放器”）。收起：向下箭头按钮（“收起全屏播放器”）、Esc、浏览器返回。
- 开合记在历史条目的 state：`useFullscreenPlayer()` 打开时 `router.history.push(当前地址, { ...state, roomusicPlayer: 本次页面加载 ID, playerFrom: 原条目 key })`，
  地址不变、不触发换页；收起是 `history.back()`。刷新后加载 ID 不同，不会自动重开。专辑页判断“新的到达”时优先看 `playerFrom`，打开全屏不会重新定位曲目。
  在全屏里点专辑或艺人是普通导航，全屏随之关闭，在新页面按返回会回到全屏。队列被清空时自动收起。
- 容器是 `ModalDialog`（原生模态 `<dialog>`）：焦点先到收起按钮，关闭后回到封面按钮；打开从封面位置放大淡入，收起缩回 180 ms 再关闭，离开当前页面时直接关闭；
  `prefers-reduced-motion` 下没有动画。
- 版面：深色面，背景是放大、模糊、压暗的封面（没有封面时深灰），容器内局部改写文字变量，歌词面板与控件沿用变量。
  宽屏两栏：左黑胶唱片，右标题（`h2`）、“专辑 · 艺人”链接、状态行、心形、歌词；底栏是收起、信号路径圆点、传输控制、波形进度（两端时间）、播放模式、队列、音量。
  窄屏（< 768px）单栏：唱片本身是按钮（“显示歌词”），切到歌词后右上角图标按钮“显示唱片”切回；窄屏不显示音量滑块；不得横向溢出。
- 黑胶：中心是封面；`status === "playing"` 时唱片转动，否则停在当前角度；“要播放”的状态（加载、准备、出声、缓冲）唱臂落下，否则抬起。减少动态效果时唱片不转、唱臂直接到位。

**播放栏**：封面是打开全屏的按钮，标题是纯文本；格式文字前是信号路径圆点；“队列（N）”是图标按钮（悬停提示“队列”）；进度条是 `WaveformSeek`。
故障就地显示在标题下（`PlayerFaultInline`）：读取失败、服务器正忙时旁边有“重试播放”图标按钮；被拒的自动播放写“请按播放”；全屏状态行同样显示。
队列为空但有可重试故障（`transient`/`busy`，例如恢复队列时暂时读取失败）时播放栏仍显示，重试入口不消失；播放栏消失时焦点放回主内容区。

**队列抽屉**：播放栏与全屏底栏各一个队列图标，各自持有开合状态。抽屉从右侧滑出，内容即原队列（播放此项、上移、下移、移除、清空并确认、存为歌单插槽、随机时的提示），
Esc、关闭图标或点外面（`ModalDialog` 的 `closeOnBackdrop`）关闭，关闭后焦点回到队列图标；在全屏里打开时是嵌套在全屏之上的对话框，Esc 只关最上层。

**信号路径弹层**
- 圆点颜色只看源编码：`flac/alac/pcm/ape/wavpack/aiff` 无损（金色实心），`mp3/aac/vorbis/opus/wavpack_hybrid` 有损（灰色实心；WavPack 混合模式没有 `.wvc` 时只有有损部分），
  其他未知（空心，如 `wavpack_float`、`wavpack_dsd`、`aiff_float`、`aifc_*`）；名称与悬停提示是“信号路径：无损/有损”或“信号路径”，不只靠颜色。
- 数据源与服务端两行的编码名用短名表：`ape` → `APE`，`wavpack`/`wavpack_hybrid` → `WavPack`，`aiff` → `AIFF`，其他取值写成大写（`FLAC`、`ALAC`、`PCM`……）。
- 点圆点打开 `ModalDialog`（`closeOnBackdrop`），宽屏在圆点上方，窄屏从底部弹出。标题写整体质量（同上），各层一个图标、名称与一行取值，没有任何解释句；响度一层只在有分析结果时出现：

| 层 | 取值 |
| --- | --- |
| 数据源 | 无损“编码 采样率 位深 声道”（如 `FLAC 44.1kHz 16bit 2ch`），有损“编码 码率 采样率 声道”；缺的项省略，全缺写“未知格式” |
| 响度 | 当前曲目分析结果（`useTrackAnalysis`，与波形共用缓存）里的积分响度、响度范围、真峰值，以“ · ”连接，如 `−14.2 LUFS · 范围 6.3 LU · 峰值 −0.8 dBTP`；一位小数，负号用 `−`；缺的项省略。分析不是 `done` 或三项全缺时整行不出现；采样峰值不显示 |
| 服务端 | `原文件直出`；派生写“源编码短名 → FLAC”（`ALAC → FLAC`、`APE → FLAC`、`WavPack → FLAC`、`AIFF → FLAC`）；格式表还没取到写“读取中”（不替派生曲目说“原文件直出”） |
| 浏览器 | `解码`，以“ · ”接上：接入 Web Audio 且均衡生效时 `音量均衡 +2.1 dB`（实际施加的增益，一位小数，总带正负号，0 写 `0.0 dB`，响度未知写 `−5.0 dB`）；渐变开着且已接入时 `交叉渐变 5 秒` |
| 系统输出 | `系统默认输出` |

**波形进度条**（`WaveformSeek`）：当前曲目有分析结果时，底层 canvas 画波形、上面覆盖透明的原生 `range`（名称“播放进度”、`aria-valuetext`、键盘、点击、拖动都由原生控件提供，焦点环画在外层）。
宽 W 像素画 `floor(W/3)` 根柱，每根取区间最大峰值，**按本曲最大峰值归一化**后再按 `^0.6` 拉伸，最低 1px；已播放与未播放两色；只订阅播放比例。
没有分析（未完成、失败、读取失败或加载中）时是普通进度条。分析数据与缓存见[播放与个人状态](./playback-and-personal-state.md)。

## 计一次播放（阶段 P）

引擎按媒体事件累计真正出声的时间，达到门槛 `min(曲长 / 2, 4 分钟)` 时经 `playRecorder` 交出一次，每次访问最多一次；服务端用同一公式校验，
完整规则与接口见[播放历史合同](../backend/listening-contracts.md)。界面与引擎的约束：

- 只累计 `playing` 状态下播放位置的前进量：预检、准备、加载、缓冲、暂停、拖动跨过的距离与后退都不算；静音与音量为 0 照常累计。
- 换曲、单曲循环的每一轮、在队首按“上一首”、停止或播完后再播是新的访问；暂停后继续、重试与卸载再挂载是同一次访问；刷新页面后从零开始，不写浏览器存储。
- 引擎不发请求、不等结果、不处理上报失败；上报失败不改变播放状态、不提示用户。会话结束时作废未发出的上报。
- 概览的“最近播放”只显示服务端给的事实（最多 8 张专辑、上次播放时间），不画进度条、剩余时间；有任何记录时有“全部历史”链接（M5 ①起，指向 `/me/history`）。

## 历史页的播放语义（M5 ①）

动作由 app 组合（`app/routes/history-playback.tsx`），反馈文案沿用专辑页：

- 行内“播放”：用这一首**替换**当前队列并开始播放，不像专辑页的“从这首开始播放”那样放入整张。“更多”菜单的“下一首播放”“加入队列”不打断当前曲目，
  提示“已设为下一首播放。”“已加入队列。”，队列满时提示“队列已满，请先移除一些条目。”且不截断；菜单里还有“从历史中移除”（始终可用）。
- 能否播放：文件缺失（`present=false`）优先，写“文件缺失，不能播放”；其次按能力表（`verdictOf` + `unplayableText`）。不能播放时“播放”与菜单里的两个入队项禁用，
  原因经 `aria-describedby` 可读（文件缺失的原因只给读屏，标签已在曲目列显示）。能力表读取失败时由“播放全部”旁的“重试检查”恢复。
- “播放全部”：每次读服务端的候选（与列表同序、最近最多 1,000 首，不受当前页影响），放入其中 present 且能力表判为可播放的，替换队列并播放；不往更早的历史补位。
  提示“已选择 N 首[，跳过 M 首不可播放的曲目]。”，`M = 候选数 − 可播放数`（截断掉的不算跳过）；`truncated` 时另说明“历史太长，只取了最近的 1,000 首。”。按钮旁不另加规则说明。
  一首都不能播放时不动当前队列并说明；队列满（理论上不会，候选不超过上限）时提示且不截断。

## 组件、权限与可访问性

- 延续 React 组件责任与边界 decoder；图标可复用已声明的 lucide-react，但不能因包存在而假定控件已有。
- 命令用 `button`，导航用链接，标题层级、列表/表格和 landmark 保持语义。
- 图标按钮必须有可访问名称；非通用图形提供 tooltip 或等价说明，不能只依赖 hover。
- 键盘支持核心导航、表单和队列操作；如采用拖拽，必须有等价非拖拽入口。
- 对话框有名称、焦点约束、安全的 Esc/取消和关闭后焦点恢复；异步状态用节制的公告，不按每个扫描文件播报。
- 权限、错误和证据等级不能只用颜色区分；焦点清楚，字体缩放和窄屏下操作仍可触达。
- UI 角色判断只控制展示；后端仍决定会话、角色、资源、路径、revision/幂等和恢复能力。

## 禁止事项

- 不在展示组件直接 `fetch`、强转原始 JSON 或构造主机文件路径。
- 不在 URL、播放器状态或浏览器持久层保存 session token、绝对源路径或凭据。
- 不静默把真实 API 错误替换为演示成功；测试受控响应不得进入生产运行路径。
- 不把扫描事件当作可撤销检查点，不向用户承诺未实现的硬件输出、删除源文件、暂停扫描或外部元数据。
- 不新增独立生产前端服务；生产资产继续由 Go 同源提供。

## M2a 可执行入口与错误矩阵

- 入口：`PlayerProvider(userId)`、`usePlayer()->{engine,snapshot}`、`usePlayerProgress()`、`usePlayerEngine()`（只发命令）、
  `usePlayerSelector()`（只订阅选出的基本值）、`usePlayerProgressSelector()`（只订阅进度里选出的基本值）、`useCurrentTrackMarker()`、`usePlaybackCapabilities()`；组件 `PlayerBar`、`FullscreenPlayer`、`PlayerAnnouncement`、`PlaybackSettingsForm`；
  曲目由 catalog 的已解码详情经 `playerTrackOf/playerTracksOf` 转换。
- 命令：`playTracks/playNext/enqueue/playEntry/removeEntry/moveEntry/clearQueue/setMode/play/pause/togglePlayback/stop/next/previous/seek/setVolume/setMuted/retry/setPlaybackSettings`。
  三种入队动作返回 `added|queue_full`，上限 10,000；拒绝超限并提示，不静默截断或部分替换。
- 能力：服务端格式表（每项带 `delivery`）+ `canPlayType`（非空即可解码）；询问的是浏览器实际拿到的表示（派生项是转换后的 `audio/flac`）。
  不用 `decodingInfo`：iOS Safari 对能播放的 FLAC/MP3 也报告 `supported: false`。虚拟 CUE、非白名单（含派生不可用时的 ALAC）与浏览器不支持各有明确原因，整张播放仅加入可播项并提示跳过数量。
- 预检成功后使用返回的同源音频路径；媒体错误再次预检以区分来源/权限与解码问题。
- 派生：预检收到 202 进入“正在准备”并立即再次预检（服务端把预检挂起约 20 秒，两次之间仍至少间隔 1 秒，防止异常的立即 202 被高速重试），
  从第一次 202 起超过 11 分钟按转换失败；切歌、暂停、停止与会话结束放弃等待。音频请求失败后的再次预检得到 202 同样回到“正在准备”。
  当前曲目第一次出声后，为下一首派生曲目预先发一次预检（单曲循环与随机不预取），结果被丢弃、不改变状态；队列或当前项变化时中止。

| 事件或失败 | 可观察处理 |
| --- | --- |
| 404/409 | 标记失败条目、显示固定安全原因（含 `derivation_failed`：无损转换失败）、按模式前进；全部失败时停止，不无限循环 |
| 网络或503 | 当前项暂停、可重试，不连续跳歌 |
| 503 `derivation_busy` | 与网络失败共用重试入口；播放栏与全屏写“服务器正忙”并给“重试播放”，公告“服务器正忙于转换，已暂停，可以重试。” |
| 202 正在准备 | 状态“正在准备”，按钮写“暂停”；公告只说一次；转换完成后进入加载 |
| 401 | 会话边界同步结束并清理，不保留旧账号媒体 |
| play被策略拒绝 | 暂停并提示请按播放，不伪装已出声 |
| 未知时长或seekable为空 | 显示未知值，禁用无依据定位 |
| 源版本变化 | 提示重新扫描；不能通过重复音频请求绕过核对 |

正常案例：下一首插入当前项后且不打断，按条目ID移除单个重复项。
边界案例：自然结束时单曲循环，手动下一首仍切曲。
失败案例：全部项不可播时停止并提供原因，不用定时器或假时间维持播放状态。

必需验证：API样本与decoder、纯队列四模式、持久数据边界、引擎媒体事件/异步竞态与会话结束、
媒体键、播放栏与全屏播放器组件、键盘菜单与队列抽屉、五种宽度布局与axe、隔离真实服务解码/定位。
手工实播另见[验收表](../../tasks/10-06-m2a-acceptance-followup/research/manual-acceptance.md)。
错误做法：忽略`queue_full`、退出时只卸载provider、凭浏览器能力宣称格式已实测。
正确做法：显式提示容量失败、订阅会话结束同步清理、逐项区分自动化结果与手工证据。

### 恢复错误与公告的审查约束

恢复失败可能同时是“队列为空 + 可重试故障”。错误/重试入口必须放在空队列与非空队列的共同区域，
不能只在有当前曲目时展示（播放栏在这种情况下仍显示，见上文“播放栏”）；至少用一个空队列恢复503的组件回归测试证明重试可达。
选中项/开始预检仅可公告“已选择/正在加载”，收到真实`playing`才可称“正在播放”。
随机历史按本次访问是否实际出声判断，而不是按某条目在其生命周期中是否曾经播放过判断；
预检中跳走的旧条目不能污染实际返回路径。随机“上一首”把离开的条目放回本轮袋子，之后的“下一首”不会跳过它。
暂时无法读取与自动播放被拒同样进入外壳常驻的公告区域，不只在播放栏或全屏里提示；公告区域本身常驻，按事件序号换内容。
`loading/preparing/playing/buffering` 共用一个“要播放”判定：按钮写“暂停”，按下即暂停（加载或准备中则放弃，并取消在途的预检）。
只有 `waiting` 进入缓冲，`stalled` 不改变状态（已缓冲的音频照常出声，之后不保证有 `playing`）。
专辑页当前曲目在任何状态都有文字与图标标记，文字是真实状态，不只在出声时出现。
