# 受治理操作的组件约定（`features/governance`）

从[组件规范](./component-guidelines.md)移出：管理员的受治理写操作（M3）、默认版本、元数据问题页（M4 第二项）与待认领页（M4 第三项）的组件约定。
通用约定（共用组件、状态、可访问性）仍在组件规范。

管理员专用；后端仍独立鉴权，界面只决定显示。结果就近显示在操作区（`ReleaseCommandNotice`：成功、明确的拒绝、结果不确定各有文案与下一步），不用全局 toast。

| 组件 | 约定 |
| --- | --- |
| `ReleaseAdminActions` | 专辑详情头部的操作区（由 app 经插槽 `renderAdminActions` 传给 catalog 的详情视图）：编辑发行信息、归入其他专辑…、移出为独立专辑（组内多于一个版本才有）与上一次操作的结果提示；成功提示里有“撤销”（撤销本身的成功提示没有）。命令状态由页面持有。M4：多于一个版本时还有“设为默认版本”（自动选出的代表版本也有，用来钉住）或默认版本上的“改回自动选择”，不弹确认，插槽上下文带专辑的 `groupRevision` 与 `defaultReleaseId`；M4 第二项：当前版本需要关注时有“查看问题”（链接到 `/issues` 并选中它）；M4 第三项：`claim-hints` 不为空时，在按钮行与结果提示之间有低调的一行“可能接替了已不可见的《…》”加“查看并认领”（链接到 `/claims?release=<旧版本>&target=<当前版本>`；读取失败不重试、不提示）；“撤销”也能撤销认领，成功后页面跟着新版本回到认领之前所在的组 |
| `EditReleaseDialog` | 八个字段各一个 `fieldset`：三选一（使用扫描值 / 自定义 / 留空，标题与专辑艺人没有“留空”）、自定义输入、写明扫描值；扫描结果不确定的字段多“确认扫描值”。**草稿只记动过的字段**：没动的字段始终显示最新基线，只提交动过且确有变化的字段，别人刚改过的字段不会被静默改回去；409 时对话框保持打开、保留草稿并重新载入最新状态；结果不确定时“保存”变成同一个键的“重试保存”。字段的 `legend` 在已有修正时带“人工修正”，测试按前缀匹配 |
| `JoinAlbumDialog`、`DetachAlbumDialog` | 归入：按标题搜索专辑（复用 `/release-groups?q=`，结果不含当前组，只显示最相关的前几张并提示输入更精确的搜索词），单选列表的可访问名称含标题与艺人（标题与元信息之间要有空格），选中后预览结果（`role="status"`），确认才提交；移出：确认对话框写明结果，移出的是默认版本时多说明“专辑改按自动规则显示，它回来时会重新成为默认版本”。成功后页面跟到新的专辑组并选中这个版本 |
| `OperationList` | `DataTable`：时间（行标题）、操作者、专辑（可见的链接到它现在所在的组并选中这个版本，专辑目标的记录链接到专辑本身，已不可见的只写标题）、改动（类型名加逐行描述）、操作；只有 `revertible` 的行有“撤销”，其余在同一位置写出原因（已撤销、之后又有修改、专辑已不可见、撤销不能再撤销）；每行按钮文字相同，时间与类型放进可访问名称（`VisuallyHidden`） |
| `RevertOperationDialog` | 确认对话框写明会改回什么（前后互换的逐行预览）与“撤销会留下一条自己的记录，不能再被撤销”；结果不确定时保持打开、“撤销”变成“重试撤销”；成功或明确的拒绝关闭对话框，由页面提示说明。撤销成功后触发它的按钮所在行已变，`useRevertFlow` 把焦点带到区块标题或折叠面板的标题行 |
| `OperationsView`、`ReleaseHistory` | “操作记录”页内容（分页、按版本与专辑筛选并写明在看谁的记录、页码越界规范化）与专辑详情折叠的“修改记录”（展开才读取这个版本和这张专辑最近 5 条、带“全部记录”链接）；两处共用 `OperationList` 与撤销流程，撤销的结果提示放在折叠区块外，收起或换专辑组之后仍看得到 |
| `IssuesView`（M4） | “元数据问题”页：容器宽于 900px 两栏（列表 `--layout-issue-list-width`、详情最宽 860px），更窄顺序导航（`release` 有值只显示详情与“返回问题列表”）。筛选是链接（`aria-current`、`aria-label` 写全“待处理，2 个版本”），详情三节各有核对状态与操作，见 [Hook 规范](./hook-guidelines.md) |
| `ClaimsView`（M4 第三项） | “待认领”页（`/claims`，`AdminGate`）：容器宽于 900px 两栏（列表 `--layout-issue-list-width`、详情最宽 860px），更窄顺序导航（`release` 有值只显示详情与“返回待认领列表”）；地址参数 `page`、`release`（选中的旧版本）、`target`（选中的新版本，没有 `release` 时丢弃，换旧版本时清掉，用替换历史项的方式更新）。结果提示（`ReleaseCommandNotice`）放在详情上方、不限定在某个版本（认领之后旧版本的详情就变成“不需要认领”的说明），提交后焦点落在提示上（`successFocusRef`），带“撤销”和“打开这张专辑” |
| `ClaimList` | 带名称的链接列表（选中写进地址，当前项 `aria-current`，链接只改 `release`、保留页码）；一行写旧版本标题（有修正时是修正后的名字）、原来的专辑、位置、最后一次看到的时间与留着的修改，各段之间用空格，可访问名称读起来是一句话 |
| `ClaimDetail`、`ClaimTargetPicker` | 详情分节列出留着的修改（字段修正、所在的专辑与默认版本、问题核对，没有的节不出现；核对人不存在写“（用户已不存在）”），再是“选择接替它的版本”：推荐是带封面的**单选组**（理由文字如“同样的文件（12 个）”“同一目录”），下面是“搜索其他版本”（与“归入其他专辑”同一个专辑搜索：先选专辑，专辑有多个版本时再选其中一个，只有一个版本就直接选中）；提交期间选择区整体 `fieldset disabled` |
| `ClaimPreview` | 选中新版本后逐项说明（迁移、因为新版本已有而保留、默认版本改回自动选择、缺失曲目的核对不迁移，以及迁过去的核对立即生效、会重新提醒或暂时无事可压），用文字而不只靠颜色区分；按钮“认领到《…》”，不弹二次确认（预览就是确认，结果可撤销）；预览读取失败 `404` / `409 not_claimable` 就地说明，其余可重试，结果不确定时按钮变“重试认领” |

对话框的实现经验：加载态换成字段时焦点会丢，所以对话框打开后初始焦点放在标题上（确认对话框仍在“取消”上）；jsdom 不实现 `<dialog>` 的 Esc 取消，Esc 由 Playwright 覆盖；
长标题与无空格长串要在表格与对话框里换行（`overflow-wrap: anywhere`），Playwright 检查对话框自己没有横向滚动。
