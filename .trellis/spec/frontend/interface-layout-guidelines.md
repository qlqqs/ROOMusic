# 界面布局与交互约定（2026-11-15）

按钮布局、设置页、侧栏、专辑详情、播放栏、信号路径与全屏播放器的整理结果。设计依据是任务 `11-14-ui-layout-polish` 与 `11-14-ui-interaction-polish` 的定稿预览（参考 Apple Music、Spotify、Roon 与系统设置），
设计层面的说明在 [DESIGN-components.md](../../../frontend/DESIGN-components.md)“界面整理（2026-11-14）”。本文件只写已实现的合同；与旧规范冲突时以本文件为准，
旧条目已在[播放器规范](./player-design-guidelines.md)与[组件目录](./component-catalog.md)里标注。

## 共用控件（`shared/ui`）

| 组件 | 约定 |
| --- | --- |
| `MenuAction.group` | 相邻且 `group` 相同的项为一组，组间一条 `role="separator"`；有名字的组包在 `role="group"` 里，组标题（`aria-hidden` 的小号灰字，经 `aria-labelledby` 作为组名，避免读两遍）是它的名称，不可聚焦，方向键跳过。不给 `group` 的项结构与以前相同；打开后先校正菜单位置，再用 `focus({ preventScroll: true })` 聚焦首项，避免底边触发器引发文档滚动而被滚动关闭监听误关；仅当打开后锚点坐标实际改变时响应滚动关闭，菜单内部滚动与打开前的迟到事件不关闭 |
| `MenuAction.danger` | 危险项与普通项分段，文字与图标用警示色；同名组不重复标题，停用项仍用次要色 |
| `MenuAction.hint`、`untitledGroup` | `hint` 是右侧说明，也是菜单项名称的一部分，与标签之间保留空格；`untitledGroup` 保留组间分隔线但不显示组标题 |
| `FilterField`、`FilterChip`、`SortMenu` | 列表筛选共用控件：250ms 后提交，首次 push、后续 replace；清空与失焦结束输入过程，前进后退由地址同步草稿。校验失败就近提示且不写地址。胶囊用 `aria-pressed`，排序菜单显示当前项；均不发请求、不判断角色 |
| `SettingsGroup` | `section` + `h2` 标题 + 卡片；可给标题旁的操作、状态（`status`）、标题 ref 与卡片下方的脚注。卡片宽度用 ResizeObserver 量出，经 context 告诉里面的 `Segmented` 是否窄（< 640px，与 CSS 里的 639px 成对修改）；没有 ResizeObserver（jsdom）时按宽处理 |
| `SettingRow` | 左名称（可带一行说明）、右控件右对齐；名称是指向 `controlId` 的 `<label>`，子内容可以是 `(ids) => ReactNode` 拿到 `controlId`/`labelId`/`descriptionId`。控件是按钮或只读值时用 `plainLabel`（`<label>` 指向按钮会改掉按钮的名称）。`nested` 是从属项：缩进、字号小一级；所属开关关闭时**由调用方不渲染**这一行，不做禁用态。容器查询：卡片窄时控件放不下才换到下一行 |
| `Segmented` | 宽卡片里是 `role="radiogroup"` 的相连分段，窄卡片里是同名同值的原生 `<select>`（`aria-labelledby` 指向行名称）。用量宽切换而不是 CSS 同时渲染两份，避免读屏与测试看到重复控件 |
| `Switch` | 开关（`role="switch"`），名称来自 `SettingRow` 的 label |
| `TextField labelHidden` | label 视觉隐藏但仍是输入框的名称；用于单行工具条，可见提示改为 placeholder |
| `useShelf` | 横向书架不截掉卡片，溢出才出现具名翻页按钮；到头方向变淡但不禁用，焦点保持；减少动态效果时不平滑滚动 |
| `StatusTable`、`StatusRow` | 具名区段内的列表，每行左侧名称与说明、右侧状态；可经 `renderLink` 生成整行链接，链接内不再放按钮；首次读取与失败分别用占位行与重试 |
| `EmptyState` | 空状态图标、标题、说明与可选下一步操作，由调用方决定权限与导航 |
| `DataTable.headerContent` | 允许表头放全选控件，列名仍用于窄屏堆叠的标签 |
| `useMediaQuery`（`shared/lib`） | 同一个查询共用一个 `MediaQueryList`，列表每行订阅不产生多个监听 |

## 曲目行（专辑页与各列表页）

- 动作显隐只在 `@media (hover: hover) and (pointer: fine)` 下生效：行内动作按钮 `opacity: 0` + `pointer-events: none`，行悬停或 `:focus-within` 时显现；
  行是最近的 `[role="row"]`（表格式列表）或 `[data-track-row]`（专辑曲目）。已收藏的心形（`aria-pressed="true"`）、展开中的“更多”（`aria-expanded="true"`）、
  等待确认的心形（`aria-busy`）常驻。触屏不隐藏任何动作。不用 `:has()`（目标浏览器含 Firefox 113）。淡入 0.12s，`prefers-reduced-motion` 下无过渡。
- 专辑页：带 `data-track-play` 的播放按钮放在序号位（`TrackActions playPlacement="lead"`），悬停或聚焦时盖住序号；触屏常驻。当前曲目的序号位是音柱（减少动态效果时静止），
  标题用强调色，“正在播放 / 已暂停”只给读屏。双击行等于点它的播放按钮；双击发生在链接或按钮里时不触发，双击不选中文字。
- 右键菜单：曲目所在的行加 `data-context-row`（专辑行、个人曲目表行、`DataTable contextRows`），行里的 `TrackActions` 用 `useRowContextMenu` 接管：鼠标右键在指针处弹出，
  行内按菜单键或 Shift+F10 弹在行左下；动作与“更多”相同，最前面多一项“播放”（专辑页最后多“曲目信息”）。输入框、链接（鼠标右键）、行内有选中文字与触屏长按（`pointerType === "touch"`）不拦截，仍是浏览器菜单。
- 一行一首、艺人单独一栏：搜索、历史、艺人页（`DataTable` 列选项 `truncate` + `width` + `cellTitle`）与收藏、歌单（`TrackTable`，“艺人”是曲目艺人）宽表里标题、艺人、专辑单行省略，
  单元格 `title` 给全文；标题单元格里不再写艺人。窄容器（< 640px）里 `secondary` 列不带标签，在标题下合成一行“艺人 · 专辑（· 时长）”。栏名统一叫“艺人”，不用“艺术家”。
- 窄屏（< 767px）心形收进行的“更多”，菜单项是“收藏 / 取消收藏”。结果不确定且重读失败时，菜单项不可用，菜单旁出现与心形相同的“重新读取”（`useFavoriteMenuAction` 返回 `{ action, retry }`，`data-favorite-retry` 常驻）。其他列表页（历史、搜索、艺人、收藏、歌单）播放按钮仍在心形旁，显隐规则相同。

## 专辑详情

- `AlbumHeader` 经 `Page header` 渲染整个页头：“‹ 专辑”返回链接（读屏名“返回专辑列表”）、封面、`h1`、专辑艺人、概况行、操作行、需要关注行；文字与封面底边对齐。
- 当前曲目与详情同一 `releaseId` 或 `groupId` 时，大按钮按播放区 `intent` 显示“暂停播放 / 继续播放”，调用 `engine.pause()` / `engine.play()`，保留队列、当前曲目与位置；其他专辑仍是从头播放整张。
- 手机封面宽度约 250px 并居中，标题、概况、共同署名与操作行一起居中。共同署名的提取规则见[组件目录](./component-catalog.md)。
- 操作行顺序固定：圆形播放（状态名称见上）、随机播放、心形、添加到歌单（只有图标）、更多。键盘顺序与视觉顺序一致，窄屏不重排。
- 随机播放（`useAlbumPlayback().shuffle`）：先检查队列上限，再 `setMode("shuffle")`，再 `playTracks(可播放曲目, 随机起始下标)`——`playTracks` 默认从 0 开始，必须传随机下标。
- “更多”菜单：下一首播放（`playNext(整张)`）、加入队列；管理员另有“管理”组（编辑发行信息、设为默认版本 / 改回自动选择、归入其他专辑…、移出为独立专辑、查看问题）。
  `useReleaseAdminActions` 返回 `{ actions, panel }`：`actions` 进菜单，`panel`（认领提示、结果提示、对话框）显示在操作行下方，结果提示位置不变。
  组合在 app（`album-detail-page.tsx`）：player、personal、governance 各出钩子，互不导入。
- 版本导航是标签（链接加 `aria-current`），“对比版本”在行尾；“版本”`h2` 只给读屏。标题不同时标签里只显示一行，完整标题在链接名称里。
- 曲目表（`ReleaseMedia`）：栏目 # / 标题 / 艺人 / 作曲 / 操作 / 时长，一行一首，过长省略、悬停看全文；任一曲有作曲署名才有作曲栏，艺人栏总在（写曲目艺人）。
  仍是 `ol/li` 列表语义（作品是嵌套列表），栏目靠 subgrid 对齐；表头 `aria-hidden`，艺人、作曲单元格前有只给读屏的“艺人：”“作曲：”。作品组标题行只写作品名与总时长。
  曲目区按自身宽度（容器查询 < 640px）折叠成两行：标题，下一行淡色“艺人 · 作曲”，艺人与专辑艺人相同时不写。行内不写署名。
- 选中即看详情（参考 Roon、foobar2000）：单击行（不在控件上、不是双击的第二下、没有选中文字）选中，选中底色加左侧 3px 黄铜线（画在行外，内容不动），标题里只给读屏“，已选中”；
  再次单击同一行、Esc（焦点不在菜单或对话框里时）或“关闭曲目信息”取消。双击仍是播放。菜单里的“曲目信息”选中该行并把焦点移到曲目信息标题。
- 右栏顺序固定：发行信息 → 制作人员（不再列“专辑艺人”，没有其他条目时整块不出现）→ 曲目信息（`TrackInfo`）：标题、第几张第几首与时长，艺人（仅与专辑艺人不同时）、
  本曲独有署名（`ownTrackCredits` 去掉页头共同署名，再去掉名字已在曲目艺人里的演奏者）、格式、响度（app 经 `renderTrackFacts` 插槽给 player 的 `TrackLoudness`，catalog 不导入 player）。
  版面宽度 < 720px（右栏在曲目下方，`ResizeObserver` 量 `.layout`）时曲目信息改在底部弹出的 `ModalDialog` 里，内容相同。

## 播放栏

- 三段：左封面（打开全屏）、标题、“艺人 — 专辑”（链接与文字同色，悬停才变深并有下划线）、心形；中段 信号路径、上一首、播放、下一首、播放模式与两端时间的进度（播放模式在 `trailing` 插槽，与左侧的信号圆点对称，2026-11-24 起）；右侧固定顺序：队列、分隔线、设备、音量。列宽 `1fr / minmax(240px, 2fr) / minmax(max-content, 1fr)`，中段最宽 560px。
  标题旁不放信号圆点。
- `TransportControls` 有 `leading` / `trailing` 两个插槽（取代旧的 `modes`），调用方放信号路径、设备、播放模式与音量；插槽里的控件与传输键同一尺寸（`--transport-button`）和间距；
  `size="compact"` 时插槽在 767px 以下随上一首一起隐藏。插槽里的设备、信号路径、音量弹层是渲染在行内的 `<dialog>`，传输键的按钮尺寸规则用 `:where(:not(.transport dialog *))` 排除它们。
- 播放模式是一个按钮 `PlayModeButton`：顺序 → 列表循环 → 单曲循环 → 随机 → 顺序，图标 `ListOrdered` / `Repeat` / `Repeat1` / `Shuffle`；名称与悬停提示“播放模式：顺序 / 列表循环 / 单曲循环 / 随机”（`playModeLabels`）；
  非顺序时 `aria-pressed`，强调色加 4px 圆点。
- 音量是一个喇叭按钮 `VolumeButton`（名称“音量”，静音时“音量（已静音）”；图标按静音或 0、低于 50%、其余分 `VolumeX` / `Volume1` / `Volume2`）：点开锚定的小弹层
  （`ModalDialog` + 锚点坐标，按钮在视口上半部时向下弹，水平夹在视口内），里面是百分比、竖向滑块“播放器音量”（`writing-mode: vertical-lr; direction: rtl`）与“静音 / 取消静音”。
  设备不能调音量时按钮禁用，外层 `title` 写“这台设备不能调音量”。宽屏与 768–1023px 都只有这个图标，不再有横向滑块。
- 封面按钮悬停或键盘聚焦时压暗（40% 黑）并在中间显示 `ChevronUp`，指针是手形（不用 `zoom-in`）；120ms 淡入，减少动态效果时无过渡；迷你栏不显示遮罩。
- 状态文字只在加载、缓冲时出现（右侧控制区）；错误仍在标题下（`PlayerFaultInline`）。
- 窄屏（< 768px）是浮起的迷你栏（封面、标题、设备、播放、下一首、队列，没有信号圆点），底边一条进度线；外层透明并让点击穿过，迷你栏在底部标签栏上方，留白计入两者实际高度与安全区，不遮最后一行。本机有当前曲目时隐藏迷你栏设备按钮，控制远端时在播放键左侧显示金色设备图标；本机无曲目而其他设备在线或有可接手队列时保留普通设备入口，因为这时没有封面可打开全屏。显隐和网格列数共用 `data-device-visible`，不依赖 `:has()`；全屏底部始终有设备入口。

## 信号路径

- 入口 `SignalPathButton` 只有呼吸圆点，放在传输键最左一格（播放栏中段、全屏控件行、手机全屏传输行），格子与传输键同宽；名称与悬停提示“信号路径：FLAC 24/96，增强”，削波时加“，削波”；
  没有 `signal` 时格子仍在（传输键不随曲目左右移动），格式只给读屏，没有按钮。弹层的可访问名称仍是“信号路径：…”。
- 设备列表已选行保留选中底色，只给未选中行叠加悬停底色；两层半透明底色叠加会降低文字对比度，验收同时覆盖选中与悬停的组合。
- `StatusTag` 的中性色字用 `--tag-neutral-text`（默认 `--color-neutral-800`），全屏深色面改写为 `--color-neutral-200`，从全屏打开的设备列表里的“本机”标签才有足够对比度。
- 圆点颜色按整体评级（无损 `--text-accent`、增强 `--color-signal-enhanced`、高质量 `--color-signal-high`、有损 `--text-secondary`），削波 `--color-warning`。
- 呼吸：只在 `playing` 时动，暂停、缓冲、出错静止。4s 一轮：0→38% 吸气（`cubic-bezier(.37,0,.63,1)`，scale .78→1、opacity .55→1），38→88% 呼气（`cubic-bezier(.45,.05,.3,1)`），88→100% 停顿；
  `::after` 光晕独立一层（8→42% scale 1→1.9、opacity 0→.26，42→80% 扩到 2.6 并淡出）。削波是红色约 0.9s 的脉冲（同样只用 transform 与 opacity）。只动画 transform 与 opacity；
  `prefers-reduced-motion` 下没有动画。
- 弹层宽 340px：头部是评级图标、评级名与“来源 → 设备”摘要；步骤链每步拆成步骤名与取值（`stepParts`），最差的一步加粗（整体无损时不加粗），最后一个节点是“输出：设备名”；
  底部测量格两列：响度、范围、峰值（`useTrackAnalysis`）与处理速度，缺的项不出现。全屏里用深色面。

## 全屏播放器

- 宽屏两栏：左唱机，下面是控制台（标题、心形、“更多”、“专辑 · 艺人”、两端时间的波形进度，一行控件：信号路径、设备、上一首、播放、下一首、播放模式、音量，间距 14px）；
  右栏 `歌词 / 接下来` 切换，有歌词时默认歌词，没有歌词时默认“接下来”。两栏整体居中，顶部只有左上的收起；设备在控件行里，设备列表向上弹出；右栏已有“接下来”，不重复放队列按钮。“更多”有“转到专辑”和每位艺人一项“转到艺人：名字”（艺人链接可用时）。
- `LyricsPanel size="large"`：当前行 32px、其余 24px，已唱行更暗，渐隐更长，当前行停在约 35% 高度。字号变化不做动画，只有颜色过渡（取代旧规则“高亮不改字号”）。
- `UpNextList`：基于 `upNext(queue, 20)`，每项是按钮“播放《标题》”，点了 `playEntry`；随机模式下显示“随机播放中…”提示；空时“队列里没有接下来的曲目”。
- 窄屏：顶部行（收起、“正在播放”与专辑名、更多），唱机本身是“显示歌词”按钮，传输行（信号路径、上一首、播放、下一首、播放模式），底部行（设备图标、“歌词”开关 `aria-pressed`、队列）。
  手机上不放音量（参考 Apple Music、Spotify，交给实体键）。不改唱机动画本身。
- 全屏根元素声明 `color-scheme: dark`，里面打开的弹层随之继承，原生控件与滚动条按深色绘制。
- 滚动条：信号路径弹层、设备列表、全屏“接下来”、宽屏左栏与窄屏全屏的滚动区用细滚动条（`scrollbar-width: thin; scrollbar-color: var(--scrollbar-thumb) transparent`，
  `--scrollbar-thumb` 用 `currentColor` 在使用处取值，深色面上自然是半透明浅色）；歌词不显示滚动条（`scrollbar-width: none` 加 `::-webkit-scrollbar { display: none }`），仍可滚轮、触控、键盘滚动。页面主滚动条不改。

## 设置

- 分栏保持 176px，顶部“设置”标题；管理员的音乐目录（2026-11-24 前叫“扫描目录”，与概览的“音乐目录”统一）、成员、自动整理、操作记录、备份在“管理”小标题下的另一个列表。< 1024px 时变成一行可横向滚动的胶囊标签，不显示小标题。
  内容最宽 720px（音乐目录与扫描详情 820px）；横滚标签两端按剩余内容显示渐隐，切换栏目只在标签行内滚动，使当前项完整可见。
- 播放设置分“播放 / 输出 / 音效处理”三组；页首写“这些设置作用于正在控制的设备：设备名”。渐变时长、目标采样率、增益是从属行，所属开关或选项关闭时不渲染。
  削波指示不是 Headroom 的从属项（后端不依赖 Headroom 使用它）。“音质”改名“串流音质”。处理顺序是一个“对调”按钮（名称“对调处理顺序”）加“卷积 → 参数均衡”链。

  批次（行尾菜单查看这一批的改动与撤销这一批；明细复用按批次筛选的操作记录）、不再提出（逐条清除）。总开关关着或暂停时，外部源的不生效原因写在分组层面一行。

  模型判断（E2）：状态与不可用原因（当前管理员是开启者时链接 Agent 设置）、整理用的模型与每日上限（即改即存，照备份自动清理：回车或失焦提交，勾“不限”立即提交；上限单位万 token，服务器值不是整万时改用 token）、
  今天的用量（有上限时带比例条）、待定项各状态的数目、最近 3 个后台会话（链接到管家会话页）；从未打开过时整组只有一句说明。审查模型与有效整理模型相同时在“整理用的模型”的说明里提示另选（U11）。
  例外（E2）：表格列提出时间、发行（链到这个发行的操作记录）、提出的修改（匹配先写带 MusicBrainz 链接的外部编号，再逐行写曲目对应、字段前后值、归组）、审查结论与理由、操作；

## 侧栏与列表页

- 管理员分组名为“管理”；侧栏用户名旁齿轮直接进设置，账号菜单包含账号与退出。歌单标题行的“＋”复用新建歌单对话框。
- 搜索框占位符“搜索全部音乐”，浅底无边框，右侧 `/` 提示（真实快捷键，`aria-keyshortcuts="/"`）；只在精确指针、输入框为空且未聚焦时显示。
- “元数据”“待认领”只在本会话已经读过对应列表时显示数字（`useCachedTodoCounts` 只读查询缓存，不发请求）；0 不显示；数字经描述给读屏（“N 个待处理的问题”），链接名称不变。
- 歌单行在名称前有 26px 封面（`PlaylistCover size="thumb"`，`Cover variant="thumb"`：无裱边、懒加载、`aria-hidden`）：4 组封面拼 2×2，1–3 组用第一张，没有时是歌单图标。
  行与主导航左对齐不缩进，当前歌单高亮；数据就是 `usePlaylists(1)` 的结果。导航列用 `minmax(0, 1fr)`，长名称省略号截断。
- 专辑与艺人列表用 `FilterField` 即时筛选，去掉提交按钮；关注与角色用胶囊、排序用菜单，控件同高，窄屏按组换行；Tab 顺序不变。
- 曲目“更多”中的播放与加入歌单项带图标；有可用引用时追加“前往艺人”（第一位），其他专辑的曲目有“前往专辑”（携带 track 定位）；当前专辑页不重复提供自己的专辑入口。

- 概览主栏依次为继续播放、最近播放、最近新增（没有播放记录时最近播放整块不出现；资料库还没有专辑时主栏是一段说明，管理员带“添加音乐目录”的链接，右栏的资料库卡片不出现）；右栏上面是资料库卡片（`LibraryStats`：标题“资料库”在卡片外，卡片里 2×2 宫格，大号数字在上、单位在下，可进入的格子单位后有箭头），下面是资料库状态；没有页底账目。
