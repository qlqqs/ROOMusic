## 1. 为什么是沙箱而不是独立进程

ADR 0006 的原则 6 是“能力由宿主分配：外部源只拿到自己那类能力的口子，不能自行取得其他权限”。独立进程与服务器有同样的系统权限，
能读数据目录、数据库凭据文件和任意网络地址，宿主只能“希望”它守规矩；这与原则 6 不符。WebAssembly 模块默认什么都没有，
宿主给什么它才有什么，原则 6 由运行时保证。

架构决策摘要原先写“只有需要运行不受信任的第三方代码时才考虑 WASM 沙箱”。第三方插件正是不受信任的第三方代码，所以这里直接采用沙箱。

## 2. 运行时与风险

- Extism 提供多语言的插件开发包（Rust、Go、JS 等）与统一的调用约定；底层 wazero 是纯 Go、不需要 CGO，适合现有的静态二进制与加固容器。
  Navidrome 自 2026 年起在生产中使用同一组合。
- Extism 的 Go SDK 自 2025 年中停止更新，内置 HTTP 存在已知缺陷且不能注销。对策：只用它的编译、实例与宿主函数部分，
  内置 HTTP 保持全部拒绝并用回归测试锁住；所有 Extism 类型封在适配层，必要时换成 fork 或直接在 wazero 上实现同一套约定。
- wazero 没有按指令计量的 CPU 上限，只能靠超时终止；内存默认上限过大，必须显式设置。生产容器里编译器模式不可用时退回解释器。

## 3. 插件与外部源的关系

插件不引入新的写入通道。它把结果交给宿主，宿主按外部源的规则决定写不写：只补空缺、人工修正优先、每条有记录、可撤销、被撤销的不再写。
插件给出的图片只是地址，由宿主下载与校验；文字由宿主清洗与限长。
