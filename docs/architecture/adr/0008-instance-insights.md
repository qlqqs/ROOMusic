## 1. 为什么需要

服务端完全开源、免费，项目的收入来自手机端与模型服务。决定要不要做这两项，需要知道有多少实例在用、多少人用到管家与局域网设备。
自托管软件默认不回报任何数据，下载量又会被升级、CI 和自动更新工具放大，得不出活跃实例数。

## 2. 为什么默认开启

默认关闭时，只有少数主动去设置里打开的实例会发送，数字偏低且偏差无法估计，起不到判断作用。
默认开启的代价由三点抵消：发送内容少且全部公开列出；管理员第一次登录就看到说明并能一键关闭；统计端程序与汇总都公开。

## 3. 发送的内容与边界

- 实例 ID 是首次启动随机生成的 UUID，与机器、IP、账号无关。
- 数字一律分档（曲目数、发行数、成员数、设备数），布尔只表示某功能是否在用。
- 出站按公网地址规则，不跟随重定向，超时 10 秒；失败等下一轮，不重试。
- 统计端只在内存里按 IP 限速；90 天没有心跳的实例被删除。
- 汇总数字来自实例自报，汇总页注明这一点。

## 4. 不采用的做法

| 做法 | 不采用的原因 |
| --- | --- |
| 默认关闭、由管理员自己打开 | 数字太少且偏差无法估计，得不出活跃实例数 |
| 使用第三方统计服务 | 数据经过第三方；国内访问不稳定；用户无法核对统计端 |
| 发送精确计数或曲库内容 | 超出判断所需；精确计数加上版本与时间可能识别出具体实例 |
