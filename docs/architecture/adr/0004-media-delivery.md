## 2. 问题与推荐方向

目标是让后端按当前权限读取确定的曲目，尽量直出；遇到已验证的兼容性缺口或 CUE 虚拟轨时，
使用有界、可丢弃的受管派生文件。播放质量描述必须区分源编码、服务端处理与浏览器/系统输出，
不能从文件名、浏览器探测或无损编码推断硬件 Bit-perfect。

推荐候选：**同源、逐请求鉴权的媒体读取 + 可选 FFmpeg 工作器 + 完整派生文件缓存**。
首版优先让完成文件承担 Range/seek，不同时承诺任意实时转码 seek、无缝衔接或硬件直通。

| 方案 | 优点 | 代价与适用边界 |
| --- | --- | --- |
| 推荐：直出优先，必要时生成完整派生缓存 | 复用浏览器媒体元素；完整表示易于定义长度、校验标识和随机读取；可复用昂贵转码 | 冷启动有等待和磁盘成本；需要取消、配额、版本失效及额外二进制部署 |
| 替代 A：仅受保护的原文件直出（**已批准为 M2a 首发范围，2026-09-28**） | 无 FFmpeg 依赖和派生空间，适合首批已验收格式 | 不支持的容器/codec 明确不可播放；ALAC/CUE 的完整目标由 M2b 的派生缓存承接 |
| 替代 B：按需流式转码或独立分段媒体服务 | 可能缩短首音等待，适合未来远程网络/自适应码率需求 | 新增会话、分段、seek、时间映射和运维复杂度；普通未完成管道不是可随机 seek 的文件，不能套用完整文件的 Range 承诺 |

FFmpeg 外部进程可作为模块化单体的媒体适配器，不必新增独立长期服务；但部署不再只有一个
无外部媒体工具依赖的 Go 文件。具体方案必须在 M2 的性能与部署实验证据后采纳。

## 3. 边界与数据流

建议职责，尚未定义最终模块名、路由或 payload：

```text
播放器：opaque Track ID + 有界客户端能力线索 / 用户质量偏好
  → 同源媒体传输：会话、请求与 Range 边界
  → 媒体用例：当前权限 + catalog 可播放来源合同 + 输出策略
  → 受限文件适配器：安全打开当前源文件并确认版本
       ├─ 已验证可直出 → 只读、可定位的表示
       └─ 需要派生 → 有界工作器 → 受管临时文件 → 校验 → 原子发布
  → 再核对授权 / 来源有效性 → 读取完整表示 → 浏览器解码 → 系统音频输出
```

- 身份模块拥有会话与角色；catalog 拥有 Track 与来源事实，library 拥有根的有效性与读取约束。
  媒体用例通过窄合同消费它们，不直接依赖跨模块私有表。前端只能提交资源身份，不能提交路径、
  FFmpeg 参数、任意 URL、滤镜文本或用于执行的 codec 名称。
- 源文件在真正打开/处理时重新验证：允许根内的正规文件、实际解析后的 containment、符号链接与
  替换竞态、缺失/离线/权限错误。CUE 父来源须同样验证，不能把扫描时保存的相对引用直接拼接执行。
  M2 必须证明“检查后打开”不会造成越界；具体安全文件句柄/快照方案留待适配器设计。
- 推荐仅允许当前可见、来源有效且根允许读取的曲目；禁用根是否立即停止已有播放需明确产品合同。
  未确认前不能把旧 `present` 记录或已有缓存当作永不过期的读取许可。
- 派生临时文件与最终文件只写入配置的受管缓存目录；该目录必须与所有音乐源根隔离，启动时验证，
  不在源旁生成转码文件、标签或 CUE 分轨。不得把整个受管数据目录作为无鉴权静态目录挂载。
- 前端队列与播放生命周期遵循 [ADR 0001](0001-frontend-foundations.md) 的会话清理边界；
  M2 的 PlayerEngine 才能把真实媒体事件作为进度和完成依据，不能沿用模拟计时器。

## 4. 容器、codec 与能力协商

容器、codec、采样率、位深和声道需要分别记录。MDN 明确区分容器与实际编码；同一扩展名不能
推出兼容性（M01）。源事实不足或已变化时，使用受限探测确认，不能伪造 MIME 或把 ALAC 当 AAC。
`ffprobe` 可提供流与格式信息，但必须与 FFmpeg 一样受进程、输入和输出预算约束（M07）。

推荐的协商顺序：

1. 后端只提供经过批准的候选表示及其必要技术描述，不暴露原始路径或可任意配置的转码参数。
2. 客户端针对实际容器/codec 组合调用 `canPlayType()`；结果是空字符串、`maybe` 或 `probably`，
   不是确定性解码证明（M02）。浏览器能力线索不得成为后端权限或资源预算依据。
3. 若环境支持，再用 Media Capabilities 的 `decodingInfo()` 辅助判断给定配置；其
   `supported`、`smooth`、`powerEfficient` 是能力信息，不保证任意文件、seek 或硬件无损输出。
   API 缺失/拒绝时使用保守回退，不据此宣称源损坏（M03）。
4. 实际加载、播放、拖动成功才计入兼容证据。失败时仅尝试批准的有限候选，不进行无限格式探测；
   `play()` 可能因自动播放策略而拒绝，应等待用户手势，不能把队列状态当作已出声（M04）。
5. 测试记录须包含浏览器及版本、操作系统、容器/codec/参数、传输方式、seek 结果和测试日期。
   本次没有浏览器实播矩阵，不写“某格式全浏览器支持”或硬编码永久浏览器名单。

### 输出策略候选

| 表示 | 适用条件 | 必须保留的真实说明 |
| --- | --- | --- |
| 原文件直出 | 物理曲目，源当前有效，候选容器/codec 已通过目标环境验证 | 字节不变不等于播放链路不重采样；按实际类型声明 Content-Type |
| 重封装 | 编码本身可用但容器不合适，且输出组合经过验证 | FFmpeg streamcopy 不经解码/重编码，但仍受目标容器限制；不是改个后缀，也不保证 CUE 精确切分（M06） |
| 无损派生 | 例如 ALAC 解码后输出经验证的 FLAC 或 PCM/WAV；也可用于 CUE 分轨 | 明确保留采样率、声道与可表达的精度，验证解码后 PCM；不能保证所有浏览器播放候选输出 |
| 有损兼容/节省带宽表示 | 仅在用户批准的质量策略下，选择经部署与浏览器验证的 AAC、Opus 等组合 | 标明有损重编码与实际参数，不能悄悄降级后仍标“原始/无损”；codec/容器与构建许可单独验证 |

ALAC 若已经可直出，无需无条件转码。对于原本有损的源，把解码结果装入无损格式不会恢复源中
已经丢失的信息。若没有通过验证的可用表示，显示“不支持/转换不可用”，而不是假播放。

### CUE 分轨与时间精度

现有解析器 `parseCueTimecode` 使用每秒 75 帧的 CUE 时间单位，`setCueTrackRanges` 保存同一
父来源内的范围；这不是 PCM sample 序号。后续实现应把已验证的区间转成明确的样本边界，记录
舍入规则、尾轨结束与 pregap/`INDEX 00` 策略，不能盲目按浮点秒或文件字节截取。

FFmpeg 文档说明输入 `-ss` 可能先到附近 seek 点，转码时的 accurate seek 与 streamcopy 行为
不同；`atrim` 可按样本裁剪，但本身不重置时间戳（M06、M08）。因此推荐先验证父音频，再精确裁剪
并为派生曲目建立从零开始的时间轴；不能把 `-ss` 加 `-c copy` 直接当作样本精确保证。

对多文件 CUE、缺失 INDEX、越界/倒序范围、未知尾长、帧到样本转换以及编码器延迟/padding
设定验收；无法确定安全区间则拒绝派生，不偷偷播放整张镜像。gapless 是另一个跨曲目验收问题，
不因分轨完成自动成立。

## 5. HTTP Range、seek 与鉴权

推荐首版只对原文件的稳定版本或**已完成、可定位**的缓存表示承诺随机读取。
HTTP byte Range 定位的是该表示的字节，浏览器时间 seek 还取决于容器索引、时间戳和解码器；
“返回 206”不是拖动准确性的证明（M05、M10）。

- Go `http.ServeContent` 可处理 Range 和条件请求，要求可定位内容；应用须在调用它之前完成
  权限、资源版本和安全文件打开，显式设置已验证的 Content-Type 与合适的校验标识。
  它不替应用鉴权，也不自动证明文件未被替换。其默认错误路径会移除 Cache-Control 等响应头，
  M2 还需验证安全错误格式与错误响应缓存策略，不能直接把默认行为当作项目合同（M05）。
- GET、HEAD、每次 Range、条件请求和缓存命中均先鉴权。未授权时不能为了命中缓存返回 304，
  也不能泄露资源长度或存在性。HEAD 不应仅因探测就启动高成本派生。
- 对有效范围返回正确的 206、Content-Range 与长度；对有效但不可满足的范围验证 416。
  对畸形、重叠、多范围和过多请求明确拒绝或有界处理策略，避免放大 CPU/IO；具体错误映射在
  M2 合同定稿。条件请求和 If-Range 必须绑定同一表示版本（M10）。
- 表示变化时更换强校验标识，不能仅用 Track ID 或旧 mtime 拼接不同版本的分段；客户端应重新
  开始读取，不能把旧字节和新字节混成一条流。头已发送后的错误只能中止传输并记录安全诊断，
  不能在音频尾部追加 JSON 错误。
- 普通转码管道没有可复用的完整文件长度和随机定位能力；不得谎报完整长度或 Range 能力。
  FFmpeg 也指出普通 MOV/MP4 在未正确完成时有可解码性问题，分片容器是不同的输出/验收路径
  （M09）。首版缓存生成中应呈现真实等待或取消状态，不把未完成文件当成完整资源。
- 建议受保护音频使用 `Cache-Control: private, no-store`，禁用共享代理/CDN 缓存及离线音频缓存；
  服务端的派生文件缓存是另一层，仍逐请求授权。RFC 的 `no-store` 不是追溯删除保证，已交付
  的字节、浏览器内存缓冲和用户另行保存的内容不能被服务器收回（M11）。
- 注销/禁用后，新的读取必须被拒绝；对于已建立的长连接，M2 须选择服务端撤销通知或有界周期
  复核等中断机制，明确上界。前端主动停止音频不等于服务端即时撤销保证。复核间隔及根禁用策略
  未定，不能把本 ADR 的“逐请求鉴权”宣传为可追溯撤回已经播放的内容。

媒体元素失败不一定能让前端直接读取错误响应正文。PlayerEngine 需通过受保护的状态/会话核对
路径区分认证、网络与解码错误，最终交互和错误 DTO 在 M2 定稿，不新增长期裸链接或 URL token
来绕过同源 Cookie。

## 6. 派生缓存、并发与取消

缓存是可重建派生物，不是资料库权威。以下为推荐约束，不是现有表结构或配置项。

| 关注点 | 推荐合同 |
| --- | --- |
| 键与失效 | 键包含实际输入内容版本、物理来源或 CUE 父来源身份、起止区间与时间解释版本、输出容器/codec/完整编码参数、处理策略及工具构建版本。权限信息不是内容摘要的替代品；仅有 Track ID、路径、mtime 或大小不能证明内容未变 |
| 输入一致性 | 在读取/派生时为实际输入字节建立版本证据，必要时使用受管不可变快照；成本、摘要计算和文件并发修改策略由 M2 决定。无法证明输出对应某个确定版本时不得发布。扫描观察变化只能触发核对，不能代表已获得强版本证明 |
| 成功发布 | 写唯一临时文件，限制大小，等待子进程成功退出，验证输出流/时长/区间与必要完整性，然后在受管目录原子发布；失败、取消和磁盘满不得留下可命中的半成品 |
| 授权 | 即使相同音频共享派生字节，每个使用者仍经当前权限与来源检查；缓存 key 不作为访问凭据。清理账号内存不等于删除所有共享派生文件，删除缓存也不等于撤销已交付字节 |
| 去重并发 | 相同键共用一个受控工作，等待者单独登记和鉴权；全局/单用户并发、等待队列长度与单任务预算有上限。多实例共享缓存时另选协调锁/租约与发布规则，不能假设进程 mutex 足够，也不自动引入 Redis |
| 取消 | 单个等待者退出只取消其等待；最后一个等待者离开可取消生成，除非另有获批的有界预热策略。工作不能继承第一个 HTTP 请求的唯一生命周期，否则一个断连会破坏其他合法等待者；也不能无所有者地永久继续 |
| 资源限额 | 同时限制 CPU/线程、内存、探测耗时、转换耗时、输出字节、临时+最终占用和最小剩余空间；磁盘耗尽安全失败，不影响数据库/源音频。配额预留须原子协调，不能让并发工作各自看见相同空闲空间而超额 |
| 清理 | 只清理已确认属于媒体缓存的文件；按配额/最近使用等有界策略淘汰，正在生成或被读取的表示保留引用。启动清理遗留临时文件和过期版本；绝不递归清空音乐根、封面目录或全部数据目录 |
| 可观测性 | 记录安全资源 ID、策略版本、耗时、命中、失败类别和限流计数；stderr 有界且脱敏，不把绝对路径、凭据、完整命令参数或用户媒体内容写进普通日志 |

路径和内容摘要只在后端受控边界使用，不作为前端能任意组合的文件名。源缺失、权限丢失或
资料库可见性变化后，即使缓存文件仍在，也不能继续凭旧记录出流。

## 7. 进程、部署与许可证门禁

### 进程安全与运维

推荐使用固定可执行文件与白名单参数数组启动工作，不经 shell，不将用户输入拼成命令。
Go `os/exec` 默认不调用 shell；`CommandContext` 提供取消机制，但不能因此假设子进程组、管道、
临时文件和等待者都已自动收尾，必须验证完整回收及有限停机等待（M12）。

FFmpeg 支持 `protocol_whitelist`，可限制输入协议；这不是完整沙箱（M13）。只允许所需的本地
文件/受控句柄协议，禁用网络输入及非必要 demuxer，不解析用户指定播放列表或外部引用。使用
非特权账号、源只读挂载、独立可写缓存、网络限制与进程资源限制；只选择目标音轨，不自动复制
附件和不必要的元数据。具体部署约束、可用编码器和探测命令必须与实际构建一起验收。

FFmpeg/ffprobe 版本、构建配置、库清单和镜像来源必须固定并记录，升级后按策略版本使旧派生物
失效或隔离。启动检查应明确哪些输出策略可用；缺少工具或 codec 时退回已经验证的直出能力，
不启动假成功任务。是否随镜像分发工具、由管理员安装或使用独立工作服务，需要明确选择。

### 许可与分发审核

本节只记录**官方说明与待完成门禁**，不是法律意见或已满足义务的声明：

- FFmpeg 官方说明其基础许可为 LGPL 2.1 或以后版本，启用某些可选部分会触发 GPL；许可范围
  取决于实际构建。官方源码还说明启用不兼容组件的 `--enable-nonfree` 构建不可再分发（M14）。
  不能只写“FFmpeg 是 LGPL”就通过所有构建。
- 在选定分发方式后，对照官方法律说明及实际组件的 LICENSE 核对适用的许可文本、版权声明、
  对应源码、修改与构建信息提供方式，以及链接/打包条件；形成可复查的构建清单与发布证据。
  本次没有确定发行二进制，也没有完成这些检查。
- 外部进程调用是技术边界，不自动证明 ROOMusic 与任意 FFmpeg 构建的许可兼容，也不免除
  分发该二进制可能产生的义务。发行前必须审核应用许可、依赖、字体/媒体 fixture 和镜像内容。
- FFmpeg 官方将专利问题与版权许可分开讨论；AAC 等候选 codec 的许可/专利影响须结合分发地区、
  用途及具体组件另行审核，必要时交由合格法律顾问确认。不能宣称“开源、只读、自托管”就全球免责。
- 未通过审核的构建或输出策略不进入发布；回退到许可与部署都已确认的能力子集，而非承诺后补合规。

## 8. 音质与硬件 Bit-perfect 的真实边界

建议 UI 分层展示：

| 层级 | 可以展示的证据 | 不得推断 |
| --- | --- | --- |
| 源文件 | 经验证的容器、codec、采样率、位深、声道；缺失标未知 | 后缀相同不等于相同编码；扫描观察不等于实时文件未变 |
| 服务端 | 原始字节直出、重封装、无损/有损派生、已发生的重采样/混音及参数 | “无损编码”不自动证明处理过程没有降位深、音量处理或丢失声道 |
| 浏览器 | 实际选定的表示、加载/解码/播放/seek 状态；可获得的能力提示 | 能力探测不报告实际 DAC 模式，媒体元素也没有端到端位一致性证明 |
| 系统/设备 | 未有可信证据时显示未知或不展示 | 不能标注已验证独占输出、系统音量旁路、硬件采样率或 DAC Bit-perfect |

无损派生的验收对象应是指定区间解码后的 PCM（包括样本数量、声道顺序和精度），不是比较两个
容器文件的 hash。若发生重采样、位深改变、声道重混或增益处理，必须展示实际处理；有损源转无损
容器不能宣传为恢复原始质量。

即使服务端 PCM 验证一致，浏览器与系统仍在证明范围之外。Web Audio 标准明确：当
AudioContext 与输出设备采样率不同时，用户代理必须重采样；因此不得从一个已知上下文采样率
推断硬件链路位一致（M15）。首版优先使用媒体元素的必要播放能力，是否引入 Web Audio、增益、
均衡、响度归一化等处理需另行决定。原型中的“Bit-perfect”“未重采样”和 DAC/硬件音量描述
必须改为可核实的局部事实或未知状态。

## 9. 阶段、兼容与回退

- M0：仅形成提案和验证清单；M1 只恢复已有 API 页面，不安装 FFmpeg，也不提供假播放。
- B0：继续行为保持拆包；媒体端点、进程管理、缓存目录和授权规则是未来业务变更，不随拆包带入。
- M2a（仅直出，2026-09-28 已批准为首发范围）：须先在规划时批准实播矩阵与撤销规则，再设计 API 和测试。
- M2b：须先批准质量策略、CUE 语义、配额/撤销规则及部署/许可门禁，再设计 API、缓存
  元数据和测试。是否需要持久化协调或迁移由实际多实例/恢复需求决定，不在本 ADR 猜测 SQL。
  2026-10-09 起按子任务推进：ALAC 无损派生（已批准并实施，缓存即目录、无迁移）、歌词，CUE 精确分轨延后。
- 运行时退化：工具缺失、缓存满、转换失败、探测不确定时，只保留已经验证且仍有权限的直出；
  没有合法回退就明确不可播放，不伪装为正在播放，也不静默转低质量。
- 回退时可关闭新派生策略，拒绝旧策略的新请求，有限等待/取消在途工作；旧缓存按版本隔离、按
  配额清理，不用旧格式元数据解读新文件，不涉及回写或回滚源音乐。若后续引入业务迁移，另行
  遵循仓库的备份/前向修复合同，不能因缓存可删就声称数据库可任意回滚。

## 10. 后续验收案例（尚未执行）

测试使用小型合成音频和获准 fixture，不依赖、递归扫描或修改仓库真实 `music/`。

| 类型 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| 成功 | 已登录用户播放已验收的物理曲目并反复 seek | 原始字节/实际 codec 一致，范围/条件请求正确，定位和结束事件来自真实媒体 |
| 成功 | 不支持直出的 ALAC 生成获批无损表示，同键两个合法请求 | 一次受控生成；完整后发布；PCM、样本数和参数符合合同；两者各自鉴权 |
| 成功 | 多文件 CUE、首/末轨、边界静音与非零 INDEX | 分轨区间和时间轴准确，不串入相邻曲目；不自动宣称 gapless |
| 失败 | 匿名/禁用/撤销用户访问已热缓存，发送 HEAD、Range 或条件请求 | 不返回字节、304、资源长度或私有错误；已有长连接按批准的撤销上界停止 |
| 失败 | 根被禁用、源 missing/离线、路径穿越、链接逃逸、FIFO 或检查后替换 | 安全拒绝，即使存在旧缓存；不向源写文件、不回显路径 |
| 失败 | 同大小/mtime 的源内容替换、CUE 区间改变、工具构建或输出策略升级 | 旧键不再证明有效；不拼接旧新分段，无法确认版本时拒绝发布 |
| 失败 | 有效但不可满足 Range、畸形/多范围、并发请求滥用 | 416 或约定的有界安全错误，不无界生成、不泄露资源或崩溃 |
| 失败 | 转码进程崩溃/超时、输出损坏、磁盘满或配额竞争 | 无可命中半成品，有限资源与等待；源/数据库不受清理影响 |
| 失败 | 一位等待者断连、全部等待者离开、服务停机、多实例竞争 | 不误杀其他合法使用者；无所有者工作停止；进程、句柄、锁和临时文件最终回收 |
| 失败 | 浏览器报告可播但解码失败、能力 API 缺失、自动播放被拒绝 | 有限候选回退或真实错误；不误判已出声，不承诺全浏览器兼容 |
| 成功/失败 | 有损降级、采样率/精度变化与系统输出未知 | UI 显示实际处理；未经批准不降级；没有硬件 Bit-perfect 假保证 |
| 失败 | 部署缺 FFmpeg/编码器，构建许可材料不完整 | 能力探测明确不可用；未经审核的构建/策略阻止发布 |

以上属于 M2 的定向测试设计，**不是 M0 已通过的媒体、性能、浏览器或合规验证**。其中 ALAC 无损派生相关的案例已由 M2b 的测试覆盖，见[无损派生合同](../../../.trellis/spec/backend/playback-derivation-contracts.md)第 7 节；CUE 相关案例仍未执行。
