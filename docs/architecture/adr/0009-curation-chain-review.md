## 1. 为什么要梳理

上次重构（ADR 0006 第 16 节）实施后，整理链规则多，等待和重试各有一套，每修一处都要重跑一整轮真实试用。同一批 28 张专辑跑了两轮，记录如下：

- 只跑程序：认出 19 张，发了 67 次 MusicBrainz 请求（每张约 2.4 次），用时 185 秒，其中约一半是请求之间原因不明的空等。
- 带模型：多认出 8 张，MusicBrainz 请求增至 441 次。模型用量约 81% 花在巡检、名字与署名核对和联网上，换来 1 次写入和 38 条建议。
- 只有带模型才认出的 8 张：
  - 3 张是上次改出的倒退：同组版本多，被判“候选过多”；
  - 3 张程序已经对上，只是被名字核对的附带项拖着，不算完成；
  - 剩下 2 张真正需要的是“知道正确的名字”。

结论：模型在专辑识别上的用处，是给出正确的名字和线索；查 MusicBrainz 和核对由程序做。巡检、联网档和整理链里的审查用量大，几乎没有带来写入。

## 2. 原则

1. **MusicBrainz 有的认出来，没有的保持本地原样**。“未匹配”只说明查过的来源里没有，不代表别处没有。
2. **错字只被动发现**：专辑对上 MusicBrainz 以后，才比较本地名字和 MusicBrainz 的写法。
3. **艺人联网查身份是独立功能**：整理链不为它建项，也不等它；它查不到，不算整理没做完。
4. **没有配置模型时不猜**：规则能确定的照常做；要在几种可能里挑一种的，不挑，保持原样，配了模型再交给模型。
5. **模型给线索，程序去查、去核对**：写进曲库的外部数据，都来自程序核对通过的那一版 MusicBrainz 数据。模型凭记忆给出的事实不写入。
6. **分清“没有”和“出错”**：出错不是结论，不能因此改用更弱的线索，也不记“未匹配”。

ADR 0006 第 16.1 节的原则 1、2、4、5，以及“模型用量不是优化目标”，继续有效。原则 3 改为：模型的产出写入前由后端核对，核对不了的不写入；整理链里不再有独立审查（第 6 节）。

## 3. 扫描

### 3.1 什么时候扫

- 手动扫描和每天定时扫描保留。
- 加目录监听：
  - 首次全量扫描完成后，才开始监听各曲库目录。
  - 文件新建、删除、改动、改名，都记到它所在的目录上，同一目录的事件合并。最后一次事件后安静 2 秒再处理；文件一直在写，就一直往后推。
  - 到期后只重扫这个目录。碟片子目录连同上一级一起扫。
- 读文件前后各取一次修改时间，变了就丢掉这次结果，等文件写完后的那次事件再读。
- 监听不到的曲库目录，改为定时增量扫描：
  - 由程序自动识别：挂载类型是网络共享（NFS、SMB 等），或系统监听数量到了上限、挂不上。程序不改系统的监听上限。
  - 间隔可选 15 分钟、1 小时、4 小时、12 小时、每天，默认 1 小时。
  - 设置页给每个曲库目录标出“实时监听”还是“定时扫描”。
- 以下沿用：跳过规则；变化判断（大小、微秒修改时间、解析规则版本）；按内容认出移动和改名；逐字节比较路径。

### 3.2 读标签

- 补读以下字段，按设计稿的读取规则存好；先不用于显示、整理和播放：
  - 总曲数；
  - 总碟数：小于碟号时改成碟号，0 当没提供；
  - 完整的发行日期、原始发行日期；
  - 单曲、现场、私录、EP、原声、主版本标记；
  - 录制或演出日期；
  - 音量增益与峰值（去掉 dB 后缀）；
  - 同步歌词：超过 75% 的行带时间戳才算；
  - 播客与有声书标记；
  - 注释：ID3 的 COMM、Vorbis 的 COMMENT 与 DESCRIPTION、MP4 的 ©cmt、APE 的 Comment。注释交给模型找编号线索（第 6.3 节）。
- MP3 的流派写成编号时（如“(17)”），按 ID3v1 编号表翻成名字。TCON 的第一个值是 Podcast 或 Literature 时，当作媒体类型，不当流派。
- 扩展名只做预筛：
  - 音频扩展名的文件和没有扩展名的文件，按文件头判断真实格式；
  - “认不出格式”和“读文件出错”分开记；
  - 图片、文本、CUE 等已知非音频扩展名，不读文件头。
- 艺人名只按明确的合作标记拆：分号（含全角）、` / `、`feat.`、`ft.`、`with`、顿号、换行、NUL。
  - `&`、逗号、紧贴的 `/` 不拆。
  - 去掉受保护名单，也去掉“`&` 两边都是多个词才拆”的规则。
  - 对上 MusicBrainz 后按它的分法拆（第 4.5 节）。含 `&`、逗号的名字，配了模型时交本地辅助（第 6.2 节）。
- 旧编码（GBK、Big5 等）的解码挪进扫描：
  - 同一张专辑里只有一种编码读得通的，扫描直接按它解整张；
  - 几种都读得通的，保持原样，不拿去搜索；配了模型时交本地辅助，判断整张用哪种。
- 中文古典流派按名单认（古典、古典音乐、古典乐），不再按“含古典两字”。“新古典”“古典跨界”之类不算古典。
- 上次加的这些规则保留：
  - 占位值（“Unknown Artist”“Track 01”）当没有值；
  - 没写专辑艺人、曲目艺人又分散的，判为合辑；
  - 黑胶曲号 A1、B2 按面解析；
  - 识别“艺人 - 年份 - 专辑”等目录名，并去掉格式字样；
  - ID3v1 只在没有 ID3v2 时读。
- 这些改动只升一次解析规则版本，升级后的第一次扫描自动重读全部文件。

### 3.3 归组

- **同一目录出现两个以上专辑名**：
  1. 先看整个目录的曲号是否从 1 到 N、不缺不重。依次用四种读法检验：标签的碟号和曲号；文件名推断的；两者混合；只用文件名曲号。任一种连续，就整个目录算一张。
  2. 不连续，就按音频格式分开，每份再检验一次。
  3. 仍不连续，才按专辑名拆；有曲目缺专辑名时，按“艺人 + 专辑名”分。
  - 不做“过半就合成一张”。
- **碟片子目录**：
  - 目录名是 disc、disk、cd 加编号的，一律并到上一级，碟号从目录名读；
  - 带名字的碟目录（如“CD1 - 早期作品”）并进同一张，名字记为碟标题；
  - Bonus、特典等附加碟也并进同一张，排在正碟后面。
- **专辑名比较**用合并键：忽略大小写、标点、空格、变音符号。上次加的两条补丁（一首异名、括号后缀不同）去掉。
- 文件里的 MusicBrainz 专辑编号不参与归组。
- **没写专辑艺人时**：有人过半，就用他；没人过半时，2–4 位并列为“A / B”，5 位以上算群星。
- **版本词**：从目录名、专辑名的括号里抽出 Deluxe、Remastered 等存好；年份和 EP、单曲、原声不算。版本词不参与归组和身份。
- **附属文件**：专辑目录及其 Art、Artwork、Scans、Extras 子目录里的图片和文档，都绑到专辑；图片记下格式和尺寸。
- **排序键**：去标点，折叠变音，开头的英文 “The ” 挪到末尾。用于艺人、专辑列表排序。
- 这些改动只升一次归组规则版本。

### 3.4 定不了时（没有配置模型）

| 情况 | 做法 |
| --- | --- |
| 只有文件名、没有标签 | 不按“ - ”拆出艺人。整串去掉开头曲号和格式字样后当标题，艺人为“未知艺术家”，专辑名用目录名 |
| 旧编码几种读法都通 | 保持原样（第 3.2 节） |
| 同目录几个专辑名、曲号不连续 | 按专辑名拆（第 3.3 节） |
| 认不出的碟目录名 | 每个目录各算一张 |
| 缺碟号、缺曲号 | 明确写出的照用（CD2、1-03、A1）。不从“曲号从 1 重新开始”推断第 2 碟；没编号的按文件名顺序排，但不写曲号 |
| 同一字段几首不一致 | 有明确多数，照多数；打平就不填，标“有冲突” |

这六类再加“专辑名里混着艺人名”，配了模型时交本地辅助（第 6.2 节）。

### 3.5 不改的

- 文件出问题（根不可用、子目录读不了、文件损坏、移动有歧义）时，先保住旧数据，下一轮再处理。
- 以下沿用：目录号与作品拆分的条件、演职员角色、流派原样保存、支持的格式。
- 不在本轮：乐器编制推导；新读字段的用法；WMA 等格式。

## 4. 程序整理

### 4.1 哪些专辑拿去查

- 已对上 MusicBrainz 的不再查；本地文件变了，才重新核对。
- 满足以下任一条件才查。散曲用同一标准。
  - 专辑名和艺人都有：标签写的，或从“艺人 - 专辑”目录名认出的。合辑算有艺人。
  - 有编号：MusicBrainz 专辑编号、光盘目录、条码、目录号、ISRC。
- 名字只有一半、又没有编号的不查。配了模型时，先由本地辅助补全名字再查。
- 标题和艺人都是占位、又没有编号的，不按名字搜；配了声纹就用声纹。
- 播客、有声书不查。
- 本地信息齐全的照查，排在最后。

### 4.2 查找顺序

按精准程度依次尝试。某一步什么都没查到，才进下一步；查到正确的就停：

1. 文件里的 MusicBrainz 专辑编号；
2. 光盘目录（抓轨 log 或 CUE 里的 TOC）；
3. 条码；
4. 目录号（连同厂牌）；
5. ISRC（抽 4 首）；
6. 声纹（AcoustID，抽 4 首），查到的直接是 MusicBrainz 的录音与发行编号；
7. 名字（只对名字齐全的）：
   1. 专辑名 + 艺人 + 曲数；
   2. 零结果，才去掉“豪华版”“320k”这类字样，不限曲数再搜；
   3. 仍是零结果，才按艺人名查 MusicBrainz 艺人；只有一位时，按他的编号搜。

- 搜索只用本地名字；配了模型时，用本地辅助理顺的名字。不再有巡检给的规范写法，也不再为它重搜。
- **有冲突**：
  - 某一步查到了，但和本地对不上（如编号指向的那一版曲数、时长差很多），就停下记“有冲突”，不再用更弱的线索去找。
  - 几个同名专辑不在同一发行组，也记“有冲突”。
  - 配了模型交识别判断（第 6.3 节），没配保持原样。

### 4.3 怎么判定是这一张

- 单个候选的结构核对沿用：
  - 按名字搜到的：每张碟曲数一样；可比的时长逐首在 3 秒或 1% 以内；至少一半曲目能比时长；4 首以下的，还要专辑名和艺人一样。
  - 按编号查到的：曲数一样，再加一样佐证。
  - 以下都算冲突：任一首时长差太多；条码或目录号不同；文件里的编号指向别处。
- **同一发行组里多版都对得上**：同组、专辑名和艺人在合并键下一样、曲数一样的，直接认到组，不逐版读详情，也不交模型。本地曲名是推断的、要补曲名时，只读最早那一版的详情。
  - 合辑、古典、4 首以下的短专辑仍逐版核对。
- **本地少几首或多几首**：除了每首的曲名、时长对上，还要专辑名和艺人在合并键下一样。

### 4.4 查询中途出错

- 单次请求的重试沿用：10 秒内最多 5 次；429、503 按对方给的等待时间。
- 来源暂停：
  - 连续失败时从 5 秒起翻倍，最长 3 分钟；成功一次清零。
  - 对方用 Retry-After 明确要求更久时，按对方的。
  - 来源长时间不可用，就按 3 分钟一轮反复试，整理进度提示该来源不可用；不给每张专辑累计失败次数。
- 因来源暂停而等着的专辑：
  - 来源一恢复就排回队列，从出错的那一步接着查，前面的结果走缓存；
  - 界面显示“等待重试”和是哪个来源。
- 只和这张专辑有关的错误（响应解析不了、本地算不出声纹），按专辑计次：
  - 间隔最长 3 分钟，连续 3 次就记“查询出错”并停下；
  - 本地文件变了或规则升级了再查。
- 声纹来源被关掉或密钥失效时，跳过这一步；临时出错则等它恢复。

### 4.5 认出来以后写什么

- 写在自动层，不改文件，人工改过的不动。规则沿用 ADR 0006 第 4、5 节与第 16.5 节。
- 认到具体一版时，只补空的：
  - 专辑名（只在占位时）、专辑艺人、厂牌、目录号、条码、年份；
  - 曲名（占位或推断时）、曲目艺人（占位时）。
  - 已有的不改。名字不同的，按第 6.4 节被动判断。
- 认到组时：
  - 建对应、补封面；
  - 年份为空时，用发行组的首发年份补；
  - 厂牌、条码、目录号不补；
  - 曲名只在本地是推断的时候，从最早那一版补。
- 艺人对应：
  - 人数相同的，按位置对应（沿用）。
  - 人数不同的：本地署名文字和 MusicBrainz 署名（各人名字加连接词）拼起来一样时，按 MusicBrainz 的分法拆成几位，各自建对应，显示仍用本地写法。
  - 拼不出来的不拆，配了模型交本地辅助。
- 两张本地专辑认到同一版：
  - 没有重复曲目、合起来正好是这一版的几张碟的，由程序直接合并；
  - 有重复曲目的不合并，放进同一个版本组；
  - 其余的，配了模型交模型，没配保持原样。

### 4.6 结论、重查与撤销

| 结论 | 显示 | 什么时候重查 |
| --- | --- | --- |
| 已匹配 | 已匹配 + 平台标签 | 本地文件变了，或规则升级要求重新核对时 |
| 未匹配 | 未匹配 + 查过的平台标签；查询时间放在提示里 | 本地文件变了、规则升级时立即重查。否则 90 天重查一次，走第 4.2 节的全部程序步骤（含声纹），不交模型 |
| 有冲突 | 有冲突 + 平台标签；提示里写冲突在哪 | 本地变了、规则升级时；配了模型交识别判断 |
| 候选都被撤销，或被别的专辑占用 | 归入未匹配，提示“候选已撤销” | 本地变了、规则升级时；撤销过的那一版不再自动认 |
| 等待重试 | 等待重试 + 来源 | 来源恢复后接着查 |
| 查询出错 | 查询出错 | 本地变了、规则升级时 |

- “未匹配”取代“未收录”，并记下来源和查询时间。以后加了别的来源，各来源的结论各记各的，互不覆盖。
- 以下沿用：
  - 撤销：单条、按批次、按来源；
  - 撤销后不再自动写同一个值；
  - 文件标签改了，对应的自动值作废；
  - 总开关默认关。

### 4.7 封面、歌词、艺人资料

- 封面、歌词只补本地没有的，规则沿用。歌词找到几份、内容不同的，不写。
- 已对上 MusicBrainz 的艺人补图片和简介，沿用；这类查询排在全部专辑识别之后。

## 5. 排队、限流与规则版本

- 5 条队列（识别、封面、歌词、艺人资料、本地声纹）各自一次处理一项，互相并行；识别一次一张。各来源的限速沿用，MusicBrainz 每秒 1 次。
- 去掉“来源失败后发送间隔翻倍放慢”：来源暂停已经挡住了失败期间的请求。
- 几项抢同一个来源时，先后是：界面上的操作 → 专辑识别（本地齐全的专辑排在识别的最后）→ 艺人资料。
- 提前查 AcoustID：
  - 声纹那条队列提前替后面的专辑算好声纹、查好 AcoustID，识别时直接用结果；
  - 只对第 4.2 节前 5 步都没有线索、会走到第 6 步的专辑提前查。
- 专辑成员 60 秒没变后，只重扫这张专辑所在的目录确认，不再为确认去扫全库。
- 请求之间原因不明的空等，实施时用模拟上游计时查清，能去掉就去掉。
- **规则版本**：
  - 扫描规则升级沿用：重读、重新归组，专辑和曲目编号尽量延续，对应、收藏、手动修改都不丢。
  - 识别规则升级，默认只重查没匹配上的（未匹配、有冲突、查询出错），已匹配的不重查。只有修的是“可能认错”的问题，才在那次升级里注明“已匹配的也重新核对”；核对只读已对上的那一版，不重新搜索。
  - 只有文件变了才算本地变化，算法变了不算。逐版兼容的代码去掉。
  - 去掉巡检提示词版本。旧编码挪进扫描后，本地整理规则版本只管本地辅助。

## 6. 模型

### 6.1 调用的通用规则

- 并发沿用：默认 4 个会话，可改为 1–16。
- 整理链里的模型任务只剩三类，按这个先后：本地辅助 → 识别判断 → 名字差异与艺人身份。
  - 所有模型任务共用一个模型，不为本地辅助单独配模型。
  - 没配模型时，三类都不做，设置页显示“未配置模型”。
- 报错分五类：
  1. **请求本身的问题**（400 等）：
     - 不暂停模型；这一项记“模型拒绝了请求”和原因，不重试；本地变了或换了模型再试。
     - 连续 10 项同样报错，按第 2 类处理。
  2. **配置问题**（401、403、模型不存在、不支持工具调用）：
     - 不重试，停下全部模型任务，设置页写明原因；
     - 改了设置，或“测试/重试”成功后恢复。
  3. **额度用完**（402，或 429、400 里写明额度、余额不足）：
     - 停下模型任务，设置页提示；
     - 每小时用一个很小的请求自动试一次，也可以手动重试。
  4. **临时问题**（429 限流，500、502、503、504、529，超时，连不上，回复中途断了）：
     - 先在 10 秒内快速重试；
     - 还不行，整个模型暂停：按对方给的时间；没给就从 5 秒起翻倍，最长 3 分钟，成功一次清零。
  5. **回复格式不对、空返回**：
     - 这一项重来，间隔最长 3 分钟；连续 3 次都这样，记“模型没给出结果”并停下；本地变了或换了模型再试。
     - 连续 10 项空返回，就暂停模型任务，设置页提示“这个模型可能不支持工具调用，建议换一个”。
- 出错不算这一项的次数。模型明确说“定不了”算一个答案：记下理由，不重试。
- 需要的来源在暂停时，不开模型会话。
- 额度：
  - 整理与艺人联网的模型用量合成一份，默认每天 1000 万 token；管家对话照旧不计入。
  - 用完就停下模型任务，排着的不丢；第二天，或用户调高额度后，接着做。
  - 去掉单独的联网额度，也去掉每项“用满后 7 天不再试”。
- 单次最多发送：
  - 默认 12.8 万 token，设置里可改，并提示本机模型的上下文长度。
  - 凑批不超过它，并给回答留出余量。
  - 单张就超长的，先只留最接近的几个候选；还超，就不交模型，记“内容太长”。
- 分批：识别判断和名字核对一次带多张同类的，按内容长短凑批；本地辅助一次一个目录。整批被拒（400）时，拆开一张一张重试。
- 升级时：清掉巡检项、联网项和“未采用的建议”；已写进曲库的结果保留，都能撤销；模型以前给的结论保留。

### 6.2 本地辅助

- 交给它的情况：
  - 只有文件名、没有标签；
  - 旧编码有几种读法；
  - 艺人名里的 `&`、逗号是不是几个人；
  - 同目录几个专辑名、曲号又不连续；
  - 认不出的碟目录名；
  - 缺碟号、缺曲号；
  - 专辑名里混着艺人名。
- 模型看到这张专辑或这个目录的完整本地内容：标签、几种读法、注释、文件名、目录名。不查外部，不联网。
- 交回四种内容，写入前各有固定核对：
  1. **文字**：和本地原文等价，不能多出本地没有的字。比较时不分大小写、全半角、变音、简繁、平假名与片假名、多余空格；下划线、点号、连字符等标点当空格看。
  2. **编码**：只能从候选编码里选一种，字由程序按它从原始字节解出。
  3. **拆名字**：拆出的几段按原顺序、加上原来的连接符，拼回去要和原文一模一样。
  4. **归组**：哪些文件是一张、第几碟、第几首。每个文件只能出现一次；同一张碟里曲号不能重复。
- 归组存成单独一条“模型归组”记录，下次归组时生效；用户手动合并、拆分过的不动；可撤销。
- 写入的值标为推断，放在自动层最低一级；MusicBrainz 对上时由它的数据替换；可撤销，不审查。
- 模型凭知识写的内容（改错字、补缺的艺人、整张曲目表）不直接写入，改作识别判断的线索。
- 需要本地辅助的专辑，先做本地辅助，再查 MusicBrainz；没配模型就跳过。

### 6.3 识别判断

- 程序定不了的专辑（未匹配、有冲突）交给模型，只调用一次，不用工具循环。
- 模型拿到：本地信息（标签、注释、文件名、目录名、曲目和时长）、程序找到的候选和详情、程序搜过什么、冲突在哪。
- 模型的回答：
  - 可以选一个候选，也可以不选；
  - 再按把握从大到小，给出 0 到 n 组线索；
  - 一个也给不出，就是“定不了”。
- 线索有五种：

| 线索 | 程序怎么用 |
| --- | --- |
| 名字：专辑名、艺人名、曲名的正确写法，或原文、简繁、英文、罗马字写法；古典的作曲家、作品名 | 按第 4.2 节第 7 步再搜；散曲按曲名、艺人、时长搜录音 |
| 同名艺人选哪一位：程序列出 MusicBrainz 上同名的几位和备注 | 按这一位的编号搜他的专辑 |
| 本地内容里的编号：目录号、条码 | 按第 4.2 节第 3、4 步查。编号必须能在本地内容（含注释）里原样找到 |
| 版本线索：本地写着的年份、地区、版本、介质 | 在同组各版里挑出这一版，从认到组提升为认到具体一版 |
| 专辑类型：原声带、合辑、现场；或其实是有声书、播客 | 合辑按群星搜；不是音乐就停止查询 |

- 程序怎么查：
  - 先核对模型选中的候选，再按顺序逐组去查；哪一组查到一张、并通过第 4.3 节的核对，就停。
  - 每张专辑最多多发 6 次请求。
  - 某一组查出几张都对得上、分不出是哪张，就记“有冲突”并停下，不再交模型。整理页列出这几张，用户点一下就能定，选中的照样过结构核对；不点就保持原样。
- 模型不联网，也不自己查 MusicBrainz。不收模型凭记忆给的事实，也不收本地内容里找不到原文的编号。写入的内容只来自那一版 MusicBrainz 数据，不审查。
- 模型回答“定不了”，就保持原样，没有下一档。本地文件变了、规则升级、90 天重查时，先由程序查，程序还定不了再交模型。
- 交给模型的专辑，程序不再处理。模型结论写入前，先核对本地是否变化（沿用）。

### 6.4 名字差异与艺人身份

专辑认到具体一版、结构核对通过后，比较本地写的专辑名、专辑艺人、曲名、曲目艺人与 MusicBrainz 的写法。专辑对上就算完成；名字核对另外排队，不拖着专辑。

| 情况 | 做法 |
| --- | --- |
| 只差大小写、标点、空格、全半角、变音、简繁 | 不算差异 |
| 一边是中日韩文，一边是拉丁字母 | 程序认定是译名或罗马字，保留本地写法 |
| 只多了 “(Remastered 2009)”“- Live”“feat. X” 这类后缀 | 保留本地写法 |
| 同一种文字，只差一两个字 | 交模型。是错字，就改用 MusicBrainz 的写法（写在自动层，可撤销，人工改过的不动）；不是，就保留本地写法 |
| 同一种文字，差很多 | 保留本地写法 |

- 不再积累“未采用的建议”。专辑页显示 MusicBrainz 的写法，用户点一下就能改用。
- 艺人是不是同一人：
  - 名字一样，或在 MusicBrainz 别名里的，直接建对应。
  - 作曲家和演奏者对调的，不建（沿用）。
  - 其余署名不同的，以及两个本地艺人对上同一位 MusicBrainz 艺人、证据又不够的，交模型判断：
    - 是同一人，就建对应，或把两个本地艺人合成一个；可撤销，艺人页注明“由模型判断”；
    - 不是，就记住结论，同一对名字不再问。
- 不审查。代价：判错时，那位艺人的图片和简介会跟着错，直到撤销（第 12 节）。
- 设置里的“审查模型”管家对话也在用，不随整理链去掉。

## 7. 艺人联网查身份

- 不再自动跑，改为两种手动入口：
  - 在艺人页点“联网查找”，查这一位；
  - “整理艺人”按钮一键把所有没对上 MusicBrainz 的艺人排进去。按钮只显示图标，文字放在提示和读屏名里。排队时专辑艺人在前，合辑里各首的艺人在后；查过且本地没变的跳过；随时可以停，额度用完就停，之后接着查。
- 每位艺人最多 10 次工具调用、5 万 token。
- 查到的候选由程序核对：用候选的 MusicBrainz 艺人编号去搜本地这位艺人的专辑。
  - 有一张结构对得上，就直接建对应，那张专辑也一起认出来。
  - 对不上，就把候选列在艺人页，用户点一下确认或否掉。
  - 不审查。
- 额度和整理共用（第 6.1 节）。管家设置里配了网页搜索，才显示这个按钮。
- 确认对应以后，图片、简介由整理链照常补。

## 8. 测试与文档

- 每个实施子任务只跑改动涉及的单元和集成测试，用合成数据；新规则都配对照样本。
- 固定样本回归：
  - 在模拟上游里做一套固定样本，覆盖这些难点：同组版本多、目录名带艺人、错字、乱码、罗马字对日文、合辑、多碟、只有文件名。
  - 程序加脚本模型对它跑，每次结果一样。
  - 看四样：认对几张、认错几张（必须为 0）、每张发几次请求、用时。
- 真实模型只在本地辅助、识别判断、名字核对的提示词定稿时，挑几张样本试，每次先问用户。全量真实轮不作门槛，只在用户要求时跑。
- 专辑是否达标只看识别和写入，附带项不影响。
- 文档：
  - 整理合同在实施完以后按本 ADR 重写，只讲现在是怎样；
  - 扫描规范随扫描子任务修正；
  - 各子任务改到哪一段，就同步改那一段的规范。

| 模型凭知识补年份、厂牌 | 没法核对，写错了也查不出来 |

| 混放目录“过半就合成一张” | 设计稿里没有，会把少数曲目吞进别的专辑 |
| 按文件里的 MusicBrainz 编号归组 | 同一张专辑的两种格式放在两个目录时，会并成一张，每首出现两遍 |
| 艺人名的受保护名单 | 名单永远列不全；`&`、逗号不拆以后也不再需要 |
| 没有模型时，按全库多数挑旧编码 | 是猜（第 2 节原则 4） |
| 联网与整理各一份额度 | 用户定为合成一份，不够再手动加 |
| 识别一次查两张 | 只能用上等 AcoustID 的空档，快不到三成，还要处理两张同时写同一位艺人；改为提前查 AcoustID |
| 加网易云、QQ 音乐等来源 | 超出第 2 节原则 1，要做就另立功能 |

## 12. 已接受的剩余风险

- 同名不同人共用一个本地艺人。这是一直以来的限制，拆开要另做一套区分规则。
- 占位词判定变宽：真名恰好叫 “Unknown”“Track 1” 的，不会拿去搜索，显示不变。
- 零候选放宽时，可能去掉独立的格式词（如 “Web of Lies” 里的 Web）；最坏是白搜一次。
- 认到组时，不给客串和合辑里的曲目艺人建对应，等认到具体一版再建。
- 模型把“同一人”或“错字”判错时，错的写入会一直留到被撤销。
- 网络共享的定时扫描每次都要把整棵目录过一遍：曲库大时要几十秒到几分钟，也可能让 NAS 硬盘无法休眠。
- 本轮扫描规则升级后的第一次扫描，要重读全部文件。
