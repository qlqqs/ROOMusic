| 2026-09-28 | 第九节第 1 项中的首批治理范围：以“字段修正”和“ReleaseGroup 成员调整”两种操作试点共同合同。前者覆盖简单字段写入，后者覆盖跨实体的结构关系（只改 Release 所属组，扫描器更新已有 Release 时不改该字段），以验证检查点与逆操作。艺人合并因尚无艺人实体，不作为试点。人工修正依赖 ADR 0002 身份稳定提供的稳定 ID | 第 1 项其余部分（选共同合同还是轻量替代、审批队列与链式恢复的范围）及第 2–7 项 | 已实施（2026-10） |
| 2026-09-29 | 第九节第 4 项中的目录部分：停用/恢复的幂等指纹绑定路由 root ID；同键同义请求串行为一次执行；同键用于另一个目录或不同参数返回 `idempotency_conflict`；旧记录不做兼容（开发阶段直接重构）。不改键作用域（actor 加操作类型），不新增迁移 | 第 4 项其余部分（资源 revision 与证据依赖、通用幂等作用域、断线对账）及第 1 项其余部分、第 2–3、5–7 项 | 已实施（2026-09-29），见[目录与扫描流程合同](../../../.trellis/spec/backend/library-scan-contracts.md) |
| 2026-10-02 | 成员写操作（创建、停用/启用、撤销会话）的 `Idempotency-Key` 这次不做，延到人工修正的规划，随“成员管理是否纳入受治理操作”一起决定；在此之前前端保持“结果不明时刷新列表核对”，不自动重试成员写操作，重复创建由用户名唯一约束返回 `409 username_taken`，不会建出第二个账号 | 第 1 项中成员管理是否纳入受治理操作及持久审计何时补齐，第 2–7 项，第 4 项其余部分 | — |
| 2026-10-13 | 人工修正范围内的第 1 项其余与第 2–6 项：**第 1 项**最小共同合同——新包 `internal/operations`（操作记录、共同写入流程 `Run`、按类型注册的撤销与展示能力 `Kind`），字段修正与归组两种试点共用；不做审批队列与链式恢复；成员管理不纳入首批（单独接入：补幂等键并写记录，不提供撤销）；**第 2 项**两种试点只有管理员可执行，人类管理员的一次明确提交即生效，不需要独立审批，普通成员只读；**第 3 项**操作者取自会话，首批不记录执行模式（随管家引入），没有批准对象因而没有批准期限与失效规则；**第 4 项**资源版本 = 发行的 `edit_revision`，幂等作用域 = 操作者 + 键（跨操作类型），指纹含类型、目标、预期版本与完整语义，同键并发由 advisory lock 串行，结果不确定时用同一个键重试对账；**第 5 项**检查点 = 记录里的类型化前后状态，永久保留，逆操作按类型注册，只支持单条撤销（只撤销发行最近一次修改，撤销不能再撤销），不支持链式恢复；**第 6 项**业务变化与记录同一事务，被拒绝与失败的尝试不记录（与目录操作一致），目录操作记录不迁移 | 第 7 项（结构操作与管家 Agent 的边界）；审批队列、链式恢复、`editor`；成员写操作的幂等与记录（单独接入） | 已实施（2026-10，[受治理操作合同](../../../.trellis/spec/backend/governance-contracts.md)） |
| 2026-10-14 | 第 7 项中的第一种版本关系操作——**设定默认版本**：新操作类型 `release_group_default`，目标类型 `release_group`（专辑）；只有管理员，提交即生效、不弹确认（随时可撤销、不丢数据），不需要独立审批；资源版本是**组自己的** `edit_revision`（只有默认版本的设定、清除与撤销递增，不借用发行的版本号）；幂等与指纹沿用共同写入流程；只能撤销专辑最近一次默认版本调整，撤销恢复前态的意图（包括已失效的前态），撤销不能再撤销；共同合同相应扩展：撤销响应改为目标类型加目标 ID，操作记录列表可按专辑筛选、与发行筛选同给时取并集，列表项增加 `album` | 第 7 项其余：Release 合并/拆分、修正迁移（认领）等结构操作与管家 Agent 的边界；审批队列、链式恢复、`editor` | 已实施（2026-10，[默认版本与版本对比合同](../../../.trellis/spec/backend/default-version-contracts.md)） |
| 2026-10-17 | 第 7 项中的**核对问题**（问题处理）：新操作类型 `release_issue_review`，目标是发行；只有管理员，提交即生效、不弹确认（随时可撤销、不丢数据）；资源版本与修正、归组共用发行的 `edit_revision`（撤销规则仍是“只撤销最近一次修改”）；请求带页面读到的依据令牌，问题在页面打开之后被扫描改了就 `409 issue_changed`；核对与取消核对都写记录、可以单条撤销，撤销恢复前态的核对（包括已过期的、原来的核对人），撤销不能再撤销；扫描观察照旧不建变更集 | 第 7 项其余：Release 合并/拆分、修正迁移（认领）等结构操作与管家 Agent 的边界；审批队列、链式恢复、`editor` | 已实施（2026-10，[核对合同](../../../.trellis/spec/backend/issue-review-contracts.md)） |
| 2026-10-17 | 第 7 项中的**认领**（修正迁移）：新操作类型 `release_claim`，目标是新版本，旧版本与相关专辑的状态写在记录的前后状态里；只有管理员，提交即生效、不弹确认（预览就是确认，随时可撤销）；请求带两个版本的 `edit_revision` 与预览令牌，页面打开之后状态变了就 `409 claim_changed`；一次认领一条记录，撤销恢复两个版本与相关专辑的全部前态（含原核对人），任一方之后又被修改过就 `revert_conflict`，撤销不能再撤销；加锁顺序固定为“记录 → 发行行（UUID 升序）→ 组行（UUID 升序）”；扫描观察照旧不建变更集 | 第 7 项其余：Release 合并/拆分等结构操作与管家 Agent 的边界；审批队列、链式恢复、`editor` | 已实施（2026-10，[认领合同](../../../.trellis/spec/backend/claim-contracts.md)） |
| 2026-11-03 | 单管理员前提下新写操作的**轻量标准**：接入 `operations.Run`；有反向操作可以恢复的不提供撤销（`Revert` 返回 `not_revertible`）；预览令牌只在版本号覆盖不到时才加。已实施的类型不变。2026-10-13 定下的“成员写操作补幂等键并写记录”撤销，不再做 | 第 7 项其余（结构操作搁置；管家 Agent 的边界）；审批队列、链式恢复、`editor` | — |
| 2026-11-04 | 新的艺人目标及合并、拆分、改名、忽略候选（`merge`/`split`/`rename`/`candidate_ignore`）接入 `operations.Run`，记录双方 revision、必要的作用域依据与主次目标；按轻量标准不提供独立的 Revert，用正常的反向命令恢复旧 ID，而不是新建同名 UUID。专辑拆分固定发行快照加既有曲目覆盖，不动态跟随组；忽略持久化具体的名字键对。艺人收藏用独立的类型化表，保留原锚点与时间，合并后按 canonical 去重再分页；治理只经 app 注入的 `personal.RefreshArtistResolution` 在同一事务刷新解析列，失败一起回滚，扫描不写收藏 | 不新增通用审批、`editor`、链式撤销或跨用户个人数据管理 | 已实施（2026-11-05，迁移 0026、0027，[艺人合同](../../../.trellis/spec/backend/artist-contracts.md)） |
| 2026-11-04 | 拆分恢复来源由管理员只读的 merged-sources 接口提供，基于真实合并快照及当前归属，不让前端猜记录文本；按专辑拆分可读取任意角色参与的组，并按专辑名筛选。成员可用有界的 tracks/summaries 接口更新队列的展示元数据；`album_artist` 筛选兼容两种发行级角色，DTO 词表不变 | 不增加写权限、重排队列或新的治理操作；不为合法的合并历史添加未经批准的读取截断、数量或原始 JSON 字节限制 | 已实施（2026-11-05） |
| 2026-11-22 | 由 [ADR 0006](0006-auto-curation-and-sources.md)（第 3、4、5、7、9、10 节）修订本 ADR：**后台自动整理**的写入同样经 `operations.Run`，操作者是开启自动整理的管理员（不新造系统用户），来源增加“自动整理”一种，记下外部源或模型、批次与依据；操作记录可按来源与批次筛选。**自动层的撤销**不核对发行的版本号，按“这个值是否仍是这条操作写的”判断，之后的人工修改不妨碍撤销，自动层的写入不递增 `edit_revision`；可以**按批、按来源撤销**（逐条撤销仍可撤的，返回撤了多少、跳过多少与原因，不是链式恢复）；用户撤销过或不采纳的修改记“不再提出”，不再自动应用。**不可撤销的操作不自动执行**：艺人合并、改名与忽略候选改为可撤销并恢复到操作前原样（修订 2026-11-04 按轻量标准“不提供独立 Revert”的做法；轻量标准对其他新写操作仍适用），艺人拆分不自动提出。**Release 合并/拆分**恢复立项（取代 2026-11-03 的搁置），一律由模型提出并审查，只在强证据下自动使用 | Release 合并/拆分的具体方案（实施前另行批准）；审批队列、链式恢复、`editor` | 已实施（2026-11-22 至 2026-11-23，[自动整理合同](../../../.trellis/spec/backend/curation-contracts.md)）；Release 合并/拆分只做了整张并入，拆分尚未实施 |
