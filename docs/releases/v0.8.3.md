本版重写了自动整理：打开后不需要手动整理、也不需要逐条确认；扫描支持实时监听与定时扫描，并新增全局出站代理。

## 新功能

- **自动整理不用人盯**：标签能定的由程序马上定，开放资料库在后台按限流慢慢补，程序定不了的才交给模型。整理按五条队列进行，某个来源限流只停它自己那一条，中断后从原处接上。整理页显示队列进度、本地分类和每项修改的依据来源。
- **模型修改要有佐证**：模型的修改只有在开放资料库、库里其他专辑的写法或带引用的网页能佐证时才写入；没有佐证的记为“未采用的建议”，可以查看并手动采纳。原来“等人处理”的项目改由核对和未采用的建议代替。
- **整理艺人**：开放资料库查不到的艺人可以手动发起联网查身份，查找进展会优先显示；艺人名字有结构核对，同名不同人会分开记住。
- **目录实时监听与定时扫描**：Linux 上的本地目录默认实时监听，文件改动后几秒内只重扫那个文件夹；网络共享或挂不上监听的目录改为定时扫描，在“设置 › 音乐目录”的目录行里选 15 分钟到每天的间隔，默认 1 小时。
- **全局出站代理**：在“设置 › 网络”里配置 HTTP 或 SOCKS5 代理，服务器访问外网（开放资料库、网页搜索与读取、模型接口）都走它，可以先测试再保存；局域网设备、局域网里的模型地址和本机地址照常直连。
- **模型任务并发**：整理时的模型调用可以并发进行，模型接口的 429/503 会在请求内短暂重试，同一次故障只让冷却翻倍一次。

## 改进

- 扫描读文件更稳：文件在读取中被改动时保留上一次的结果；能识别乱码与 ID3v1、占位词、无专辑艺人的合辑、重起曲号与黑胶分碟、目录噪声与混放目录。
- 扫描归组规则重整，合辑、混放目录和多版本专辑归组更准确；名字来自文件名的曲目可以由本地整理补全字段。
- 自动写入的值按依据分级保存，扫描值变化后对应的自动值会作废并重新判断；每项自动修改都能单条或整批撤销。
- 操作记录里显示模型的归组判断。
- 图标统一：管家用星光，自动整理用魔术棒，网络搜索用地球；修正喜欢页封面、更多菜单和管家面板滚动条的显示。

## 修复

- 来源返回 503/429 时在请求内短重试并按秒级退避，单项的用量跨重试累计。
- 修正子集、超集与部分吻合的发行匹配，旧发行的署名按位置建立艺人对应。
- 收窄乱码判定和合辑判定，正常专辑恢复原来的归组。

## 升级注意

- **不再提供 bridge 部署**，生产只用 host 网络。仍在用 `compose.bridge.yaml` 的实例，升级时下载新版 `compose.yaml`，保留部署目录、项目名、容器名、密码文件和数据挂载；先用 `ss -ltn` 确认 HTTP 端口和回环数据库端口（默认 55439）未被占用。详见部署说明的升级一节。
- 启动时自动执行数据库迁移 0086–0106（整理队列、规则版本、扫描标签与归组、目录监听、出站代理等），无需手动操作。
- 升级后艺人页会在后台重建一次；自动整理按新规则重新检查曲库，开启自动整理的曲库首次会有一段时间的资料库查询和模型调用。之前在后台等待的旧版整理计划会被新规则取代，已采纳的修改和历史记录保留。
