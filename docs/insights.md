# 匿名统计

ROOMusic 默认每天向项目的统计端发送一次匿名心跳，让项目知道大约有多少实例在用、用到了哪些功能。
统计端程序开源在门户项目 [roomusic-site](https://github.com/qlqqs/roomusic-site)，汇总公开在 <https://insights.roomusic.org/>。

## 发送什么

| 字段 | 内容 |
| --- | --- |
| 实例 ID | 首次启动时随机生成，与机器、IP、账号无关 |
| 版本、系统、CPU 架构、是否在容器里运行 | 例如 `0.9.0`、`linux`、`arm64`、是 |
| 曲库规模 | 曲目数与发行数的分档：0、1–999、1 千–1 万、1 万–5 万、5 万以上 |
| 成员数 | 启用账号数的分档：1、2–5、6–20、21 以上 |
| 用到的功能 | 是否开着自动整理、是否配置了管家模型、是否有 MCP 令牌、是否开着局域网设备、是否有人开着参数均衡或卷积、是否开着定时扫描；启用的插件数分档 |
| 用过的播放设备 | 30 天内用过的浏览器、UPnP/DLNA 设备与 Google Cast 设备数，各自分档：0、1、2–5、6 以上 |

**不发送**：曲目、艺人、专辑、文件名、路径、用户名、邮箱、IP、模型地址、密钥，以及任何文字内容。

管理员可以在“设置 › 匿名统计”里看到将要发送的完整内容，和实际发出去的逐字相同。

## 什么时候发

新实例运行满 24 小时后发第一次，之后每天一次。发送失败不重试，等第二天。

## 怎么关闭

- **界面**：“设置 › 匿名统计”关掉开关，立即生效。
- **部署时**：在 `.env` 里加 `ROOMUSIC_INSIGHTS_DISABLED=true` 后重启。第一次启动前就加上，就一次都不会发；界面里的开关会显示为由部署配置关闭。

## 统计端怎么处理

- 只在内存里按 IP 限速，不把 IP 写进文件或日志。
- 同一个实例 ID 只算一个；按最近 7 天、30 天有心跳的实例计数。
- 90 天没有心跳的实例被删除。
- 汇总数字来自各实例自报。
- 公开的使用统计只有活跃实例数和各版本的占比；其他字段只供项目方判断该做什么，不公开。
